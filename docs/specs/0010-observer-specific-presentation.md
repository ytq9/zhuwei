# SPEC 0010：观察者专属呈现与当前回应投递

- 状态：**已裁定（本 Goal 授权）**
- 裁定日期：2026-08-26
- 产品：烛帷
- 上位与协作规格：`SPEC 0001`、`SPEC 0003`、`SPEC 0005`、`SPEC 0007`、`SPEC 0008`、`SPEC 0009`、`SPEC 0011`、`SPEC 0013`
- 适用规则：D&D 5e 2014 / SRD 5.1
- 范围：观察者资格、个人线索、世界内分享、统一投影、观察者专属亲历记录、当前回应可靠投递，以及所有呈现旁路的秘密约束

## 1. 继承关系与变更规则

本规格实现 `SPEC 0001` 对角色知识、秘密投影、多人聚光灯、叙述、裁决说明和错误更正的冻结要求，不修改、缩小或取代 `SPEC 0001`。任何冲突都以 `SPEC 0001` 为准。

本规格裁定的是可执行呈现协议，不把叙述文本变成正史，也不建立新的状态权威。结构化世界事实、角色知识、来源、关系和更正由 Room Durable Object 中的权威事件永久保存；KP 的具体措辞只用于当前回应投递及原冻结 ViewerKey 的亲历记录。

本规格不授权：

- 向玩家提供跨观察者、可补取、可搜索或可由事件重建的完整 KP 旁白、模型消息或语音转写历史；
- 以可靠送达为名建立聊天记录、消息队列、D1 叙述归档或第二套事件日志；
- 让房主、队长、页面、语音 Adapter 或日志系统扩大观察者权限；
- 根据后来入场、后来入席、后来加入队伍或后来获得角色控制权，回补过去的回应；
- 删除现有语音输入能力，或为本协议创建新的 KV、R2、Queue 或其他持久化资源。

### 1.1 2026-08-28 用户修订：亲历对话可回看

用户已明确裁定：角色当时实际在场并取得的对话，离开场景、刷新或稍后回到该场景后仍应可查看；只有当时不在场、没有观察资格的角色才没有相应记录。本修订在“不可回看”“无历史 UI”与固定单槽正文删除等条款发生冲突时优先，且不扩大任何观察者权限。

实现必须把可靠投递槽与亲历记录分开：

- `DeliveryFrame` 仍是每个 ViewerKey 的唯一当前可靠投递槽；
- Room DO 另按 `principal + character` ViewerKey 保存亲历记录，只能由提交时冻结的 AudienceSnapshot 决定谁获得其专属 KP 回应；
- “亲历”以文本成功发布到冻结 ViewerKey 为界：ACK 只证明呈现并清空当前槽，不是取得历史资格的前提；从未成功发布的候选、失败输出和安全撤销内容不进入记录；
- 行动者的原始意图只进入行动者自己的亲历记录，不因同场而广播其可能包含的秘密意图；其他在场者保留其各自实际收到的观察者专属回应；
- 待决问题只进入每个冻结 `pending controller` 自己的 ViewerKey；多人同意不得把受邀者的问题写给发起者。控制权转移后，新控制者不继承旧 ViewerKey 的其他记录，但其实际查看或回答的仍开放问题必须在回答前补入自己的亲历记录；
- 记录绑定当时地点；离场、回场、刷新、断线和普通 DO 重启不删除，后来入场者不得补取；控制权转移或继任 principal 不继承原 principal 的记录；
- ACK 或新回应覆盖只改变当前可靠投递槽，不删除已经亲历的记录；安全暂停、权限撤销和尚未成功发布的回应不得形成可回看副本；
- 亲历记录不是 WorldEvent、机械正史或第二套状态权威，不参与 replay，也不写入 D1 事件归档；更正必须追加明确的新记录，不静默改写旧话；
- 本修订上线前已经被覆盖且只剩哈希 tombstone 的旧正文不得猜测或从事件伪造，历史从仍可取得的当前帧及上线后的新回应开始保存。

因此，下文“完整 KP 旁白历史”专指跨观察者、可补取或可重建的全局历史；本修订允许的 ViewerKey 专属亲历记录不属于该禁止范围。

## 2. 产品结果

玩家只收到其角色在相应世界时刻能够观察、其可信 principal 有权读取的回应。个人线索默认保持私有，直到角色通过同一权威行动事务在世界内分享，或其他角色独立取得相应证据。

玩家界面可以持续查看当前结构化 Read Model，以及同一 ViewerKey 已亲历的有界对话记录，包括其角色已经合法获得的知识、可见世界事实、资源、待决输入和脱敏 Receipt；但不能全文搜索、按旧 ID 重建，或补取从未向该观察者成功发布的 KP 旁白。

可靠投递采用固定单槽协议：

> 每个 ViewerKey 至多保存一个未确认的 DeliveryFrame；刷新、重复轮询、断线和 Worker 重启恢复同一 deliveryId；ACK 或新回应只清空/覆盖当前槽，成功发布的文本进入同一 ViewerKey 的亲历记录；结构化事实与角色知识不受覆盖或 ACK 影响。

## 3. 领域语言

**可信 principal（Trusted Principal）**：由已认证会话得到的用户身份。请求体中的 `userId`、`principalId`、`viewerId` 或 `actorId` 不能建立权限。

**观察者主体（Viewer Subject）**：投影所代表的主体，可以是受控玩家角色、NPC、KP 主持视角或 Room DO 内部视角。普通玩家不能请求 KP、NPC 或内部主体。

**ViewerKey**：`roomId + trustedPrincipal + authorizedViewerSubject + viewerRole` 的稳定组合。它由服务端按当前席位和控制权构造，不由客户端自报。同一 principal 的多个浏览器设备共享同一个 ViewerKey；同一 principal 合法控制多个角色时，每个角色主体具有不同 ViewerKey。

**虚构在场（Fictional Presence）**：观察者主体在结果提交时位于能够通过感官、能力、通信媒介或已固化特殊联系接触该结果的世界位置。仅仅是房间成员、房主、队长、网络在线或正在看页面，不构成虚构在场。

**观察资格（Observation Entitlement）**：由虚构在场、感官与能力、遮挡、知识、控制权、内容权限和结果的公开级别共同决定的读取资格。

**AudienceSnapshot**：世界或机械结果提交时，由统一 projector 根据冻结状态确定的具体 ViewerKey 集合及各自 `projectionHash`。它绑定 `eventRange`、`activeBranchId`、相关作用域版本和呈现策略版本；之后不能扩大。

**个人线索（Personal Clue）**：只由一个角色或一组明确角色取得的感官证据、来源主张、角色推断或其他结构化知识。它不是房间级布尔标记，也不因为实物被移动而消失。

**知识所有者（Knowledge Holder）**：权威状态中持有某项结构化知识的角色或 NPC。知识属于世界内主体；其当前合法控制者可以查看该主体的当前知识投影，但不能因此读取先前控制者收到的叙述帧。

**KnowledgeShare**：角色通过说、写、展示、演示、传讯或其他世界内手段，把具体内容传播给冻结接收者的一次权威行动。它必须记录来源、内容粒度、媒介、接收者、时间、地点和因果依据。

**DeliveryFrame**：面向一个 ViewerKey 的当前、可确认、非正史呈现载荷。它绑定已提交结果和专属投影，可以包含文本以及同一内容的语音呈现元数据；它不是 `WorldEvent`、角色知识、聊天消息或 D1 归档记录。

**ACK**：相应可信 principal 明确确认已经收到当前 DeliveryFrame 的 UX 操作。ACK 不代表角色同意、接受、放弃、行动、结束回合或推进虚构时间。

**当前帧不可重取（Non-retrievable Delivery）**：DeliveryFrame 在 ACK、被同一 ViewerKey 的新回应覆盖、权限撤销或安全失效后，不能再通过旧 `deliveryId`、Receipt、实时流、轮询、错误、候选项、日志、语音或归档取得；成功发布且未被安全撤销的文本只可作为原 ViewerKey 的亲历记录保留，音频、TTS 资产、模型 Prompt 和逐字转写不随之归档。

## 4. 观察资格与 Audience 冻结

### 4.1 谁能够观察当前回应

一个玩家 ViewerKey 只有同时满足以下条件才进入 AudienceSnapshot：

1. principal 在结果提交时是合法房间成员并具有相应观察者主体的控制或查看权限；
2. 观察者主体在虚构上位于能够接触结果的位置，或存在已固化、当前有效的远程感知/通信渠道；
3. 该主体的感官、能力、状态和遮挡允许取得相应信息；
4. 结果的可见性策略允许向该主体公开；
5. 内容安全或私人窗口规则没有进一步收窄投影。

网络断线、页面关闭或设备休眠不改变虚构在场。一个断线但角色仍在场且有观察资格的玩家可以进入 AudienceSnapshot，并在恢复连接后取得其仍为当前的 DeliveryFrame。

角色位于另一地点、尚未加入场景、没有相应感官、只拥有房主或队长身份，或者仅能从 KP 全知上下文推知结果时，均不得进入 AudienceSnapshot。

### 4.2 Audience 在提交时冻结

AudienceSnapshot 必须与产生可叙述结果的权威提交绑定。Audience 不能由 LLM、页面、投递器或读取时的当前成员列表决定。

以下变化不能把新 ViewerKey 加入旧 AudienceSnapshot：

- 后来进入该地点或与队伍会合；
- 后来入席、加入房间、接管角色或成为房主/队长；
- 后来获得远程感知能力；
- 后来通过分享获知相关结构化内容；
- 后来因更正以外的原因获得更高权限。

后来入场者可以从当前仍然存在的世界状态形成新的感官证据，例如看到已经烧毁的门；这是一项新的观察事件，不是旧回应回补。短暂声响、已结束的对话和旧旁白不能仅因后来进入同一地点而重现。

席位或控制权转移后，新 principal 可以查看所控制角色当前合法持有的结构化知识，但不能取得该角色以前的 DeliveryFrame。原 principal 一旦失去成员或控制权限，即使曾在 AudienceSnapshot 中，也不能再读取尚未确认的帧；相应槽位必须安全失效或清除。

## 5. 个人线索的取得与私有期

### 5.1 何时保持私有

下列信息默认成为对应角色的个人线索：

- 只有该角色通过位置、感官、被动能力、检定或特殊能力取得的证据；
- NPC、文献、梦境、心灵联系或私人窗口只向该角色传达的来源主张；
- 只有该角色有资格形成的角色推断；
- 玩家为自己角色作出的秘密选择及其尚未公开的结果；
- 内容安全协议明确限定给请求者的现实玩家私人信息。

同一结果如果被多个角色在提交时直接观察，则每个角色分别获得自己的知识事件；这不是一份房间全局线索。角色共同看见一段墙上文字，可以分别取得相同内容，但其来源、完整度和理解层级仍可不同。

个人线索的私有期没有自动到期。以下事实不会自动公开它：

- 角色与队伍重新会合；
- 场景、章节或现实团次结束；
- 玩家刷新、重连或离线；
- 房主、队长或其他玩家请求查看；
- 持有线索的实物被转移、毁坏或遗失；
- 原角色死亡或退役。

角色死亡、退役和继任角色不会自动复制知识。跨角色继承必须由长团生命周期规格允许的世界内来源或明确继承事件建立；在该规格落地前默认不继承。

### 5.2 谁能读取个人线索

个人线索的结构化内容只投影给：

- 该知识所有者的当前合法控制者；
- 按有限知识需要使用该信息的相应 NPC Viewer；
- 可信服务端内部的 KP Viewer 和 Room DO 内部 Viewer；
- 经世界内分享后成为新知识所有者的角色或 NPC。

KP Viewer 的可见性不授权把信息写入玩家回应。房主、队长、同队成员或角色原控制者没有默认读取权。

## 6. 世界内分享协议

### 6.1 分享必须是一项权威行动

玩家分享个人线索时，客户端仍只提交自然语言意图或待决回答。Room Action Module 从可信会话确定 principal 和受控角色，KP 判断媒介、可行性、耗时、是否会被听见或中断，Rules Module 验证必要机械，Room DO 原子提交传播事件及其时间、位置和后果。

分享不能由页面直接把接收者的知识数组补齐，也不能通过桌外“转发 KP 消息”按钮绕过世界。若玩家确实在现实桌外把秘密告诉了另一玩家，产品仍不能把接收者角色视为已经知道；角色知识只由世界内事件改变。

### 6.2 分享内容和范围

每次分享必须冻结以下内容：

- `sourceKnowledgeRef` 或被展示的 Artifact/文献/世界事实引用；
- 分享者实际表达或展示的内容；
- 内容类型：精确转述、摘要、来源主张、推断、感官展示或实物转移；
- 媒介及其可达、可听、可见、可拦截条件；
- 具体接收角色/NPC 集合；
- 分享发生的虚构时间、地点和相关因果范围；
- 接收者取得的知识层级、来源和可信度。

支持的接收范围可以是：

1. 明确点名的一个或多个世界内主体；
2. 当前地点内能够感知该次交流的全部主体；
3. 当前小队或当前房间中满足指定世界内通信条件的主体；
4. 经已固化广播、书面材料、传讯或公开展示实际覆盖的主体。

`全队`、`所有在场者`、`房间里的人` 等集合必须在分享提交时解析为具体世界内主体 ID，并按感官、位置和媒介过滤。以后加入该集合的角色不自动获得知识。

角色声称“门后有宝藏”时，接收者获得带说话者、时间和依据的 SourceClaim，不自动获得门后真实情况。展示火药残留可以让有资格的接收者取得新的 SensoryEvidence；递交遗嘱会改变实物持有关系，但不会撤销分享者已经读过的知识。

### 6.3 分享一律不追溯回应

KnowledgeShare 从其提交时开始影响接收者知识，默认不追溯。接收者可以在之后的 Read Model 中看到新获得的结构化知识及其允许公开的来源，但不能取得：

- 分享者最初收到的 KP 旁白；
- 分享发生前只投递给分享者的 DeliveryFrame；
- 分享者没有表达的额外证据、推断或秘密上下文；
- 同一线索过去的语音、逐字转写、候选项或错误信息。

若分享者希望补充更多内容，必须再次通过世界内行动表达；系统不能从旧叙述文本自动扩写。

## 7. 统一 Read Model 与 projector

`project(module, source, viewer)` 是所有观察者专属领域内容的唯一 Interface。页面、Room Action Module、KP 结果叙述、NPC 决策、快照、增量、结构化知识、Receipt、待决输入、候选项、错误说明和玩家可见活动日志都必须从同一个内部 projector 得到。

统一 projector 必须：

- 从可信服务端构造的判别式 Viewer 取得权限，不接受裸 `viewerId`；
- 同时应用角色知识、感官、位置、AudienceSnapshot、控制权、分支、规则版本和内容安全策略；
- 对快照、增量、错误和候选项采用同一字段可见性，不能在某一路径另写脱敏逻辑；
- 拒绝缺片、断序、哈希不符或版本不匹配的增量，而不是退回原始事件；
- 永不把原始 WorldEvent、KP Viewer、模组真相或内部 flags 交给普通客户端；
- 让同一有效值来源同时服务机械裁决和投影，页面不另算资源、位置、效果或知识；
- 在角色控制因死亡或退役结束后，仍由可信 lifecycle Viewer 经同一 projector 产生最小 `successorRequired` Read Model；服务层和页面不得手写继任视图；
- 由 Rules projector 产出 `restRecoveryOptions` 等机械候选及其上限、资格和预算；页面只能消费并冻结玩家选择，不得重算恢复机械；
- 生成 `projectionHash`，使 DeliveryFrame、Receipt 和重试绑定准确观察者状态。

Read Model 可以包含：

- 当前可见世界事实和感官信息；
- 自己角色的精确资源、状态、物品和结构化知识；
- 被授权的待决输入和候选项；
- 脱敏、无叙述正文的 Receipt；
- 当前 DeliveryFrame 或其 `none/acknowledged/superseded` 状态；
- 已公开且该角色已经取得的裁决更正。

Read Model 可以保留结构化线索簿、角色知识及允许公开的来源链，因为它们是权威世界事实；观察响应还可以附带该 ViewerKey 已成功取得的亲历文本。任何投影都不能保存或重建其他 ViewerKey 或未成功发布的 KP 措辞、模型 Prompt、音频或转写历史。

## 8. DeliveryFrame 单槽协议

### 8.1 帧结构

每个 DeliveryFrame 至少绑定：

- `deliveryId`；
- `roomId` 与 ViewerKey；
- 权威 `receiptId`、`eventRange` 和 `activeBranchId`；
- `projectionHash`；
- `presentationPolicyVersion` 与 `narrationPolicyVersion`；
- 当前回应的文本载荷；
- 可选的同内容语音呈现元数据；
- 创建时间和幂等载荷哈希；
- `unacknowledged` 状态。

DeliveryFrame 不能携带 KP 全知上下文、未投影事实、其他 ViewerKey 的文本、原始 Prompt 或未选候选。

### 8.2 产生顺序

当前回应必须按以下顺序产生：

1. Room DO 原子提交叙事事实、机械结果、Receipt、待决状态和私有 AudienceSnapshot；
2. `project` 根据该提交为 AudienceSnapshot 中每个 ViewerKey 生成专属投影；
3. LLM/KP 在 DO 事务外，仅依据相应专属投影生成结果叙述；
4. Room Action Module 以内部、单次、幂等 capability 请求 Room DO 发布 DeliveryFrame；
5. Room DO 验证 `eventRange + activeBranchId + ViewerKey + projectionHash + policyVersion + payloadHash`，并写入该 ViewerKey 唯一投递槽；
6. 页面经 `observe(viewer)` 取得 Read Model 和当前帧，并在实际呈现后显式 ACK。

LLM 失败时，已经提交的世界结果不回滚。系统停在最近稳定状态，并可用同一绑定重试叙述；重试不能重新掷骰、扣资源、改变 Audience 或产生第二组世界事件。若叙述引入投影中不存在、会影响因果的新事实，则不能发布，必须另走权威行动事务。

### 8.3 刷新、轮询、断线和重启恢复

同一 ViewerKey 在 ACK 前的所有合法读取必须返回相同 `deliveryId`、相同正文和相同载荷哈希。刷新、重复轮询、浏览器多标签、网络响应丢失、断线重连和 Worker/DO 重启不能生成新帧或重复世界结果。

客户端可以携带最后见到的 `deliveryId`，但服务端以 Room DO 当前槽为准。客户端缓存不能恢复已经被服务端 ACK、覆盖、撤销或失效的正文。

现实经过时间不自动 ACK、不产生 `pass`、不推进虚构时间。单槽容量而非完整消息队列是可靠送达的边界：只要该帧仍是相应 ViewerKey 的当前未确认回应且权限未撤销，断线者可以恢复它；系统不承诺恢复被后来回应覆盖的旧叙述。

### 8.4 ACK

ACK 必须携带当前 `deliveryId`，并由可信会话重新鉴权。只有对应 ViewerKey 可以确认。

首次有效 ACK 原子完成：

- 把当前槽标记为已确认；
- 把已呈现文本追加到该 ViewerKey 的亲历记录；
- 删除或使当前槽中的正文、音频载荷和逐字转写不可读取；
- 保留最小化的非内容 tombstone、载荷哈希和幂等 Receipt，以回答重复 ACK；
- 不改变 WorldState、角色知识、待决输入、控制权或虚构时间。

同一 ACK 重试返回原 ACK Receipt，但不返回正文。错误 `deliveryId`、其他 ViewerKey 或已被新帧覆盖的 ID 只能得到统一脱敏结果，不能泄露曾经存在什么内容。

ACK 表示产品已经向该 principal 的 ViewerKey 呈现当前回应。一个设备 ACK 后，同一 ViewerKey 的其他设备不能再把它作为当前 DeliveryFrame 取得，但可以通过该 ViewerKey 的亲历记录查看已呈现文本。

### 8.5 新回应覆盖旧回应

向同一 ViewerKey 发布新的合法 DeliveryFrame 时，Room DO 必须在同一原子写入中：

1. 把旧帧已呈现文本追加到该 ViewerKey 的亲历记录，并使旧 `deliveryId`、音频载荷和当前槽正文不可再取；
2. 保留不含内容的 superseded tombstone；
3. 把唯一槽替换为新 `deliveryId`；
4. 不删除旧帧所对应的结构化事实、知识、Receipt 或更正记录。

没有进入新回应 AudienceSnapshot 的 ViewerKey 不会因该回应获得新帧；其原有当前帧可以继续存在，直到 ACK、收到自己的新回应、权限撤销或安全失效。

### 8.6 更正和分支变化

DeliveryFrame 必须绑定 `activeBranchId` 和 `projectionHash`。更正使当前未确认帧依据失效时，旧正文立即失去“当前真相”资格，只进入原冻结受众各自的亲历记录；更正后的专属投影生成明确的新帧，不能在旧文字上静默打补丁。

已经 ACK 或覆盖的旧帧不会因更正恢复为当前帧。玩家从当前 Read Model 和新的更正回应了解其有权知道的变化；审计所需的旧事件与结构化更正仍由权威事件保存，D1 事件归档不保存亲历叙述正文。

## 9. “不可回看”的精确定义

对普通玩家，以下 Interface 必须不存在或恒不返回超出其 ViewerKey 亲历记录的旧叙述正文：

- KP 回应分页、滚动聊天记录、全文搜索或按时间范围查询；
- 按旧 `deliveryId`、Receipt、eventSeq、branchId 或 projectionHash 重取正文；
- 从 D1 `room_event_archive`、DO 事件、快照或增量重建旁白；
- 从错误堆栈、候选数量、调试字段、网络缓存或模型任务状态取得正文；
- 从语音录音、TTS 资产、逐字转写、字幕或浏览器重连恢复已 ACK/覆盖内容；
- 通过后来加入 Audience、接管角色、加入队伍或到达地点补取过去回应。

当前帧不可重取不删除正史，也不要求玩家忘记已经看到的内容。玩家可以查看其 ViewerKey 的亲历文本，以及角色仍合法持有的结构化事实与知识；产品不会提供跨观察者全局聊天历史，也不会从事件或知识反向伪造旧 KP 措辞。

## 10. 语音、转写、错误、候选项与日志旁路

### 10.1 玩家语音与转写

玩家语音是提交意图的输入 Adapter，不是公开房间消息。原始音频和转写草稿只向提交 principal 显示，直到其成为已认证意图；它们不能因为语音通道而广播给其他玩家、写入运行日志或成为角色知识。

需要澄清时，转写内容及澄清只投影给相应控制者。语音 Adapter 不能自报 actor、选择机械结果、掷骰或扩大 Audience。

### 10.2 KP 语音与字幕

KP 语音、字幕和逐字转写必须是同一 DeliveryFrame 文本的呈现形式，服从相同 ViewerKey、AudienceSnapshot、单槽、覆盖和 ACK。不得存在独立的音频历史、转写历史或无鉴权媒体 URL。

默认可以由客户端对当前帧文本执行本地语音呈现；若使用服务端音频，访问必须绑定同一 ViewerKey 和当前 `deliveryId`，且不得为此新增持久化资源。帧 ACK、覆盖或失效后，相应服务端音频同样不可取得。

### 10.3 错误和候选项

错误、合法动作、目标候选、反应窗口和待决选项必须先经统一 projector。无权观察者不能从“目标不存在”、错误种类、候选数量、响应长度、隐藏 ID、窗口是否存在或重试差异推断秘密。

对无权、不存在、已关闭和已覆盖的秘密引用，应返回在产品上不可区分的脱敏拒绝；内部诊断可以引用秘密原因，但不得进入普通客户端或 Runtime 日志。

### 10.4 日志和可观测性

玩家可见活动日志属于 Read Model，必须经统一 projector，且不能包含旧 KP 旁白。

Runtime telemetry 不是第二个领域内容 projector。它只能记录固定白名单中的非内容元数据，例如脱敏请求类型、结果分类、耗时桶、状态码、规则/策略版本、哈希和关联 ID；不得记录 Cookie、Token、Prompt、自然语言意图、DeliveryFrame 正文、音频、转写、模组真相、未公开线索、内部 flags、候选定义、私人窗口内容或 KP/NPC 秘密投影。

D1 可重建归档可以保存重建正史所需的版本化结构化事件，但不保存 DeliveryFrame、模型输出、语音或逐字转写，并且不能向玩家提供原始读取入口。

## 11. 权威状态、Receipt 与版本

Room DO 是以下活跃数据的唯一权威：

- AudienceSnapshot 及其提交绑定；
- 每个 ViewerKey 的唯一 DeliveryFrame 槽；
- ACK/superseded tombstone 和投递幂等 Receipt；
- 当前角色控制权、观察资格所依赖的世界状态和结构化知识。

DeliveryFrame 不是 WorldEvent，不能参与机械回放，也不能成为世界状态的恢复依据。普通 Worker/DO 实例重启必须从同一 Durable Object 存储恢复当前槽；若发生需要从 D1 事件归档重建整个 DO 的灾难性存储丢失，只重建结构化世界和知识，投递槽为空，不能从 Prompt 或事件生成旧消息历史。需要向玩家说明重建后的当前状态时，必须基于新的当前投影发布新 deliveryId，而不是伪造丢失的旧帧。

`presentationPolicyVersion`、`projectionPolicyVersion` 和 `deliveryProtocolVersion` 必须进入房间版本清单和 DeliveryFrame 绑定。旧房间不得被新 projector 静默扩大可见范围；需要改变旧房间秘密语义时，必须经版本化迁移或可审计更正。安全收窄可以立即使当前帧失效，但不能借机公开新内容。

当前冻结实现把上述统一读取语义固定为 Projection Policy Profile `projection-observer-safe-v1` **1.2.0**，`profileHash = sha256:9312f68960f1c53f79b5c95bfd8c95ab87aec903603796f455a6c1d2d4514d8c`；其完整 Runtime manifest 为 `runtime-srd51-2014-authoritative-v2@sha256:2f7af76e9a7262675210c18528ca9c6bead5c676aecc71113304eaf01f42dbe9`，当前 canonical genesis golden hash 为 `sha256:7e858e340283252d67779ddb1ae773fb5ac5a98d3859fdcef467c58a34935355`。三者是当前 conformance 快照，不是 `latest` 别名；旧房仍按其 genesis 中精确引用选择 Adapter。

新规则版本迁移时不得把旧聊天、线索日志文本或旁白历史导入 DeliveryFrame 槽。Legacy Adapter 只服务明确旧 `ruleset_version`，不能成为新房间的第二投影路径。

## 12. Interface 约束

具体 TypeScript 命名可以变化，但责任语义至少覆盖：

```ts
type ObserverDeliveryOutcome =
  | { kind: "none" }
  | { kind: "current"; frame: DeliveryFrame }
  | { kind: "acknowledged"; deliveryId: string }
  | { kind: "superseded"; deliveryId: string };

observe(viewer: AuthenticatedViewer): Promise<ViewerReadModel>

ackDelivery(input: {
  authenticatedViewer: AuthenticatedViewer;
  deliveryId: string;
  acknowledgementId: string;
}): Promise<AcknowledgementReceipt>
```

`publishDelivery`、AudienceSnapshot 构造和失效操作只属于 Room Action Module 与 Room DO 之间的内部 capability，不是页面 Interface。页面只允许 `observe`、提交意图、回答待决输入和 ACK；不能上传 Audience、projectionHash、叙述正文或授权 ViewerKey。

同一领域事实的外部观察仍只能来自 `project`。`observe` 组合 projector 输出和当前 DeliveryFrame，不自行解释 WorldEvent 或重新计算权限。

## 14. 固定不变量

1. 世界事实和角色知识永久保存在权威事件中；叙述文本不进入正史。
2. 每个 ViewerKey 至多一个未确认 DeliveryFrame。
3. AudienceSnapshot 在结果提交时冻结，后来入场或入席不回补。
4. 只有同一 ViewerKey 的刷新、断线恢复和重启恢复能够取回同一当前帧。
5. ACK、覆盖、权限撤销或安全失效后旧正文不可再取。
6. 新帧覆盖旧文本，不覆盖结构化事实、知识或 Receipt。
7. 个人线索保持私有，直到世界内分享或独立取得；会合、章节切换和角色死亡不自动分享。
8. 分享从提交时向冻结接收者生效，不追溯旧回应。
9. 所有玩家可见领域内容复用同一个 projector。
10. 语音、转写、错误、候选项、增量、日志和重连不能成为秘密旁路。
11. principal、ViewerKey、控制权和 Audience 不能来自请求体自报字段。
12. ACK、断线、现实超时和模型失败都不替角色行动，也不推进虚构时间。

## 15. 验收场景

### O01 私人取得

角色甲单独闻到火药味并收到专属回应。甲的 Read Model 保存相应 SensoryEvidence；角色乙、房主身份下的乙、另一地点玩家、候选项和错误均看不到该证据或回应。

### O02 多个直接观察者

甲乙同时在场并能够看见墙上文字。提交时 AudienceSnapshot 分别包含甲乙 ViewerKey，并为两角色建立各自知识；两人的 DeliveryFrame 可以因背景与能力不同而不同，任何一个 ACK 不影响另一个槽。

### O03 世界内点名分享

甲对乙准确转述个人线索。分享经可信 principal、角色控制权、虚构位置和媒介验证后提交；乙获得带来源的结构化知识，但不能取得甲最初的 KP 旁白或旧 deliveryId。

### O04 主张不等于真相

甲对乙撒谎称门后有宝藏。乙只获得以甲为来源的 SourceClaim，不获得隐藏真相或甲没有表达的感官证据。

### O05 集合范围冻结

甲向“当前全队”展示文献。提交时把当前有资格观察的角色解析为具体接收者；后来加入队伍、后来入席或后来进入地点的角色不获得旧分享和旧回应。

### O06 实物与知识分离

甲把已经读过的遗嘱交给乙，随后遗嘱被毁。实物所有权与销毁状态正确变化；甲乙已经取得的结构化知识仍存在，未在场角色没有自动获得内容。

### O07 刷新与重复轮询

同一 ViewerKey 在 ACK 前连续刷新、轮询和多标签读取，始终取得同一 deliveryId、正文和哈希，只存在一个槽和一次世界结果。

### O08 断线与 Worker 重启

Audience 中的玩家在回应到达前断线，并经历 Worker/DO 重启。恢复后仍取得同一当前 deliveryId；没有重复骰面、资源、事件或叙述帧，虚构时间未推进。

### O09 ACK 后不可回看

玩家 ACK 当前帧后，使用旧 deliveryId、Receipt、eventSeq 或语音字幕均不能把它重新取作当前帧；刷新、重连和另一个设备可以在同一 ViewerKey 的亲历记录中查看已呈现文本。当前结构化世界与角色知识仍可查看。

### O10 新回应覆盖

同一 ViewerKey 尚未 ACK 旧帧时收到新回应。唯一槽原子替换为新 deliveryId；旧正文只进入该 ViewerKey 的亲历记录，不能通过旧 deliveryId 或其他观察者入口取得；旧回应对应的事实、知识和脱敏 Receipt 不丢失。

### O11 虚构缺席与后来到场

乙在另一地点时甲收到回应。乙后来进入现场，只能观察仍存在的当前世界事实并形成新证据；乙不能取得甲的旧旁白、已经消散的声响或旧候选项。

### O12 换席与控制权撤销

甲的 principal 在帧未 ACK 时失去角色控制权，新 principal 接管同一角色。旧 principal 不能再读取槽，新 principal 可以看角色当前结构化知识但不能取得旧 DeliveryFrame。

### O13 语音和转写旁路

玩家用语音提交秘密意图，KP 以语音呈现私人结果。原始音频、草稿转写、输出音频和 TTS 均只向对应 ViewerKey 可用，并随当前帧 ACK/覆盖失效；成功提交的意图文本和成功发布的 KP 文本可以进入该 ViewerKey 的亲历记录，其他玩家和日志无法取得。

### O14 错误与候选侧信道

隐藏敌人、私人反应或秘密出口存在。无权观察者提交猜测 ID、请求候选项或制造错误时，响应与对象不存在的情况产品上不可区分，且日志不记录秘密对象或正文。

### O15 模型失败与叙述重试

世界结果已提交后叙述模型失败。状态停在稳定点；以相同事件范围、分支、ViewerKey、projectionHash 和策略版本重试，只发布一个帧，不改变 Audience、不重复机械或世界事件。

### O16 更正使当前帧失效

未 ACK 帧所依据的结果被可审计更正。旧正文立即退出当前槽并只保留在原冻结受众各自的亲历记录；新活动分支按专属投影产生明确的新帧。旧结构化事件仍可审计，无权观察者看不到旧叙述或秘密更正依据。

### O17 跨章节知识与叙述

个人线索跨章节继续存在于原角色知识中；原 ViewerKey 仍可查看其有界亲历文本，但它不转移给继任 principal，也不成为章节级或房间级聊天历史。继任角色默认没有该知识，直到合法世界内来源或生命周期事件授予。

### O18 完整旁路矩阵

同一秘密回应分别从实时流、轮询、增量、亲历记录、刷新、断线重连、错误、候选项、玩家可见日志、Runtime telemetry、语音、转写、Receipt 和 D1 玩家入口尝试读取。只有冻结 Audience 中相应 ViewerKey 的当前槽或亲历记录可以返回其已成功发布文本；其他 ViewerKey、后来入场者、旧 ID、日志、媒体和 D1 入口均不泄漏。

## 16. 自主裁定记录

以下决策均依据本 Goal 的明确授权裁定；测试证据如实标为尚待实现，不把验收设计冒充已运行结果。

### OBS-D001：个人线索的所有权与私有期

- 日期：2026-08-26
- 问题：个人线索归房间、principal 还是世界内角色持有，以及何时自动公开。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + Agent 自主协议裁定。
- 关联 `SPEC 0001`：§9 信息与角色知识、§15 多人桌、§16 连续性；验收 F、K、M。
- 候选方案：房间级已揭示；principal 私人消息；角色级结构化知识且无限期私有。
- 最终选择：知识归世界内角色/NPC；当前合法控制者可看结构化知识；除世界内分享、独立取得或可审计更正外不自动公开。
- 理由：同时保持角色知识连续性、换席合法性、NPC 有限知识和秘密隔离，且不依赖叙述历史。
- 玩家可观察行为：会合、章节切换、房主请求或实物毁坏都不会自动把个人线索显示给别人。
- 秘密与权限影响：房主、队长和原控制者无额外读取权；KP Viewer 只可内部使用。
- 迁移/可逆性：新规则版本把旧房间级 clue 标记隔离在 Legacy Adapter；不能把既有全桌线索猜测为个人线索。未来改变所有权需新版本和显式迁移。
- 验收场景：O01、O02、O06、O12、O17。
- 测试证据：尚未实现；应由 `project`、控制权变更和跨章节 Interface 测试提供。

### OBS-D002：世界内分享、范围与非追溯

- 日期：2026-08-26
- 问题：玩家如何分享个人线索，接收范围如何确定，是否回补旧叙述。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + Agent 自主协议裁定。
- 关联 `SPEC 0001`：§9 来源/证据/知识、§19 标准 KP 循环；验收 A、F、M。
- 候选方案：桌外一键复制知识；直接转发旧 KP 消息；通过权威世界内行动传播结构化内容。
- 最终选择：只通过权威行动事务提交 KnowledgeShare；集合范围在提交时解析为具体主体；分享从该时刻生效且永不回补旧 DeliveryFrame。
- 理由：传播本身可能耗时、被听见、中断或失真，必须成为因果事实；非追溯避免可靠缓存退化为历史。
- 玩家可观察行为：可以点名告知、当众展示或通过已固化媒介广播；接收者看到所得知识及来源，不看到分享者旧旁白。
- 秘密与权限影响：页面不能直接改接收者知识；SourceClaim 不提升为隐藏真相；后来加入集合者不补发。
- 迁移/可逆性：新增分享事件可追加而不改旧知识；错误传播通过更正或后续世界事件处理，不能删除历史。
- 验收场景：O03、O04、O05、O06。
- 测试证据：尚未实现；应由 Room Action、`step/project` 和 Viewer 矩阵测试提供。

### OBS-D003：Audience 在结果提交时冻结

- 日期：2026-08-26
- 问题：回应 Audience 应在提交、叙述生成还是读取时计算。
- 来源类别：Goal 明确指定 + `SPEC 0001` 冻结原则。
- 关联 `SPEC 0001`：§7 隐藏现实固化、§9 私人投影、§15 私人信息；验收 E、F、K、M。
- 候选方案：读取时按当前成员计算；叙述发布时由模型选择；结果提交时由 projector 冻结 ViewerKey。
- 最终选择：AudienceSnapshot 在权威结果提交时冻结并绑定事件范围、分支、作用域、投影哈希和策略版本；后来入场/入席不加入。
- 理由：读取时计算会向后来者泄漏已经消失的现场信息；模型选择会让 LLM 取得权限权威。
- 玩家可观察行为：断线但虚构在场者可恢复当前帧；虚构缺席者后来到场只看仍存在的世界事实。
- 秘密与权限影响：成员身份、房主/队长权限和网络在线状态不能替代虚构观察资格；控制权撤销仍立即停止访问。
- 迁移/可逆性：新规则版本启用；旧消息不构造 AudienceSnapshot。改变冻结语义需新呈现协议版本。
- 验收场景：O02、O05、O08、O11、O12。
- 测试证据：尚未实现；应由原子提交、并发入席和断线恢复测试提供。

### OBS-D004：不可回看与单槽可靠投递

- 日期：2026-08-26
- 问题：如何同时保证当前回应可靠送达并禁止完整 KP 历史。
- 来源类别：Goal 明确指定 + Agent 自主协议细化。
- 关联 `SPEC 0001`：§12 场景叙述、§15 多人桌、§17 更正、§19 标准循环；验收 M、N。
- 候选方案：永久聊天历史；每 viewer 有界多消息队列；每 ViewerKey 一个未确认单槽。
- 最终选择：当前回应固定单槽；刷新/断线/重启返回同一 ID；ACK 或新回应结束当前槽；成功发布文本另存于原 ViewerKey 的亲历记录，只保留非内容 delivery tombstone。
- 理由：单槽提供当前回应的至少一次可见和幂等恢复；ViewerKey 专属记录满足离场回看，同时冻结 Audience 阻止缺席者补取。
- 玩家可观察行为：刷新不会重复回应；断线可恢复当前回应；确认或收到下一回应后仍可查看自己亲历的文本，知识簿不丢失。
- 秘密与权限影响：槽和亲历记录都按 ViewerKey 隔离；多设备共享 ACK；旧 ID 与 Receipt 不能绕过 transcript 边界取回正文。
- 迁移/可逆性：不导入已丢失的旧聊天，也不从事件伪造；安全收窄可使当前槽失效而不形成亲历副本。
- 验收场景：O07–O10、O15、O16、O18。
- 测试证据：尚未实现；应由可重启 Room DO、丢响应和多设备 Interface 测试提供。

### OBS-D005：统一 projector 与旁路封闭

- 日期：2026-08-26
- 问题：快照、增量、错误、候选、语音、日志和叙述是否各自脱敏。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + 单一权威架构约束。
- 关联 `SPEC 0001`：§9 信息边界、§14 NPC 有限知识、§15 私人信息、§17 裁决说明；验收 F、K、M、N。
- 候选方案：各层手写删字段；各通道独立 projector；所有领域内容复用一个 projector，telemetry 只允许非内容白名单。
- 最终选择：所有玩家可见领域内容统一经 `project`，包括控制结束后的 `successorRequired` lifecycle 与 Rules 派生的恢复候选；语音和字幕只是当前帧呈现；Runtime telemetry 不投影领域正文，只记录固定非内容元数据。
- 理由：多套删字段规则必然漂移并产生侧信道；非内容 telemetry 无权解释事实，因此不构成第二 projector。
- 玩家可观察行为：同一秘密在快照、错误、候选、语音和日志中得到一致保护；NPC 与玩家投影不会混用。
- 秘密与权限影响：原始事件、KP Viewer、Prompt、转写和候选定义不离开可信服务端；猜测 ID 不能确认秘密存在。
- 迁移/可逆性：旧页面/API 脱敏路径必须删除或隔离在 Legacy Adapter；未来新通道只能消费现有 projector 输出。
- 验收场景：O01、O13、O14、O18。
- 测试证据：`tests/world-campaign-v2.test.mjs` 已通过公开 `project` 覆盖 `successorRequired` 与 `restRecoveryOptions`，`tests/multiplayer-room-v2.test.ts` 覆盖死亡/退役后的 Room `observe` lifecycle，`tests/authoritative-table-v2.test.mjs` 证明页面消费投影候选而不重算；错误等价、日志捕获和线上语音旁路仍按 O01–O18 完成门单列。

## 17. 五项交叉审查

### 17.1 跨规格矛盾审查

- 与 `SPEC 0001` 一致：保护角色知识与私人投影，不限制 KP 在专属投影内叙述，也不把叙述文本当正史。
- 与权威行动事务一致：知识取得、分享和更正均走同一事务；DeliveryFrame 只在提交后产生。
- 与长团方向一致：结构化知识与原 ViewerKey 的有界亲历记录可跨章节保留；死亡/退役不自动向继任 principal 转移知识或文本。
- 与现有语音能力一致：保留语音输入和呈现，但收拢到同一身份、Audience 和投递协议。
- 结论：未发现需要修改 `SPEC 0001` 的冲突；后续通用事务、多人和长团规格必须引用本规格，不能重定义 Audience、ACK 或分享追溯语义。

### 17.2 权限审查

- principal、ViewerKey、角色控制权和 ACK 权限均来自可信会话与 Room DO 状态。
- 房主、队长、在线状态和请求体字段不能扩大观察权。
- Audience 冻结不阻止后来权限撤销；撤销只能收窄访问，不能新增旧 Audience。
- 内部发布 capability 不暴露给页面；普通客户端不能上传投影或叙述正文。
- 结论：权限入口唯一，未发现调用者自报身份路径。

### 17.3 秘密审查

- 私有知识、KP/NPC Viewer、隐藏候选和未公开事实不进入普通 Frame、错误或日志。
- 世界内分享只传播明确内容和来源，不复制未表达秘密。
- 单槽、ViewerKey 隔离、非追溯 Audience 和无跨观察者历史 Interface 共同阻止越权补看。
- 语音、转写、媒体访问和多设备 ACK 服从同一 ViewerKey。
- 结论：实时、轮询、历史、重连、错误、候选、日志、语音和转写均有明确封闭规则。

### 17.4 版本审查

- Audience、projectionHash、活动分支和三个呈现协议版本绑定当前帧。
- 旧事件不能用最新 projector 静默扩大；更正使失效帧替换而非改写。
- Legacy 消息不迁入新单槽，旧房间行为明确隔离。
- 结论：不存在“部署后用新可见性解释旧房间”的静默版本污染；当前统一读取语义由 `projection-observer-safe-v1` 1.2.0 及其精确 manifest/genesis hash 固定。

### 17.5 第二权威审查

- Room DO 唯一保存活跃 Audience、投递槽、ACK 和结构化世界/知识；D1 仅保存可重建结构化归档。
- `project` 是唯一领域内容投影 Interface；`observe` 只组合其结果与当前槽。
- DeliveryFrame 非正史、不可回放，不参与机械或知识计算。
- 页面、Room Action Module、语音 Adapter、LLM、客户端缓存和 telemetry 都不能提交世界事实或另算可见性。
- 结论：本规格没有引入第二条机械裁决、状态提交、观察者投影或事件回放路径。

## 18. 实施完成门

本规格只有在以下证据全部成立时才算实现完成：

- O01–O18 均通过其责任 Interface，且至少包含一个无权观察者；
- Viewer 矩阵证明同一权威状态对玩家、NPC、KP 和内部 Viewer 的结果相互隔离；
- 可重启 DO 测试证明单槽、同 ID 恢复、ACK、覆盖和幂等不重复；
- 席位、控制权、位置和 Audience 并发变化没有回补或越权；
- 个人线索取得、持有、分享、跨章节持续和默认不继承均有权威事件测试；
- 实时、历史、刷新、重连、错误、候选、日志、语音和转写旁路测试均不泄漏；
- 页面不存在跨观察者完整 KP 旁白历史，D1/客户端也不存在叙述归档；DO 仅保存 ViewerKey 专属亲历文本且不参与事件 replay；
- 所有玩家可见领域内容来自统一 projector；
- Runtime 日志捕获测试证明未记录任何禁止字段；
- 实现映射和测试证据回填到总追踪矩阵及决策记录，未执行项不得写成已验证。
