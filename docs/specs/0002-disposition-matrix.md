# SPEC 0002 逐条处置矩阵

- 处置日期：2026-08-26
- 原件：`0002-authoritative-combat-framework.md`
- 原件性质：待审查、未批准草案；未曾获得用户逐条批准。
- 裁定权限：本 Goal 授权，可裁定替代规格；不得修改冻结 SPEC 0001。
- 总结：否决“把通用行动事务和全部产品责任放在战斗规格中”的组织方式；保留符合 D&D 5e 2014 / SRD 5.1 与 SPEC 0001 的产品意图，并由 SPEC 0003–0013 取代。

处置词义：

- **保留**：语义属于纯战斗机械，进入 SPEC 0012/0013。
- **修订**：产品意图成立，但责任、权限或时序需要更改后拆分。
- **拆往通用规格**：不是战斗特例，进入 0003–0011/0013。
- **否决**：与 Goal/SPEC 0001/单一权威冲突，不进入新规则。

## 3. 处置统计与审查

- 保留：B07–B12、B14–B15、B17、B19–B20、B35–B37、B39–B40（纯战斗核心）。
- 修订：B04–B06、B13、B18、B21–B22、B29–B30、B38、B49、B53。
- 拆往通用规格：其余 B 项。
- 否决：没有否决 B 项的玩家可观察意图；否决的是独立 CombatCoordinator、单体战斗规格作为全产品事务、自动 Legacy fallback 和原实施批准流程。

五项检查：

- 跨规格：每项只有一个主要责任 Interface；跨层场景在 traceability 中组合。
- 权限：Principal/玩家/NPC/KP/内部/更正入口由 0003、0007、0010、0011 统一。
- 秘密：所有 B 项的快照、增量、错误、候选、语音与叙述经 0010 projector。
- 版本：Ruleset/Event/Ability/Geometry/Trigger/Time 由 0013 固定，旧房不重算。
- 第二权威：所有变化只经 step、Room DO commit、project 和 replay；Legacy 只在明确旧版本。
