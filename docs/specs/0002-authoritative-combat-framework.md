## 1. 继承关系与变更规则

本规格定义战斗框架如何实现 `SPEC 0001`，不修改、缩小或取代 `SPEC 0001`。两者冲突时，在本规格再次获得用户明确批准前以 `SPEC 0001` 为准；任何“战斗例外”都不能暗改玩家意图、KP 叙事权威、规则机械权威或权威状态边界。

本规格冻结产品行为、权威接缝、状态机不变量和验收结果，不固定具体模型、Prompt、页面布局、文件拆分、数据库表名或 TypeScript 命名。文中的类型用于准确描述 Interface；实现可以改名，但不得改变其语义、权限或因果顺序。

本规格获批后，新战斗行为必须通过新的 `ruleset_version` 启用。旧房间继续使用创建时固定的规则版本，不得因部署或目录更新改变既有战斗的回放结果。

## 2. 目标与非目标

### 2.1 目标

战斗框架必须做到：

1. 玩家、KP、页面、NPC 编排和骰源共享一条机械裁决路径。
2. 攻击、移动、法术、职业能力、怪物能力、物件与环境危险能够在同一状态机内组合。
3. 每个反应、选择、骰子和中断发生在准确时点，并可跨请求、断线和 Worker 重启恢复。
4. 机械结果、位置、资源、伤势、持续效果和死亡成为可重放的权威事实。
5. 玩家只决定自己的角色，KP 依据有限知识决定 NPC，规则内核不替故事选择危险或战术。
6. 战场具有唯一规范空间，区域、距离、路径、遮蔽和移动后果由内核计算。
7. 战斗可以因死亡以外的事实结束，并在结束后保留全部长期后果。
8. 不同观察者获得各自有权知道的战斗投影，秘密不能从状态、候选项、错误或窗口侧漏。

### 2.2 非目标

本规格不要求：

- 为所有 SRD 法术、怪物和职业能力立即补齐内容目录；
- 在首版显示战棋地图或要求玩家输入坐标；
- 让规则内核评价遭遇是否平衡、是否适合队伍或是否具有戏剧性；
- 让结构化结束条件决定整个故事已经结束；
- 引入 D&D 2024、5.5e 或混合规则；
- 为战斗另建一套 D1 活跃状态、页面状态或 AI Prompt 状态。

## 3. 战斗中的五种权威

### 3.1 玩家意图权威

玩家决定自己的角色想做什么、目标是什么、采用什么方法，以及所有未被规则强制的台词、思想、情绪和行动。重大歧义必须在提交前确认。系统、队长、房主、KP 和其他玩家都不能替角色选择可选动作、反应、目标、资源或是否接受投降。

### 3.2 KP 叙事权威

KP 负责：

- 对自由行动作五类可行性裁决；
- 在证据和骰面出现前固化开放留白中的敌人、危险、地形和隐藏事实；
- 决定 NPC 为何战斗，并依据 NPC 的目标、知识、资源、恐惧和错误判断选择行动；
- 设定即兴行动的虚构风险、DC、时间、前提和结果范围；
- 决定 NPC 是否投降、撤退、谈判或停止敌对；
- 在机械结果提交后诚实叙述，不改判、不补救、不追加惩罚。

KP 不能替玩家角色作选择，也不能用全知上下文让 NPC 采取其无从知道的反制。

### 3.3 规则机械权威

Rules Module 最终决定目标是否合法、区域实际影响谁，以及距离、路径、行动经济、资源、骰式、优势劣势、攻击、豁免、伤害、治疗、持续效果、专注、状态、虚构时间和死亡如何结算。目标意图仍由相应玩家或 KP 选择。

规则内核可以拒绝机械上不可执行的提案并返回具体问题，但不能因为敌人过强、玩家可能死亡、路线偏离预想或故事不够精彩而拒绝、削弱或缩放提案。

### 3.4 权威状态

每房间 Room Durable Object 独占活跃 `WorldState`、`WorldEvent`、战斗待决状态、幂等结果和版本的提交权。敌人、地形、隐藏位置、资源、伤势、窗口、骰面和战斗结论进入因果链后必须持久、可投影、可审计和可回放。

### 3.5 服务端协调权威

Worker 从可信登录会话取得用户身份，验证房间成员、角色控制权、地点、遭遇、回合、窗口所有者、相关作用域版本和幂等 ID。CombatCoordinator（战斗协调器，原草案称 CombatFrame）可以协调 KP、DO 和投影，但不拥有机械规则、活跃状态、骰面或故事选择权。

## 4. 领域语言

**遭遇（Encounter）**：需要按结构化顺序处理威胁、冲突或危险的一段世界状态。遭遇可以没有传统敌人，也不等同于整个场景或故事。

**参战者（Combatant）**：加入某一活跃遭遇并拥有位置、先攻、控制者和机械状态的世界实体。世界中同地点的实体不会因此自动成为参战者。

**控制者（Controller）**：有权为一个实体作出非强制机械选择的主体；可以是特定玩家或 KP。控制权是权威状态，不由客户端声明。

**敌对关系（Hostility Relation）**：实体或阵营之间当前是否有意继续机械冲突的结构化事实。它可以随投降、魅惑、停战、背叛或目标变化而改变，但不限制玩家明确攻击非敌对目标。

**机械提案（Mechanical Proposal）**：KP 根据玩家意图、NPC 意图和已固化事实提出的结构化尝试。它描述想要调用的规则、目标、选择、路径、风险依据和必要机械效果，不是状态补丁；确定性 Adapter 只能编译已经冻结的提案。

**隐藏现实候选（Hidden Reality Candidate Set）**：KP 在开放留白不能由单一因果结果推出时提交的秘密候选、隐藏权重和因果依据。它不携带预选结果；全部候选在随机发生前完成验证和冻结。

**能力定义（Ability Definition）**：规则版本内可验证的武器、法术、职业特性、怪物动作、物件能力或危险定义。

**能力引用（Ability Ref）**：绑定规则集、定义版本或哈希、拥有者与能力实例的稳定引用。它不能在回放时解析到“最新定义”。

**结算状态（Resolution State）**：当前尚未完成的动作、移动、触发、选择、骰子与继续点的唯一聚合根。它拥有结算帧及至多一个当前待决输入，不与遭遇字段另存第二份窗口或继续点。

**结算帧（Resolution Frame）**：一段可暂停机械过程及其继续点，例如一次移动分段、一次攻击、一次施法或一个伤害来源。

**待决输入（Pending Input）**：结算继续前必须由指定权威提供的判别式输入；机械分支是 `DecisionWindow` 或 `RandomnessRequest`，每个待决输入只引用一个继续帧。玩家选择、KP/NPC 选择和平手顺序使用决策窗口，内部权威骰面使用随机请求。

**决策窗口（Decision Window）**：面向特定控制者的可选或必选决定；反应窗口只是决策窗口的一种。

**反应窗口（Reaction Window）**：由具体触发条件在准确机械时点开启、允许合资格实体使用反应或明确放弃的决策窗口。

**随机请求（Randomness Request）**：由规则内核在全部相关参数冻结后提出、仅由 Room DO 权威骰源满足的一次性骰子请求。

**伤害包（Damage Packet）**：来自同一来源、包含一个或多个伤害分量并按固定顺序结算的伤害事实。

**效果实例（Effect Instance）**：已经提交、具有来源、目标、持续时间、触发点、专注关系和机械标签的持续事实。

**稳定等待点（Stable Wait Point）**：状态已经原子提交，当前没有可自动完成的确定性步骤，只等待指定玩家、KP、外部恢复或下一项合法意图。

**裁定先例（Adjudication Precedent）**：一次重要即兴裁定的情境、依据、机械选择和适用范围。它帮助 KP 在相似情境保持一致，不把临时裁定变成不可更改的全局规则；事实或做法变化时可以形成有依据的新裁定。

**作用域基线（Scope Baseline）**：某次授权解释所依据的相关作用域及其版本集合。外部意图使用 TurnTicket，内部结算使用随事件持久化的 `ResolutionScopeBaseline`，更正使用 `CorrectionContext`；全局事件头只用于溯源，不代替相关作用域版本。

## 5. 深模块与唯一 Interface

### 5.1 Rules Module

战斗是现有 Rules Module 的内部实现。生产调用者和行为测试只能通过以下 Interface 观察和推动机械：

```ts
step(module, state, command): StepResult
project(module, source: ProjectionSource, viewer, query?): ViewerProjection
replay(roomGenesis, contiguousRoomEvents): WorldState

type ProjectionSource = {
  state: WorldState;
  headEventSeq: number;
  stateHash: string;
  contiguousEvents?: ContiguousEventSlice;
};

type StepResult =
  | { kind: "rejected"; baseEventSeq: number; violations: RuleViolation[] }
  | {
      kind: "advanced";
      nextState: WorldState;
      events: NonEmptyArray<WorldEvent>;
      finalEventSeq: number;
      stateHash: string;
      scopeProof: RuleScopeProof;
      next:
        | { kind: "automatic"; continuationId: AutomaticContinuationId }
        | { kind: "awaiting"; pendingInputId: PendingInputId }
        | { kind: "settled" };
    };
```

这些操作的语义固定如下：

- `step` 是唯一机械裁决入口。给定相同规则版本、状态和显式输入，它必须产生相同结果；内部不得调用 LLM、网络、数据库、时钟或随机源。
- `project` 是唯一观察者投影入口。页面、KP 叙述、NPC 决策、快照、增量事件和日志都必须使用同一个内部 projector。快照只需当前状态与头哈希；请求 `query.sinceEventSeq` 时，Room DO 必须同时提供从该游标后一项到当前头部的连续事件片段及起止哈希，`project` 验证无缺口且与当前状态匹配后再脱敏。缺少片段、序号断裂或哈希不符必须拒绝，不能由页面或另一个日志模块自行解释事件；原始 `WorldEvent` 永不离开 DO。
- `replay` 只折叠已经提交的版本化事件，不重跑 LLM、随机数、当前能力目录或当前规则验证。
- `fold/applyEvents` 是 Rules Module 的私有实现，不是页面、Worker 编排或测试可以绕过 `step` 使用的第四条裁决路径。
- 已提交事件是唯一持久真相；`nextState` 只是可丢弃缓存，必须满足 `canonicalStateHash(privateFold(previousState, events))`、`canonicalStateHash(nextState)` 与返回的 `stateHash` 三者相等，并以 `finalEventSeq` 验证。`step` 返回该缓存、等价事件及下一稳定方向，或返回拒绝诊断。
- `scopeProof` 由 Rules Module 根据区域目标、触发闭包、隐藏依据和派生效果计算实际读取、写入与新建作用域；Room DO 只验证该证明绑定的作用域版本并原子更新，不复制机械依赖算法。
- `next.kind` 只告诉协调器继续确定性推进、等待一个待决输入或已经结清，不暴露结算帧、窗口队列或内部事件类型。`automatic` 返回的 opaque continuation 只引用已经在事件中保存的继续点，并绑定 `resolutionId`、`continuationHash`、`ResolutionScopeBaseline` 与单次使用语义；当时的全局 `finalEventSeq` 和 `stateHash` 只作审计溯源，不能因无关作用域推进而单独使续接失效。
- 调用者不能提交字段路径、任意补丁、任意脚本或完整替代状态。
- `Viewer` 必须是区分玩家、NPC、KP 和内部状态的判别式身份，不能只接受一个无权限语义的裸字符串。

### 5.2 CombatCoordinator

CombatCoordinator 是 Worker 侧无状态协调 Module。其调用者只提交已认证意图或待决响应，不需要理解内部结算阶段：

```ts
type CombatCoordinatorInput =
  | AuthenticatedPlayerIntent
  | AuthorizedPendingResponse
  | AuthorizedKpProposal
  | InternalResume;

type CombatCoordinatorOutcome =
  | CommittedProjection
  | NeedsPlayer
  | NeedsKp
  | Rejected
  | Concluded;

handle(input: CombatCoordinatorInput): Promise<CombatCoordinatorOutcome>
```

`driveUntilStable` 是 CombatCoordinator 内部循环，不是页面 Interface。循环只能推进确定性步骤、请求 DO 骰面或调用有权作决定的主体；它不能选择默认攻击、最近目标、最优战术、玩家反应或超时放弃。

状态机一旦需要 LLM、玩家、网络或下一次 Worker 执行，必须先由 DO 提交此前事件、唯一 `PendingInput` 和继续帧，再离开当前执行；协调器不能跨外部等待持有未提交机械状态。初次玩家意图可以依据 `prepare` 票据在事务外解释。一次外部模型调用在尚未成功提交其提案前失败，不产生由该调用引起的新世界变化；此前已经提交的到期行动或其他事件永久保留，原玩家意图停在重新投影后的稳定点等待重试或必要确认。

为满足 Worker 执行预算，CombatCoordinator 可以在不改变虚构事实的工作预算边界让出执行。`InternalResume` 必须是 DO 持久化、不可伪造、单次且幂等的 continuation capability，不能作为普通客户端输入；技术让出不是角色放弃、回合结束或虚构时间推进。

### 5.3 Room Durable Object

Room DO 保留既有 `prepare → 外部解释 → commit` Seam，并提供不签发行动票据的 `observe` 投影读取及仅供更正权威使用的 `commitCorrection`：

1. `prepare` 基于可信身份签发带房间审计游标、相关作用域版本和个人投影的短期票据；CombatCoordinator 另以可信服务端身份取得独立 KP Viewer 上下文。
2. KP 在 DO 事务外完成 `SPEC 0001` 标准循环并产生机械提案；确定性 Adapter 只能机械化 KP 已冻结的裁决，或续接无需新叙事判断的既有 `ResolutionState`。
3. `commit` 按输入来源选择 `ScopeBaselineSource`：外部提案和决策响应使用 TurnTicket，内部随机满足和自动续接使用已提交的 `ResolutionScopeBaseline`。它重验身份或内部能力、控制权、基线版本、窗口和提案，并在同一房间事务内调用 `step`。实际读写闭包只由 Rules Module 计算并作为 `scopeProof` 返回；DO 不解析区域目标、触发、隐藏依据或效果依赖。证明引用的每个既有作用域都必须在相应基线中绑定同一版本，否则整笔废弃；外部输入重新 `prepare`，内部结算保持原等待点并报告需要重新裁决，不能读取当前版本后自动扩大基线。只有 Rules Module 标记为本命令新建且不存在冲突的作用域无需旧基线。验证通过后，DO 才原子提交事件、缓存、Receipt 与待决状态。它不接受调用者提供的 `WorldEvent[]`、`MechanicOp[]`、状态补丁或骰面。
4. 需要随机数时，DO 根据规则内核生成的请求使用权威骰源满足；客户端、KP 和 CombatCoordinator 不能自报骰面。
5. 提交后由 `project` 生成观察者结果，并把已提交事件异步追加到可重建 D1 归档。
6. `observe` 只返回当前观察者投影；页面轮询不能为了读取状态反复签发 TurnTicket。
7. `commitCorrection` 只接受重新鉴权的 `CorrectionAuthority` 或系统审计器请求，从完整日志构造 `CorrectionContext` 并调用 `step`；普通成员、CombatCoordinator 和 `commit` 不能代用该入口。

TurnTicket 必须绑定可信 principal、受控实体、用途、规则版本、`roomRevision`、相关 `scopeRevision`、个人投影与 TTL；请求体中的 `userId` 或 `actorId` 不构成权限。`roomRevision` 只是审计游标，无关作用域变化不能单独使票据或窗口失效。

`ResolutionScopeBaseline` 在结算建立时由 Rules Module 的证明确定，并随 `ResolutionState`、随机请求或 automatic continuation 一起写入事件；它覆盖该结算已知的全部实体、空间、隐藏触发和派生效果依赖，在每次内部提交后按新证明更新。它的有效性只比较 `resolutionId + continuationHash + 相关 scopeRevision`；全局事件头和状态哈希只用于证明来源。内部结算若出现基线外的既有作用域，说明原机械闭包已经不充分，必须停在稳定点重新裁决，不能由 DO 悄悄吸收当前版本。

KP Viewer 上下文至少包含 `SPEC 0001` 标准循环所需的故事锚点、已固化秘密、NPC/势力目标、虚构时间、到期活动、相关裁定先例和最近聚光灯；它只在可信服务端按 `project` 生成，永不写入 TurnTicket、客户端响应或普通日志。处理原玩家意图前，KP 若发现已经真实到期的幕后行动，必须先为其形成提案并经 `step` 提交，然后重新 `prepare`、重新 `project`，再依据新状态处理同一份尚未提交的原意图。到期事件使原意图的含义或重大风险实质变化时，决定权先交回玩家重新确认，不能在过期情境上自动执行。

ID 语义必须分离：`submissionId` 标识一次幂等写入，`rootCommandId` 关联原始行动，`resolutionId` 关联跨请求结算，`pendingInputId` 标识一个等待项，`responseId` 标识一次回答，`randomnessId` 标识一次骰子请求。幂等命名空间必须包含房间、可信 principal、输入种类与规范载荷哈希。

同一 `submissionId` 与同一规范化载荷返回原提交 Receipt；同一 ID 携带不同载荷必须拒绝。重试仍须重新鉴权，并基于当前权限重新 `project`，不能直接返回缓存的私人投影。相同随机请求、响应重试或 Worker 重启不能重复掷骰、重复扣资源或重复结算。D1 归档失败不能把已经由 DO 提交的命令报告为未提交。

## 6. 输入与命令协议

玩家自然语言不是 Rules Module 的 `Command`。CombatCoordinator 先保留原始目标和做法，再由 KP 完成标准循环并形成机械提案。确定性 Adapter 只能把 KP 已冻结的裁决编译为命令，或继续纯机械待决结算；它不能独立理解新意图、作五类裁决、选择 NPC 行动、设定风险或形成隐藏事实。

### 6.1 玩家自由行动

玩家提出非目录行动时，KP 必须先作以下一种裁决：

1. 直接成功；
2. 需要检定；
3. 高风险可行；
4. 缺少前提；
5. 违反世界规律。

会造成重大危险、显著资源消耗、攻击同伴或不可逆结果的歧义必须形成意图澄清。澄清后的玩家选择成为票据的一部分；KP 不得自行选择更危险解释。自然语言澄清和 KP 对非法提案的修订发生在合法机械结算开始前；凡会约束后续提交的澄清都必须持久化在 Room DO 并绑定原意图与控制者，但不伪装成 `ResolutionState` 内的机械反应窗口。

直接成功、检定或高风险行动若改变世界，也必须通过 `step` 产生事件。缺少前提和不可能可以返回诚实的世界内说明；若尝试本身已经消耗时间、暴露位置或造成其他后果，相应变化同样必须提交。

相似事实与做法必须得到一致裁定；重要即兴裁定必须形成可追溯的 `AdjudicationPrecedent` 并进入下一次 KP Viewer 上下文。角色采用合适工具、情报、位置、协助、更多虚构时间或其他聪明准备时，准备必须真实改善结果：降低 DC、获得优势、改变检定方式、缩小失败后果或让行动直接成功，取其符合虚构事实者；不能仅在叙述上称赞准备而保持完全相同的机械机会。事实或做法实质变化时，KP 可以记录有依据的新裁定，不被旧先例机械锁死。

### 6.2 机械提案族

具体 TypeScript 可以变化，但语义至少覆盖：

```ts
type MechanicalProposal =
  | BeginEncounterProposal
  | InvokeKnownAbilityProposal
  | ResolveImprovisedActionProposal
  | MaterializeHiddenRealityProposal
  | ChangeEncounterProposal
  | EndTurnIntent
  | ConcludeEncounterProposal;

type RulesInput =
  | MechanicalProposal
  | PendingResolutionResponse
  | AutomaticContinuationInput
  | CorrectionResolutionInput;

type PendingResolutionResponse =
  | DecisionResponse
  | InternalRandomnessResponse;

type AutomaticContinuationInput = {
  kind: "continue-resolution";
  continuationId: AutomaticContinuationId;
};

type CorrectionResolutionInput = {
  kind: "resolve-correction";
  request: AuthorizedCorrectionRequest;
  context: CorrectionContext;
};
```

- `InvokeKnownAbilityProposal` 引用已固化能力，并只携带目标、路径、区域原点/方向及定义允许的封闭选择。
- `ResolveImprovisedActionProposal` 携带可行性裁决、事实依据、检定或直接结果、骰前固定的 DC/风险/时间/结果范围，以及受限机械效果提案。
- `MaterializeHiddenRealityProposal` 携带尚未预选结果的秘密候选集、隐藏权重、因果依据、每个候选的完整定义和公开级别；Rules Module 必须在请求随机数前验证并冻结全部可能被选中的候选。
- `ChangeEncounterProposal` 允许在战斗中按因果加入增援、召唤物、危险、地形变化、出口或敌对关系；框架不能假设所有内容只在开战时存在。
- `ConcludeEncounterProposal` 是带事实依据的结束提案，不是无条件状态命令。
- `InternalRandomnessResponse` 是服务端内部输入，不属于客户端可序列化的战斗操作。
- `AutomaticContinuationInput` 只能由 Room DO 从已提交事件中的 opaque continuation 构造；Rules Module 验证其 `resolutionId`、`continuationHash`、`ResolutionScopeBaseline` 和未使用状态。客户端、KP 和普通 Worker 请求不能构造或重放它，CombatCoordinator 的 `InternalResume` 只请求 DO 续接，并不携带结算帧；无关作用域的全局事件不会使它失效。
- `CorrectionResolutionInput` 只能由 Room DO 的唯一更正入口把已授权请求与哈希绑定的历史上下文组合后构造，语义见第 20.3 节。

## 7. 权威战斗状态

每个活跃遭遇至少保存：

- 遭遇 ID、场景/地点、规则版本、几何 Profile、房间审计游标与相关作用域版本；
- 参战实体、控制者、敌对关系、可见性和是否隐藏；
- 先攻条目、平手顺序、当前轮、当前回合与回合阶段；
- 每个实体的位置、占位、移动方式、速度、朝向要求和空间限制；
- 地形、屏障、出口、掩体、困难地形、危险与可破坏环境；
- HP、临时 HP、资源、动作授予、移动账本、反应、效果、专注和死亡状态；
- 当前 `ResolutionState`，其中包含结算帧、对应 `ResolutionScopeBaseline` 和至多一个当前 `PendingInput`；窗口所有者、继续点与内部续接基线只在该聚合及其生成事件中各有一个来源；
- 已请求和已满足的随机请求；
- 开始时间、当前六秒轮窗口及所在分支的虚构时间；
- 潜在结束条件、已提交结束原因和退出者状态。

影响裁决的字段必须由世界事件重建。UX 租约、加载状态和模型调用状态不属于战斗事实。

一个实体同一时刻最多参加一个活跃遭遇。一个房间可以在不同地点存在多个遭遇；它们共享 Room DO 的原子事实权威，但按相关作用域并发，并通过虚构时间和因果前沿协调。

## 8. 遭遇建立与战中变化

开放留白第一次影响战斗时，KP 除了“提前固化”还必须服从 `SPEC 0001` 的选择公正：先服从已有因果；多种结果合理性不同时选择更合理结果或先固定隐藏权重再使用可信随机；同样合理时优先形成有意义选择、回应既有行动或延续关系；仍无法区分才随机。戏剧性只能在同样合理候选之间决胜，不能为了保护角色、惩罚偏航或制造高潮临时增加或撤销敌人、增援、危险和出口。

可预见的严重风险必须在玩家作出不可逆选择前，通过其角色按感官、经验和能力理应获得的痕迹、环境、传闻或 NPC 反应呈现。预示不公开隐藏数值或完整答案，但不能等到致命效果发生后才补写依据。

因果只能推出一个结果时，KP 直接提议该隐藏事实；需要按隐藏权重随机选择时，KP 必须提交 `MaterializeHiddenRealityProposal`，不能先在模型或 Worker 内抽取结果。Rules Module 验证权限、候选结构、非负权重、引用、定义完整性和所有候选的机械合法性，保存但不评价 KP 的叙事合理性依据，然后冻结整个秘密候选集并产生仅 KP/内部可见的 `RandomnessRequest`。DO 骰面恢复同一结算后，Rules Module 选择候选，并把选中事实及所需 `DefinitionRegistered` 与结算事件原子提交；任一候选不能合法落地时，随机请求不得开始。候选、权重、未选结果和秘密依据只进入有权投影，玩家只获得角色能够感知的预兆与后续证据。

### 8.1 建立遭遇

KP 必须在相应内容产生感官证据、影响先攻或进入机械结算前固化：

- 参与者，而不是把同地点所有实体自动加入；
- 每个参与者的控制者、位置、阵营和敌对关系；
- 任意数量的阵营及其当前关系，不限于“玩家/敌人”二分；
- 地形、屏障、危险、出口和与当前行动相关的可破坏环境；
- 逐个实体的突袭依据、感知依据和隐藏状态；
- 新动态敌人的完整定义、能力、资源、感官和死亡策略；
- 先攻需要的规则参数，随后由 DO 权威骰源请求骰面。

动态实体、危险与能力定义必须先通过验证，并在 `BeginEncounterProposal` 提交前或与遭遇建立同一原子提交中成为权威事实；它们不能只作为临时文本埋在开战命令中。

未被玩家发现的敌人可以作为秘密权威事实存在，但不得出现在无权观察者的投影、候选目标、错误文本或窗口中。

### 8.2 突袭与先攻

本规则版本没有“突袭轮”。双方都没有尝试隐匿时彼此察觉；存在隐匿时，KP 按每名隐藏者的敏捷（Stealth）与每个潜在对手的被动感知分别确定是否察觉威胁。开战时没有察觉任何威胁的实体被突袭，特定能力可以按明文覆盖。

是否被突袭按实体分别固化；被突袭实体在自己的第一回合不能移动、采取动作或采取附赠动作，并且在该回合结束前不能采取反应。其第一回合结束后，即使仍处于遭遇第一轮，也可以在符合条件时采取反应。

先攻是敏捷能力检定，适用相应检定加值、优势与劣势；自然 1 和自然 20 不自动决定先攻成功或失败。所有先攻骰面来自 DO。KP 为一组相同生物进行一次先攻检定并共享先攻条目，每个实体仍分别保存自己的回合资源和状态。平手按 SRD 5.1 / 2014 权限解决：玩家控制的并列角色由相应玩家决定顺序，KP 控制的并列实体以及玩家与 NPC 的平手由 KP 决定；需要选择时形成待决窗口，不能依赖数组顺序或客户端排序。

以下是版本化产品规则而非 SRD 明文：新参战者在加入时取得权威先攻条目；若其顺位在当前轮已经经过，则默认从下一轮开始拥有回合，只有明确规则能力可以授予立即行动。

### 8.3 战中加入、离开与改变

增援、召唤、变形、地形破坏、危险出现、阵营改变和出口封闭都必须通过 `ChangeEncounterProposal` 或已验证能力产生事件。新事实在出现证据前固化，之后不得根据玩家 HP、骰面或战术更换。

离开遭遇不等于从世界消失。逃跑者、被传送者、俘虏和脱离者保留位置、伤势、资源、装备、知识和持续效果。

## 9. 唯一战场空间

新规则版本必须绑定一个且仅一个 `BattlefieldGeometryProfile`。该 Profile 是距离、路径、占位、范围、视线和遮蔽的唯一机械来源；同一房间不得同时维护一维距离、距离段和二维坐标三套权威真相。

首个 Profile 必须支持：

- 以尺为单位的二维位置和独立高度；
- 实体体型、占位、触及和可穿越性；
- 有序移动路径与不同移动方式；
- 屏障、门、困难地形、不可通行区域和可破坏地形；
- 视线、清晰路径与半掩护/四分之三掩护/全掩护；
- 球、柱、立方、锥、线等规则区域；
- 区域与实体占位的相交计算；
- 强制移动、传送、坠落、攀爬、游泳和飞行的区分。

几何 Profile 必须版本化并使用确定性算法；具体距离、斜线、取整、体型占位、区域边界和遮蔽算法必须在该 Profile 获批后才能发布新规则版本。

几何 Profile 还必须固定以下 2014 语义：实体按体型占据空间而不是一个无体积点；任何可通过的另一生物空间都视为困难地形；经过敌对生物空间需要满足至少相差两个体型等级；实体不能自愿在另一实体占位中结束移动。挤入小一体型生物可占据的空间时，每移动 1 尺额外花费 1 尺，并且该实体的攻击与敏捷豁免具有劣势、攻击该实体具有优势。半掩护为 AC 与敏捷豁免提供 +2，四分之三掩护提供 +5，全掩护阻止直接以其为目标；多个掩护只采用最高者。

每段位置变化必须记录来源是自主移动、动作移动、反应移动、强制移动、传送、坠落还是其他明确能力，以便触发规则按移动来源而不是只比较起终坐标。

玩家和 KP 可以继续使用自然语言描述位置。Adapter 负责把叙事描述映射为结构化空间提案；若多个解释会显著改变射程、危险、资源或不可逆结果，必须先澄清。

区域能力只提交原点、方向、尺寸选项和其他定义允许的选择；实际受影响实体由 Rules Module 根据权威空间计算。调用者不能提交一份可漏选受害者的完整 `targetIds` 作为区域真相。

目标或区域原点首先服从清晰路径：来源到目标之间存在全掩护时不能直接指定；指定一个不可见点而障碍位于途中时，原点落在障碍物近侧。区域随后从原点按其形状沿未阻挡直线扩张，全掩护后的空间默认不受影响。

通用区域传播可以被版本化能力定义中的明确规则覆盖。例如火球术按明文绕过拐角传播，但不能穿透没有开口的封闭空间；特例仍由几何 Profile 执行，不能交给调用者手选受影响者。

移动按路径分段结算。每个可能触发反应或改变合法性的边界必须先暂停；若中途被击倒、速度变为零、道路被封闭或移动方式失效，剩余路径不再提前生效。

## 10. 轮、回合与虚构时间

战斗轮与 Spotlight Beat 完全分离。SRD 将一轮描述为约六秒；烛帷按 ADR-0002 采用版本化产品规则，把一个战斗轮固定为六秒虚构时间窗口，包含该轮有资格行动的各参战者回合。单个角色回合、模型响应或现实等待不会各自推进六秒。

遭遇开始时记录当前分支虚构时间并打开第一轮窗口。以下是同一时间 Profile 的版本化产品规则：最后一个有效先攻条目完成，或遭遇在本轮中途合法结束时，当前轮窗口关闭且该分支虚构时间只推进六秒一次。之后仍在运行的持续效果、活动和其他地点时间线按因果前沿协调。

持续时间优先使用规则定义的相位锚点，例如“直到你的下回合开始”或“在目标回合结束时重复豁免”；不得仅用累计秒数替代这些相位。分钟级施法、危险和活动同时记录虚构时间期限。

遭遇在一轮中途结束时，相位锚点不能立即消失或永久残留。版本化 Time Profile 必须保留结束时的先攻顺序，把“下回合开始/结束”等尚未到达的锚点转换为其下一次假想先攻边界对应的绝对虚构时间并调度到期；该调度只处理效果到期，不授予新的战斗动作。转换、到期与 replay 结果必须确定一致。

现实中的思考、掉线、页面关闭、TurnTicket 过期、模型超时或 UX 租约到期都不推进回合、轮或虚构时间。

## 11. 回合状态机与行动经济

### 11.1 回合阶段

每个回合至少具有：

1. **回合开始**：进入回合边界时恢复该实体可用反应，再收集开始时触发、死亡豁免及其他到期效果；同时触发项先服从能力明文。仍同时时由当前回合实体的控制者选择顺序并形成事件，这是版本化产品排序规则，不声称为 SRD 明文。
2. **回合进行**：处理动作授予、附赠动作资格、移动分段、物件互动和其他合法能力。
3. **回合结束**：处理结束时触发、重复豁免、效果到期和回合记录，然后才移动先攻游标。

有未结算帧或待决窗口时不能结束回合。失能实体可以由规则自动跳过其不能采取的选择，但所有开始/结束触发仍须结算。

### 11.2 行动授予而非布尔槽位

行动经济不得只保存 `action: boolean`。状态必须表达带限制的行动授予和本回合历史：

- 普通动作；
- 只有能力明确授予时才存在的附赠动作资格；
- 在自己下回合开始时恢复的反应；
- 与移动或动作结合的一次免费物件互动，以及额外互动的动作成本；
- 动作如潮等额外普通动作；
- 加速术等只能用于受限行动集合的额外动作；
- 本回合已经施放的法术、消耗的资源和触发的限制。

额外动作不会自动授予额外附赠动作、反应，也不会刷新每回合一次的免费物件互动；该额外动作仍可以在来源允许时用于“使用物件”动作。

### 11.3 移动与多次攻击

移动可以在动作前后拆分；包含多次武器攻击的动作可以在各次攻击之间继续移动和更换目标。一次 Attack 动作、角色 Extra Attack 和怪物 Multiattack 必须保留各自规则语义，不能因为都包含多次攻击而合并成同一个浅层计数器。

每次移动段和单次攻击都是可暂停结算帧。后续攻击、移动和效果只有在前一帧及其反应窗口完成后才能发生。

不同移动方式必须分别保存速度，并按本回合已经移动的距离计算剩余预算。站起、匍匐、攀爬、游泳、飞行、困难地形、速度为零和 Dash 必须使用 2014 规则；多个困难地形来源不会把同一尺移动反复倍增。飞行实体失去维持飞行条件时是否坠落必须由 hover、能力和状态确定。

### 11.4 基础动作

能力目录至少能够表达攻击、施法、疾走、撤离、闪避、帮助、躲藏、预备、搜索、使用物件、擒抱和推撞。它们都通过同一 `step` 入口执行，但各自保留 SRD 5.1 / 2014 的目标、检定、资源和时序语义。

2014 的擒抱和推撞是 Attack 动作中替代一次攻击的特殊近战攻击，使用攻击者 Athletics 与目标自行选择的 Athletics 或 Acrobatics 对抗检定；它们不是徒手攻击命中后的力量/敏捷豁免。Extra Attack 可以让不同攻击分别用于擒抱、推撞或武器攻击。

预备动作必须固化可感知触发，以及一个准备动作或“移动至多自身速度”。触发完成后，控制者可以使用反应执行或放弃；未在自己下一回合开始前使用的准备失效。只有施法时间为一个动作的法术可以预备；预备法术在预备时施放并消耗法术位，以专注持有，之后用反应释放。

传奇动作等非反应的回合外选择也使用决策窗口，但不会被错误记为反应或消耗反应资源。

## 12. 可暂停结算与准确时点

`ResolutionState` 必须由事件完整重建。它可以在实现中使用帧、队列或栈，但产品语义不是“所有反应统一后进先出”。

一个机械结算开始后，相关遭遇只能接受该 `resolutionId` 当前允许的响应、内部骰面或明确更正；不能用另一条普通行动越过未完成结算。无关地点和无关作用域仍可继续，不得把结算状态实现成全房间长锁。

每个可触发能力必须声明：

- 触发谓词；
- 触发者必须能够感知的信息；
- 相对于原动作的准确插入点；
- 合资格控制者与可选响应；
- 使用后消耗的资源；
- 原动作在响应后继续、改变、取消或失效的方式；
- 窗口关闭条件。

至少必须区分：

- 离开触及时、在实际离开前发生的借机攻击；
- 攻击已经命中但伤害尚未结算，或自身成为魔法飞弹目标时的护盾术；
- 看见 60 尺内生物正在施法、且法术尚未生效时的反制法术；
- 可感知触发完成后的预备动作；
- 伤害前、伤害后、回合开始和回合结束的不同触发点。

借机攻击是可选反应。只有反应者看得见的敌对生物使用自己的移动、动作或反应离开其触及时才可能触发；采取撤离（Disengage）、传送、不使用该生物移动/动作/反应的强制移动、看不见的生物和非敌对生物离开都不打开该窗口。

反制法术窗口只有在反应者看见 60 尺内生物正在施法时打开。目标法术等级不高于所用反制法术位等级时自动反制；否则进行使用者施法属性检定，DC 为 `10 + 目标法术等级`。它不是体质豁免，成功反制也不返还目标已经承诺的动作或法术位。

护盾术在触发攻击已命中但伤害前，或使用者成为魔法飞弹目标时开启；其 AC 加值适用于触发攻击，并持续到使用者下回合开始，同时在持续期内免疫魔法飞弹伤害。

多个同时触发项不得依赖对象遍历顺序、网络先到先得或统一“优先权轮”。规则已经规定顺序时服从规则；由控制者决定时打开相应选择；KP 只能为其控制的 NPC 或世界效果选择，不得替玩家选择。嵌套反应建立新的结算帧并保留原继续点，不能覆盖或提前提交原效果。

不同控制者在同一因果点同时合资格时，规则版本必须绑定一个 `TriggerOrderingProfile`：它先基于同一冻结状态收集合资格者，再按版本化、与网络延迟无关的顺序逐个打开私人窗口。较早响应使后续选项失效时，后续窗口以无消耗事件关闭；未到其顺位的选择不会提前公开。该 Profile 的确切排序算法必须在新规则版本发布前获批。

决策窗口必须具有稳定 `pendingInputId`、所属遭遇和相关 `scopeRevision`、控制者、可感知依据、合法选项、打开时点与所引用的唯一继续帧。响应必须显式选择能力、选项或 `pass`。

每个待决输入只接受一次有效响应。同一 ID 与同一响应重试返回原结果；同一 ID 的不同第二响应、非控制者响应或窗口关闭后的响应必须拒绝。

现实超时不能自动产生 `pass`。断线后窗口保持为权威待决状态；玩家重新连接后可以继续或明确放弃。未来自动反应策略只能由控制者预先明确配置、成为权威事实并按版本执行。

存在未完成结算帧、随机请求、机械选择或反应窗口时，`EndTurnIntent` 与 `ConcludeEncounterProposal` 必须拒绝；显式取消只有在具体规则允许并能确定性恢复或终止原结算时成立。

## 13. 权威随机数

Rules Module 只能请求随机数，不能自行生成；Room DO 是生产权威骰源。测试可以在同一内部 Seam 注入确定性骰源，但测试骰源不是生产命令。

`RandomnessRequest` 至少包含：

- 稳定 `randomnessId` 与所属 `resolutionId`；
- 规则版本、遭遇、结算帧和用途；
- 骰子数量、面数及需要保留的原始骰面；
- 已冻结的目标、DC、修正、优势劣势、伤害式和相关输入摘要；
- 骰面及结果的公开级别；
- 规范载荷哈希。

请求产生前，隐藏现实、目标、距离、DC、优势劣势、资源成本、风险和成功/失败范围必须已经冻结。骰面出现后不得修改这些参数；机械非法提案不得先掷骰再修补。

骰面与用途必须成为不可变事件。相同请求重试只能返回原结果；回放读取已提交骰面，不重新抽取。规则只在到达相应时点时请求必要骰子，不提前为尚可能被反应取消的后续攻击或伤害掷骰。

随机恢复协议固定为：

1. `step` 产生 `RandomnessRequested`、唯一 `randomnessId` 和继续帧，DO 先原子提交它们。
2. DO 权威骰源生成一个仅存在于当前执行内存中的候选骰面，并在同一 DO 事务内以内部 `RandomnessFulfillment` 调用 `step`；候选本身不能先写入独立随机结果表或幂等缓存。
3. `step` 验证请求 ID、骰式、载荷哈希和同一 `resolutionId`，产生 `DiceRolled` 事件、后续机械事件或 opaque continuation。DO 在一个事务中提交这些事件、状态缓存、作用域版本和幂等 Receipt；事务提交前骰面没有权威性，提交后事件流是其唯一恢复依据。
4. 提交前崩溃允许重新生成候选，因为没有骰面事实存在；提交成功但响应丢失时，重试按 `randomnessId` 从已提交事件与 Receipt 返回原结果。不同骰式、载荷或结算引用必须拒绝；骰面事件之后尚未完成的纯机械步骤只使用已提交的 `AutomaticContinuationInput` 继续。

随机请求、继续点、幂等 Receipt 和骰面事件都保存在 Room DO 的权威提交中；客户端、LLM、独立随机结果表、D1 归档副本和 Worker 内存不能成为第二恢复依据。

## 14. 统一能力模型与动态定义

武器、法术、职业特性、怪物动作、物件能力和环境危险都经 `AbilityDefinition` 与 `InvokeKnownAbilityProposal` 进入相同结算框架。

能力定义至少能够声明：

- 使用者、控制权与使用时点；
- 动作、附赠动作、反应、移动、次数、充能、法术位、材料或其他成本；
- 目标、范围、区域、视线、清晰路径和封闭选择；
- 攻击、检定、豁免、优势劣势和派生数值；
- 伤害、治疗、临时 HP、移动、资源与效果；
- 持续时间、专注、重复豁免、触发和终止条件；
- 对环境、实体、物品或危险的结构化变化。

内部 `MechanicOp` 是规则编译器私有、封闭、版本化的中间表示。它必须是有语义的受限原语，不接受任意字段路径、脚本、函数或状态补丁。新增原语会改变可表达机械，必须随规则版本和 `eventSchemaVersion` 审查。

KP 创建动态敌人、危险或即兴能力时提交 `MechanicalProposal`，而不是直接提交 `MechanicOp[]`。规则内核验证完整结构、引用、行动经济、目标、距离、骰式、持续时间、资源和原语可执行性；非法项逐项返回，KP 修订后重提。

动态敌人定义至少覆盖属性、AC、HP、速度、感官、豁免、技能、攻击、伤害、法术、资源、状态免疫、动作、附赠动作、反应、特殊能力、控制者、死亡策略、目标和初始有限知识。动态危险至少覆盖触发条件、可感知迹象、调查/解除方法、攻击或豁免、范围、伤害、状态、持续时间和环境后果。

高 AC、高 HP、高攻击、高伤害或高危险本身不是机械非法。危险度报告只提供信息，不能自动拒绝、削弱、替换或按队伍缩放实体。

## 15. 施法生命周期

版本化 `SpellDefinition` 编译为统一能力定义，不再拥有平行战斗结算路径。施法必须验证：

- 已知、准备、法术来源与施法档案；
- 施法时间、动作经济和本回合施法历史；
- 法术位、次数和有价或消耗材料；
- 言语、姿势、材料及当前状态是否允许；
- 目标、射程、视线、清晰路径和区域；
- 法术攻击、豁免 DC、专注和持续时间。

D&D 5e 2014 的附赠动作施法限制必须通过整回合施法账本双向验证：本回合一旦施放附赠动作法术，其他法术只能是施法时间为一个动作的戏法；先施放不符合条件的法术也会阻止之后施放附赠动作法术。

没有施放附赠动作法术时，2014 规则不存在“每回合只能花费一个法术位”的通则；动作如潮可以允许同一回合施放两个施法时间为一个动作的非戏法法术。不得混入 2024 的每回合法术位上限。

普通一动作、附赠动作或反应法术在规则确定施法合法并开始施放时承诺动作与法术位；反制法术取消其效果时不自动返还。预备法术在预备时已经施放并消耗法术位。施法时间长于一个动作的法术必须每回合投入动作并维持专注，只有完成时才消耗适用的法术位；完成前中断会使法术失败但不消耗该法术位。合法仪式施法在通常施法时间上增加十分钟，完成时不消耗法术位。所有长施法、仪式和其他耗时行为必须以可中断 Activity 或结算帧保存，效果只在完成后提交。

区域法术的受影响实体由权威空间计算。法术攻击使用结算时的有效 AC；豁免使用结算时的有效属性、熟练与效果。任何目录效果只有在规则内核存在对应可执行语义时才可标为已支持。

同一个法术或效果同时对多个目标造成伤害时，共享一次权威伤害骰结果；各目标分别进行需要的豁免，并分别应用免疫、抗性、易伤、临时 HP 和 HP 后果。能力明文要求分别掷骰时才可例外。

专注规则统一执行：一个实体同一时刻只能专注一个效果，并且可以随时、无需动作主动结束专注。一旦施放另一个需要专注的法术，旧专注立即结束；新法术随后被反制也不会恢复旧效果。每个独立伤害来源分别触发体质豁免，DC 为 10 或 `floor(damageTaken / 2)` 取较高者；`damageTaken` 是免疫、抗性、易伤及其他减免后、本次分配给临时 HP 或 HP 前的伤害，完全降为 0 时不触发。失能或死亡直接结束专注；浪涛等环境现象通常由 KP 在事前固定后触发 DC 10 体质豁免，只有能力明文时才直接结束。

## 16. 效果、伤害、0 HP 与死亡

### 16.1 效果

所有持续效果使用 `EffectInstance`，至少记录来源能力、来源实体、目标或区域、规则版本、开始时点、持续与到期条件、专注者、叠加规则、可见性和机械标签。

效果不能只以叙述字符串存在。投影显示的 AC、速度、优势劣势、感官和资源必须与攻击、移动和豁免使用同一有效值计算。

### 16.2 伤害包

一个 `DamagePacket` 对应一次机械伤害实例。一次攻击同时造成的多种伤害类型可以位于同一包；同一个法术、危险或能力可以因多次独立攻击、射线或不同时点的持续伤害产生多个包。不同包分别结算，以保留反应、专注和 0 HP 触发的正确次数。

管线至少按以下因果顺序执行：

1. 固定命中、豁免或其他命中条件；
2. 请求并记录各伤害分量和暴击附加骰；
3. 先应用其他伤害修正；免疫把相应伤害分量归零，否则同一分量的抗性不论来源只减半一次，再让易伤不论来源只加倍一次，每次除法向下取整，得到该来源的 `damageTaken`；
4. 计算临时 HP 吸收和 HP 的暂定结果，但尚不提交 0 HP 与死亡；
5. 若近战攻击将目标从正 HP 降到 0，立即向攻击者打开非致命选择窗口；
6. 按选择提交临时 HP、HP、0 HP、巨量伤害、昏迷、稳定或即死；
7. 对该来源触发专注、死亡失败、状态和其他伤害后效果；
8. 打开仍然合法的后续窗口，再恢复原结算。

伤害类型分别保留到免疫、抗性和易伤处理完成。临时 HP 不叠加、不是治疗，也不会因为吸收全部伤害而取消本已发生的伤害触发。攻击掷骰的自然 1、自然 20 和暴击语义不能误用于普通检定或豁免；暴击只增加相应伤害骰，不把固定加值翻倍。

### 16.3 0 HP 与死亡

规则必须表达：

- 降到 0 HP、昏迷、稳定、恢复 HP 和死亡；
- 0 HP 时受伤造成的死亡豁免失败，暴击造成两次失败；
- 单次剩余伤害达到最大 HP 时即死；
- 所有 `deathPolicy = deathSaves` 的实体在自己回合开始时进行死亡豁免；
- 成功、失败、自然 1、自然 20、稳定和恢复 HP 的结果；
- 近战攻击将目标降到 0 HP 时由攻击者选择非致命击倒；
- 实体固化的 `deathPolicy`。

死亡豁免累计三次成功时稳定，三次失败时死亡；自然 1 计两次失败，自然 20 立即恢复 1 HP。恢复 HP 或稳定会把累计成功与失败重置。

稳定实体不再进行死亡豁免，但仍处于 0 HP 且昏迷；再次受伤会使其失去稳定并按 0 HP 受伤处理。未接受治疗的稳定实体在 `1d4` 小时后恢复 1 HP，该骰面和恢复 Activity 必须由权威状态保存。角色可以用动作进行 DC 10 Wisdom（Medicine）检定使 0 HP 生物稳定。0 HP 实体获得临时 HP 不会恢复意识、恢复真实 HP 或自动稳定。

大多数普通 NPC 可以按其已固化策略在 0 HP 死亡；重要 NPC 可以使用死亡豁免。KP 必须在死亡结果可知前固化策略，不能看到伤害或剧情需要后临时保护或处决 NPC。非致命选择只适用于将目标降到 0 HP 的近战攻击，选择后目标昏迷且稳定；远程攻击和仅要求豁免的效果不能使用该选择。

SRD 没有明确写出非致命击倒与巨量伤害即死同时成立时的优先级。烛帷采用版本化产品裁定：`KnockOutChoice` 先于巨量伤害和普通 NPC 的 0 HP 死亡策略结算；攻击者选择非致命后，目标昏迷且稳定，即使剩余伤害达到其最大 HP 也不即死。该选择与骰面必须进入事件并可回放。

死亡、稳定和战斗结束不会自动清除位置、物品、伤势、知识或仍应存在的世界效果。

## 17. NPC、有限知识与战术选择

NPC 回合和反应由 KP 根据该 NPC 的专属决策投影提出。该投影只包含 NPC 自己的目标、性格、知识、感官证据、位置、资源、伤势、恐惧、可见实体和已知能力。

KP 的主持全知投影与 NPC 决策投影必须分开。完整模型上下文即使包含玩家计划、隐藏位置或未公开法术，NPC 也不能据此选择目标、移动、反制或撤退。

CombatCoordinator 不得自动选择第一攻击、最近目标、最低 HP、最优解或固定仇恨。NPC 可以攻击、移动、使用资源、保留反应、帮助、逃跑、投降、谈判、误判或浪费机会；提案一经形成，与玩家机械行动接受相同 `step` 验证。

KP 不响应或模型暂时失败时，战斗保持在最近的稳定等待点。系统可以重试同一未提交决策，但不能伪造默认行动或跳过 NPC 回合。

## 18. 遭遇结束

“只剩一个存活阵营”只能产生结束候选，不是唯一条件。遭遇可以因以下事实结束：

- 所有仍敌对的实体都死亡、失能、无法继续或已经离开；
- NPC 投降且玩家明确接受停止冲突；
- 玩家角色主动撤退并完成逃离；
- 双方接受停战、谈判或其他停止敌对的结果；
- 遭遇目标完成，且当前没有实体选择继续机械冲突；
- KP 依据已固化事实判断当前机械冲突已经不再需要先攻顺序。

KP 可以决定 NPC 和世界是否继续敌对，玩家分别决定自己的角色是否继续。KP 不能替玩家角色投降、接受条件或停止合法追击。

`ConcludeEncounterProposal` 必须说明已成立事实、各方意图和结束原因。Rules Module 验证：

- 没有尚未结清的伤害、移动、死亡或强制效果；
- 没有需要相应控制者回答的窗口；
- 退出、俘虏、尸体、位置、资源和持续效果已经成为世界事实；
- 结束不会清除或回滚合法后果。

遭遇结束后状态不可被静默重新打开；之后重新爆发敌对行动建立新的遭遇，并引用此前结果。遭遇结束不等于核心故事结束；故事收束继续服从 `SPEC 0001`。

## 19. 观察者专属投影

`project` 必须按观察者身份、角色知识、感官、位置、效果和公开权限生成战斗投影。至少区分：

- 玩家查看自己角色；
- 玩家查看其角色能够感知的其他实体和战场；
- NPC 用于行动选择的有限知识投影；
- KP 用于主持的秘密投影；
- Room DO 内部完整状态。

KP 主持投影只在可信服务端内部使用，不能序列化给普通客户端。NPC 决策必须显式请求 NPC Viewer 投影，不能把 KP Viewer 投影裁剪几项后当成同一输入。

未经获得不得公开：

- 隐藏或未发现实体及其精确位置；
- NPC 精确 HP、AC、资源、未公开能力与死亡策略；
- 未使用反应、预备动作及其秘密触发；
- 未触发危险、秘密出口、隐藏地形机制和敌方目标；
- 其他玩家的私人窗口、秘密选择和未公开信息。

自己角色的精确机械资源和待决窗口必须可见。其他角色或 NPC 的伤势可以通过感官证据、公开桌规和已获知识呈现，但不能因页面需要直接投影内部状态。

投影约束适用于快照、增量事件、候选目标、合法动作、错误信息、随机请求、日志和 KP 叙述输入。系统不能通过“目标不存在”“对方保留了反应”等错误文本泄露秘密。

玩家询问裁决时，系统应说明可公开规则和已知事实，并将隐藏依据概括为不泄密的世界内原因。

## 20. 持久化、并发、回放与更正

### 20.1 持久化与并发

`ResolutionState`、窗口、骰子请求、骰面、行动资源和继续点都属于 Room DO 活跃状态。只存在于进程内 Promise、页面状态、Prompt 或 UX 租约中的待决结算不具有权威性。

每次提交必须验证可信 actor 或内部 capability、控制实体、房间、地点、遭遇、回合/窗口权限、幂等 ID 和对应 `ScopeBaselineSource` 的相关 `scopeRevision`。客户端字段不能覆盖可信身份或控制权，`roomRevision` 的无关变化不能单独造成冲突。Rules Module 的 `scopeProof` 是实际机械读写闭包的唯一来源；DO 只比较证明与 TurnTicket、`ResolutionScopeBaseline` 或 `CorrectionContext` 中相应的基线并更新版本，不实现第二套作用域推导。

同一遭遇内影响相同实体、空间、窗口或效果的提交必须串行原子化。WorldState、WorldEvent、幂等 Receipt、`ResolutionState` 和窗口必须在同一 DO 事务内一起提交，不能出现“扣了资源但窗口没保存”或“事件成功但幂等记录缺失”的半提交。

不同地点的无关动作可以并发；发生作用域冲突或 `scopeProof` 引用相应基线未绑定的既有作用域时不得提交部分事件。外部提案废弃未提交结果、重新 `prepare` 并基于新投影重提；内部结算保留最近稳定点并交回重新裁决，不能读取该作用域当前版本后把旧解释直接接受，也不能把任一种基线当全房间锁。LLM 永远位于 DO 事务外；内部推进达到工作预算时保存 opaque continuation，并由 DO 授权构造 `AutomaticContinuationInput` 恢复，不伪造成功。

### 20.2 回放

`replay` 以房间 genesis 和房间内连续 `eventSeq` 的事件流重建完整 `WorldState`；遭遇建立只是该事件流中的 `EncounterStarted`，不是第二套独立 genesis。房间 genesis 必须固定规则集、`eventSchemaVersion`、模组/世界定义版本、初始能力目录哈希、几何 Profile 和初始权威状态。

`eventSeq` 必须在房间内单调连续，并与 `eventSchemaVersion`、`roomRevision` 和 `scopeRevision` 分开。快照只是带 `eventSeq` 与状态哈希的可重建缓存。事件必须保存足够信息，使未来回放不依赖当前目录或 LLM。

战中动态能力、敌人或危险通过 `DefinitionRegistered` 或等价事件保存规范定义、编译器版本与内容哈希；之后的 `AbilityRef` 引用该精确哈希。`step`、`project` 和 `replay` 必须拒绝规则集、事件 schema、编译器、几何或定义哈希不匹配的输入，而不是尝试用“最新版本”解释。

回放只能折叠已提交事件，包括窗口打开/响应、随机请求/骰面、结算帧推进、效果产生/终止和遭遇结束。回放不得生成新随机数、重新选择 NPC 行动、重新判定隐藏现实或重新运行能力编译器。

房间全局审计 `eventSeq` 在发生更正分支后仍保持单调连续；每个事件同时绑定 `branchId`，初始事件属于根分支。`CorrectionBranchOpened` 必须记录父分支、分叉事件、被取代的因果闭包、继续沿用的无关作用域头及其哈希；`BranchActivated` 明确房间当前活动分支和活动 head。两者本身也是不可变事件。`replay` 折叠完整全局事件流，按最终已提交的活动分支选择其祖先、沿用的无关作用域和未被 supersede 的事件，并拒绝断裂、循环或哈希不符的分支图；调用者不能通过遗漏旧事件伪造一条“干净历史”。

### 20.3 可审计更正

尚未提交的错误提案直接废弃并重做。玩家和 LLM/KP 可以报告疑似错误，但不能直接提交更正事件。唯一执行入口是 Room Authority 的 `commitCorrection`；普通 `commit`、CombatCoordinator、页面和模型都不能构造 `CorrectionResolutionInput`。该入口只接受房间桌规预先指定的可信 `CorrectionAuthority` 或可证明机械错误的系统审计器签发的 `AuthorizedCorrectionRequest`，并在每次调用时重新验证授权。

请求只引用错误事件、错误类型、规则/事实依据、预期受影响范围和获批更正策略，不能携带状态补丁、`MechanicOp`、分支图或调用者生成的补偿事件。Room DO 从完整已提交日志构造 opaque、规范哈希绑定的 `CorrectionContext`，至少包含：

- 当前活动 `branchId`、活动 head、规则版本和事件头哈希；
- 被引用事件、其前置状态哈希、机械与玩家选择的因果后继闭包；
- 受影响作用域及不受影响作用域的当前 head/hash；
- 属于该闭包的 `ResolutionState`、待决输入、随机请求/骰面和幂等 Receipt；
- 用于证明日志连续、上下文未被裁剪或替换的事件片段与上下文哈希。

DO 把授权请求和该上下文组合成内部 `CorrectionResolutionInput` 交给 `step`。Rules Module 验证上下文、因果闭包和规则依据后，才生成 `CorrectionEvent`、前向补偿或分支事件；DO 不能自行计算补偿。存在与更正无关的未结算 `ResolutionState` 时先拒绝更正，避免跨结算改写事实；活动结算本身属于受影响闭包时，Rules Module 必须在同一更正提交中显式产生 `PendingInputSuperseded`、`ResolutionSuperseded` 或等价事件，无默认回答、无额外资源消耗地关闭它，不能让 DO 直接删除窗口。

已经影响权威状态的错误必须追加版本化更正，并满足：

- 引用被更正事件、受影响范围、可公开说明与必要秘密依据；
- 保留旧事件、旧骰面、旧 Receipt 和旧分支供审计；
- 当前状态能够诚实恢复且后续玩家选择不依赖错误结果时，使用 Rules Module 生成的前向补偿；
- 错误已经造成角色死亡、位置变化、资源选择或其他因果分歧时，打开并激活新分支，明确 supersede 的因果闭包，让受影响主体重新裁决，同时按哈希沿用无关作用域事件；
- 属于 supersede 闭包的待决输入、随机结果和 Receipt 只保留历史状态，不能在活动分支继续消费；旧 `submissionId` 仍返回带 superseded 状态的历史 Receipt，重新裁决使用新 ID；
- `replay` 从同一全局日志确定得到当前活动状态，`project` 只向观察者公开其有权知道的更正与分支信息。

是否需要新随机请求由错误是否改变原骰式、目标、DC、优势劣势或其他冻结输入决定；输入未变时沿用原骰面，输入改变时旧骰面仅留在旧分支，并在新输入冻结后产生新的 `randomnessId`。幂等重试、不喜欢结果或剧情偏好都不是重掷理由。更正不能编辑、删除或静默替换旧事件，也不能声称历史从未发生。

## 21. 拒绝、失败与重试

框架必须区分：

1. **权限拒绝**：身份、控制权、地点、回合或窗口不合法；不产生世界结果。
2. **版本冲突**：票据相关作用域已变化；重新投影和重提。
3. **机械提案非法**：返回具体字段、规则和不可执行原因；KP 修订后重提，不先掷骰、不伪造成功。
4. **缺少澄清**：交回对应玩家，不由系统选择。
5. **世界内不可行**：KP 按缺少前提或违反规律说明；尝试若已有真实成本则提交成本。
6. **合法行动失败**：完整提交动作、时间、资源、暴露、伤害或其他相称后果，并形成新的可行动局面。

机械错误诊断不是角色能够感知的世界事件，不能直接由结果叙述器包装成“你失败了”。同一行动只有做法、条件、成本或局势实质变化后才能重新检定。

任何 Adapter、模型或外部依赖失败都必须停在最近稳定等待点。重试不能重复扣资源、推进回合、掷骰或叙述成虚假成功。

## 22. 叙述与提交顺序

机械或世界结果必须先由 Room DO 原子提交，再由 `project` 生成相应观察者事实，最后交给 KP 叙述：

```text
玩家意图 / NPC 意图
        ↓
KP 裁决与机械提案
        ↓
step → 待决输入 / 权威骰面 / 已提交事件
        ↓
project(viewer)
        ↓
KP 依据真实结果叙述并交还决定权
```

结果叙述不能改写命中、伤害、资源、死亡、位置或其他已提交事实。若叙述需要引入会影响因果的新事实，KP 必须另行提出并经 `step` 固化。

叙述只能描述玩家角色的外界刺激、身体反应和规则状态，不能替其决定情绪、信念、台词、是否恐惧或下一步行动；每次结算应呈现可感知变化和当前压力，并把决定权交还正确玩家。多人或分头战斗在自然决定点维护聚光灯，房主、队长和活跃玩家不能替其他玩家行动。

玩家请求暂停、淡化或避开现实敏感内容时，CombatCoordinator 与 KP 必须立即停止或调整相关呈现，并保持房间在最近已提交的稳定等待点；即时生效不需要房主、队长、全桌或其他玩家批准。请求原因和个人边界只向请求者及可信安全处理器投影。只有请求者明确选择时，系统才持久化满足后续避让所需的最小化、脱敏边界；是否另行修改全桌公开桌规是独立的自愿流程。内容安全处理不修改骰面、伤害、资源或已经发生的世界事实。

叙述模型失败不回滚机械结果。叙述幂等键必须绑定 `eventRange + activeBranchId + viewer/principal + projectionHash + narrationPolicyVersion`，不能只使用事件 ID；同一事件对不同观察者、不同活动分支或不同投影必须生成相互隔离的叙述任务。重试不能重新掷骰或再次执行动作；公开叙述只使用公开投影，私人结果分别发送给有权观察者。

## 23. 版本与迁移

本框架只能通过新规则集版本启用。版本至少固定：

- D&D 5e 2014 / SRD 5.1；
- 战斗状态与事件 schema；
- Ability Definition 与内部机械原语版本；
- Battlefield Geometry Profile；
- 触发点、反应时序和同时事件排序规则；
- 施法、伤害、专注和死亡管线；
- 投影与秘密字段策略。

### 23.1 2014 规则护栏

实现和内容目录必须通过回归测试阻止以下 2024/5.5e 语义混入：

- 突袭使用本规格的首回合限制，不使用先攻劣势；
- 施法使用附赠动作法术限制，不使用“每回合只能消耗一个法术位”；
- 反制法术使用 2014 的等级比较与施法属性检定，不改成目标体质豁免，也不返还目标已经消耗的法术位；
- 擒抱与推撞使用特殊近战攻击和对抗检定，不使用徒手攻击后的力量/敏捷豁免；
- 不引入 Weapon Mastery、每次攻击自由装备/卸下武器或 2024 的 Magic、Utilize、Influence、Study 动作语义；
- 躲藏由环境是否允许及 Stealth 对 Perception 决定，不使用固定 DC 15 后获得 Invisible 状态；
- 只有具体能力明文允许时才能自愿失败豁免，不存在通用自愿失败规则；
- 疲乏使用 2014 六级规则，不使用每级 D20 Test -2 或通用 Bloodied 机械状态。

本规格的 2014 机械基线是 Wizards of the Coast 发布的 [Systems Reference Document 5.1](https://media.wizards.com/2016/downloads/DND/SRD-OGL_V5.1.pdf)。项目产品约定（例如数字空间几何和并发排序）必须明确标为版本化产品规则，不能伪装成 SRD 明文。

迁移不得把旧房间的事件用新解释器重算。旧战斗实现应保留为显式 Legacy Adapter，直到所有活跃旧房间结束或存在经批准的确定性迁移。

现有行为可以用 characterization tests 记录，但已知违反本规格的行为不能因“保持行为”被复制到新内核，包括全员零距离、自动借机攻击、固定 NPC 目标、客户端范围选人、平行法术结算和 D1 战斗状态镜像。

## 24. 验收场景

后续实现至少必须通过以下 Interface 级行为测试。每项测试在拥有该责任的公开 Interface 上运行，不能为了方便把所有行为伪装成 Rules Module 单测：

| 验收面 | 驱动入口 | 允许观察的结果 |
| --- | --- | --- |
| Rules Module | `step`、`project`、`replay` | 拒绝诊断、权威事件、下一稳定方向、观察者投影与确定性回放 |
| Room Authority | `prepare`、`commit`、`observe`、受限 `commitCorrection` 及可重启 DO 测试夹具 | 鉴权、作用域并发、幂等 Receipt、待决持久化、权威随机数、崩溃恢复与更正授权 |
| CombatCoordinator / KP | `handle`、受控模型夹具和 Room Authority 的公开 Interface | 标准 KP 循环、澄清、自由行动、NPC 决策、叙述、模型失败与聚光灯 |
| 跨层产品路径 | 已认证玩家意图到观察者投影的生产接缝 | 单一路径、秘密边界、暂停恢复和完整遭遇闭环 |

所有机械或世界变化最终仍必须经 `step` 产生事件，并只能经 `project` 对外观察；回放只能经 `replay`。任何测试都不能直接改写 `WorldState`、结算帧、窗口、骰面或内部事件来构造“通过”结果。一个场景可以跨越多个 Interface，但每层只验证自己拥有的责任。

### 24.1 意图与权威

**B01 非目录环境战术**：玩家提出利用环境的合理动作且不存在 `AbilityRef`。KP 作五类裁决之一并形成直接结果或合法机械提案；系统不得以“能力不存在”拒绝。

**B02 重大歧义**：自然语言可能伤害友军、消耗重要资源或造成不可逆结果。系统先向该玩家澄清，其他主体不能代答；确认后不反复劝阻。

**B03 无意义检定**：不存在真实不确定性和失败后果。KP 直接成功并经 `step` 提交必要变化，不请求骰子。

**B04 动态强敌**：KP 依据已有因果和选择公正规则提出远强于队伍但机械完整的敌人，并在不可逆选择前投影角色理应察觉的严重风险。内核可以报告危险，不拒绝、削弱或缩放；敌人固化后保留全部资源和伤势。

**B05 动态敌人非法**：特殊能力包含无效引用、错误行动经济或不可执行原语。内核逐项返回问题，KP 修订后重提；玩家看不到虚假成功。

### 24.2 遭遇与空间

**B06 秘密伏击者**：隐藏敌人在产生感官证据和先攻结果前固化。未发现者的玩家投影、目标候选和错误中均无该敌人；之后不得按玩家 HP 更换它。

**B07 多阵营遭遇**：三个以上阵营以不同敌对关系进入遭遇，其中一方中途停战。规则不把所有非玩家实体视为同一敌方，关系变化可回放。

**B08 区域自动取目标**：多个实体位于同一区域。调用者只提交区域原点和方向，内核计算全部受影响实体，不能漏选或额外选择。

**B09 路径中断**：可见敌对角色沿多段路径自主移动并即将离开触及，在实际越界前打开可选借机攻击；隐形、非敌对或不满足移动来源的实体不打开。若反应使目标倒地、速度变为零或改变位置，原剩余路径不自动提交，决定权返回控制者重新规划；只有后续攻击因死亡、失能、距离或其他规则变得非法时才取消。

**B10 强制移动**：传送或不使用目标自身移动、动作、反应的强制移动离开触及，不打开借机攻击。

### 24.3 回合、反应与施法

**B11 拆分移动与多次攻击**：角色在一次含多次武器攻击的动作中攻击、移动、换目标、再次攻击。每段合法结算并可被中断，不能原子预提交全部结果；该许可不能被泛化为所有多次法术攻击都能在射线之间移动。

**B12 额外动作限制**：动作如潮和加速术分别提供正确的普通或受限动作；加速术动作选择攻击时只能进行一次武器攻击。额外动作不恢复附赠动作、反应或免费物件互动，但在来源允许时仍可选择“使用物件”。

**B13 护盾术窗口**：攻击已判定命中、伤害尚未掷出时，或角色成为魔法飞弹目标时，合资格角色看到私人反应窗口；使用后触发攻击按有效 AC 重新确定，并在持续期内免疫魔法飞弹，窗口外不能补用。

**B14 反制法术链**：反应者看见 60 尺内生物正在施法时，在法术生效前获得窗口；只听见或看不见施法者时没有窗口。低于或等于反制法术位等级时自动反制，更高等级使用施法属性检定对 `DC 10 + 法术等级`；嵌套反制可暂停恢复，已消耗资源不因效果取消自动返还。

**B15 预备动作**：角色预备一个动作或“移动至多自身速度”，并声明可感知触发。触发完成后可选择使用反应或放弃；只有施法时间为一个动作的法术可以预备，且在预备时消耗法术位并占用专注。

**B16 断线窗口**：玩家在反应窗口断线。窗口与继续点跨重启恢复，现实超时不产生 `pass`、不推进时间、不重复结算。

**B17 附赠动作施法限制**：同一回合不同施法顺序均服从 2014 附赠动作法术规则，额外动作不能绕过该限制；未施放附赠动作法术时，动作如潮允许两个一动作非戏法法术，不能被 2024 规则误拒绝。

### 24.4 效果、伤害与死亡

**B18 有效 AC 单一来源**：护盾术、虔诚护盾或其他 AC 效果同时影响投影和所有攻击路径；不存在“投影 AC 与命中 AC 不同”。

**B19 伤害与专注**：一支含多种伤害类型的箭只产生一个伤害包和一次专注豁免，两支箭或同一施法的两次独立射线分别命中则产生两次；临时 HP 吸收伤害不会取消专注豁免，伤害降为 0 时不触发。非专注法术不会结束旧专注；施放新专注时旧效果立即结束，即使新法术随后被反制也不恢复；角色可以在回合外无动作结束专注，浪涛等环境扰动按事前固定的 DC 10 豁免处理。

**B20 混合伤害与临时 HP**：不同伤害类型分别处理。一个 25 点分量先减 5 点其他修正、再受抗性后为 10；重复来源的同类抗性仍为 10，有易伤时再变为 20。之后正确处理临时 HP、HP 与伤害后触发；除法向下取整，回放得到相同结果。

**B21 0 HP 管线**：覆盖剩余伤害达到最大 HP 时即死、0 HP 受伤、暴击两次失败、三次成功/失败、自然 1/20、Medicine 稳定、稳定后再次受伤、权威 `1d4` 小时恢复、治疗和临时 HP；稳定或恢复 HP 重置累计，临时 HP 不唤醒或稳定，所有状态按来源与时点持久。

**B22 非致命与 NPC 死亡策略**：近战攻击已知会把目标从正 HP 降到 0、但 0 HP/死亡尚未提交时，攻击者获得非致命选择；选择后目标昏迷且稳定，包括剩余伤害达到最大 HP 的情况。普通和重要 NPC 分别服从事先固化的死亡策略，KP 不能在看到伤害后改变；重试和 replay 得到同一选择与结果。

### 24.5 NPC、秘密与并发

**B23 NPC 有限知识**：玩家秘密计划存在于 KP 全知上下文，但 NPC 决策投影中不存在；NPC 不得采取针对性反制。

**B24 NPC 自主选择**：NPC 可以攻击、保留反应、撤退或投降。CombatCoordinator 不自动使用第一攻击、最近目标或最低 HP 目标；所有选择有 KP 事实依据。

**B25 私人窗口和错误侧信道**：只有窗口控制者看到秘密反应、预备动作和可选目标；其他观察者不能从错误、日志或候选数量推断秘密。

**B26 分头并发遭遇**：不同地点的无关遭遇可以推进；同一实体不能同时行动于两个遭遇，跨地点事实冲突由 Room DO 原子拒绝并重提。

**B27 伪造与重试**：伪造 actor、替他人响应、越回合命令和过期窗口均被拒绝。同一 `submissionId` 与同一载荷只产生一次结果，换载荷复用 ID 被拒绝；同一 `randomnessId` 只产生一个权威骰面。

### 24.6 失败、结束、回放与更正

**B28 有意义失败**：即兴战斗行动失败后，动作、时间、资源、位置、暴露或局势发生相称变化；条件未变不能原样重掷。

**B29 非歼灭结束**：敌人投降、玩家接受，或玩家完成逃离。仍有伤害帧或私人窗口时结束提案被拒，结清后才可在无人死亡时结束；双方保留伤势、资源、位置、装备、俘虏和持续效果。一个“直到自身下回合开始”的效果在遭遇中途结束时转换为 Time Profile 到期任务，在对应假想先攻边界恰好到期一次、不授予新战斗动作，重试与 `replay` 结果一致。

**B30 玩家拒绝接受投降**：NPC 投降后玩家明确继续追击。KP 不能替玩家停止；框架依据新意图继续或建立后续机械状态。

**B31 模型失败恢复**：KP 或叙述模型调用失败。房间停在最近稳定等待点；重试不重新掷骰、扣资源或重复事件。另验证到期 NPC 计划已经提交、重新投影后处理原玩家意图的第二次模型调用失败：计划事件只存在一次且永久保留，原意图尚未提交，重试使用最新投影并在含义或重大风险变化时重新确认。

**B32 确定性回放**：从 genesis 和事件重建遭遇，不调用 LLM、随机源或最新目录，得到同一权威状态和相同观察者投影。

**B33 已提交错误更正**：错误攻击或伤害已经影响状态。系统追加可审计更正和补偿事件，旧事件仍存在，回放得到一致的新状态。

**B34 战斗与故事收束分离**：分别验证核心冲突被解决、已经不可逆失败、以及玩家明确放弃三条路径。每条路径都结束已无意义的机械冲突，展示人物、势力、承诺和世界状态的长期后果，并允许进入相称的尾声；玩家之后选择继续时才建立明确的续篇或新冒险，不能暗加敌人或幕后黑手撤销已经取得的胜利、失败或牺牲。

### 24.7 2014 规则与数字空间

**B35 先攻与逐个突袭**：同一隐藏者面对两个被动感知不同的角色时，可以只有一人被突袭；被突袭者首回合不能移动、动作或附赠动作，其回合结束后同轮可以恢复反应。先攻按敏捷能力检定应用加值和优势劣势，自然 1/20 不自动决定结果；三个相同哥布林只产生一次共享先攻骰和一个先攻条目，平手由有权控制者决定。

**B36 擒抱与推撞**：Extra Attack 角色可以用一次攻击擒抱、另一次推撞；目标选择 Athletics 或 Acrobatics 进行对抗检定，不生成 2024 式力量/敏捷豁免。

**B37 多目标法术**：同一法术同时伤害多个目标时只产生一次共享伤害骰，各目标独立豁免并应用防御；自然 20 豁免不会自动成功。

**B38 长施法资源时点**：长于一个动作的法术逐回合消耗动作并维持专注，中断后失败且不消耗法术位；完成时才消耗适用法术位并产生效果。合法仪式增加十分钟且完成后法术位不变；普通法术被反制时已经消耗法术位。

**B39 几何与能力特例**：Geometry Profile 的数值符合其获批 conformance table：恰好射程边界合法、超出最小精度即非法；半掩护为 AC/敏捷豁免 +2、四分之三掩护 +5、全掩护阻止直接目标；挤入狭窄空间每移动 1 尺花费 2 尺并应用攻防影响；指定的不可见区域原点被墙阻挡时落在墙的近侧。普通区域受全掩护阻断，明确声明绕角传播的能力使用版本化特例；同一输入 replay 得到相同集合。

**B40 版本污染回归**：突袭、附赠动作施法、擒抱/推撞、躲藏、疲乏和自愿失败豁免均使用 2014 语义，目录或 Adapter 不能引入对应 2024 行为。

### 24.8 跨层权威、恢复与玩家体验

**B41 目录动作仍走 KP 标准循环**：玩家明确说“用长剑攻击眼前的哥布林”。即使能力、目标和默认路径都能由目录解析，CombatCoordinator 仍先让 KP 读取故事锚点、独立秘密上下文、NPC/势力目标、虚构时间、裁定先例与聚光灯，再形成冻结提案；测试证明 Adapter 不能只解析命令、直接结算，再让 KP 事后补一段叙述。另设一个已经到期、会改变攻击情境的隐藏 NPC 计划：它先经 `step` 提交，协调器重新投影后才处理原意图；玩家票据与客户端从未获得 KP 秘密上下文。

**B42 五类裁定与骰前冻结**：用五组自由行动分别触发直接成功、需要检定、高风险可行、缺少前提和违反世界规律。只有需要随机性的合法行动产生 `RandomnessRequest`；目标、DC、优势劣势、成本、风险与成功/失败范围在骰前固定，看到骰面后修改任一项或补换目标均被拒绝。同一事实与做法重现时命中已有裁定先例；加入合适工具、情报、协助或额外虚构时间后，裁定按事实降低 DC、给予优势、改变检定方式、缩小失败后果或直接成功，而不是机械机会完全不变。

**B43 动态致命危险与选择公正**：模组留白中出现可能致死的环境危险。KP/审计投影保存因果依据，玩家只看见角色有权感知的预示；系统按“因果约束 → 合理性或隐藏权重 → 有意义选择 → 可信随机”的顺序固化触发、迹象、调查/解除、范围、攻击或豁免、伤害、状态与后果。需要隐藏随机时，KP 提交未预选结果的候选与权重，`step` 验证全部候选后请求 DO 骰面，选中事实与定义原子提交且未选项不泄漏。危险可以致命，但不能依据当前 HP 临时出现、消失或改数值；非法定义逐项返回，不产生虚假成功或半个危险。

**B44 观察者投影矩阵**：同一权威状态分别投影给两名知识不同的玩家、一个 NPC、KP 和 Room DO 内部观察者。自己角色的精确资源和窗口可见；未发现敌人、敌方精确 HP/AC/资源、私人反应和秘密能力不向无权者公开；NPC 只见其有限知识；快照、增量、日志、错误和候选项使用同一 projector 与脱敏结果，KP 投影无法被客户端取得。增量请求必须附连续事件片段及匹配的起止哈希；缺片、断序或错误哈希被拒绝，不能退回第二套日志脱敏。

**B45 更正权限与因果分支**：本场景从 Room Authority 的受限 `commitCorrection` 驱动；普通玩家、LLM、普通 `commit` 或 CombatCoordinator 提交状态补丁、更正事件或 `MechanicOp` 时被拒绝，只有重新鉴权的更正入口构造哈希绑定历史上下文。可信更正权威引用一个不影响后继选择的算错伤害时，Rules Module 生成前向补偿；引用一个已导致角色死亡并改变后续选择的错误时，系统建立审计可见的新活动分支，显式 supersede 相应窗口/骰面/Receipt 并重新裁决，同时沿用无关作用域。无关未结算流程会阻止更正，属于错误闭包的待决流程则由更正事件原子关闭；旧事件和旧分支保留，两类结果均可确定回放且秘密依据仍被投影保护。

**B46 内容安全暂停**：玩家要求暂停、淡化或避开现实敏感内容。协调器立即在最近已提交的稳定等待点停止或调整呈现，无需任何其他人批准；请求原因和个人边界不向其他玩家公开。只有请求者明确选择时才持久化最小化、脱敏的后续边界；系统不把安全请求解释为角色动作、反应放弃、机械失败、重掷或既有资源回滚。

**B47 多人聚光灯与私人能动性**：两名玩家分头处于相关战斗，且各自出现自然决定点和私人窗口。系统分别向正确控制者交还选择，不因另一玩家更活跃、是队长或是房主而代答；聚光灯调度不改变先攻、窗口时点或虚构时间。

**B48 叙述不夺取角色**：机械结果提交后，KP 只从对应观察者投影叙述可感知变化、压力与规则状态，不替玩家决定台词、信念、情绪或下一步行动，并明确交还决定权。叙述失败按 `eventRange + activeBranchId + viewer/principal + projectionHash + narrationPolicyVersion` 幂等重试；同一事件分别投影给两个玩家或更正后的新分支时不会复用含秘密或过期事实的文本，也不会生成第二组机械事件或骰面。

**B49 同时触发的确定排序**：两个不同控制者在同一冻结因果点同时获得合法反应。`TriggerOrderingProfile` 收集合资格者并以与对象遍历和网络延迟无关的顺序逐个开私人窗口；先发生的响应使后项失效时，后项无资源消耗地关闭。交换请求到达顺序、断线重连和 `replay` 都得到同一事件顺序与结果。

**B50 随机数崩溃恢复**：分别在随机请求提交后、候选骰面生成但事务提交前、骰面事件与 Receipt 已提交但响应丢失、以及骰面事件已提交但自动机械继续前模拟 Worker/DO 重启。事务提交前的候选不具有权威性且不在事件外保存；提交后同一 `randomnessId` 只从事件与 Receipt 复用原结果，最终只存在一份骰面事件、一次资源消耗和一次机械后果。

**B51 作用域并发**：票据签发后，无关地点提交事件并只改变房间审计游标，原提案仍可提交；相关实体、空间或秘密依据变化时提案被完整拒绝并重新投影。区域取目标、隐藏触发和派生效果的实际闭包由 `step` 的 `scopeProof` 给出，DO 不复算；外部证明出现 TurnTicket 未绑定的既有作用域时整笔拒绝并重新 `prepare`，内部证明超出 `ResolutionScopeBaseline` 时停在稳定点重新裁决，二者都不能读取当前版本后接受旧解释。另验证 automatic 让出后，无关地点提交事件，再以原 `resolutionId + continuationHash + 相关 scopeRevision` 续接仍成功；Rules Module 明确证明为本命令创建的新作用域在无冲突时可以原子加入。

**B52 动态定义与版本回放**：战中注册一个动态危险或敌人能力，事件保存规范定义、编译器版本和哈希；使用该能力并完成回放时不查询最新目录或重新编译。用不同规则集、事件 schema、几何 Profile、编译器或定义哈希解释同一事件流必须显式拒绝，不能静默采用当前版本。

**B53 完整垂直切片**：一个多人遭遇从自然语言自由行动开始，包含动态环境、移动中断、玩家反应、NPC 有限知识选择、权威骰面、伤害/专注、断线恢复、私人投影和非歼灭结束。结束后的伤势、资源、俘虏、承诺与世界关系进入后续场景；KP 可以诚实收束已解决冲突，不能用新敌人撤销本次胜利。

## 25. 实施顺序与完成门

实施必须从权威内核向外进行：

1. 批准本规格及其依赖的 Geometry Profile、提案协议和能力原语版本。
2. 按验收面建立上述 Interface 级测试；现有测试只作为 Legacy 行为记录，不直接修改状态构造战场。
3. 在新 `ruleset_version` 下建立遭遇、空间、先攻、回合、`ResolutionState` 和事件模型。
4. 接入 DO 权威随机数、幂等恢复和待决窗口。
5. 统一攻击、移动、法术、伤害、专注、死亡和持续效果。
6. 接入 KP 自由行动提案、动态敌人/危险和 NPC 有限知识决策。
7. 完成观察者投影、页面待决交互、叙述重试、结束和更正。
8. 删除旧 D1 战斗写路径、自动 NPC 战术、客户端骰面/区域选人和旧平行结算 Adapter。

本规格的实现完成门是：

- B01–B53 全部在其责任 Interface 上通过，跨层用例穿过真实生产接缝；
- 所有产生机械或世界变化的用例都证明其事件来自 `step`，对外观察来自 `project`，回放来自 `replay`；涉及秘密的用例至少验证一个无权观察者投影；
- 随机、断线、并发与回放测试证明不重复结算；
- 新旧规则版本隔离，旧房间回放不变；
- Room DO 是唯一活跃战斗状态，D1 只保存可重建归档；
- 页面和 CombatCoordinator 不再计算机械结果或替控制者作决定，目录动作也不能绕过 KP 标准循环；
- 代表性完整遭遇能够从建立运行到投降、逃跑、胜利或死亡，并在暂停后恢复。

## 26. 后续设计边界

以下主题必须以本规格为上位约束继续设计，但其详细 schema 或算法不在本文件内展开：

- KP 自由行动、动态事实和机械提案协议；
- `BattlefieldGeometryProfile` 的精确几何算法；
- `AbilityDefinition`、私有 `MechanicOp` 和动态实体/危险编译器；
- 感官、角色知识、秘密事件与观察者投影协议；
- 分头地点、虚构时间、Activity 和因果前沿协调；
- 世界事件更正、审计和回放工具；
- NPC 计划、势力推进、投降/逃跑与故事收束；
- 多人聚光灯、私人窗口和房间恢复交互。

后续规格不得：

- 把 `AbilityRef` 变成玩家行动白名单；
- 让 CombatCoordinator、页面、D1 或 LLM 拥有第二套机械或状态权威；
- 让 NPC 决策读取 KP 全知投影；
- 让现实超时替玩家放弃反应；
- 让机械原语成为任意状态补丁语言；
- 让新目录或新几何算法改变旧房间回放；
- 以实现困难为理由缩小 `SPEC 0001` 的叙事权威。

核心原则固定为：

> 战斗框架决定机械顺序、合法性与已结算后果；玩家决定玩家角色的意图，KP 依据故事锚点和 NPC 的有限知识决定世界与 NPC 的意图；权威状态只在待决输入结清且结束事实成立时提交遭遇结束。
