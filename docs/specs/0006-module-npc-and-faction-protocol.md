# SPEC 0006：模组、动态实体、NPC 与势力协议


## 1. 模组是故事圣经，不是流程图

版本化 `ModuleBible` 至少包含：

- 模组 ID、版本、兼容 `ruleset_version`、内容边界与主题/基调；
- 核心真相、重要历史和不可任意改写的 Story Anchor；
- 已知地点、势力、关键 NPC、初始关系、资源和起始世界事实；
- 开放留白及其因果约束，而非穷举可执行场景；
- 初始冲突、承诺、威胁和潜在收束信号；
- 可选的目录定义与 Legacy Anchor；
- 章节入口和扩展点，不预定唯一场景顺序、路线或结局。

模组不得把 `Interaction`、Portal、NPC Plan、Scheduled Event 或 Ending 的封闭清单当成玩家行动白名单。未登记但合理的行动由 KP 按 SPEC 0001/0004 裁决。

## 2. 模组版本

房间 genesis 固定 `moduleId + moduleVersion`，并记下当时的内容哈希作为引用的一部分；房间按版本认模组，模组正文按版本维护，不以哈希锁定。动态事实属于房间事件，不回写静态模组。可以登记多个模组版本：新房间用当前版本，已有房间保留创建时的版本，章节沿用 Campaign 的 `moduleRef`；不接受迁移提案，不产生模组迁移事件，也不为旧版本另设 Adapter。会让已有房间的状态与模组正文对不上的改动（例如开场地图与站位），登记为新版本。

## 3. 开放留白与动态实体

KP 可依据现有事实动态提出地点、通路、NPC、敌人、盟友、物品、陷阱、危险、机会、支线和空白结果。提案至少包含：

- 叙事身份、因果依据、与 Story Anchor 的关系；
- 首次可见/机械生效时点和 Visibility Policy；
- 规则需要的完整定义、控制者和初始状态；
- 定义/Profile/编译器版本与引用；
- 若有多候选，未预选候选集和隐藏权重。

Rules Module 验证结构与机械可执行性，不以危险太高、奖励太强、队伍等级或戏剧偏好拒绝。非法项逐条返回 KP 修订；定义固化后持续存在。

## 4. NPC 领域模型

每个重要 NPC 至少保存：

- 稳定实体 ID、动态/预写来源和版本化机械定义；
- 目标、价值/性格约束、顾虑、恐惧和错误倾向；
- 当前地点（只随本人的移动改变，见 §7）、资源、伤势、装备、关系、承诺和债务；
- 已获得的感官证据、来源主张、推断与有限知识；
- 可用能力、死亡策略、控制权与当前计划；
- 声口只作为叙述提示，不替代结构化事实。

NPC 不能读取 KP 的全知投影。`project({kind: "npc", npcId})` 只提供该 NPC 知道、感知或合理记得的事实。相同模型处理多个 NPC 时也必须分别请求投影；不能共享隐形群体大脑。

## 5. 势力领域模型

`Faction` 至少包含目标、成员/代理、资源、控制区域、知识、关系、公开立场、秘密议程和计划。势力知识不是成员自动共享；必须由通信或组织能力传播。势力行动通过有权 NPC/代理或明确世界机制执行。

势力可以误判、内部不一致、资源不足或选择不行动。KP 不得因为知道玩家计划而让无信息势力提前反制。

## 6. NPC/势力计划

`ActorPlan` 是具有前提、下一步、资源、Activity、到期/触发、可察觉痕迹和备选目标的权威计划。它不是必然剧情脚本；世界事实变化后，KP 可依据该主体有限知识提出修订。

计划推进条件只来自虚构时间、已提交事件、已取得知识或明确触发；现实等待、模型延迟、掉线和 UX TTL 不推进。到期计划必须在处理受影响玩家意图前经同一 Room Action 事务提交，再重新投影。

计划执行可成功、失败、中断、取消或形成新问题；所有机械行动与玩家行动一样经 `step`。NPC 回合不能由协调器自动使用第一攻击、最近目标、最低 HP、固定仇恨或默认 `pass`。

## 7. NPC 决策协议

1. Room Action Module 向 Room Authority 请求指定 NPC Viewer。
2. KP 仅依据该投影、NPC 目标/性格/错误形成意图和提案。
3. 机械定义/目标/成本冻结后由 `step` 验证与结算。
4. 模型失败时保持最近稳定等待点；不自动行动或推进时间。
5. 提交后分别按每位观察者 `project`，再生成隔离叙述。

KP 可以选择攻击、保留反应、帮助、撤退、投降、谈判、误判、浪费机会或改变计划，只要与 NPC 知识和事实相容。Rules Module 只判断机械合法性，不优化战术。

交谈中的回答：玩家对 NPC 说话时，裁决决定对方是谁、对方听到什么和看到什么、这番话是否需要检定，以及玩家自己作出的承诺和对既有承诺的变更。NPC 说什么、为什么这样说、答应什么、欠下什么、对说话人的态度怎样变化，由该 NPC 本人单独作答，每名被交谈的 NPC 调用一次模型。这次调用读到的是：该 NPC 本人的投影（身份、目标、行为边界、声口，本人的记忆、关系、承诺和债务，在场看得到的人和物），听到的话，亲眼看到的举动，以及本次方案明确交给它知道的新事实。它读不到主持人的资料、裁决的目标、做法和摘要、玩家的原始输入和他人的知识；模组为主持人列出的“该 NPC 不知道什么”也不给它。本人明确未知的事不能补写成一直知道，未加载的材料也不构成开放留白。本人可以提出符合身份、围绕已有对象的生活习惯或往事候选，逐条记录稳定的本次标识、原内容、发生时间、认知态度及取得来源；当前 A 段不开放新增人物、地点或物件。候选经主持人一侧审核批准，并在发布前与本人知情记录沿正常权威链一同固化，才成为真实经历。NPC 仍可依自身目标隐瞒、误信、夸张或说谎，但必须有成立的来源、时间和动机，不能事后将矛盾改称谎言。需要检定时，NPC 在骰前对成功和失败各写一份回答，它只被告知这番话对自己有没有起作用。主要察觉对象在隐蔽动作失败后的当场回答，依据它察觉到的举动。Room 只提交本人调用保存、并经对应审核通过的回答；调用次数、重问和恢复见 SPEC 0016 §7.2。

每个有效裁决版本的整组回答都经主持人审核，包括新增清单为空的回答。审核检查全部台词、本人后果、遗漏申报、知识权限、与已有记录的连续性及各可达分支的共同过去。审核可以复用本人已知内容、批准有知识依据的合理留白、只认可有来源的说法，或退回相关 NPC；不能改写本人台词。退回只传字段位置、受限错误类别、原回答与本人原先已读记录，主持人的秘密与自由文本理由不传给 NPC。结构错误和语义退回共用同一份回答的一次修改资格。

共同过去不能随检定结果改变；实际说法、听众知识和行动后果只在真正发生的分支保存。新增真实经历与本人知识在同一行动内提交；未提交的审核候选不产生世界变化。误信、谎言或不确定内容只保存来源关系，不据此改变命题真假；本人私有来源与实际听众所得内容分开。相关事实和原话沿知识目录及冻结版本回读；目录在记忆多时把较早的记忆按场景和天数归组，按组读取（列法见 SPEC 0016 §4.3）。六轮默认正文窗口和目录分组都不删除记录，也不授权以新编内容替换未读取的历史。

旁人察觉后的当场反应：隐蔽动作的主要察觉对象以外，每个察觉了的 NPC（SPEC 0005 §6.2）在同一次行动中单独调用一次模型，只依据该角色本人的投影（身份、目标、性格、知识和刚看到的内容），决定是否反应以及怎样反应；不反应也是合法结果。反应经 `step` 结算，随本次行动在同一次回复里发布。各察觉者独立决定；一人的反应给别人带来的新感知进入他们的记忆，但不在本次行动里再引发新的反应。某个察觉者的调用失败时，他这次不反应，感知记录保留，行动结果照常发布。每次调用计入本次行动的模型预算。玩家角色不做被动察觉判定（SPEC 0005 §6.2），只从看得见的反应或自己的观察得知。

被擒抱后的当场反应：战斗外被玩家角色擒抱的 NPC 能立即行动时，在同一次行动中单独调用一次模型，按本人投影和它对被擒抱的感知，决定是否当场挣脱或做别的反应；不反应也是合法结果。调用失败、预算和发布与旁人察觉后的当场反应相同。

听到交谈后的当场插话：一段交谈让在场所有能听见的人都听到时，说话人和交谈对象以外、听到了并能立即行动的 NPC 都可以在同一次行动中插话或做点别的。能立即行动指在任、不在遭遇中、没有正在执行的 Activity。每一步交谈最多 2 人，依次这样选：先选说话人的话或交谈对象的回答里点到名字的（按角色名逐字查找，名字写成"奈斯 / 奈斯卡尔"时任一段都算）；再选本人的关系、承诺、债务或计划记录涉及说话人或交谈对象的；最后选其余的。同一组里按角色登记的先后，再按标识。这里读的记录是这步交谈开始前的，交谈本身新建的承诺和关系不算。选中的 NPC 各单独调用一次模型，只依据本人投影和它听到的两句话：谁对谁说了什么，对方怎样回答或者没有回答。两句话各标明说话人，用本人看得见的人的名字。它决定是否插话、回答、反对、离开或做别的事；不反应也是合法结果。它说的话成为在场者听到的感知证据。调用失败、预算和发布与旁人察觉后的当场反应相同；插话不再引出新的反应，交谈对象在这次行动里也不回应插话。只有参与者听到的交谈不触发。同一次结算里已因察觉隐蔽动作开了当场反应的 NPC，以及本次行动里已有当场反应尚未结算的 NPC，不再开第二个，名额顺延给下一个。

NPC 场景移动：NPC 的所在场景只随本人的决定改变（履行本人承诺的工作、察觉后的当场反应、听到交谈后的当场插话）。交谈中 NPC 答应马上动身去别处，也记为本人的承诺：这次交谈的结果不写其已离开，玩家下一次行动开始时由本人的工作执行离开。KP 按本人投影写一步移动：去一个已登记场景（模组地点或已创建的动态地点）并写路上耗时，或经一条从当前场景出发、本人看得见的连接走；要去的地方还没有地点时，同一次决定里先创建动态地点和连接，再经这条连接走。Rules 核对该 NPC 是这次的行动者、在任、能移动（未失能、未被擒抱或束缚）、不在遭遇中、目的地可达，提交与玩家移动相同的 `CharacterMoved`：出发即离开原场景，场景、战术地图位置和时间线一起改变。NPC 按本人的时钟出发，到达后用目的地已有角色的时钟（先用玩家的），到达时刻不早于出发加路上耗时，也不早于该时钟的当前时刻。只是离开的决定不另占原地的时间，时长只算出发前在原地做事的时间。原场景的在场者得到其离开，目的地的在场者得到其到达，别处的观察者不得到任何记录。玩家角色仍按 SPEC 0007 §5 移动。

## 8. 动态敌人与危险定义

动态生物至少包含：属性、AC、HP、速度/移动方式、感官、豁免、技能、攻击、伤害、法术、资源、免疫/抗性、动作/附赠/反应、特殊能力、体型/位置、控制者、死亡策略和初始有限知识。

动态危险至少包含触发、迹象、调查/解除、攻击或豁免、范围、伤害/状态、持续和环境后果。自创效果必须编译为版本化受限机械原语；不接受任意脚本、字段路径或状态补丁。

高数值不是非法理由。定义一旦产生证据或机械作用即成为 Canonical Fact，不能按角色 HP、骰面或剧情需要替换。

## 9. 0.4 当前模组输入边界

当前静态模组源码只在构建已登记版本的 `ModuleBible` 时提供 Story Anchor、初始事实和目录输入；这些源码字段不是运行时 Adapter、行动白名单或第二权威。0.4 以前的房间与模组版本已退役，生产树不保留其解释、继续、迁移或 fallback 路径。

## 10. 故事推动与收束接缝

当玩家停滞时，KP 先重新定向，再依据 NPC/势力计划提供机会或代价，最后才在事实到期时兑现威胁。计划不能替玩家解决问题、传送回主线或制造无因果惩罚。

NPC 投降/撤退、势力目标达成/失败和冲突停止可以产生 `EndingCandidate`，但真正故事收束由 SPEC 0009 的 KP 协调，不由模组唯一谓词或战斗存活阵营自动决定。

## 12. 验收场景

1. 玩家走模组未登记路线，KP 在锚点内动态创建通路/场景并经同一事务固化。
2. 门后合法为空；系统不强制生成战斗、线索或奖励。
3. 动态强敌数值远超队伍但结构合法时被接受；非法能力逐项退回修订。
4. NPC 不知道玩家秘密计划时不作针对性反制；世界内获知后才可反应。
5. NPC 模型失败或玩家断线不会自动攻击、pass、结束回合或推进时间。
6. 到期势力计划先提交并改变情境；原玩家意图需要时重新澄清。
7. 0.4 以前的房间、模组版本和 DSL 解释路径稳定拒绝；当前房间接受未登记合理行动且不写 D1 活跃状态。
8. NPC 投降后玩家仍决定是否停止追击，系统不替玩家接受。
9. NPC 答应去别处办事，下一次行动前按本人的决定离开：原场景不再把他算作在场，地图上不再显示，原场景的人得到他离开，目的地的人得到他到达；去未登记的地方时先有动态地点和连接。
