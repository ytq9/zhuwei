# SPEC 0010 非规范附录

本文件收录原 SPEC 0010 中不规定产品行为的章节：自主裁定记录、实现映射、交叉审查与完成门。
它们是证据与历史，不是合同；规范条款仍在 [SPEC 0010](./0010-observer-specific-presentation.md) 正文，编号未变。

## 13. 实现映射

| 责任 | 目标实现位置 | 禁止的平行路径 |
| --- | --- | --- |
| Viewer、字段可见性、知识、错误脱敏、`successorRequired` lifecycle 与恢复候选 | Rules Module 的 `project` Interface 及其私有 projector | 页面条件隐藏、API 手写删字段、服务层拼继任视图、页面重算休整选项、日志二次解释事件 |
| AudienceSnapshot、单槽、ACK、覆盖、幂等恢复 | Room Durable Object | D1 活跃消息表、Worker 内存队列、客户端 localStorage 历史 |
| 提交后专属投影、模型叙述、内部发布 capability | Room Action Module | 战斗专属协调器、语音专属协调器、LLM 直接写客户端 |
| `observe`、ACK、意图/待决回答鉴权 | Room server/API | 请求体自报 principal/actor/viewer |
| 当前帧显示、呈现后 ACK、无历史 UI | play table 页面 | 聊天滚动列表、按事件补取旁白、客户端拼装知识 |
| 语音输入和当前回应语音呈现 | 现有语音 Adapter | 公共转写流、独立录音历史、绕过 projector 的 TTS URL |
| 结构化事实与知识归档 | D1 `room_event_archive` | DeliveryFrame、Prompt、模型输出、音频或转写归档 |
| 运维可观测性 | 固定白名单结构化 telemetry | 请求/响应正文、秘密对象、候选定义、私人叙述 |

实施测试必须通过真实责任 Interface：projector 测试经 `project`，可靠投递测试经可重启 Room DO 的 `observe/ack`，跨层测试从已认证意图到专属投影和 DeliveryFrame。测试不能直接改 AudienceSnapshot、槽位、角色知识、WorldState 或内部事件来伪造成功。

## 16. 自主裁定记录

以下决策均依据本 Goal 的明确授权裁定；测试证据如实标为尚待实现，不把验收设计冒充已运行结果。

### OBS-D001：个人线索的所有权与私有期

- 日期：2026-08-26
- 问题：个人线索归房间、principal 还是世界内角色持有，以及何时自动公开。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + Agent 自主协议裁定。
- 关联 `SPEC 0001`：§9 信息与角色知识、§15 多人桌、§16 连续性；验收 F、K、M。
- 候选方案：房间级已揭示；principal 私人消息；角色级结构化知识且无限期私有。
- 最终选择：知识归世界内角色/NPC；当前合法控制者可看结构化知识；除世界内分享、独立取得或可审计更正外不自动公开。
- 理由：同时保持角色知识连续性、换席合法性、NPC 有限知识和秘密隔离，且不依赖叙述历史。
- 玩家可观察行为：会合、章节切换、房主请求或实物毁坏都不会自动把个人线索显示给别人。
- 秘密与权限影响：房主、队长和原控制者无额外读取权；KP Viewer 只可内部使用。
- 迁移/可逆性：新规则版本把旧房间级 clue 标记隔离在 Legacy Adapter；不能把既有全桌线索猜测为个人线索。未来改变所有权需新版本和显式迁移。
- 验收场景：O01、O02、O06、O12、O17。
- 测试证据：尚未实现；应由 `project`、控制权变更和跨章节 Interface 测试提供。

### OBS-D002：世界内分享、范围与非追溯

- 日期：2026-08-26
- 问题：玩家如何分享个人线索，接收范围如何确定，是否回补旧叙述。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + Agent 自主协议裁定。
- 关联 `SPEC 0001`：§9 来源/证据/知识、§19 标准 KP 循环；验收 A、F、M。
- 候选方案：桌外一键复制知识；直接转发旧 KP 消息；通过权威世界内行动传播结构化内容。
- 最终选择：只通过权威行动事务提交 KnowledgeShare；集合范围在提交时解析为具体主体；分享从该时刻生效且永不回补旧 DeliveryFrame。
- 理由：传播本身可能耗时、被听见、中断或失真，必须成为因果事实；非追溯避免可靠缓存退化为历史。
- 玩家可观察行为：可以点名告知、当众展示或通过已固化媒介广播；接收者看到所得知识及来源，不看到分享者旧旁白。
- 秘密与权限影响：页面不能直接改接收者知识；SourceClaim 不提升为隐藏真相；后来加入集合者不补发。
- 迁移/可逆性：新增分享事件可追加而不改旧知识；错误传播通过更正或后续世界事件处理，不能删除历史。
- 验收场景：O03、O04、O05、O06。
- 测试证据：尚未实现；应由 Room Action、`step/project` 和 Viewer 矩阵测试提供。

### OBS-D003：Audience 在结果提交时冻结

- 日期：2026-08-26
- 问题：回应 Audience 应在提交、叙述生成还是读取时计算。
- 来源类别：Goal 明确指定 + `SPEC 0001` 冻结原则。
- 关联 `SPEC 0001`：§7 隐藏现实固化、§9 私人投影、§15 私人信息；验收 E、F、K、M。
- 候选方案：读取时按当前成员计算；叙述发布时由模型选择；结果提交时由 projector 冻结 ViewerKey。
- 最终选择：AudienceSnapshot 在权威结果提交时冻结并绑定事件范围、分支、作用域、投影哈希和策略版本；后来入场/入席不加入。
- 理由：读取时计算会向后来者泄漏已经消失的现场信息；模型选择会让 LLM 取得权限权威。
- 玩家可观察行为：断线但虚构在场者可恢复当前帧；虚构缺席者后来到场只看仍存在的世界事实。
- 秘密与权限影响：成员身份、房主/队长权限和网络在线状态不能替代虚构观察资格；控制权撤销仍立即停止访问。
- 迁移/可逆性：新规则版本启用；旧消息不构造 AudienceSnapshot。改变冻结语义需新呈现协议版本。
- 验收场景：O02、O05、O08、O11、O12。
- 测试证据：尚未实现；应由原子提交、并发入席和断线恢复测试提供。

### OBS-D004：不可回看与单槽可靠投递

- 日期：2026-08-26
- 问题：如何同时保证当前回应可靠送达并禁止完整 KP 历史。
- 来源类别：Goal 明确指定 + Agent 自主协议细化。
- 关联 `SPEC 0001`：§12 场景叙述、§15 多人桌、§17 更正、§19 标准循环；验收 M、N。
- 候选方案：永久聊天历史；每 viewer 有界多消息队列；每 ViewerKey 一个未确认单槽。
- 最终选择：当前回应固定单槽；刷新/断线/重启返回同一 ID；ACK 或新回应结束当前槽；成功发布文本另存于原 ViewerKey 的亲历记录，只保留非内容 delivery tombstone。
- 理由：单槽提供当前回应的至少一次可见和幂等恢复；ViewerKey 专属记录满足离场回看，同时冻结 Audience 阻止缺席者补取。
- 玩家可观察行为：刷新不会重复回应；断线可恢复当前回应；确认或收到下一回应后仍可查看自己亲历的文本，知识簿不丢失。
- 秘密与权限影响：槽和亲历记录都按 ViewerKey 隔离；多设备共享 ACK；旧 ID 与 Receipt 不能绕过 transcript 边界取回正文。
- 迁移/可逆性：不导入已丢失的旧聊天，也不从事件伪造；安全收窄可使当前槽失效而不形成亲历副本。
- 验收场景：O07–O10、O15、O16、O18。
- 测试证据：尚未实现；应由可重启 Room DO、丢响应和多设备 Interface 测试提供。

### OBS-D005：统一 projector 与旁路封闭

- 日期：2026-08-26
- 问题：快照、增量、错误、候选、语音、日志和叙述是否各自脱敏。
- 来源类别：Goal 明确要求 + `SPEC 0001` 冻结原则 + 单一权威架构约束。
- 关联 `SPEC 0001`：§9 信息边界、§14 NPC 有限知识、§15 私人信息、§17 裁决说明；验收 F、K、M、N。
- 候选方案：各层手写删字段；各通道独立 projector；所有领域内容复用一个 projector，telemetry 只允许非内容白名单。
- 最终选择：所有玩家可见领域内容统一经 `project`，包括控制结束后的 `successorRequired` lifecycle 与 Rules 派生的恢复候选；语音和字幕只是当前帧呈现；Runtime telemetry 不投影领域正文，只记录固定非内容元数据。
- 理由：多套删字段规则必然漂移并产生侧信道；非内容 telemetry 无权解释事实，因此不构成第二 projector。
- 玩家可观察行为：同一秘密在快照、错误、候选、语音和日志中得到一致保护；NPC 与玩家投影不会混用。
- 秘密与权限影响：原始事件、KP Viewer、Prompt、转写和候选定义不离开可信服务端；猜测 ID 不能确认秘密存在。
- 迁移/可逆性：旧页面/API 脱敏路径必须删除或隔离在 Legacy Adapter；未来新通道只能消费现有 projector 输出。
- 验收场景：O01、O13、O14、O18。
- 测试证据：`tests/world-campaign-v2.test.mjs` 已通过公开 `project` 覆盖 `successorRequired` 与 `restRecoveryOptions`，`tests/multiplayer-room-v2.test.ts` 覆盖死亡/退役后的 Room `observe` lifecycle，`tests/authoritative-table-v2.test.mjs` 证明页面消费投影候选而不重算；错误等价、日志捕获和线上语音旁路仍按 O01–O18 完成门单列。

## 17. 五项交叉审查

### 17.1 跨规格矛盾审查

- 与 `SPEC 0001` 一致：保护角色知识与私人投影，不限制 KP 在专属投影内叙述，也不把叙述文本当正史。
- 与权威行动事务一致：知识取得、分享和更正均走同一事务；DeliveryFrame 只在提交后产生。
- 与长团方向一致：结构化知识与原 ViewerKey 的有界亲历记录可跨章节保留；死亡/退役不自动向继任 principal 转移知识或文本。
- 与现有语音能力一致：保留语音输入和呈现，但收拢到同一身份、Audience 和投递协议。
- 结论：未发现需要修改 `SPEC 0001` 的冲突；后续通用事务、多人和长团规格必须引用本规格，不能重定义 Audience、ACK 或分享追溯语义。

### 17.2 权限审查

- principal、ViewerKey、角色控制权和 ACK 权限均来自可信会话与 Room DO 状态。
- 房主、队长、在线状态和请求体字段不能扩大观察权。
- Audience 冻结不阻止后来权限撤销；撤销只能收窄访问，不能新增旧 Audience。
- 内部发布 capability 不暴露给页面；普通客户端不能上传投影或叙述正文。
- 结论：权限入口唯一，未发现调用者自报身份路径。

### 17.3 秘密审查

- 私有知识、KP/NPC Viewer、隐藏候选和未公开事实不进入普通 Frame、错误或日志。
- 世界内分享只传播明确内容和来源，不复制未表达秘密。
- 单槽、ViewerKey 隔离、非追溯 Audience 和无跨观察者历史 Interface 共同阻止越权补看。
- 语音、转写、媒体访问和多设备 ACK 服从同一 ViewerKey。
- 结论：实时、轮询、历史、重连、错误、候选、日志、语音和转写均有明确封闭规则。

### 17.4 版本审查

- Audience、projectionHash、活动分支和三个呈现协议版本绑定当前帧。
- 旧事件不能用最新 projector 静默扩大；更正使失效帧替换而非改写。
- Legacy 消息不迁入新单槽，旧房间行为明确隔离。
- 结论：不存在“部署后用新可见性解释旧房间”的静默版本污染；当前统一读取语义由 `projection-observer-safe-v1` 1.2.0 及其精确 manifest/genesis hash 固定。

### 17.5 第二权威审查

- Room DO 唯一保存活跃 Audience、投递槽、ACK 和结构化世界/知识；D1 仅保存可重建结构化归档。
- `project` 是唯一领域内容投影 Interface；`observe` 只组合其结果与当前槽。
- DeliveryFrame 非正史、不可回放，不参与机械或知识计算。
- 页面、Room Action Module、语音 Adapter、LLM、客户端缓存和 telemetry 都不能提交世界事实或另算可见性。
- 结论：本规格没有引入第二条机械裁决、状态提交、观察者投影或事件回放路径。

## 18. 实施完成门

本规格只有在以下证据全部成立时才算实现完成：

- O01–O18 均通过其责任 Interface，且至少包含一个无权观察者；
- Viewer 矩阵证明同一权威状态对玩家、NPC、KP 和内部 Viewer 的结果相互隔离；
- 可重启 DO 测试证明单槽、同 ID 恢复、ACK、覆盖和幂等不重复；
- 席位、控制权、位置和 Audience 并发变化没有回补或越权；
- 个人线索取得、持有、分享、跨章节持续和默认不继承均有权威事件测试；
- 实时、历史、刷新、重连、错误、候选、日志、语音和转写旁路测试均不泄漏；
- 页面不存在跨观察者完整 KP 旁白历史，D1/客户端也不存在叙述归档；DO 仅保存 ViewerKey 专属亲历文本且不参与事件 replay；
- 所有玩家可见领域内容来自统一 projector；
- Runtime 日志捕获测试证明未记录任何禁止字段；
- 实现映射和测试证据回填到总追踪矩阵及决策记录，未执行项不得写成已验证。
