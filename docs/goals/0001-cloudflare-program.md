### 二维战术地图（用户批准的交付硬阻塞项）

- 为 authoritative-v2 房间交付一个简单、可操作的二维战术地图。地图是观察者专属 Player Projection 的展示 Adapter，不是机械或状态权威。
- 第一版采用俯视格子或等价简化二维表示，显示玩家有权知道的场景边界、人物占位、已知障碍、地形、门、可互动物、持续区域效果和高度信息；不要求点云、写实 3D、通用物理引擎、碎片模拟、流体模拟或结构力学模拟。
- 权威空间仍使用唯一 Geometry Profile 的 `x/y`、`elevation`、`height`、`footprint`、路径、屏障、掩护和区域规则。地图可以默认按 5 尺格吸附和显示，但显示格子、像素坐标及视觉舍入不得成为第二空间真相。
- LLM/KP 按 `SPEC 0001` 的叙事权威决定环境与物品的定性事实和有限状态，例如完整、损坏、毁坏、打开、关闭、燃烧、结冰、坍塌、困难地形及持续区域效果。Rules Module 不建立通用物理模拟器。
- LLM/KP 只能提出结构化、可验证的状态或状态转换，不能直接修改客户端地图、提交任意状态 patch、伪造骰面或绕过 `step`。所有进入因果链的环境变化必须由 Rules 验证，经 Room Durable Object 原子提交为可回放 `WorldEvent`，再由 `project(viewer)` 投影。
- 若环境事实或状态转换会影响目标集合、DC、风险、资源、随机结果或不可逆后果，其事实、条件或阈值必须在权威骰面出现前冻结。LLM 不得看到骰面后追溯修改环境性质来偏袒或惩罚玩家。
- 人物移动可以由地图手势、自然语言或 LLM/KP 形成路径提案，但速度、移动方式、占位、碰撞、困难地形、高度、反应时点、危险中断和合法终点由 Rules Module 验证。只提交已经实际通过的路径前缀。
- 法术和能力的数值、目标约束、范围、传播、伤害、豁免、持续时间与资源消耗来自版本化 `AbilityDefinition` 和 Rules；LLM/KP 根据已固化环境事实决定合理的环境后果，并通过同一结构化提案与事件链提交。
- 区域能力的客户端只能提交能力定义允许的原点、方向、路径或封闭选项。实际受影响集合由 Rules 从完整权威空间计算，必须正确覆盖能力定义允许的施法者、盟友、敌人、环境实体及隐藏实体，不能使用客户端 `targetIds` 代替区域计算。
- 预览只能依据当前 Viewer 有权知道的事实，必须显示已知的自伤、友军波及、公开遮挡和高度影响，同时不能通过候选数量、错误、响应差异、阴影层或完整 GM 地图泄露隐藏实体、隐藏障碍和未公开区域。提交时必须针对最新完整 `WorldState` 重新结算。
- 地图、文字战术读数和无障碍信息必须来自同一个观察者专属战术投影。页面不得自行计算距离、掩护、碰撞、区域目标或环境状态。
- 旧 ruleset 只通过明确 Legacy Adapter 保持原行为，不得将旧一维距离或页面坐标猜测迁移为 authoritative-v2 空间事实。

3. 世界事实与知识：
   `CanonicalFact`、`WorldEvent`、来源、可见性、因果链、关系、承诺、动态定义、传闻、感官证据、角色推断、知识传播、分支与更正。
4. 模组与 NPC：
   故事圣经、核心真相、开放留白、势力、动态实体、NPC 有限知识、NPC/势力计划、模组版本和 Legacy Adapter。
5. 多人房间：
   可信 principal、席位、角色控制权、掉线/换席/请离、私人窗口、并发意图、原子分队、跨地点虚构时间、因果前沿和聚光灯账本。

   角色成长、章节切换、跨章节物品/伤势/知识/关系/债务/承诺/未决威胁、角色死亡或退役、继任角色及其合法继承边界。
7. 失败、节奏、收束与交互：
   场景问题、有意义失败、重复检定、势力推进、结局候选、尾声/续篇、统一 Read Model 和 Receipt。
8. 观察者专属呈现：
   KP 回应只投影给虚构上在场且有权观察的人；不在场者不得从实时流、轮询、历史、重连、错误、候选项、日志、语音或转写旁路获知。
   你必须自主裁定并明确记录：
   - 个人线索何时保持私有；
   - 如何通过世界内交流分享；
   - 分享范围和是否追溯；
   - “不可回看”的精确定义；
   - 当前回应的可靠送达、确认、刷新和断线恢复方式。
   默认约束是：玩家界面不能提供完整 KP 旁白历史；结构化世界事实和角色知识仍须权威保存。可靠送达所需的短期缓存不得演变为缺席者可以补看的聊天记录。
9. 可靠性、纠错、可观测性与评测：
   全局故障分类、SLO、免费额度内的成本/延迟预算、结构化日志、幂等、回放、归档重建、模型版本、可审计更正及多轮 KP 评测。
10. 战术空间与观察者地图：
   版本化权威 Geometry、场景/实体/屏障/地形/门/可互动物/持续区域/高度的事件与状态、移动和区域能力提案、秘密安全预览、统一文字战术读数、二维 Player Projection Adapter、Legacy 空间隔离及浏览器/无障碍验收。

每项 Agent 自主裁定必须留下决策记录，至少包括：决策 ID、日期、问题、来源类别、关联 `SPEC 0001` 条款、候选方案、最终选择、理由、玩家可观察行为、秘密与权限影响、迁移/可逆性、验收场景和测试证据。不得以“现有代码容易实现”作为产品理由。

## 四、目标架构

必须形成两个深 Module：

- 外层 Room Action Module：负责可信身份、自由意图、澄清、KP 提案、待决回答、重试、恢复、更正和结局协调。
- 内层 Rules Module：公开机械 Interface `step / project / replay`；内部 fold、事件应用、机械原语和状态缓存不得成为外部第四条裁决路径。

完整事务链必须是：

可信玩家意图
→ KP 依据专属投影作可行性与叙事裁决
→ 规则内核诊断或执行机械提案
→ Room Durable Object 原子提交叙事事实、机械结果、Receipt 和待决状态
→ `project(viewer)` 生成观察者专属投影
→ KP 依据已提交结果叙述并交还决定权

固定不变量：

- 玩家控制玩家角色；NPC 只依据有限知识由 KP 控制。
- actor/principal 必须来自可信会话，不能来自请求体自报字段。
- 全局 `expectedRevision` 应被相关作用域版本替代。
- 外层结果必须能够区分 committed、awaitingInput、needsKp、retryableFailure、rejected 和 concluded。
- Room Durable Object 是活跃世界状态、事件、幂等结果和待决输入的唯一权威。
- D1 只保存身份、目录、静态人物卡和可重建归档，不保存新规则版本的第二份活跃状态。
- LLM 调用永远位于 DO 事务外。
- 参数、DC、风险、候选结果和资源成本必须在权威骰面出现前冻结。
- 骰面只能由 Room DO 的权威骰源产生。
- 动态事实在首次证据、引用或机械影响前固化。
- 新规则使用新的 `ruleset_version`；旧房间保持可回放，不得被新解释器静默重算。
- 封闭 DSL 只能作为 Legacy Adapter 或故事锚点输入，不能拒绝未登记但合理的玩家行动。
- 现实超时、断线或模型失败不能自动替玩家 `pass`，也不能推进虚构时间。
- Runtime 日志不得泄露 Cookie、Token、Prompt、模组真相、未公开线索、内部 flags 或私人叙述。
- 地图、文字战术读数和预览只能消费 `project(viewer)` 产生的同一战术投影；页面坐标、格子和像素不得成为空间状态或机械输入的第二事实源。
- 移动、环境状态、破坏和区域效果仍必须穿过同一 Room Action Module、Rules `step`、Room DO、`project` 与 `replay`；客户端不得自报实际命中目标、掩护或合法路径。
