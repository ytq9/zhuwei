# NPC 提到的新内容：审核、成真与支线触发（方案草案）

- 日期：2026-09-29。
- 状态：**草案，等待用户裁定。不授权实现、修改规格、真实调用或部署。**
- 来源：用户看过 [round154](../receipts/vnext-round154-validation.md) 后的两条意见。
  1. “无关紧要的 kp 可以编造来补充，但应保持前后一致。”
  2. “先审核，有差错的相关设定再发给 npc 来改。并且我一直想让 npc 提出的地点，人物，事件等可以成真，可以动态生成，但我目前只是做了一点相关的工作，不清楚具体应该怎么让她触发，具体的这种支线故事又该怎么让模型去写，然后应用到游戏中。”
- 上位依据：[SPEC 0001](../../specs/0001-llm-kp-responsibility-contract.md) §§3、7、9、14；[SPEC 0006 §7](../../specs/0006-module-npc-and-faction-protocol.md)；[SPEC 0016 §§7.2、7.3、8](../../specs/0016-part-c-compound-actions-and-claims.md)；[故事创作能力合同](story-creation-capability-contract-proposal.md) C01、C04、C05、C09。

本文回答三个问题：NPC 编出来的内容怎么审核和改、怎么成真、什么时候以及怎样变成支线。

## 1. 现在的情况

### 1.1 已经有的机制

| 机制 | 能做什么 | 位置 | 证据 |
| --- | --- | --- | --- |
| NPC 本人作答 | 每名被交谈的 NPC 用一次只读本人视图的调用写回答；回答不合格时重问一次 | `kp/vnext/npc-reply.ts` | round153、154 真实通过 |
| 本人说过的话 | NPC 说的每句话记在本人记忆里；按 [ADR 0048](../../adr/0048-each-character-carries-its-latest-six-rounds.md)，最近六轮全文进入她的视图，她自己说的还带当时的依据和动机，更早的只剩目录摘要 | `rules/v2/npc-decision-context.ts` | 本地测试；round154 的状态里可见 |
| 固化新事实 | 裁决可以写一条此前没有记载的经历或事实，并指定哪些人知道；被指定的 NPC 作答时就知道它 | `materializeObject` 的 `worldFact` | 本地测试通过；round153、154 的五次交谈里裁决一次也没有用 |
| 叙述承诺 | 先把还没有因果作用的描写存下来，玩家以后用到时按原描述固化成对象 | `commitNarrativeDetail`，[ADR 0017](../../adr/0017-environment-narration-and-on-demand-materialization.md) | 本地测试通过 |
| 创建人物和地点 | 裁决可以创建有完整身份的 NPC、地点和连接、物品 | `materializeNpc`、`materializeObject`、`materializeItem` | 本地测试通过；NPC 去没有登记的地方时已在用 |
| 故事准备 | 选择阶段选了“故事准备”后，写稿加独立评审（最多四次调用），存入故事库，再由裁决把稿里的人物和事实接入世界 | `room/story-creation/`、`materializeStory`、`admitStoryFacts` | 只有脚本回应的本地验证；2026-09-09、09-14 两次真实运行里模型都选了普通交谈，**故事准备从来没有在真实调用里触发过** |
| 幕后故事机会 | NPC 的计划到期执行后，由一次调用决定要不要展开故事 | `room/story-world-event.ts` | 本地测试通过 |

### 1.2 缺的环节

1. NPC 的回答是一段文字。服务器不知道里面哪些是她新编的，也就没法审核、没法保存。
2. 没有一步拿主持人的材料核对 NPC 的回答。round154 里莉安对同一个问题先说“常来”，重新作答时说“不常来”，没有任何一步发现。
3. NPC 说出的内容只是“她说过这句话”，不会变成世界里的事实、人物或地点。
4. 故事准备完全靠选择阶段的模型自己想到去选。没有任何记录告诉它“这里有一件可以展开的事”，所以它一直选普通交谈。

## 2. 方案

四步：申报、审核、落地、追查时展开。前三步发生在交谈当时，第四步发生在玩家后来去追这件事的时候。

### 2.1 申报：NPC 列出自己新提到的内容

作答表单加一张表“新提到的内容”。NPC 的回答里说到了她的视图里没有的事，就在表里各登记一条；没有就填空表。每条包含：

| 字段 | 含义 |
| --- | --- |
| 种类 | 习惯或日常、往事、人物、地点、物件、正在发生的事 |
| 名字 | 有名字时填写 |
| 说法 | 她这次说的内容，一句话 |
| 态度 | 她当真这么认为、她在说谎、她自己也不确定 |

提示词里“记录里没有的事说不知道”改成：与眼前这件事的真相有关的仍然说不知道；其余可以按身份编，编了就登记，并且与自己说过的话一致。

### 2.2 审核：主持人一侧核对

表不为空时，增加一次主持人一侧的调用。它读到的是裁决用的那份完整材料，加上 NPC 的回答和这张表。对每一条给出三种结论之一：

| 结论 | 条件 | 后果 |
| --- | --- | --- |
| 成立 | 与已有事实、人物经历、故事锚点都不冲突，她也确实可能知道 | 按 2.4 保存，成为世界里的事实 |
| 只算她的说法 | 与她不知道的真相不符，或者她在说谎、不确定 | 回答照常发布，只记为“她说过”；不成为事实 |
| 退回 | 与她本人的记录、她自己说过的话或公开事实冲突，或者说出了她不可能知道的事 | 按 2.3 退回重写 |

审核同时检查回答里有没有没登记的新内容，有就按退回处理。对“成立”的条目，审核另外标一项：是不是一件可以展开的事（见 2.5）。

“只算她的说法”这一档是必要的。规格允许 NPC 误信和说谎，所以她说的话和真相不符不一定是错。只有和她自己该知道的事冲突才是错。

### 2.3 退回重写

沿用已有的重问：带上原回答和审核意见，向这名 NPC 重问一次。审核意见只说哪一句不能这样说、她自己的哪条记录与之不符，不写她不知道的真相。重问后仍被退回，行动按技术失败结束，保持未提交。这与现在“同一份回答只重问一次”的规则相同。

### 2.4 落地：成立的内容怎么保存

| 种类 | 保存成什么 | 什么时候变成可以互动的对象 |
| --- | --- | --- |
| 习惯、日常、往事 | 世界事实，该 NPC 列为知情者 | 不需要；以后裁决和她本人都读得到，回答自然一致 |
| 人物、地点、物件 | 叙述承诺：名字、她的说法、谁说的、谁听到了 | 玩家以后提到、寻找或前往时，由裁决按原说法创建人物、地点和连接或物品 |
| 正在发生的事 | 世界事实，外加一条“可以展开的事”的记录（2.5） | 玩家去追查时 |

这些记录由审核这次调用按现有表单写出（`worldFact`、`commitNarrativeDetail`），与方案其余部分一起经过现有的校验、lowering、Rules 预检和原子提交。不新建存储，也不由服务器从文字里猜。

“只算她的说法”和“她在说谎”的条目不保存为事实，只保留已有的原话记录。

### 2.5 追查时展开：支线什么时候写

审核标为“可以展开”的条目，在故事库目录里登记一条**线索种子**：是谁说的、说了什么、涉及哪些人物和地点。登记种子不写故事，不花调用。

之后玩家的行动涉及这条种子（去那个地方、找那个人、打听那件事、投入时间去办），选择阶段会在目录里看到它，可以选“故事准备”并指明种子。故事准备沿用现有流程：

1. 写稿：以种子的说法、相关叙述承诺和当前世界材料为固定前提，按所选的创作方法（利益冲突或档案调查）和规模写出准备包。
2. 独立评审：检查因果、人物动机、线索、收束，以及与既有事实是否冲突。
3. 接入：裁决用 `materializeStory`、`admitStoryFacts` 把稿里的人物、地点和事实接入世界。提到这件事的 NPC 通过接入的事实取得相应知识。
4. 游玩：之后就是普通行动。稿里的路线只是准备，不限制玩家的做法。

不在提到的当时写故事，原因有两条。多数随口提到的事玩家不会去追，当时就写会白花调用。能力合同 C04 也规定展开的依据是玩家实际的目标和投入，不是一句闲聊。

### 2.6 走一遍

玩家问莉安：“你父亲的旧账谁最清楚？”假设她的记录里没有这件事。

1. 莉安回答“磨坊的老巴恩替他记过几年账”，并登记两条：人物“老巴恩”，地点“磨坊”，态度都是当真。
2. 审核对照主持人材料：镇上没有与之冲突的记录，这件事也不触及任何已定的真相。两条都成立，并标为可以展开。
3. 落地：老巴恩和磨坊各存一条叙述承诺；故事库目录登记一条种子“老巴恩替赫斯记过账”。旁白照常发布莉安的回答。
4. 两轮以后玩家说“我去磨坊找老巴恩”。选择阶段看到种子，选了故事准备（档案调查、短篇、当地）。写稿和评审完成后，裁决创建磨坊这个地点、老巴恩这个人物，接入稿里的事实，玩家到达磨坊。
5. 如果玩家始终没有去，种子一直留在目录里，不产生任何调用。

对照情形：莉安说“第三份遗嘱在父亲床下”。她的记录写明她不知道藏处，审核退回，她重新作答。

## 3. 调用次数与费用

| 情形 | 增加的调用 | 估算 |
| --- | --- | --- |
| NPC 没有新提到任何内容 | 0 | — |
| NPC 登记了新内容 | 1 次审核 | 输入约 3 万 token，其中大部分是与裁决相同的前缀，可以命中缓存；每次约 ¥0.01–0.03 |
| 审核退回 | 再加 1 次重问、1 次审核 | 每次作答约 7,800 输入 token |
| 玩家追查种子并展开故事 | 2–4 次（写稿、评审、必要时修订和复审） | 沿用[已批准的故事创作预算](story-creation-call-budget-decision.md) |

这些都是估算，没有实测。作答表单加一张表，每次作答的输入会增加，具体数字要实现后量。

## 4. 分期

| 期 | 内容 | 依赖 |
| --- | --- | --- |
| 一 | 申报、审核、退回；习惯和往事保存为世界事实 | 只依赖已有机制 |
| 二 | 人物、地点、物件保存为叙述承诺；玩家用到时按原说法创建 | 一期；按需固化已有，需要核对裁决会不会在真实调用里照做 |
| 三 | 线索种子进目录；追查时触发故事准备并接入 | 一期、二期；故事准备还没有过一次真实成功，风险最大 |

每一期各自改规格、写 ADR、做本地测试、跑一个有预算的真实批次。前一期的真实批次通过后再开下一期。

## 5. 需要你定的事

1. **哪些说法可以成真。** 建议：只有 NPC 当真、审核判为成立的才成真；说谎和不确定的只算说法。
2. **审核什么时候跑。** 建议：只在 NPC 登记了新内容时跑。代价是她没登记的新内容查不到。另一种做法是每次交谈都审核，每次多一次调用。
3. **支线什么时候写。** 建议：玩家去追查时才写。另一种做法是审核标为可以展开时就在后台写好，玩家去的时候不用等，但多数稿子会用不上。
4. **从哪一期开始。** 建议：先做一期，跑一个真实批次看 NPC 会不会老实登记、审核会不会误判，再决定二、三期。
5. **重问后仍被退回怎么办。** 建议：沿用现有规则，行动按技术失败结束。另一种做法是发布一句不含新内容的回答（例如她说不清楚），行动照常提交；这需要再定由谁来写这句话。

## 6. 风险和没有把握的地方

- **NPC 不登记。** 模型可能编了却不填表。这一点只有真实批次能回答。
- **审核误判。** 审核可能把无害的说法退回，也可能放过冲突。旁白审核在 round149、150 出现过漏判。
- **审核意见泄密。** 退回时告诉 NPC 的话不能带出她不知道的真相。需要在表单里把“给 NPC 的话”和“主持人自己的理由”分开，前者才发给她。
- **六轮以前的话。** NPC 六轮以前说过的话只剩目录摘要。成立的内容已经存成世界事实，不受影响；只算说法的内容仍可能前后不一致。
- **故事准备本身。** 它从来没有在真实调用里成功过一次。三期开始前应先单独验证“玩家明确要求展开一件事时，故事准备能跑通”，否则种子加上去也不知道问题出在哪一环。
- **种子堆积。** 聊得多了目录里会有很多种子，选择阶段的输入会变大。需要定一个上限或按场景和话题筛选。

## 7. 不做的事

- 不让 NPC 读主持人的材料。她仍然只读本人的视图。
- 不从回答的文字里用程序猜新内容。新内容只认她登记的和审核指出的。
- 不因为 NPC 提到了一件事就推进世界时间、创建机械对象或改变玩家的状态。
- 不改旁白的规则：材料里没有答案时，旁白仍然说角色不知道（[ADR 0072](../../adr/0072-narration-says-what-is-not-known-when-the-material-holds-no-answer.md)）。
