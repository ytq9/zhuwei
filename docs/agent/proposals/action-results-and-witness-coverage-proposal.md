# 动作结果与见证覆盖填写合同修订草案

状态：review 后修订，待裁定；2026-09-28。六项缺陷修复与本草案分开验收。本文不是现行 SPEC，也不授权发布或真实模型批次。

## 目标与不变量

能力合同：KP 在一个动作的结果中显式填写该动作造成的物品变化，并在骰前交代每个公开步骤、执行阶段、可达结果下各 NPC 候选的感知；服务器保留原填写位置，确定性展开为库存与知识权威操作，预检覆盖义务，按实际执行阶段和结果提交。支持不同物品、数量、操作种类、交谈或物理动作、成功/失败及独立条件操作。越权、依赖不唯一或机械不可表达仍整束拒绝。嵌套说明因果归属，条件绑定说明何时执行，授权说明谁能改变物品；三个维度分别验证。

依据：[SPEC 0001 §§2、6、9、14、16、19](../../specs/0001-llm-kp-responsibility-contract.md)、[SPEC 0005 §6.2](../../specs/0005-world-facts-and-knowledge.md)、[SPEC 0013](../../specs/0013-versioned-runtime-profiles.md)、[SPEC 0016 §7](../../specs/0016-part-c-compound-actions-and-claims.md)。模型填写位置与物品权威归属分开：库存转换仍由 inventoryOperation 和 Rules 执行，动作摘要不产生库存写入。

“当着莉安取叶、顺进袖子”覆盖物理动作、持有变化与旁人感知的组合；“边说话边递交一部分堆叠物品”覆盖 social 宿主、转交、数量与新目标；独立使用或装备覆盖无宿主的操作。不得以叶子、人名或动词路由替代这项能力。

## 本轮已实施与本草案的关系

解码层仅隔离可恢复的多余根键、未知分组和放错位置的结果集合，继续现有领域校验并合并诊断；原稿保留且仍拒绝。混合 requestedCapabilities、requestedNpcRefs 或 requestedKnowledgeRefs 与填写内容先专项拒绝，不能清除选择意图后进入修订。结构无法完整转换时不输出领域稿。它减少阶段间遮挡，不承诺提前报出同一对象所有错误、lowering 或 Rules 预检错误。承诺是保留原文并指导迁移，不是程序保证内容保全；修订仍可删除幻觉和错误后果，必要后果靠领域检查与最终状态验收。

隐蔽失败的证据策略、整条失败路径的精确来源及旧冻结计划语义见 [ADR 0067](../../adr/0067-freeze-primary-noticing-evidence-policy-and-source.md)。主要对象不新增反应调用；第三方耳语可另写 onFailure social 冻结主要对象的回应，不写则没有该回应。成功时仍可合法听到公开问话。onFailure social 是一次完整交谈，包含实际 actorSpeech，并非只有 NPC 台词的纯反应步骤；不能为写回应而伪造玩家再次发言。听觉 noticedEvidence 不填入只表示视觉的 npcPerceives，无额外视觉举动时填 none。观察或对话检定不再签发跨持有人库存授权；隐蔽直接目标的取得只准 onSuccess，失败损坏、消耗和掉落仍合法。旧库存方案按 [ADR 0068](../../adr/0068-freeze-inventory-admission-policy-with-the-plan.md) 的冻结版本恢复。若取物才是被瞒动作，检定必须属于取物；若真正被瞒的是耳语，另一项公开且合法的取物可独立成立。程序不从两种步骤并存推断其意图，不扩大为一概拒绝。

探针检查实际持有、失败时原物品留在原处且没有凭空新增持有副本，以及动作的事件—事实—知识链。使用本次玩家命令完成、后续 NPC 工作 settle 前的快照。默认动作的取得、指定话语和秘密词断言不套到任意 `--action` 上；daily-witnessed 仍要求公开可感知动作，并保留本次根行动的见证来源链验收。自定义内容的持有结果、证据含义和保密语义另列未覆盖，不以来源链检查代替。这不能代替公开见证能力实现，也不证明模型理解了证据原文。

## 1. 动作中的库存结果

保留根 decision、唯一 check 步骤及其他 steps。具有结果的步骤新增 `inventoryOperations` 数组；仅选择了 inventoryOperation 能力时才提供此字段。元素显式填写现有 `operation`、`basisRefs`、`summary`，其余服务端字段继续派生。

不按取得/放下/转交建立特殊白名单。现有库存操作的所有种类在真正由宿主结果造成时都可嵌入；机械支持、使用成本和物品生命周期仍按原合同。独立操作保留 inventoryOperation 行及 always/onSuccess/onFailure，不能为省字段伪造宿主。例如“谈妥后再拿桌上钥匙”允许独立绑定成功；装备、辨认、使用、损坏修理、组装拆解不强制增加宿主动作。

条件映射固定：check.success 的子操作为 onSuccess；check.failure 为 onFailure；普通 result 子操作继承宿主 outcomeBinding。每项操作只写一次。同一动作的直接后果优先嵌入，后续独立操作独立表达；程序不能从文字可靠判断两者，填写位置由指引约束。重复、冲突、执行顺序和数量由现有依赖与逐步候选状态检查，允许有合法依赖的 acquire→transfer、取得→装备等链条，不能按“同物操作两次”拒绝。共享检定仍只有一个拥有者，不增加每个库存操作各自掷骰的能力。

允许交谈结果携带有独立合法授权的当场交付；答应未来交付仍是承诺，不能直接转移。嵌套位置和检定成功本身不产生处分权：观察、对话检定都不能提供跨持有人转移授权。观察时操作自己的物件或消耗合法材料不被一概禁止。当前根行动者固定的库存路径并未闭合“NPC 当场给玩家东西”的本人决策与执行授权；本次不通过扩大 social directTargetRefs 绕过，不宣称已支持这项授权。

本次保留现行隐蔽取物的 onSuccess 限制，不引入“检定失败但已拿到物品”。未来若需要该产品结果，须另行修改 SPEC 0016 §7.3；普通合法失败成本仍可在失败结果中显式填写。

示意（省略现行必填字段）：

```json
{
  "check": {
    "worldInteraction": [{
      "success": {
        "inventoryOperations": [{
          "operation": {"kind": "acquire", "entryRef": "<冻结实例>", "quantity": 1},
          "basisRefs": ["<本次权限与事实依据>"],
          "summary": "叶片由行动者持有。"
        }]
      },
      "failure": {"inventoryOperations": []}
    }]
  }
}
```

## 2. 展开、出处和反向编码

展开必须发生在 producer/consumes 推导之前。内部仍是当前 typed proposals，库存仍进入现行 graph、lowering、Rules 和事件 reducer，不能在填写适配器直接改 ItemSystem。数组顺序不是执行授权或依赖边。

每个展开条目及字段保存原填写路径，例如 `check.worldInteraction[0].success.inventoryOperations[1].operation`。来源映射用于领域诊断、补丁定位、生产者补全、未加载类型检查、clarification continuation、Room 修订工单与恢复复证，以及 NPC 工作和反应。逐一核对无填写稿的兜底、写死在诊断文字里的序号、修订额度与进展签名。运行时 proposalRef 等内部身份可继续由规范展开束派生；只有需要指向模型位置的消费者使用来源路径，不能把全部序号身份都改成填写路径。来源是转换元数据，不由模型填写。

子项 basisRefs 自有且显式；summary 自有且显式。宿主的依据不能冒充子项权限，子项也不自动复制全部宿主依据。服务端按原规则从真实子项字段生成读集和 prospective 依赖，根依据取合法步骤的并集。

反向编码只有一套：有原始填写/来源映射时按原路径还原；人工领域夹具显式声明嵌套宿主与分支，或声明独立项并保留 outcomeBinding。没有关联的项不能靠“最近一步”、同名文本或首个 check 猜成嵌套项；不完整的归属元数据拒绝并更新夹具。结构互转必须保持数量、分支、读集和知识权限。

库存嵌套展开沿用内部库存操作；填写来源映射服务未冻结稿的转换与修订。公开见证的阶段/原生结果绑定需要冻结并持久化，不能因此承诺所有内部计划结构不变；具体版本与旧计划解释在该步骤的 ADR 写清。解析合同与提示词版本同步变化，workflow hash 自动更新。按 [ADR 0038](../../adr/0038-reask-unfinished-work-after-a-version-change.md) 只重问尚未冻结的模型工作，不能重问已经冻结或掷骰的行动。

## 3. 公开见证的覆盖合同

程序覆盖义务是“执行阶段 × 可达结果分支 × 公开步骤 × NPC 候选”，每个组合恰好一份交代。内容和感官是该行的属性，不能由模型先列内容再决定程序检查哪些义务。候选行可包含多条 `{sense, evidence, basisRefs}`，一条感知对应具体感官和具体内容；支持现有 sight/hearing/smell/touch/taste/special。同一人可以看到手部动作却听不清低语，不能压成整个 RootAction 一个布尔值。这个覆盖检查保证人没被整行漏掉，不证明自然语言已写全。

服务器依据场景、角色、空间和已知感官条件提供每个相关阶段的 NPC 候选名单。模型不得自行删减名单；同场仅代表候选，不等于已经察觉。跨场景动作按可观察阶段分别确定候选；此前步骤改变在场状态时，使用现有分支预检的候选状态，并在随机前完成所有可达分支覆盖。阶段或依赖不能确定时明确诊断，不用最终场景倒推。

候选输入必须在现有调用阶段闭合：首次填写收到冻结上下文内各已加载相关场景的候选目录，包含判定所需的既有引用，不含额外 NPC 私有认知。填写后，预检从同一冻结快照及所写步骤导出各分支的实际覆盖义务；缺写但目录已经提供的候选，沿原有修订额度返回精确路径和候选引用，不增加“再填一次见证”的调用。新增同束 NPC 用明确 prospective handle 与已填写身份/场景派生候选。若后续场景或候选所需事实不在冻结上下文中，不能在修订时偷换上下文或猜填，按现有依赖不闭合路径诊断、澄清或拆为后续 RootAction。本次跨场景覆盖只承诺冻结信息内可以证明的阶段；不得把这个边界宣传为任意移动后的全场景感知模拟。

步骤范围明确包含 worldInteraction、social、主动 observe 与 inventoryOperation 的公开部分；纯内心知识回顾继续原知识路径，不产生公开见证义务。具有结果的动作在结果中填写 witnesses；独立库存行有自己的 witnesses，并继承自己的条件绑定。一个动作的嵌套库存不重复要求第二份同内容见证。行动者为 NPC 的工作和反应走同一覆盖路径；候选不含行动者自身，不给玩家角色新增见证行。

| 现有填写位置 | 新合同的对应归属 |
| --- | --- |
| NPC 旁观者的 sensoryEvidence | 由 witnesses 承担，禁止两处重复填写；内部仍降低为感官证据 |
| social.npcPerceives | 由该交谈对象的 witnesses 行承担，同步 social 私有证据与精确结算复证 |
| Rules 已按听众传播的话语原文 | 沿用 SourceClaim/Knowledge，不在 witnesses 再抄一次 |
| 声线颤抖、音量变化、环境声音等 | 仍可填写 hearing 感知，不因是 social 而删除 |
| 行动者自己的发现、推断及玩家信息 | 沿用现有权限路径，不被旁观者覆盖表替代 |

普通转换、组装拆解、use/Ability 与待随机恢复全部纳入本合同。阶段见证是后续公开见证步骤中的新增 Rules 工作，单独验收，不混进前述六项 Bug 修复。骰前冻结阶段/结果绑定并验证完整性，实际原生事件发生时才授予；消耗、施放、命中或未命中、最终效果分别处理。现有 Ability 预演用代表骰收集请求，不能证明所有随机结果覆盖；须增加冻结阶段/结果绑定的结构检查，不能仅靠多跑几个骰面。

授予随实际阶段进入同一 RootAction 事务，未发生效果不预先授予。证据身份由规范操作、阶段/结果、观察者与感知项确定；pending continuation、social 前缀复证、恢复与事件回放共用身份，不重骰、不重发。不能只在 InventoryOperationApplied 后补记录，或只覆盖骰前可见部分就宣称 use 闭合。

每个候选行显式给出 observed（至少一条 observations）或 notObserved（明确感官阻隔与依据）；允许已观察行另记某种感官不可达的例外。例外只能说明对应感官不具备或内容无法经该感官到达，例如失明、视线遮挡、声音不可达，不把“分心”当成免检获得隐蔽效果的理由。其他感官遵循同样原则。服务器可证明的机械排除直接执行；语义理由的真实性仍由 KP 裁决，引用存在不等于语义已证明。理由只留私有裁决资料，不写成 NPC 知识。同场与 canSee/canHear 不等于实际获得内容，不采用按感官默认批量发放。

只执行实际分支，未走分支不授予。隐蔽内容继续由 Rules 判定并用 noticedEvidence 授予；不能另写 observed 覆盖判定。同一步允许包含公开掩饰内容，不为记“整理衣领”强制多造一个动作；但程序不能仅凭 actor subjectRef 分辨“理衣领”和“取叶”，这条泄漏边界仍在文字语义。探针检查本次未察觉者没有新增获得隐蔽取叶信息，不要求整个旧知识库都不含“叶子”。公开见证本身不新增 NPC 反应调用，现有 NPC 决策触发保持；反应造成的新感知入记忆，不产生递归反应链。

拟新增的公开 witnesses 不再承接隐蔽 noticedEvidence 的显式去重来源。待裁定方案是新 evidencePolicy 由 Rules 独占隐蔽证据，不从 witnesses.observed 推导 primaryFailureSource；旧无策略及 primary-failure-v1 计划保留原解释、来源与事件身份。实施 ADR 必须明确对 ADR 0067 新稿来源规则的局部取代，以及阶段 witness 身份与冻结恢复的绑定，不能在删除 npcPerceives 时丢掉旧计划的来源。交谈对象作为隐蔽耳语参与者仍获得察觉记录和反应调用的既有行为，也在该合同中单列裁定，本轮不改变。

## 4. 保留标签与检查能力边界

此次保留其他结果的 entries 与 recordKind，不同时实施全面分栏或无标签 anyOf。库存与见证采用独立数组，便于固定归属与覆盖诊断；这是对 ADR 0015 多集合统一 entries 决定的局部取代，须在实施前的合同 ADR 写明。标签与内容矛盾继续准确诊断。

新数组明确要求出现，无义务时写 []；遗漏返回缺字段，不自动补空。有候选义务时 witnesses=[] 必须被领域覆盖检查拒绝；改成 entries 中的 recordKind 同样会遇到空列表，布局不能代替检查。若必填空数组导致额外失败，记录实测再另裁定。

嵌套不能自行识别自然语言里漏掉的库存转换，也没有解决 check/steps 两个容器造成的重复填写。当前库存操作本身就是唯一类型化取得声明，不能声称另有“已声明取得却漏操作”的检查。若以后增加“目标物品操作或持有不变”的表，只能检查已列目标的交代完整性，仍发现不了漏列目标或误填不变；持有不变也不等于没有损坏、装备或认知变化。程序拒绝可证明的矛盾，模型语义完整性仍靠最终状态和证据链探针，不宣称已全由结构保证。

## 5. 直接消费者与实施顺序

直接影响：filling schema/codec、来源与诊断映射、provider 工单、capability 补全、Bundle reference/producer 推导、lowering、Room 冻结和复证、修订额度与进展签名、测试夹具反向编码、提示词、请求体积与 workflow hash；包括 NPC 工作/反应、social 形状与精确折叠。Rules 库存权限、数量、成本沿用原入口；公开感知扩展还须接入普通库存、assembly/disassembly、use 转 Ability、pending continuation 的实际完成与回放消费者。不另建库存 effect 或知识数据库。

先以一份合同 ADR 定下库存与见证填写形态、取代范围及阶段持久化边界，再完成嵌套到持有者变化的路径，随后接公开见证及阶段结算。各步单独验收，中间不部署；最终同步合同版本，不让在途工作因这两步分别重问。动手前按 [ADR 0057](../../adr/0057-request-size-may-grow-for-a-feature-the-user-was-told-about.md) 测量新增 schema 与候选名单体积，报告单能力、组合与全量增量。新结构输出 2,700–3,260 或增加 60–250 token 只是假设估算，不是 Provider 实测，不作为验收结论。真实批次另核授权与预算。

批准后同步 SPEC 0016 §7 的填写合同与 §7.3 的库存写法，并以新 ADR 说明对 ADR 0015、0066 的局部取代；ADR 0059 的隐蔽旁人规则继续有效，明确其与新公开见证范围的关系。ADR 0062 仅提供隐蔽注意档位默认，不用作公开知识默认授予依据。库存权威、首骰前预检和失败取物限制不变；见证遵从 SPEC 0005/0006 的感知与 NPC 知识边界。现行批准 SPEC 不在本草案修订时提前修改。
