# 玩家桌面统合方案：角色栏、行动、背包与资源

日期：2026-10-11。状态：用户已确认方向；第一、二期已在本地实现（见第 7、8 节），第三、四期未开始。基线 `cloudflare` 07119839，第二期起接在包含地图改动（`f0fe8d43`，ADR 0140）的 `cloudflare` 上。

本方案只调整页面的放置、触发与展示，不改产品规则。约束来自：

- [SPEC 0009 §7](../../specs/0009-failure-pacing-conclusion-and-interaction.md)：自然语言输入框是主入口，不是封闭命令菜单；页面不自己拼状态或预测机械结果。
- [SPEC 0010 §7](../../specs/0010-observer-specific-presentation.md)：资源、物品、恢复选项都来自同一 projector，页面只消费。
- [SPEC 0014 §8](../../specs/0014-observer-tactical-map-and-environment.md)：地图在窄屏与桌面无横向溢出，键盘与触摸可操作，文字版保留完整可操作路径，地图不计算机械。
- [ADR 0091](../../adr/0091-map-moves-and-structured-combat-actions-go-straight-to-rules.md)：战斗中自己回合的结构化动作直接交给 Rules；战斗外从地图选的施法与攻击交给 KP。

## 1. 现状

证据来自源码与本地预览（`app/dev-ui-preview`，用 `tests/support/fixtures/tactical-map-v2.mjs` 渲染，桌面 1440 宽与手机 375 宽）。

**位置**

- 整个桌面是一列：顶栏、状态条、地图、对话、待决、输入框依次堆叠（`play-table.tsx` 998–1523）。宽屏两侧空白，没有侧栏。
- 角色的一切（资源、法术、职业能力、装备、背包）都在"桌边册 → 人物"抽屉里，与在场、线索、日志并列。抽屉打开后遮住地图与对话。
- 装备一面盾牌：打开桌边册 → 人物 → 往下翻过库存、属性、技能、熟练、动作、12 个装备槽 → 展开背包 → 点盾牌 → 装备到副手。
- 战斗动作条在地图面板内部。主检出的新地图把桌面地图限高 65dvh 并在内部滚动，动作条要在地图里往下滚才看得到，对话区更小。
- 手机宽度下状态条隐藏生命与护甲（`hidden sm:inline-flex`），地图默认收起；"轮到你"时页面上没有任何动作按钮。

**同一能力有多个入口，走不同路径**

| 能力 | 入口 | 提交 | 去向 |
| --- | --- | --- | --- |
| 施法 | 人物卡法术条 | `castSpell` | 拼成文字意图交 KP，法术与目标是原始 id；目标列表取自生产中恒为 null 的 `ruleProjection`，需要目标的法术在实际房间里点不了 |
| 施法 | 战斗地图动作条 | `combatAbility` | Rules 直接结算 |
| 施法 | 战斗外地图"对人使用能力" | `submitText` | 文字意图交 KP |
| 动作如潮 / 回气 / 狂暴 | 人物卡"库存"下方按钮 | `useFeature` | 文字意图"我使用特性 surge。"交 KP |
| 动作如潮 / 回气 | 战斗地图"职业能力"组 | `combatAbility` | Rules 直接结算 |
| 治疗药水 | 背包展开后"使用" | `useInventoryItem` | Rules（`itemActivity`） |
| 治疗药水 | 战斗地图"物品"组 | `combatAbility` | Rules 直接结算 |

**展示**

- "库存"格子把法术位、职业资源、生命骰与金币、箭、火把、口粮放在一起。后四项由背包实物折算（`rules/v2/item-resources.ts`），背包里又列一遍。
- 法术位只有一环、二环两个键；Rules 战斗运行时用 `spellSlot:N`，页面看不到三环以上。
- 权威状态的 conditions 由 projector 产出，但桌面适配层的白名单把它丢掉了（`authoritative.ts` 约 2289–2307），状态与专注只读静态人物卡。
- 动作经济是一行灰字（"动作 1 · 附赠动作 1 · 反应 1 · 剩余移动 30 尺"）。
- 装备 12 个槽每槽一行，空槽占大半；背包不分类，操作按钮要展开才出现；没有丢下、交给、放入容器的入口，只能打字。
- "离开这一桌"是顶栏的小字按钮，点了直接离开，没有确认。

**无消费者的旧界面**

`fetchTable` 对现役房间固定返回 `combat: null`、`ruleProjection: null`、`restVote: null`、`restHold: null`、`squadQueue: []`、`logs: []`（`table/server.ts` 1140–1165）。因此 `CombatStrip`（加入战斗、撤离、投降、护盾术反应、死亡豁免按钮）、休息投票与保持、`SquadQueueBar`、日志标签、依赖 `activeRule` 的人物卡分支在生产中都不显示。

**样式**

颜色、字体 token 是统一的（`app/globals.css`），但按钮有三套（`ui/button`、地图里的 `ACTION_BUTTON`/`PRIMARY_BUTTON`、小字链接），折叠有三种（`Fold`、`InventorySection`、原生 `<details>`），圆角混用 8/10/12/14/16/20/24/28px，取消与返回也用实心主按钮，`bg-panel/40` 是未定义的类。

## 2. 方案

### 2.1 三类信息各有固定位置

| 类别 | 内容 | 位置 |
| --- | --- | --- |
| 场景 | KP 回应、地图、待决、输入 | 主区 |
| 角色 | 我的状态、我能做什么、我带着什么 | 角色栏 |
| 见闻 | 在场的人、线索、到过的地方 | 桌边册（只保留这三项） |

### 2.2 桌面布局（≥1024px）

- 主区在左，角色栏在右（宽 22rem，1024–1279px 可收起为一列图标，≥1280px 默认展开）。
- 主区顶部一个切换：对话 / 地图 / 分屏。战斗中默认分屏（地图在上约 55%，对话在下），战斗外默认对话。切换状态按房间记在本地，战斗开始与结束不再重挂载地图、丢失展开状态。
- 输入框上方依次是：回合条（战斗中）、确认条（正在选目标时）、待决卡与掷骰卡。这几样都靠近输入框，眼睛不用在地图和页面底部之间来回。
- 顶栏只留模组、章节、场景、时间推进，以及桌边册入口和"离开"（改为二次确认）。

### 2.3 手机布局（<768px）

- 顶部常驻一行状态：生命条与数值、AC、最紧要的一项资源（施法者为最低可用环位，其他职业为第一项职业资源），有状态时显示状态标记。点这一行打开角色栏。
- 主区：对话 / 地图 切换。
- 输入框左侧两个按钮："行动"、"背包"，各打开底部半屏面板。选目标时面板自动收起成确认条，地图露出来供点选；文字版地图同样可选。
- 战斗中回合条压缩为一行：轮次、三个动作点、剩余移动、结束回合。

### 2.4 行动：一个列表，一条触发规则

- 数据源只有一个：`combatControls`（`abilities` + `basicActions`）。地图的探索分支已经在战斗外使用同一份 `abilities`，所以战斗内外是同一张表。
- 分组：武器、法术（按环分组，环标题旁显示该环剩余点数）、职业能力、物品、基础动作（收成一行小按钮）、休息（仅战斗外，来自 `restRecoveryOptions`）。
- 每一行显示：名称、消耗（动作 / 附赠 / 反应 / 不占动作）、需要的法术位或次数及剩余、射程与目标提示。
- 触发：
  - 无目标或以自己为目标：一次点击，战斗中直接提交。
  - 需要目标：进入选目标状态，地图高亮可选对象，输入框上方出现确认条（"魔法飞弹 · 1 环 · 已选 2/3 [取消] [施放]"），确认条里也列出候选名字，地图收起时照样能选。
  - 战斗中自己回合：`combatAbility` → Rules，按钮旁标"直接结算"。
  - 不是自己回合：列表照常可看，按钮不可提交，并写明"等待 X 行动"。
  - 战斗外：选好目标后生成一句意图（复用地图现有的 `intentSentence`），放进输入框，玩家可补充说法后自己发送（用户 2026-10-11 裁定）。
  - 有待决输入时：行动提交暂停，提示先回答上方的待决卡（与现在 `intentUnavailable` 的规则相同）。
- 删除人物卡里的 `SpellLine` 施放表单与 `useFeature` 按钮及其文本意图路径；法术与职业能力的说明文字保留在"角色"标签里只读展示。删除前核对 `castSpell`、`useFeature` 是否还有待决回答等其他调用者，无调用者则同次删除服务端入口与对应测试。
- 地图组件只保留显示、点选与移动路径；动作条、结束回合按钮迁到行动面板与回合条。地图通过已有的 `TacticalMapActions` 接口接收"当前正在选什么目标"，不另建状态。

### 2.5 背包

- 顶部"身上"：主手、副手、护甲三格始终显示；其余槽位只显示已占用的，空槽合为一行"其他 9 个槽位空着"，点开再看。
- 货币单独一行（金币 15），不再出现在资源区。
- 背包按 `category` 分组：武器、护甲与盾牌、弹药、消耗品、工具、杂物、货币；容器显示开合状态与上次查看的内容（`containerMemories`）。
- 行内直接给出 Rules 允许的操作，不用先展开：可装备的显示"装备"（多个可选槽时弹出槽位选择）、已装备的显示"卸下"、有 `use` 活动的显示"使用"或不可用原因。点行本身展开说明、伤害、次数、耐久。
- 丢下、交给某人、放进容器：没有结构化命令，保持由 KP 裁定。行尾"更多"菜单里给"说出来"，把"我把麻绳（50 尺）……"放进输入框，玩家补完再发送。不新增规则通路。
- 战斗中换装是否花动作由 Rules 决定；被拒时在该行下方显示原因，不用全局 toast。

### 2.6 资源与状态

- 拆掉"库存"格子。
- 角色栏顶部状态卡：生命条（当前/最大，临时生命叠在条上）、AC、速度、状态标记、专注中的法术。
- 下面一行资源点：每个法术环位一组点、每项职业资源一组点（旁注短休 / 长休恢复）、生命骰。
- 金币、火把、口粮只在背包；弹药数量显示在对应武器行（需要投影提供时再加，见第 3 节）。
- 短休、长休移到行动面板的"休息"组，用次要按钮样式。

### 2.7 回合条与待决

- 回合条固定在输入框上方：第 N 轮 · 轮到你 / 等待某人；动作、附赠、反应三个点；剩余移动；"移动"与"结束回合"。数据仍是 `combatControls.turn` 与 `movement`。
- 待决卡与掷骰卡保持在输入框上方，统一为一种卡片样式，每张卡只有一个主按钮。选目标类待决（`combatChoice` 的 `target`）同时在地图上高亮候选。

### 2.8 样式统一

- 按钮四级：主按钮（每个视图最多一个：发送、确认施放、掷骰）、次要、幽灵、危险（离开、投降）。地图里的 `ACTION_BUTTON`/`PRIMARY_BUTTON` 改用共用组件。
- 新增几个共用小组件：列表行、消耗标签、资源点、折叠区（沿用 `InventorySection` 的无障碍写法，替换 `Fold` 与零散 `<details>`）。
- 圆角收敛为三档：面板 16px、行与控件 10px、标签全圆；改用 `@theme` 里的 radius token。
- 消耗标签配色：动作用黄铜色，附赠用苔绿，反应用描边，不占动作无边框。
- 补上或删掉未定义的 `bg-panel`。

### 2.9 清理

替代路径闭合后同次删除第 1 节列出的无消费者旧界面及其类型、样式和结构测试中的对应断言（`tests/product/characters/interaction-contract.structure.test.mjs` 188–219 要求这些标识存在，需要同步修改）。

## 3. 需要投影补上的数据

页面不自己计算，下列内容由 Rules 或桌面适配层提供：

| 数据 | 现状 | 处理 |
| --- | --- | --- |
| 状态（conditions） | projector 已产出，适配层丢弃 | 适配层放行 |
| 按环法术位 | 只有 slot1、slot2 | 适配层按 `spellSlot:N` 给出各环剩余与上限 |
| 临时生命、专注、死亡豁免 | 页面读静态人物卡或没有 | 从权威状态投影 |
| 每个能力当前能否使用及原因 | 只有"是否轮到我"，其余等服务器拒绝 | 可选：Rules 在 `combatControls` 每项上给出；在此之前页面不预判 |
| 武器对应弹药数 | 无 | 可选，后做 |
| 战斗外能力清单是否覆盖全部已备法术 | 未核对 | 实施第 2 阶段前核对；缺的由 Rules 投影补，页面不另列 |

## 4. 分期

1. **骨架与状态**：两栏与手机状态条；角色栏状态卡与资源点（含第 3 节前三行数据）；桌边册只留在场、线索；"离开"二次确认；删除无消费者旧界面。
2. **行动**：行动面板接 `combatControls`；回合条与确认条迁到输入框上方；地图只负责显示、点选与移动；删除人物卡施放与 `useFeature` 文本路径。
3. **背包**：分组、行内操作、空槽收起、货币一行、"说出来"。
4. **样式收口**：按钮、圆角、折叠组件统一，地图内按钮换成共用组件。

每期单独可交付。第 2 期改动 `tactical-map.tsx` 较多，应在主检出那批地图改动提交到 `cloudflare` 之后开始，避免两边同时改同一文件。

## 5. 代表性验收

| 样例 | 验证的变化 |
| --- | --- |
| 战士在自己回合，从行动面板用长剑攻击守夜人 | 单目标、直接结算；与地图点选走同一 `combatAbility` |
| 法师在战斗外，对两个目标施放魔法飞弹 | 多目标、法术位、战斗外交 KP |
| 背包里把盾牌装备到副手，喝一瓶治疗药水，再卸下长剑 | 结构化 `gear` 与 `itemActivity`，行内操作 |
| 不是自己回合 / 有待决选目标时点攻击 | 拒绝边界：不提交，说明原因并指向待决卡 |
| 375 宽手机：从输入框旁"行动"施法并在地图上选目标 | 无横向溢出、面板收起成确认条、文字版地图也能选 |

验证方式：目标组件的渲染测试（现有 `react-test-renderer` 用例扩展）、受影响的结构测试，加一次桌面与手机宽度的浏览器检查。共享类型变化时跑一次 `npm run typecheck`。

## 7. 第一期实施记录（2026-10-11，本地）

- 新组件 [character-panel.tsx](../../../app/_runtime/components/character-panel.tsx)：状态卡（生命条、临时生命、护甲、速度、状态、专注、濒死时的死亡豁免）、资源点（各环法术位、职业资源、生命骰）、"行动 / 背包 / 角色"三个标签页，以及窄屏的一行状态条。
- 宽度 ≥1280px 时角色栏停靠在主区右侧；更窄时主区顶部显示一行状态条，点开为抽屉。方案原写 ≥1024px 停靠、1024–1279px 可收起，实际改为 1280px 一个断点，以免主区和地图在 1024px 宽度下过窄。
- 桌边册去掉"人物"和"日志"（生产中日志恒为空），保留"在场""线索"；有其他玩家时多一个"同伴"标签，放组队、交队长、请离等原人物卡上的控件。
- "离开这一桌"改为二次确认。
- 资源区"库存"格子删除；金币、箭、火把、口粮只在背包。休整与职业能力按钮改为次要样式。原"动作"折叠区（实为特性说明）改名"特性"，移到"角色"标签。
- 数据：Rules `combatControls` 增加 `vitals`（临时生命、专注的法术、生命状态、死亡豁免），仍在 `controlledCharacter` 之外；桌面适配层放行本人 `conditions`（不含擒抱者身份）。资源点直接读权威 `resources` / `resourceMaximums`，三环及以上法术位第一次能显示。
- 未做：背包页里"身上 / 背包"仍默认收起（第三期重做背包时处理）；人物卡法术条仍走旧的 `castSpell` 路径，与权威法术位可能不同步（第二期替换）；战斗中地图与动作条仍会挤压对话区（第二期把动作条移出地图）。

## 8. 第二期实施记录（2026-10-11，本地）

裁定与规则见 [ADR 0146](../../adr/0146-picked-sentences-go-into-the-composer.md) 与 [SPEC 0014 §§4、8](../../specs/0014-observer-tactical-map-and-environment.md)。

- 角色栏"行动"页改为一个行动列表，数据只来自 `combatControls`：武器与攻击、法术（显示所需环位与剩余）、职业能力、物品、基础动作。遭遇中不是自己回合时整列不可用并写明在等谁；遭遇之外不列基础动作。
