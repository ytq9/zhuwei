# 隔离 Worker 并行流程

本文件只在至少两个范围可独立验收、修改路径不重叠且确有并行收益时读取。一个 Bug、多文件但同一因果链、共享接口或重叠文件修改继续由当前代理在当前 worktree 串行完成。

## 启动条件

协调代理在派工前固定：

- 共享需求、公共接口与验收条件；
- 可恢复基线或 checkpoint commit；
- 每个 Worker 唯一拥有的修改路径；
- 指定的定向验证；
- 集成依赖顺序与禁止触碰的共享文件。

与在途修改独立且文件所有权不重叠的问题可进入隔离 Worktree。触及相同文件或公共接口的问题先只读诊断或排队；依赖在途修复的问题等待 checkpoint。共享远端 D1、Durable Object、Worker、本地服务端口、migration、部署和 push 始终串行。

## Worker 合同

Worker 只能修改派工列出的路径，从指定基线开始，并运行指定的最小验证。Worker 不修改 `AGENTS.md`、共享规格或 `docs/refactor-log.md`，不执行远端 migration、部署或 Git push。

Worker 回执必须包含：

- 症状或需求；
- 根因或决策；
- 修改文件；
- 实际验证命令、退出码和证据；
- 未覆盖范围与剩余限制；
- 可收回的 commit SHA；未提交或不建议集成时明确说明。

## 协调与集成

并行期间由协调代理单写 `docs/refactor-log.md`。协调代理按依赖顺序收回改动，逐项审查 diff、处理冲突，并只运行受影响范围的组合回归。全量回归只按 `docs/agent/release.md` 的显式触发条件执行。

每个 Worker 无论集成、放弃或冲突，都由协调代理记录基线、文件、验证、commit、冲突与处置。缺少结构化回执、日志集成状态或剩余限制说明的修改不得宣告完成。
