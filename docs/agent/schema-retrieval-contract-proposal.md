# 按需 Proposal schema：调用边界修订

- 日期：2026-09-06
- 状态：2026-09-06 用户明确批准调用例外；2026-09-07 收敛首轮呈现后，又批准[完整填写边界前移与一次补选](vnext-selection-composition-validation.md)，2026-09-09 重申“可以补选”。下文保留各日期方案和预算的历史记录；当前阶段与调用合同统一以 [SPEC 0016 §7.2](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md#72-bundle-语义冻结与一次窄修复)为准。实现、真实验证和模型采用门独立记账。
- 目标：普通行动不再携带完整创作 schema；复杂行动可取回完整定义，不按物品名、动词或已有对象存在性限制 KP 合理能力。

## 现有条款与最小修订

修订前，SPEC 0015 §6.1 的“总调用数最多两次，不得第三次发送完整 Prompt”，以及 SPEC 0016 §12 的“1+1 调用预算”，覆盖主 KP 的调用路径。首次响应可选提交或 schema 请求后，再允许提交与一次窄修订，会把最坏次数从 2 增至 3；不能仅将第一次改名为检索来宣称已符合旧限制。

用户批准仅增加如下例外，并同步直接引用、验收及预算计数：

> Proposal 前允许至多一次只返回能力标识的 schema 补取。初次请求只提供 knowledgeReview、passTime、inWorldRefusal 的完整小表单，以及全部可召回能力的轻量目录；其他行动先选择所需家族，clarification 也须一次选齐完整 continuation 所需家族。补取响应不得包含裁决、草稿、风险、成本、结果或世界事实，不产生语义冻结或状态变化。服务端从当前注册表精确读取选中家族及其类型依赖，不额外并入未选家族，并冻结下一请求；后续请求不再允许补取。首份 ProposalBundle 仍只有一次，随后最多一次不改变语义的窄 correction。普通路径最多 2 次调用，发生补取时最多 3 次；所有调用均计入实际 token、费用、延迟与 RootAction 总次数。

2026-09-07 的具体首轮集合是实现选择，依据用户已经授权的填写接口简化与真实验收调整；不将它表述为用户逐字批准的方案。此变更只取代“常用能力均可首轮提交”的呈现及对应验证要求，不豁免权限、机械、持久化、语义冻结和调用上限。不能用小表单改变原行动方法或以 schema 缺失作世界内拒绝。

该例外不改变 SPEC 0001 的玩家意图、KP 叙事权威、Rules 机械权威、Room 原子提交或 Viewer 权限；schema 标识不是创建权限，也不是存在证明。

## 实现与失败边界

2026-09-07 round66 后的同源选择修正：请求标识由实际初始小表单与 step 注册表共同派生；纯查询可以包含已加载小表单，服务端复用已提供结构，只加载所选 step 和类型依赖。纯小表单查询也消耗唯一补取阶段，下一请求不再允许查询。未知、重复 ID、混合草稿仍拒绝，不清洗或重采；此处理尚未形成裁决，不属于 Proposal 窄修订。见 [实现与证据](vnext-terminal-selection-validation.md)。

1. 以现有严格 schema 为唯一字段源，注册 worldInteraction、叙述承诺、场景物化、库存、Ability/Hazard/Item 定义和物品实例等能力及其依赖。轻量目录不含秘密或场景事实。
2. 首轮装配三个小表单，其余由模型从目录一次选齐；依赖按类型传递闭合，不使用自然语言关键词硬路由。所有已注册能力仍可取得，空 step 集合不生成 direct/check/clarification 的无效空结构。
3. 使用单一严格工具响应表达“提交”或“取 schema”，保持 Provider 单工具约束。最终 Proposal 经过所选工具 schema、本地域解析及完整 Rules 校验；不允许利用较宽解析器提交未加载类型。
4. Room 在每次外部调用前保存确切请求及 hash，在下一阶段前保存响应。恢复从同一请求与已保存响应继续；不得重选能力、切换版本或重新决定世界事实。
5. 未知标识、重复补取、混合裁决草稿、预算超限和不可闭合定义明确技术失败，不变成玩家 clarification、世界内拒绝或假成功。不追加第四次模型调用。

## 代表性验收与有界真实验证

- 知识回顾与主动等待可首轮提交；库存操作、场景交互和独立观察先选家族再填完整提案，同走正常 Room/Rules 链。澄清不能借无 steps 的 refusal/cancel 选项绕过首轮准入。
- 请求 Item 创作后，Ability 依赖自动闭合，物化并使用沿同一原子 Bundle；另验 Hazard 创作的依赖结构。
- 未加载类型、未知能力及非法混合请求在任何世界/随机/资源副作用前拒绝。
- 补取响应保存后恢复、最终 Proposal 恢复、一次 correction、429 与预算阻断保留确切请求及次数证据。
- 真实 DeepSeek 首批最多 2 个 RootAction、8 次总外部调用、120k 输入/12k 输出 tokens；第一个明确失败即停止，仅在能区分原因时追加一次对照，仍受总预算限制。统计包含旁白与审核。
- schema 字节、实际模型 tokens、请求次数和端到端延迟分别记账。V11 的成本与调用采用门保持原值，未达到就报告未达标。
