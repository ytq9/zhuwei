# Round102：选择阶段召回第一次跑真实模型；瓦罗拒绝抄送；等待句客户端超时

2026-09-10 凌晨，源码 `add92b1`（选择阶段召回 NPC 视图与记忆正文），场景同 round82–91，本地上限 10。setup 前先用只读 HTTP 预热路由。**首句 6 次调用提交并发布，等待句 4 次调用在权威侧提交，但客户端 120 秒超时中止了仍在发布的请求，批次按首个技术失败停止，第三句未发。10 次调用，131,108 / 7,326 tokens，¥0.706986（峰值计）。**

## 召回机制的真实表现

| 阶段 | 默认送出 | 可请求 | 模型实际请求 |
| --- | --- | --- | --- |
| 首句 offer（点名瓦罗） | 瓦罗视图 | 莉安、奈斯；瓦罗 2 条记忆 handle | 不加 NPC；两条记忆 handle 全取 |
| 首句填写 | 瓦罗视图 + 上述 2 条正文 | — | — |
| 等待句 offer（无人点名） | 无 | 三位 NPC；无 handle | 莉安、奈斯 |
| 等待句填写 | 莉安、奈斯视图 | 11 条记忆 handle | — |

模型看懂了 gist 目录并按 handle 取正文：首句它挑了瓦罗的 `module-knowledge:02`、`:03`（正是与文书、账台相关的两条）。旁观者未被请求时不提供 handle，被请求后才连同其目录一起出现——这与设计一致。

## 世界内拒绝（合法结果，非失败）

瓦罗当面拒绝抄送：备案文书是镇公所的档，原件不离手、不借不外带、不许旁人誊抄，「要我抄一份送到账台——这不办」；只肯再宣读一遍，或让玩家自己坐在账台边抄完给他过目。因此**本轮没有新承诺、没有新计划，承诺派生链未被覆盖**。gate1 仍判 `wait`：公开回复邀请玩家留在厅里抄，固定的等待句没有被排除。

## 为什么停

等待句的 HTTP 在 120 秒时被客户端中止，而服务端已经提交：权威时间 +3,900,000,000 微秒、11 个事件、stateVersion 11，只有第三份 audience 停在 `retryableFailure`（旁白发布未完成）。这是客户端中止，不是产品失败；按纪律记为本批首个技术失败并停止，第三句未发。第三句（去账台看副本、无人点名）仍未在真实批次上覆盖。
