## 1. 需要处理的具体规格

现役依据是 [SPEC 0015 §6](../specs/0015-private-form-context-rag-and-narration.md) 与 [SPEC 0016 §7.2](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)。SPEC 0016 当前条款包括：

> 普通小表单最多 2 次模型调用，选择与填写用完后不得再调用 correction；实际包含所选执行家族的复杂提案最多 3 次，即一次纯选择、一次 Proposal 和最多一次窄 correction，不得增加第四阶段。

条款还要求实际调用及 Provider 重试计入 RootAction 调用、token、费用和延迟预算。SPEC 0011 §3 的旧 1+2 已被后续规格取代，不能单独用来规定当前上限；近期填写修复的具体实现差异也不构成完整故事创作的预算授权。

[故事能力合同 C03/C08](story-creation-capability-contract-proposal.md) 要求完整准备、语义与玩法检查及有界修订；[框架 §7](story-creation-modular-framework-proposal.md) 已明确它们需要独立工作流。若把这些步骤塞进原 Proposal 的选择、填写或机械修订，会改变上述次数与修订含义；若另起不关联的根行动规避额度，则违反同源计量与恢复要求。

用户已同意开发该能力，并于 2026-09-09 确认本补充；按以下条款更新对应规格及直接消费者。

## 2. 已批准的最小补充

为绑定新故事创作合同的开发期 Profile 增加以下例外：

1. **完整故事采用独立、版本化且有界的创作作业。** 作业关联触发它的根行动或已提交世界事件，不改变普通行动的现役调用及窄修订合同。
2. **首版每份新准备包最多 4 次实际模型调用：初稿、独立审查、必要时的一轮修订、修订后复审。** 初稿通过审查时使用 2 次；第三、四次仅在存在可修订问题时使用。这个数字是待验证的初始策略，不是已测得的质量或成本结论。
3. 结构解析失败、Provider 重试与任何其他付费模型步骤都占用该作业额度；不能通过换阶段、换 HTTP 请求、改 jobId 或重新包装同一机会重置额度。已保存结果恢复不再调用；结果未知时不自动重新采样。
4. 故事修订可以修改尚未固化的草稿，但不能改变玩家意图、锚点、已固化事实、已发布叙述承诺或骰前冻结的机械结果。它与现役 Proposal 的一次修订分别验证；普通 Proposal 的修订范围与最终执行方案冻结时点遵循 SPEC 0016 §7.2 的 2026-09-09 用户决定。
5. 创作作业、后续正常提案、NPC 决策及逐 Viewer 叙述仍共同归入宿主来源预算；新作业额度是一个明确子额度，不意味着整个根行动不再设总额。所有实际调用、token、费用和延迟保留关联记录。
6. token、输出长度、总金额及房间共享额度由版本化预算配置限制，并在代表性样例中测量。估算 token 不是精确金额保证；未知 usage 不记录为零费用。额度不足时保留明确状态，不省略必需材料或审查来伪造完整。
7. 触发完整创作只来自已授权的玩家目标或真实虚构因果；普通询问可正常回应，现实等待不推进世界，也不安排无因果的后台创作。

这会增加实际展开完整支线时的调用成本与等待时间；配方复用和准备包复用用于减少重复创作。该例外不允许无限修订、投机批量生成候选、自动更换主 KP 或用创作费用惩罚玩家。
