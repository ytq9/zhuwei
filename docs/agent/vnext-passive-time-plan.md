# 主动度过时间的最小纵切

2026-09-07，承接 [round60 真实失败](vnext-round60-validation.md)。Rules、Room/交付与数值表示修复已串行集成并完成主树定向检查，round61真实等待及NPC到期通过，后续观察因服务器知识引用表示不一致拒绝；见[实施回执](vnext-passive-time-validation.md)。不替代主 PRD/SPEC0016。

能力合同：获授权玩家主动等待或守望，让本人所在地点的虚构时间真实经过；服务器保存 Activity、原意图与时长，以 Rules 的时间/活动权威推进，遇到既有到期义务先结算，活动中断则只保留实际经过时间。Viewer 只收到已提交的开始、经过时间、完成/中断及其有权感知的到期结果。现实阅读、知识回顾继续零耗时。模型不填写未来感官证据、身份、活动ID或阶段hash。

首纵切支持没有预定额外机械效果的主动时间经过。等待期间NPC真正执行的可观察痕迹走已有due→Rules→Claims→Viewer链；不能提前把计划trace写成观察事实。调查、制造、移动、休整、检定型长动作及冻结成败后果不借这个类型伪装支持，后续应各自接入原机械机制；这里也不增加未来随机遭遇或额外完成阶段KP调用。

模型表面拟为单独的最小终止型 `passTime`，只填写实际durationMicros；原意图由服务器保存。不能与即时observe结果或其他效果混束。它与普通direct/check仍使用同一领域schema、filling转换和校验器；不可从自由文本解析/补造时长，缺失或越界时长按通用诊断失败，不允许窄修订改变时间裁决。

执行接缝待Rules/Room核定：复用campaignRuntime.activities保存活动，复用现有Room持久任务队列/阶段表。每个时间推进以最早的活动完成点或相关到期点为上界，独立Rules root提交；到期NPC沿原一次调用预算/原响应journal执行，之后重读权威活动状态，仍active才继续剩余时间。禁止放宽atomic-world-input旧candidateState恢复的完整状态匹配，也不存储未来候选state以覆盖到期后的世界。

定向矩阵：原“等待一分钟并留意动静”且第2秒NPC到期；不同时间/无NPC的守望；中途活动被打断；重复请求/驱逐恢复不重复经过时间或NPC调用；两个时间线与同地点权限；知识回顾不触发推进。时间Claims必须来自FictionTimeAdvanced/活动事件，不能根据自然语言方法判断是否经过时间。只在最小纵切闭合后运行同原三句真实API新批，不把纯Node/受控Room通过当作稳定性通过。

普通复杂耗时裁决、完整NPC新计划、多人20+连续链及整体Goal继续未完成。本阶段不部署、push或commit。
