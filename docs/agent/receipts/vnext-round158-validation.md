# round158：做不到在填写时总可选之后，再争取与对抗动作

2026-10-03。`tools/run-story-room-probe.mjs --live`，每个用例一个新房间，真实 HTTP 路径，DeepSeek `deepseek-flash`。用户同意按五项修改并按计划验证（"可以，按1-5改"）；计划里的编号真实批次约 30 次调用。我设的上限是每个房间 16 次、合计 40 次，首个产品失败即停，不重采样，不部署、不 push。实际 23 次调用，没有失败。运行在国庆假期（14:32 UTC 起），按空闲价（缓存命中 0.02、其余输入 1、输出 4，单位 ¥/百万 token，2026-10-03 只读核对官方价格页）约 ¥0.21，按高峰价约 ¥0.43。

在 `kp-battle` 工作树运行，源码等于 cloudflare `5f17ead` 加本分支提交，HEAD `d510def`（含 [ADR 0084](../../adr/0084-a-review-returns-the-ruling-when-the-npc-keeps-to-its-records.md)、[ADR 0085](../../adr/0085-a-refusal-is-always-offered-at-filling.md) 与探针用例）。运行前后源码清单一致，每个用例先做 `--preflight`（0 次调用）。没有远端 migration、Secrets 修改或部署。

## 这批验证什么

- ADR 0085：玩家行动的填写表单总提供"做不到"，KP 对不可能的行动能直接判做不到，而不是写 DC 27 或"成功但纹丝不动"（[round156](vnext-round156-validation.md)、[round157](vnext-round157-validation.md)、[小测](kp-refusal-form-mini-test-20261003.md)）。
- [ADR 0081](../../adr/0081-ask-once-after-a-failed-conversation.md)、[ADR 0083](../../adr/0083-record-check-and-refusal-precedents.md) 中至今没跑通的一段：被判做不到后再争取，KP 问一次；回答一个不需要新物品的做法，或不补充，同一行动重新裁决并提交。
- 误拒：需要先走过去、对方可能反抗的动作不被判成做不到（新用例 `contested-carry`，见 `d510def`）。

### 158-3

选择 worldInteraction、observe；填写时补选 social 并加载莉安、瓦罗的视图；补选后的填写给出运动检定 DC 13，成功分支是把奈斯扛到炉边。掷出 13 + 5 = 18，成功，提交并发布。没有判成做不到。

## 看到的

- **做不到可以直接判了。** 两个房间的第一步，选择阶段都没选拒绝，填写阶段直接给出拒绝；依据写的是真实前提，没有 DC。之前同一请求的 4 次运行都是检定或"成功但纹丝不动"。
- **再争取的整条链路第一次在真实调用里走通**：拒绝记先例 → 提问引用该先例 → 回答（新做法或不补充）后同一行动重新裁决 → 提交。
- **对抗动作没有误拒**，但成功只体现在文字上：奈斯在权威状态里的场景和位置没有变化，表单写不出"把人扛走"。这一点由另开的"行动者移动"和"对抗检定"任务处理。
- **旁白替奈斯说了一句话**："请，先放我下来。"这一步没有奈斯本人的作答调用，旁白审核放行了。按旁白规则，NPC 没说过的话不能写进旁白；这里没有进一步排查，记为待查。

## 没有覆盖的

- 回答后的新做法真正可行、改判为检定或直接成功的情形（两次回答都仍判做不到）。
- 炉台以外的不可能行动；缺工具、缺能力类拒绝的真实运行。
- 交谈失败后的再争取，以及 ADR 0084 的审核退回裁决（本批没有交谈检定失败）。
- 漏选执行类型时，KP 会不会用拒绝代替补选。
