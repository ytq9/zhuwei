# round123：请 NPC 配合时判检定

2026-09-24。用例 `daily-spoken-intent`，行动文本换成本地预览测试中第 8 次行动的原话：“我向lian介绍，我是一名剑湾法庭的猎魔人，今天特意来调查她父亲死亡的事件，名字叫散木，希望她可以尽力配合”。调用上限 10，真实 HTTP 路径，`deepseek-v4-flash`，源码 `69c3471`。未部署、未 push、未做远端 migration、未改 Secrets。工作区里另一个会话未提交的改动只涉及 GPT-6 Luna 的传输方言，不经过本用例的 DeepSeek 路径。承接 [round122](./vnext-round122-validation.md)。

## 背景

本地预览里，模型把这句话判为 directSuccess，它自己写的风险却是“这句话会决定她接下来是继续谈，还是把话收回去”。按 SPEC 0001 §5，存在真实不确定性、失败有意义的行动要检定。指引同时写着“NPC依据自己的目标和知识行动”和“失败会改变关系或处境的尝试都算有意义风险”，但没有说两者怎么配合，模型按莉安的动机直接写了她的反应。

- `2ae1482`（[ADR 0045](../../adr/0045-the-proposal-gets-writing-guidance-without-review-criteria.md)）：提案只带中文写作要求，不带审核标准，每个选择少 329 个估算 token。
- `69c3471`：社交指引写明，请交谈对象配合、答应、透露或相信而对方未必同意时要检定，成败两边都按对方本人的目标和知识回应（指引 v46）。

### 裁决

- 首稿判说服检定，魅力，DC 15。交谈写在 `check.social`，`checkStep: "social"`。失败后果写的是莉安追问来历、不回应“配合”的请求。
- 骰面 12，对 DC 15，失败。事件含 RelationshipChanged。莉安反问他是哪个镇上的人、谁让他来的，先弄清来处才肯谈。旁白审核通过。

### 修订

首稿还有三处错，用满了三轮修订。再多一处，行动就会失败。

1. 同一段交谈在 `steps.social` 里又写了一遍，绑 always（`bundle:social-npc-repeated`）。第一轮删掉。
2. 检定行的 basisRefs 引用了 `definition:module-npc:npc:black-oak-will:lian`（`proposal:basis-ref-not-authorized`）。第二轮换成 `npc:black-oak-will:lian`。
3. 换上的引用和第 0 项重复（`reference-array-unique`）。第三轮改好。

### 缓存与 ADR 0044

- 第 2 次调用补选加载了莉安的视图。第 3 次的上下文把她的条目接在所有不随请求变化的条目之后。两次系统消息前 39,068 个字符相同，第 3 次命中 14,720 token。这是 [ADR 0044](../../adr/0044-what-the-selection-loads-goes-last-in-the-context.md) 的排序第一次在真实批次里用到。
