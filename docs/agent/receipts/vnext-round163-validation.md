# round163：跳过与躲藏的真实验证

2026-10-04（北京时间 13:57 起）。`tools/run-story-room-probe.mjs --live --max-calls 16`，每批一个新房间，真实 HTTP 路径，DeepSeek `deepseek-flash`。用户要求"躲藏合并后跑真实验证""等合并后直接跑"：用例 jump-tables 与 hide-tables，每个一个房间、上限 16 次调用，首个失败即停、修好再跑，不部署、不 push。两个用例都用 `--dice` 预定行动者的骰面（跳过 15、躲藏 18），只为走到成功那一侧；骰面在 KP 提案冻结后才掷，模型看不到。四批共 16 次调用，按国庆假期空闲价（缓存命中 0.02、其余输入 1、输出 4，单位 ¥/百万 token）约 ¥0.20，按高峰价约 ¥0.40。

都在 `relaxed-saha-bd59ee` 工作树运行，工作区干净，每批前做了 `--preflight`（0 次调用）。没有远端 migration、Secrets 修改或部署。

## 这批验证什么

- [ADR 0092](../../adr/0092-common-action-scripts.md) 的跳过：KP 写 `commonAction: jump`，行动者先走到起跳处，再跳到长桌对侧；SPEC 0014 §4 的距离、高度与检定。判定：有一次 `CharacterJumped` 跳过 `feature:wake:joined-tables`，行动者停在落点。
- [ADR 0093](../../adr/0093-hide-and-search.md)、[ADR 0094](../../adr/0094-hide-dc-follows-cover.md) 的躲藏：KP 用 concealedCheck（敏捷隐匿）与 `commonAction: hide`，Rules 按各 NPC 的被动察觉加掩护调整决定对谁隐藏。判定：Rules 结算了一次 `hid`，状态里记下的隐藏对象与它一致。

### 163-1：走到了最近处，跳不过去

KP 写了 `commonAction: jump`（目标长桌）、`directSuccess`。脚本让行动者先"走到长桌旁"，路线规划选了离西门最近的长桌西端 (-270,0)；从那里起跳的方向沿着 480 寸长的桌面，超出力量 16 的助跑最远 192 寸，Rules 以 `worldLawViolation` / `jump:beyond-reach` 拒绝。这类拒绝不会作为修订单回给 KP，玩家只看到"这次操作未能完成"。用初始状态离线复算确认了这条路径。

修复 `53d0a4a1`：Rules 新增 `planJumpTakeoff`，在要素周围的可站处里找能跳成的起跳点（先判跳跃，再按距离由近到远找第一个走得到的，本局状态上 24 毫秒）；KP 降级让行动者走到该点；一个可行起跳点都没有时，KP 收到可修订的 `commonAction:jump-impossible` 和原因，可以判做不到。

### 163-2：同一跳写了三次

| --- | --- | --- | --- |
| 1 | 选择 | 21,549（384）/ 88 | worldInteraction、observe |
| 2 | 填写 | 31,806（15,744）/ 3,229 | 运动 DC 10；check 里一步 jump，steps 里又各写一步 jump，分别绑 onSuccess 与 onFailure |
| 3 | 旁白 | 3,368（896）/ 50 | "你退后几步助跑，从拼起的长桌上一跃而过，落到桌子另一边。" |

掷骰 15，成功。check 那一步走到 (-270,60) 跳到 (-150,-60)；随后绑 onSuccess 的那一步又走回 (-270,60) 再跳一次，于是有两次 `CharacterJumped`，判定要求一次。round162-1 的扛人也重复写过一次，那次因为不是对抗所判的步骤被挡下。

修复 `39c34bfa`：同一次行动里，同一个常用动作（种类、目标、目的地、选项都相同）写在两个世界互动步骤上时，后一个返回可修订的 `commonAction:repeated`。

## 看到的

- **两个动作都在世界状态里发生了。** 跳跃移动了行动者并可重放；躲藏让三个 NPC 失去行动者的位置，旁白与状态一致。
- **KP 常把常用动作写两遍。** 自 ADR 0092 以来四次用到脚本的真实调用里有三次（162-1、163-2、163-4）。诊断能挡下，但每次多一轮修订；指引 v81 的那句是否减少重复，需要下一批验证。
- **Rules 的世界规律拒绝不会回给 KP。** 163-1 那样的拒绝让玩家看到无原因的失败。跳跃改为在降级时判断；其他会被 `worldLawViolation` 拒绝的效果仍是这样，没有在本轮处理。

## 没有覆盖的

- 预定骰面之外的随机结果（跳跃检定失败、隐匿结果低于 DC）。
- 躲藏之后的结束条件（移动后重算 DC、攻击、出声、NPC 察觉检定搜到）的真实调用。
- 推撞、开关门、趴下与起身、扛到后放下的真实调用。
- 指引 v81 与省略字段解码的效果。
