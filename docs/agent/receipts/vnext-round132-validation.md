### round132 第 2 句为什么没等到

莉安答应去叫瓦罗后，房间定时器在回复后 68 毫秒尝试这项 NPC 任务。定时器不带请求通道，任务返回 `ACTOR_PLAN_DECISION_TRANSPORT_REQUIRED`，被留在 `prepared`、不再排时间，按现有设计等玩家下一个请求带着通道来执行。`7abddcc` 把这个「停着等请求」的状态也当成进行中，于是等满 180 秒。`56a2f98` 改为只看定时器上有没有排着的到期任务。

## 结论

- 问题一（探针）：已修好，round133 第 1 句走到了 round127 那种情况并通过。
- 问题二：补选后的大请求不再被上限挡住（60,313 放行）。但 v54 的补选说明没有拦住多余的补选：唯一一次补选仍加了用不上的表单和两个旁观者的视图。「其反应影响裁决时才加载」对隐蔽动作有歧义：旁人是否察觉本身就影响裁决。这次失败的直接原因是模型输出了重复的 JSON 键，与上限无关。
