# round156：失败后只说"再试一次"，KP 问了一次

2026-10-02。`tools/run-story-room-probe.mjs --live --case retry-refusal`，一个新房间，真实 HTTP 路径，DeepSeek `deepseek-flash`。用户要求"先做第1项，再跑一次"：只跑这一个用例，上限 16 次物理调用；首个产品失败即停，不重采样，不部署、不 push。实际 8 次调用，按高峰标价约 ¥0.24。在 `kp-battle` 工作树运行，源码等于 cloudflare `d95865e` 加探针提交 `eef9259`，运行前后源码清单一致。没有远端 migration、Secrets 修改或部署。

承接 [round155](vnext-round155-validation.md)：那一批的炉台检定都碰巧成功，没有走到提问。

## 这批验证什么

[ADR 0081](../../adr/0081-ask-once-after-a-failed-conversation.md) 与 [ADR 0083](../../adr/0083-record-check-and-refusal-precedents.md) 中提问的那一段：失败的检定记为先例；玩家只说"再试一次"时 KP 问一次；回答后同一行动接着裁决。

用例改为（`eef9259`）：第一步徒手把整座石砌炉台拔起来、举过头顶；之后两次再争取，只在没有问题等待时发出；最后一步只在有问题等待时，回答一个新办法。运行前做了 `--preflight`，0 次模型调用，通过。

## 看到的

**KP 提问了。** 第二步的选择请求同时提供了选择工具和提问工具；最近一次裁决是第一步的失败检定（先例 `precedent:92a4…`）。KP 调用提问，引用了这条先例，问题是：

> 上次你已经扣住砖沿、沉腰往上提，炉台纹丝没动，砖缝硬得像一体。这回你说「再试一次」，跟上次比有什么不一样——是换个抓法、换个用力的位置，还是先动哪里？先说清这一次的做法，我再接着往下判。

问题复述了上次的结果，问这次有什么不同，给了几个方向，没有替玩家决定。这一步没有提交事件，探针确认重复提交返回同样的等待、没有新调用。

**回答接上了同一行动。** 回答保存在提问的那条准备记录里，同一行动从选择重新开始，任务消息带上了问题和回答。续跑的选择命中缓存 18,560 / 19,116：它的系统消息和提问那一轮相同，与 ADR 0081 的设计一致。

**续跑的填写失败了。** 回答里的新办法（用火钳撬灰浆）让选择一次加载了 6 种类型（物化物品、创作物品、库存操作、世界交互、补全对象、观察）。填写时模型补选了已加载的 materializeItem；按 [ADR 0065](../../adr/0065-a-selection-repeated-without-addition-refills-the-form-instead-of-ending-the-action.md) 服务器不带选择工具重发表单，模型只返回 `{"decide": ""}`（36 个输出 token）。诊断是 `arguments.decision` 缺失、`arguments` 无效、没有可修订的草稿，行动以 `PROPOSAL_REPAIR_EXHAUSTED` 结束。这与提问和回答的机制无关，是大表单下模型没有给出裁决。该行动没有形成裁决，按 ADR 0083 不算用掉这次追问。

**第一步不该给 DC。** 指引写"不可能则说明真实前提，不伪造DC"。KP 给了 DC 27（超过角色能骰到的上限），成功分支写着"不可能发生的成功也被列出以防万一"。按规则这一步应判做不到（inWorldRefusal），而不是给一个骰不到的 DC。

## 结论

- KP 在玩家只说"再试一次"时提问了一次，问题内容合适。
- 提问挂在原行动上等待、回答后同一行动续跑，这两点在真实调用里成立，缓存命中也符合设计。
- 回答之后的裁决没有完成：续跑的填写在 6 种类型的大表单上失败。所以"回答之后重新裁决"在真实调用里仍未验证。

## 没有覆盖的

- 回答之后的裁决（有理由的回答、不补充的回答）。
- 回答后的裁决是定案、不再被问。服务器保证，Room 测试已覆盖。
- 交谈失败后的再争取（round155-3 停在 NPC 作答）。
- 说出理由或愿意再付代价时不问。
