# NPC 整组回答审核与经历接入：A 段回执

- 日期：2026-09-30。
- 授权：用户明确回复“方案通过，去做”，按[方案](../proposals/npc-introduced-content-proposal.md)推荐顺序先实施 A 段；规则与理由见 [当时编号 ADR 0075 的决定](../../adr/0076-review-npc-replies-and-admit-experiences-with-knowledge.md)。

- 本回执为本次持久化表约束升级、恢复与验收的操作审计。外部模型调用 **0 次**；全部 Provider 回应为受控脚本。

## 实现结果

每组交谈回答增加 `review_npc_replies` 审核；即使 NPC 的 `introducedContent` 为空，也不能跳过。退回只携带本人可见的字段、受限理由与本人记录，秘密与审核自由文本不传给 NPC。语义退回与原有结构/Rules 拒绝共用每份回答一次修改资格，修改后至多复核一次。

批准的已有对象经历沿正常 `worldFact` 与 `initialKnowledge` 接入。说法、听众知识与本人私有来源仍分开，谎言不会生成所声称的真相；共同过去不随成功/失败分支改变。新增候选、原裁决、本人响应和审核均绑定到最终提交，篡改审核后的事实不能提交。

审核和本人作答使用同一 proposal 调用账本、来源/房间预算与显式未知调用恢复。重复请求不重采样，已用过本人作答替补时，审核未知不能再申请第二次替补。普通非交谈行动沿用原有 Rules 修订路径。

- 新建 `authority_vnext_stage_proofs` 与 `authority_vnext_superseded_stage_proofs` 使用序号范围 1–146。
- 保留原 1–6 到 1–138 的历史构造迁移；另增一次 1–138 到 1–146 的同步事务重建，逐列复制全部记录，再移除临时表。
- 1–6 旧结构与 1–138 旧结构分别测试。后者保存原三个调用证明，旧表拒绝序号 139；驱逐重建后原记录完整，新行动能在 139 写入并读回审核证明。
- 实际审核证明随既有归档导出/恢复；原未知调用、替补及用量来源沿同一账本保留。
- 未创建远端资源、修改 Secrets、退役房间或改写已发布 migration。

## 请求体积

离线使用仓库 `conservative-v1` 计数器，单 NPC authored-probe 合成上下文：本人作答约 **6,607** 输入 token，新增整组审核约 **7,452**。本人指令从 1,156 增至 1,275，增加 **119**；该差值只计算指令，不包含新增表单。普通 Proposal 的 22 项固定请求体积全部与基线持平。

这些数字不是完整黑橡房间的实测 usage，也不代表价格、延迟或缓存命中。真实房间的主持人材料会更大；本次没有花费真实模型额度。首次通过通常增加一次审核；修改、裁决换稿与显式替补按合同分别计入同一总预算。
