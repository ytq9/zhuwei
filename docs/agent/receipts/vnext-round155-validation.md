# round155：失败或被拒后再争取，KP 是否问一次

2026-10-02。`tools/run-story-room-probe.mjs --live`，每次运行一个新房间，真实 HTTP 路径，DeepSeek `deepseek-flash`（[ADR 0080](../../adr/0080-deepseek-is-sent-the-current-model-name.md)）。用户要求"跑一批真实测试验证一下"；我设的上限是合计 32 次物理调用、¥3，首个产品失败即停，不重采样，不部署、不 push。实际 23 次调用，按高峰标价约 ¥0.87。在 `kp-battle` 工作树运行，源码等于 cloudflare `9c4472e` 加两次探针提交（155-1 在 `7624778`，155-2、155-3 在 `4b65a37`），每次运行前后源码清单一致。没有远端 migration、Secrets 修改或部署。

## 这批验证什么

[ADR 0081](../../adr/0081-ask-once-after-a-failed-conversation.md) 与 [ADR 0083](../../adr/0083-record-check-and-refusal-precedents.md)：交谈以外的检定和"做不到"记为先例；行动者最近一次失败或被拒的裁决可以被问一次；回答后同一行动接着裁决。此前只有本地测试。

探针新加两个用例（`7624778`）：`retry-refusal`（对石砌炉台动手，再说"我再试一次。"，再回答一个新办法）和 `retry-conversation`（劝莉安交出酒窖铁钥，再说"我再试一次。"，再选择不补充）。KP 提问的那一步允许以待决问题结束；回答步骤在没有等待中的问题时记为跳过。每次运行前做了 `--preflight`，0 次模型调用，通过。

## 看到的

**先例在真实运行里记录了。** 155-1 记了两条：推炉台的运动检定 DC 20 成功、再推一次的力量检定 DC 20 失败，目标都是炉台和守灵厅，耗时 5 分钟。155-2 记了一条（运动 DC 18 成功）；第二步是直接成功，不记录。

**KP 看到了先例，并沿用了 DC。** 155-1 第二步的选择请求里有第一步先例的精简形式（意图、做法、目标、公开说明、属性/技能/DC/结果），KP 对同一个推炉台的动作仍定 DC 20。

**提问工具按规则没有出现。** 两次炉台运行的第二步，行动者最近一次裁决都是成功，选择请求里只有选择工具，没有提问工具。

**提问本身没有走到。** 155-1 第一步 DC 20、155-2 第一步 DC 18 的检定都成功了（运动 +5，成功率约 30% 和 40%）。KP 没有把"砸碎炉台"判成做不到，而是改成成功只能"砸出凹痕"的检定。所以 KP 提问、玩家回答、回答后的裁决，这一整段在真实调用里还没有验证。

**155-3 停在 NPC 作答。** KP 判了说服检定 DC 13，成功分支写"她愿意就铁钥和酒窖的事继续谈下去"。莉安本人的作答调用在成功、失败两个分支写了同一句："你先把你叫什么、来守灵还是办事告诉我。酒窖的事今晚先不提。"她的记忆里铁钥本来就不在她手上，也不会交给没报姓名的外乡人。审核指出成功分支的回答和成功后果冲突，退回；重答还是同一句，第二次审核又退回，行动未提交。这是裁决的成功分支与 NPC 本人立场的冲突，发生在任何失败之前，与 ADR 0081/0083 无关（第一步没有可问的裁决，也没有提问工具）。

**审核没有命中填写调用写入的缓存（推断）。** 155-3 的第一次审核输入 26,617、只命中 512 个 token；它的系统消息与刚发出的填写请求有 56,462 个字符相同（[ADR 0078](../../adr/0078-the-review-request-opens-like-its-filling-call.md) 的前缀对齐生效）。两者的区别是审核开启了思考（[ADR 0082](../../adr/0082-the-npc-reply-review-reasons-before-it-reports.md)），填写没有。第二次审核命中 25,728，命中的是第一次审核写入的前缀。由此推断 DeepSeek 不在开思考与不开思考的请求之间共用前缀缓存，ADR 0078 对每个行动第一次审核的节省因此没有实现。只有这一个样本。

## 没有覆盖的

- KP 在玩家只说"再试一次"时是否提问、提问的写法、回答（有理由或不补充）后的裁决。
- 交谈失败后的再争取（155-3 停在第一步）。
- 玩家说出理由或愿意再付代价时不问，直接重新裁决。
- 不同角色对同一目标是否沿用先例。

## 下一步可选

1. 要稳定走到提问，第一步需要一个不可能成功的裁决：KP 判做不到，或 DC 高于角色能骰到的最大值。可以换一个更难、更明确的目标，或换一个相关属性很低的角色；或者在同一次运行里重复争取，直到出现失败（每多一次约 4 次调用）。
2. 155-3 的冲突（裁决的成功分支与 NPC 本人立场不符）需要单独处理，否则交谈检定的再争取在这类请求上走不到第二步。
3. 审核开思考与缓存的关系，需要再一个样本确认。
