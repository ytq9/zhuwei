# round120–121：检定步骤单独成组后的两批，以及一个检定失败时的结算错误

2026-09-24。两批都是用例 `daily-hidden-act`，调用上限 10，真实 HTTP 路径，`deepseek-v4-flash`。未部署、未 push、未做远端 migration、未改 Secrets。承接 [round119](./vnext-round119-validation.md)。工作区里另有一个会话未提交的改动（`openai.ts`、`runtime-policy.ts` 与两个测试，只涉及 GPT-6 Luna 的传输方言），不经过本用例的 DeepSeek 路径。

## 背景

用户在“骰后再写实际那一边”和“改表单结构”之间选了后者，并要求成功和失败对模型的比重一样。`8d815a2`（[ADR 0041](../../adr/0041-the-check-step-gets-its-own-group.md)）把检定决定的那一步放进单独的 `check` 组，`success` 与 `failure` 同一个表单、都必填、都没有单独说明；其他步骤写在 `steps` 里，各一个 `result`。

## round120（源码 `8d815a2`）

2 次调用，72,678 输入 / 1,503 输出 token，失败。

- 首稿结构正确，没有修订：检定步骤是对黑橡叶的 `worldInteraction`，成功与失败都写全；取物绑 `onSuccess`；交谈在 `steps` 里绑 `always`，只有一个结果。
- 掷出 3（+2 对 DC 14），失败。提交时 Rules 拒绝，`invalidRulesInput`，玩家看到“参数未通过规则检查”。

**定位。** 复制一份探针，把真实请求换成按顺序返回本批保存的两次回复，房间 ID 按请求上下文替换，不调用网络。重放在失败骰上同样被拒，在成功骰上能走过 Rules。临时记录 Rules 兜底吞掉的错误，得到 `social:accepted-cost-prefix-not-proven`。改保存的回复做变体：去掉绑成功的取物后失败骰通过；去掉检定步骤的感官证据或交谈对象的 `npcPerceives` 仍被拒。

**原因。** 执行时交谈只有一个结果，按 success 结算，绑成功的取物因检定失败被跳过。回放核对交谈之前的步骤时，用的是交谈事件自己的分支（success），于是去找那次取物，找不到就拒绝。执行端核对时用的是检定的实际结果。`e711345` 让回放端也用检定结果：交谈是检定步骤时就是它自己的分支，否则从挂起记录或已提交骰面算出，算法与执行端共用 `worldInteractionRollOutcome`。Rules 测试覆盖失败与成功两种骰点和回放；用本批原样回复离线重放，失败骰（11）走过了 Rules。

**另一处。** 这份草稿的交谈绑 `always`，检定失败时莉安照常回答，和草稿自己写的失败后果（莉安当场质问）矛盾。只有检定步骤随骰子变化，所以莉安的反应要变，交谈就得是检定步骤。`a3dd575` 在交谈指引里写明这条结构规则（不涉及台词写法）。
