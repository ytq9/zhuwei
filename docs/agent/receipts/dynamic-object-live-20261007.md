预置条件明确不算真实模型成功：原生 Rules 与事件折叠建立“本人看过三块布条，另一角色拿走一块，本人现在持有关闭木盒”的前史。实际布条数为 **2**，本人上次查看数为 **3**。两个样本使用同一句玩家输入：

> 我打开随身木盒，从里面取出一块干净布条，然后把盒盖合上。

首批预登记还有放回及重新打开两步；第一步失败后未执行。唯一对照使用仅包含原第一步的 `dynamic-container-atomic`，不自动推进后续行动。运行前另做零模型 preflight；两个付费样本的首尾源码 manifest 均一致。

## 本地修复与影响

按 [SPEC 0001 §16](../../specs/0001-llm-kp-responsibility-contract.md) 与 [SPEC 0016 §7.3](../../specs/0016-part-c-compound-actions-and-claims.md) 修复库存规划接缝：新增专用 `proposalInventoryEntryRefs`，只从获授权的冻结原实物及可见父容器导出候选，支持自己持有的容器和当前场景容器。不能从历史清单重建条目，不提供他人的私人包、隐藏策略内容、未打开的内层容器或缺少授权/实物记录的引用。

首填、修订、Room 精确请求证明，以及 NPC 自身执行提案共享该候选。观察、本人作答和社交承诺继续沿当前可见候选；执行仍需真实打开前缀，原权限、读集及库存校验未放宽。公共读取面仅导出已有物品策略判定，未新增另一条状态写入路径。

对于本人确实看过、仍有真实记录的关闭内容，诊断明确要求先打开，保留原库存行。对照以后又将预期操作结构化为 `worldInteraction / operateObject / open`，保证修订工单保留类型信息；**这项最后调整只做了本地验证，没有第三次付费采样**。parser 更新为 `v85`，展示上下文更新为 `vnext-15`；固定提示词仍为 `v103`，没有增加调用阶段、修订次数或固定提示词文本。
