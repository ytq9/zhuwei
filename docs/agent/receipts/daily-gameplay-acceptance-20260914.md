### 初次施法失败属于验收脚本问题

首次施法实际已生成合法待掷骰，耗用 2 次调用。公共 HTTP 响应是 `action: awaitingInput`，内部结果为 `outcome.kind: awaitingPlayerRoll`；脚本误把内部枚举当作公共 `action`，因此提前停止。修正脚本后，唯一一次付费对照使用相同角色条件、玩家原话、模型和生产源码，按公开 `resolveRoll` 完成。首次失败记录仍保留，费用仍计入总额，没有把它改记为通过。

### 药水上下文缺口

初始夹具通过真实 `initializeAuthoritative` 加入公开、无主、位于 `wake` 的 SRD 治疗药水，角色初始 HP 为 1。没有注入取得、治疗、骰面或任何行动结果。

读取冻结初态后，以相同意图调用现有上下文准备函数，得到 `criticalUnavailable`：

```text
entry:ability:item:potion-of-healing:drink:entry:item-entry:daily:healing-potion:notLoaded
entry:ability:item:potion-of-healing:drink:notLoaded
```

这将范围缩小到初始可用物品的能力注册/上下文装载边界。离线诊断使用重建的最小 KP 投影，属于辅助证据；真实 HTTP 失败和未提交状态另行保存。尚未修改初始化或读取规则，也未用手工补入能力的成功样例掩盖该缺口。

### 交谈、旁白与恢复的覆盖边界

本批没有新增普通交谈的付费样例。受控 `social-plan` 与社交 Room 恢复通过；同日先前的[旁白修复与真实恢复回执](narration-strict-generation-20260914.md)另有普通 NPC 回应、冻结正文恢复和重复零结算证据。该历史样例仍有语病，不能当作完整社交质量通过。

本次调查旁白能够区分可见断口特征和对断裂时间的推断，并明确单凭观察不能确定时间或成因。施法旁白的资源数字准确，但“完成结算”仍不符合自然叙述要求。技术断言通过与旁白质量分别判定。
