# 交谈旁白中的检定播报排查与修复

2026-09-13；在用户已授权的 3000 预览工作树处理。用户指出：“这次交谈已经完成，交涉检定成功（总值13，难度11）”也不应进入旁白。

## 根因与修改

8D9B5M 的私有捕获 143 是原旁白，144 是原审核。原生成请求把“这次交谈已完成”“交谈检定成功”“检定总值为 13”“难度为 11”列为 `required: true` 的四条事实；原审核把对应 `m3` 组判为 `complete`。这证明播报直接来自程序的必说材料与审核义务，不只是模型偶然添加。

已有 `isSettlementOnly` 只排除没有检定的成功结算，带检定的交谈与观察被保留为正文义务。依据 [SPEC 0016 §8.3](../../specs/0016-part-c-compound-actions-and-claims.md)，在已有具体回应或感官结果时，将交谈、观察的能力检定结算归入记录性材料：不进入 required facts 或机械结果审核组，传给旁白的对应 payload 不再携带总结句和 check 统计。完整 FrozenRenderableClaims、骰点、DC、事件、回执均未修改；这里只改变模型输入的表达选择。

生成和审核共用 `policy:check-presentation`，要求用实际回应和后果表现成功或失败，禁止追加检定播报及同义套话。旁白 policy v15；没有按玩家原句做字符串删除，也没有修改生成后的正文。没有具体结果的孤立结算仍保留现有处理；世界互动失败、攻击、伤害与资源结果不因其他内容存在就被省略。
