# 旁白写作时思考：存档请求的对比实验

2026-10-05（北京时间约 15:33–15:38）。用户提出："旁白与其审核加思考，不如在写的时候就进行思考"，并选择先试"写时思考、暂时保留审核"，用一批真实调用对比后再定。

## 做法

- **样本。** 当天各批真实探针存档里，凡能和自己的首次审核配对的写作请求都取了，共 46 份，多数是战斗回合、移动、躲藏、攀爬、去别处的旁白。
- **A 组（现状）。** 用存档里的稿子：DeepSeek `deepseek-flash`，写作时不思考。
- **B 组（候选）。** 同一份材料重新写一稿，有两处不同：
  - 打开低强度思考（`thinking: enabled`，`reasoning_effort: low`）；
  - 写作说明末尾加一句自查："动笔前先在思考里对照冻结资料核对：facts都写到，没有资料外的新事实、台词或动作，来源和把握不加强，不泄露观察者无权知道的，不替玩家决定，观察者没有认错。"
- **审核。** 两组稿子都交给现行审核（低强度思考），各审一次，审核请求与存档完全相同，只换 `candidateBody`。
- **规模与花费。** 共 138 次调用。国庆法定假日按空闲价，约 ¥0.56；按高峰价约 ¥1.12。
- **执行方式。** 用临时脚本直接调用 DeepSeek，复用仓库的 `deepSeekTransportBody`；没有改动仓库代码，没有部署。

## 结果

| | A：不思考 | B：写时思考 |
| --- | --- | --- |
| 审核通过 | 43 | 43 |
| 审核退回 | 2 | 3 |
| 审核回复读不成 | 1 | 0 |
| 写作耗时中位 / 平均 | 约 0.9 秒（存档） | 3.4 / 4.4 秒 |
| 写作输出 token（其中思考） | 约 75 | 734（656） |
| 写作每次花费（空闲价） | 约 ¥0.0016 | ¥0.0044 |
| 正文长度中位 | 108 字 | 114 字 |

两组都通过的有 40 份；A 退回、B 通过 2 份；A 审核读不成、B 通过 1 份；A 通过、B 退回 3 份。

### 被退回的稿子

- **B 改好了 A 的两处编造。** 两处都是只有"轮到某人行动"的旁白：
  - A 写了"奈斯仍站在守灵夜那边，没有开口"；
  - A 给奈斯编了一整段台词。

  B 只写轮到谁行动。
- **B 新出了三处错。**
  - 躲藏后多写"暂时没有谁注意到你"，断言了察觉结果；
  - 写"门一关上"，与"后门敞开着"冲突；
  - 把"轮到原团旅人行动"写成"轮到奈斯行动"，改了结果的主体。

  三处都被审核拦下。

## 结论

- 写时思考没有降低审核退回的比例，每段旁白多用约 2.5 秒、约 ¥0.003。
- 它能少编一些，但会出别的错，其中包括主体写错这种实质错误。
- 去掉独立审核、只靠写时思考，这 46 段里会有 3 段错误的旁白发布。

因此没有采用。写作仍不思考，审核照旧（ADR 0069），代码不变。候选改动的补丁只保存在当次会话的临时目录。

## 局限

- 样本偏向战斗与移动的短旁白；带 NPC 台词的交谈旁白很少。
- A 组稿子来自当天较早的运行，部分材料是 ADR 0108 之前的形状。两组用的是同一份材料，可以比较，但不代表修复后的材料。
- 每份稿子只写一次、审一次，抽样波动没有消除。
