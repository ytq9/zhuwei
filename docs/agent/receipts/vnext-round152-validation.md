2026-09-29。`tools/run-story-room-probe.mjs --live`，每次运行一个新房间，真实 HTTP 路径，`deepseek-v4-flash`。用户授权上限 20 次物理调用、¥5，首个技术失败即停，不重采样，不部署、不 push。实际 14 次，没有技术失败。在主工作区运行，HEAD `e14f67c`；另一个会话未提交的 OpenAI 提供方改动不在 DeepSeek 路径上。没有远端 migration、Secrets 修改或部署。

## 这批验证什么

[ADR 0072](../../adr/0072-narration-says-what-is-not-known-when-the-material-holds-no-answer.md) 的规则，以及 [ADR 0070](../../adr/0070-a-refusing-review-writes-the-corrected-body-which-is-reviewed-once.md)、[ADR 0071](../../adr/0071-the-second-review-may-correct-once-more-before-a-final-review.md) 的改稿流程在真实 HTTP 路径上的表现。策略 `zhuwei.text-narration/v6`。

[round151](vnext-round151-validation.md) 用的是 9DCMQN 的“什么纸”，那一轮带着更早的错误。用户要求换别的问题。三个问题都在新房间里提出，角色只持有开场知识。玩家原话用 `--action` 传入。

两次打回的理由：

- 152-1：初稿在“这些是你亲眼见到的”之前同时列了守灵介绍里的说法和遗体的样子，把听来的说法当成了亲眼所见。改稿把两类分开写。初稿里还有一个英文词 `introductions`，改稿换成了“那份介绍”。
- 152-3：莉安的原话是“你要找，去问他平时一个人待的地方”，初稿写成“她要找的话”，受话人错了。改稿改回“你要找的话”。

两条发布的正文都与审核报告里的 `body` 逐字相同。

## 结论

- 三个问题里，旁白都没有编造答案。152-1 和 152-2 明确写了角色还不知道什么。
- “审核打回、改稿、复审通过、发布改好的正文”在真实 HTTP 路径上走通了两次，每次五次调用里有三次属于旁白。
- 152-3 里莉安的台词指向了神龛：“神龛那边他常去，可我没跟进去过”。这一轮送给提案模型的冻结上下文里，莉安自己的知识只有铜钥、门外的声音和“父亲说过有第三份遗嘱”三件事，没有神龛；“神龛”只出现在剧本的核心真相、第三份遗嘱的物品定义、神龛场景和回声 NPC 这些 KP 才有的材料里。第三份遗嘱按剧本正藏在神龛的石座里。这句台词在提案阶段生成，随后成为冻结材料，旁白忠实转述，审核无从发现。
