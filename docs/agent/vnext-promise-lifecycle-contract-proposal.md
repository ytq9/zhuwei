## 1. 目标、范围与依据

能力合同：玩家或 NPC 向明确对象作出的承诺，在实际条件、约定时限和虚构事件下持续有效；KP 依据具体情境判断是否履约、违约以及延期、修改、取消如何影响承诺，不设置统一的同意流程、宽限期或变更次数。玩家保留自身决定权，NPC 依据自身知识行动；义务、变更、原因和履约历史由 Room 权威保存，观察者只获知其实际有权知道的部分，跨场景、章节和恢复保持连续。

本次并行产出可以完成到：产品规则、争议裁定记录、代表性验收矩阵、主任务完成后的实施交接。当前不编写运行时代码、测试或 schema，也不冻结具体枚举、接口、调用次数与存储结构。

## 2. 承诺到底是什么

**承诺（Promise）**是某主体对受诺者承担的未来行为、结果或持续约束。它区别于 KP 对环境描写的“叙述承诺”，也区别于 NPC 准备如何行动的“计划”。

成立时应保留原表达，并明确本次会影响判断的条款：谁向谁承担、要做到什么、触发条件、交付对象或地点、时限或持续范围。时限和条件可以没有，但不能在将来判违约时临时补一个。

1. “我一定把信送到”和“我会试着送信”承担的内容不同。对后一项，真实且符合原约的尝试可能完成义务；不能把结果承诺事后降为尝试承诺，也不能把礼貌表达升级为保证结果。
2. 预测、愿望、转述不自动成立承诺。“他应该会来”是判断；“他说会来”是来源主张；它们不能直接替第三人建立义务。
3. 谎称愿意履行仍可能形成已作出的承诺；记录承诺不证明其内心诚实，也不保证其有能力成功。不允许因此强制另一个玩家、NPC 或势力照办。
4. 玩家承诺及其变更必须来自玩家本人的明确意图或已有合法授权。接受 NPC 的有条件承诺，不自动使玩家承担付款、同行或其他对价义务。
5. 条款由 KP 结合原表达和情境理解，不要求玩家填写合同。玩家真实意图存在涉及重大成本、风险或不可逆结果的多种解释时，按主 PRD 澄清；不能为普通承诺额外增加逐项确认流程。

已有“哪些约定进入机械”的裁定继续适用。Promise 是否需要自动派生计划，与它是否存在义务分别判断；`due: none` 不能被拿来证明“没有义务”或“可以随意反悔”。保密承诺可能没有定时动作，却持续约束后续行为。

## 3. 履约：原约实际完成

履约依据是**KP 结合原约与情境，判定承诺要求的行为、结果和约束已经真实满足**。计划执行、活动结束、留下痕迹、NPC 声称完成或玩家收到通知，单独都不等于履约。下列例子用于区分事实与条款的关系；是否接受替代履行、怎样理解足够完成，仍由 KP 裁定并保留理由。

- 承诺“把副本放到账台”：副本真实存在并按约放置，可以完成交付；不要求玩家已经看见。
- 承诺“把副本交到你手里”：只放到账台不够；需要真实交付，除非此前有效改约。
- 承诺“抄完整副本且原件不离手”：数量、完整性和原件约束同样要满足；仅证明“抄了一页”或“开始抄写”不够。
- 承诺“今晚替你保密”：持续期间没有违背仍是义务存续；约定期间正常结束后才能完成。无终点的持续义务不会因某一次守约就永久完成。
- 分阶段义务可保存已完成部分；只有全部仍有效的必需部分完成，才算整体完成。尚可在原时限内补齐的不足，先记录部分进展，不提前判整个承诺违约。

是否必须由受诺者验收，以成立时的条款为准。客观交付不默认要求点击确认；约定需要验收的义务，也不能绕过验收。

KP 判断自然语言条款与真实事实之间的语义关系，必须说明对应依据。Rules 验证权限、条款版本、引用、时限、实际机械结果与合法转换，Room 原子保存；不能把模型一句“已完成”当成机械证明，也不宣称程序能形式化证明任意自然语言。需要交付物品、开门、移动或消耗资源时，必须有相应权威效果，不能用预写痕迹替代。

## 4. 违约：没按生效条款做到，另记原因

本节的“结果与责任分离”已获用户裁定。KP 判断原约是否仍然有效、条件是否触发、是否已有有效变更，再对实际履行结果作裁定；不能仅按时钟或计划枚举自动贴违约标签。

1. 条件已满足、履行窗口已结束，承诺仍然有效且没有适用变更，实际未按约完成，记违约。
2. 违反持续约束或造成原约已无法挽回的失败，可以在截止前构成违约，例如已泄露应保守的秘密。
3. 承诺者明确拒绝履行时，KP 结合原约与情境判断是有效取消、改变剩余义务，还是提前违约；单纯犹豫、内心想反悔或取消一条内部计划不自动得出其中任何一个结论。
4. 没有明确截止点，不能因“等得够久”或现实时间过去而自动判逾期。对明确拒绝、持续约束被破坏等已有事实仍可判断。
5. 送信途中被截住、主动作假或忘记履行，都可能产生未按约完成的事实；分别记录实际原因。受诺者知不知道、是否谅解，与违约是否已发生分开。
6. 模型失败、网络失败、证据未加载、排程工作尚未恢复，不等于世界内违约。决定性依据不足时保留待裁定与恢复，不擅自认定成功或失败；不能为了结清状态而捏造截止前没有完成，或把技术原因写成 NPC 的失信。

时间判断使用相应虚构时间与真实因果顺序。先结清在截止点合法发生的履行动作，再判断是否错过窗口；不能因为调度器稍后处理就把按时履行算成迟到，也不能把实际迟到的行为回写到截止前。边界是否包含截止瞬间应符合原约语义，跨时间线不能用另一角色的未来时刻提前裁决。

“没有完成”的判断需要覆盖对应对象、地点和时段的权威依据；查询零命中、受诺者没看见或 NPC 没回复，都不足以证明全世界没有发生履行。

## 5. 当前义务与履约历史分开

产品必须同时回答两个问题：**现在还需要做什么；以前有没有按约做到。** 不要求在本次决定用几个字段实现。

| 当前事实 | 正确表达 |
| --- | --- |
| 条件尚未触发 | 承诺仍在，等待条件；尚不构成逾期 |
| 条件已满足，仍可按约完成 | 仍需履行；可以有部分进展 |
| 按全部有效条款完成 | 已履约 |
| 已错过时限，但交付仍有意义且义务未解除 | 已违约，仍需履行剩余义务 |
| 迟到后真实补齐 | 已补履行，保留此前违约与实际补交时间 |
| 有权主体免除剩余义务 | 已解除相应义务，保留解除前的全部历史 |
| 触发窗口关闭，约定条件始终未成就 | 因条件未成就而结束；不冒充履约、违约或主动免除 |

补交、赔礼、后来原谅或重新约定，都不能抹成“从未违约”。另一方面，一次违约也不自动消灭全部剩余义务，更不能无依据生成罚金、债务、强制敌对或全局声誉扣分。

持续性或复合承诺按实际条款处理剩余范围。例如一部分秘密已泄露，已经发生的泄密无法撤回；其他仍可保守的内容不会因此自动解禁。

## 6. 延期、修改与取消由 KP 裁定

**用户已裁定不设置统一硬规则。** 不要求所有变更都双方同意，不设置固定宽限期、最多延期几次、单方取消必然违约等通则。KP 按原话、关系、习惯、当前原因、实际交流与已经发生的行为，决定这次变更是否成立、何时生效、影响什么，以及是否同时留下违约或补救记录。

| 行为 | KP 需要裁定并保存的内容 |
| --- | --- |
| 承诺者说“再给我一小时”，对方尚未答复 | 这次是否足以形成延期，还是仍需后续交流；新的履行时间或仍适用的原期限；情境依据 |
| 截止前延期 | 生效时刻与新的预期；不因某套统一审批规则强制接受或拒绝 |
| 已失约后再延期 | 剩余义务如何继续，是否宽免或改变后果；此前实际失约保持 |
| 换路线、换信使或提供替代物 | 属于正常履行方法、可接受替代、实质改约，还是不足以履行；不能凭空生成交付事实 |
| 改数量、内容、对象或重要限制 | 什么被改变、什么仍需完成、为何成立；涉及玩家自身新选择时保留其决定权 |
| NPC 停止、推迟或重做内部计划 | 这只是执行手段变化，还是有新的承诺裁定；旧计划状态不能自动代替这项判断 |
| 承诺者单方说“不做了” | 按此次关系与情境裁定有效取消、剩余义务或违约，不采用统一结论 |
| 受诺者免除、双方取消、条件消失或客观无法完成 | 实际结束或保留的范围，是否已有违约、补救或新承诺；不自动结清其他债务 |

KP 的裁定不是 NPC 自报成功或任意覆写状态。变更须有具体因果依据，绑定原承诺并保留生效时刻、原条款和新结果。叙述可以自然表达，不要求玩家观看内部裁定表。

允许某次变更不需要双方同意，不等于允许 KP 编造玩家“已经答应”、替玩家作出新的承诺或未经意图直接支付对价。必要的玩家选择继续服从主 PRD；普通 NPC/world 裁定不为此强制增加玩家审批。

实际变更不能回写成从来没有许诺或从来没有失约。KP 可以裁定后续宽免、补救或取消成立；确实判错旧事实时按审计更正处理。客观受阻、死亡或物品毁坏都由 KP 依据原约及当前事实判断影响，不在系统中写死为自动违约或自动解除。

同一承诺的变更保持连续身份；若实质形成另一义务，须讲清旧义务怎样处理、新义务如何成立。不自动把承诺转给继任角色或旁人。解除不自动退钱、归还实物或结算债务；真实机械变化仍走对应规则。

## 7. 条件、知情者与后果

- “如果你今晚交介绍信，我明早开门”：触发条件从真实提交判断。窗口结束还没交介绍信，不是 NPC 违约；玩家仅接受这个条件，不等于承诺一定交信。
- 条件若明确要求 NPC 收到或知道某事，须有真实传递；纯客观条件与“承诺者知情”不能混为一谈。NPC 不知道条件已经满足时，世界仍按原条款记结果，但 NPC 决策不能凭全知自动反应。
- 受诺者免除、隐蔽履行或秘密违约的事实，不会自动通知全部参与者。NPC 未获消息仍可能按自己所知行动；状态、界面、错误、恢复与候选都不能泄漏隐藏原因或未来结果。
- 后续声誉、关系或 NPC 计划由其实际知识、性格、利益、原约和世界后果决定。善意受阻可以被谅解，背叛可以引发报复；不会为制造戏剧性统一奖惩，也不强制玩家角色产生特定情绪。
- 换场景、章节切换、角色离线与技术恢复不清除承诺；继任和转授按已有授权边界处理。系统误判使用可审计更正，NPC 后来改口或原谅不等于系统更正。

## 8. 代表性验收矩阵

这是后续行为验收要求，当前没有执行代码测试。全部样例应经过同一承诺规则与权威提交路径，不能按 NPC 名称、文书或保密字样硬编码。

| 编号 | 变化维度与场景 | 必须成立的结果 |
| --- | --- | --- |
| P01 | 承接现有样例：NPC 一小时内把完整副本放到账台，按时完成 | 核对真实物件、地点、数量及必要约束后履约；计划 resolved 和 trace 不单独算证据 |
| P02 | 同样一份副本，但原约改为交到玩家手里 | 放到账台只算进展；按真正条款裁决，不能复用 P01 的成功结论 |
| P03 | 结构不同：NPC 承诺今晚不泄露位置，无需到期执行动作 | 提前泄密构成违约；正常守密到期才完成；没有 timer 不代表无义务 |
| P04 | 条件承诺：收到介绍信才开门；窗口内始终没收到 | 尚未触发或条件未成就而结束；不提前开门、不判 NPC 逾期、不替玩家承担交信义务 |
| P05 | 承诺仍有效且没有适用变更时，送信被截；对照主动失信 | 未按约完成都记违约；原因不同；后果依知情者判断，无统一扣声誉 |
| P06 | 对方未答复的延期：KP 有依据接受；结构相同但情境不同，KP 有依据不接受 | 两种裁定均能沿通用路径成立，保存各自期限与原因；不强制双边批准，也不编造玩家同意 |
| P07 | 已经违约后 KP 裁定延期/宽免成立，随后真实补交 | 仍保留原先违约；按新裁定处理剩余义务和补履行，不洗掉历史 |
| P08 | KP 接受/不接受替代交付；对照只换执行方法 | 按原约、情境及真实事件核定；不把任意替代物当成功，也不把所有调整强制送审 |
| P09 | 取消内部计划、单方拒绝、受诺者免除、约定取消 | 各自接受 KP 有依据的影响裁定；不按 cancel 字样自动折成 broken 或 released |
| P10 | 部分交付及“尝试送信”承诺 | 部分完成不冒充全部；真实履行尝试义务不要求保证送达；标准不可事后改变 |
| P11 | 最高风险：NPC 在别处履行/违约，玩家睡眠中尚未获知 | 权威状态正确；无越权状态标签、通知或原因；合法传递后才可呈现并触发主任务通知机制 |
| P12 | 截止瞬间履行、跨时间线、处理中断后恢复 | 依真实时序裁决；不能技术延迟造违约、未来事实回填，或重复结算、奖惩与调用 |
| P13 | 履约或改约后跨章节、授权继任、已提交错误更正 | 保留当前义务与历史；不能让新角色自动继承，不能复活已解除的义务或静默覆写误判 |
