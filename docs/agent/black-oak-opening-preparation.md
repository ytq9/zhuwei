# 黑橡居酒屋：开场准备补充

日期：2026-09-09。适用当前《黑橡居酒屋的第三份遗嘱》，开发期完成，尚未部署。

通用流程与检查标准见 [剧本写作与开场准备指导](module-writing-guide.md)。本文记录当前剧本的材料和证据，字段值以链接的 JSON 为准。

## 目标与边界

为当前剧本预先准备关键实物、藏处、持有者、线索关联和角色有限知识。新房间通过同一个 Rules genesis 保存这些材料；玩家按实际开场地点与角色卡技能取得信息，NPC 只取得自己的经历和来源主张。实物后续转移、毁坏与发现继续使用原有物品事务，知识继续使用原有获取、分享、回顾和 Viewer 投影。

主 PRD 依据：[SPEC 0001](../specs/0001-llm-kp-responsibility-contract.md) §§3、8、9、14、16；模组依据：[SPEC 0006](../specs/0006-module-npc-and-faction-protocol.md) §§1–4。补充是开场定义目录，绑定现有精确 `moduleRef`，没有改写原故事圣经的核心真相、哈希或运行时 manifest，也没有登记第二个模组版本。

数据源：[black-oak-will-preparation.json](../../app/_runtime/lib/module/black-oak-will-preparation.json)。目录 ID 为 `definition-catalog:black-oak-will:opening-v1`，内容哈希由规范 JSON 计算并保存为 genesis 的 `initialDefinitionCatalogRef`。未来修改已使用的目录内容时应使用新的目录 ID，不能把新内容冒充旧引用。

10 件实物均使用原有 `ItemDefinitionV1`。其中 7 个实例进入开场物品状态，3 个隐藏实例在发现时通过现有 `materializeItem + uniquenessBasisRef` 生成。所有预留实例 ID 都使用原有唯一性算法从同一来源事实计算，因此初始实例与之后的发现使用同一身份，已存在实例不能沿该唯一性依据再生成。

实物定义只包含外观和可执行的已有物品字段；遗嘱真伪、全文、来源、藏处和相关线索放在权限为 Room/KP 的开场事实中。`openingPlacement` 记录开场位置，后续位置和持有人以实际 ItemEntry 为准。这里的实物库存不裁定房产继承权；文书在谁手中与其正文是否有效是两回事。

## 开场知识

JSON 新增 12 条知识准备：4 条玩家模板、8 条 NPC 补充，保留故事圣经已有的各人初始知识和未知边界。

- 在大厅开场的玩家获得亲自在场的经历，以及有来源、尚未核验的身份介绍。奈斯的血亲身份明确标为自称。
- 具备调查或历史技能的角色获得文书核验常识；具备宗教技能的角色获得声音、亡魂身份与教派证据的区分。技能依据来自服务端处理后的角色卡，不按姓名、职业称呼或临时声称猜背景。
- 其他地点开场的角色不会获得自己没有听见的大厅介绍，也不会收到大厅开场旁白。
- 莉安知道铜钥的交代、第三份遗嘱的口头消息和自己的听觉经历；没有读过第三份，也没有认定母亲回魂。
- 瓦罗知道自己的改写、封门、原件和铁钥保管情况；未查明死因，也没有读过第三份。
- 奈斯知道自己的伪造、真印和仪式经历；石座附近是他的猜测，精确夹层藏处仍未知。
- 回声保留旧誓、歌句与自己的感知范围，没有大厅争论和陌生来客姓名。

每条准备明确知识种类、接收条件、内容、来源引用和取得依据；实例化后使用现有可叙述的文字 KnowledgeRecord，来源引用和目录哈希保存在 provenanceChain。知道、相信、听到主张和读到文书不合并为一种世界真相。未建立的玩家亲属关系、委托、债务和个人经历继续由原有角色前提流程处理。

## 验收与直接消费者

| 代表性路径 | 证据 |
| --- | --- |
| NPC 持钥与场景浅夹层文书 | 同一目录、ItemDefinition、Rules genesis、Viewer 和 Room 库存路径 |
| 木盒中的隐藏日记 | 实际 Room prepare 能取回来源事实和预建定义；Rules 发现后生成一次，第二次拒绝，精确 replay 一致 |
| 两个同场角色技能不同、第三人异地 | 私人知识按地点和技能选择，NPC 造假细节不进入玩家投影 |
| 畸形目录与重复实物 | 重复 ID、错误模组哈希、不存在的持有者/线索/知识来源及重复 genesis 条目拒绝 |
| 开场确认与恢复 | ACK 不清空知识；DO 驱逐后原库存和知识恢复；重复初始化不再发放 |

直接消费者：`module/preparation.ts` 在开场校验和转换 JSON；`RoomDurableObject.initializeAuthoritative` 合并目录、权威事实和初始知识后调用 `Rules.step`；原有 `project`、知识回顾与 NPC 决策上下文读取持久状态。归档仍按现有格式复制完整 genesis 及其目录引用，不引入新 D1 schema。

实际定向检查与退出码记在 [执行日志](../refactor-log.md)。这些证据不等于真实模型已连续完成整部剧本，也不证明普通火把的全部照明能力、全场机关、继承争议和所有物品组合都已补齐。本次没有改写既有房间或开展线上测试、部署、push。

已有正文还存在一处独立时间线矛盾：莉安 28 岁、母亲死时她 8 岁，与“亡妻交易后封印三十年”无法同时成立。本补充没有新增具体年份或据此编造她的经历；调整这些已固定的圣经内容需要单独处理模组版本和现役房间边界。
