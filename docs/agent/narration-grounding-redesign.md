# Narration：事实校验、自然表达与人物一致性

日期：2026-09-05。用户要求：校验器允许忠实改写；面向玩家的 Narration 必须自然可读、符合人物性格。本切片已实现；**已完成一项正常 HTTP 真实库存操作及自然旁白发布，完整产品矩阵未完成**。实现与测试见 [round6](vnext-round6-validation.md)。依据 SPEC 0001 §§9、12、16、19 与 SPEC 0016 §8；不改 Rules、Room 或玩家意图权威。

## 能力合同

Narration 使用本次已提交结果及当前 Viewer 获授权、已冻结的表达材料，组织自然、明确、人物一致的玩家回应。允许同义改写、句式重组、恰当代词、信息排序和去重，以及不改变原意图或实际后果的普通动作表现；必要后果和来源归属不能丢失，不能新增世界事实、机械结果、NPC 决策或玩家思想/台词/下一步。失败恢复复用同一冻结材料，不重跑动作或资源结算。

本轮用户进一步明确：“俯身、轻轻放下”一类表现已提交动作、没有独立后果的细节可以接受，不要求每个动作修饰词出现在原子事实中。判断依据是是否追加独立行动、持续规则状态、机械优势或可供他人利用的新证据；不是某个词是否出现。轻轻放下不能被后续当作潜行成功或无人察觉。实现没有姿态白名单或对象名称分支；最终 Prompt 同步此边界，未为改写再次采样。

完整事实句是清楚的输入依据，不是要求玩家阅读的固定模板。当前逐句文字相等不能作为最终合格定义。提高字符串相似度阈值、堆同义词/对象名称正则，或让模型自行宣布有依据，都不能替代这个合同。

## 输入与单一事实源

1. 完整 FrozenRenderableClaims 保持原有 hash、Receipt、Viewer 与 conformance 绑定。模型侧派生材料包含真实作用者、对象、数量/资源/状态变化、成败、感官事实、来源主张与必要覆盖义务；事实已结构化的部分直接使用其类型，不反向分析摘要重建机械。
2. Viewer 与行动者关系由服务端冻结；只在关系允许时使用“你”。不解析 opaque viewerKey、不从排序后的角色列表推断身份。
3. 表达材料从已有权威/获授权投影中选取并在首次投递前冻结：场景基调、相关 NPC 的公开表达特征、当前已表现出的态度、与本次发言直接相关的近期对话和既有叙述承诺。只保存本次需要的内容，不灌入完整历史或 Story Bible。
4. NPC 私密目标、未公开动机及其他玩家秘密不因“符合性格”进入 Narration。风格可以约束如何说，不能自行产生新的主张、承诺、情绪变化或行为。玩家性格不授权 Narration 代其做决定。
5. 后续重试使用同一快照。必要事实/连续性材料不能为预算截断；确实不能容纳时显式报告输入容量问题，不能输出残缺结果。

## 校验器改法

**程序层保留硬边界。** 校验材料 hash/版本、Viewer grants、结构化结果一致性、返回值只含 `{body}`、内部引用和秘密边界、明确遗漏及非法引用。原词表达可以提供确定的事实匹配证据，但“原词通过”不自动等于自然可读。

**正文层检查语义与质量。** 对照冻结事实，逐项检查候选正文的断言、主张/推断归因、代词对象、数量/资源/成败含义及必要后果覆盖。正常改写可以通过；“某人声称”变成世界真相、“角色”错误变成“你”、伤害/消耗/失败被弱化、追加危险或替玩家决定均拒绝。中文语义不能靠若干正则或词面相似度可靠判定。

现役使用一个受限的独立审核调用，只读冻结材料与精确候选正文，不改正文、不读世界新状态。review/v10取消逐片段、逐标量证据和assertion×fact覆盖表，改为results、continuity、attribution、agency、presentation五项检查及仅错误时的issues。每个错误给出code、原文quote/occurrence、允许的constraintRef及具体reason；服务端准确计算位置、验证引用/检查维度和报告一致性。reviewId绑定完整冻结材料与原文，通过后仍发布原文。

round50的真实反例显示，仅一个总结果判断会漏检资源消耗遗漏。因此当前仅对已提交mechanicalOutcome、inventoryOutcome、abilityEffectApplied每组增加一次complete/changed/omitted/uncertain选择；不要求每句引用或每条事实正证据，新经历、NPC台词、环境承诺不填机械结果表。缺项、矛盾报告或无法判断拒绝；完整错误保留在非公开异常字段，公开回执仍只有安全汇总。不同对象/事件不按名字或相同文字去重。

普通创作没有旧出处不是错误；本次合法创建的经历及环境承诺可正常表达。具体矛盾应指出相悖的旧事实。NPC错误、谎话与转述保留归属，不要求其内容为真；公开秘密、知识层级升级与归属偷换仍拒绝。需要持续的新事实仍走原Room保存/Viewer投影链，不能凭审核报告写正史。

任意自然语言绝对无矛盾不可证明，独立模型和复杂表格都不能提供该保证。此限制不作为无限追加审核或阻止产品交付的理由：程序严格执行可判定的机械、授权和结构化冲突；KP取得相关完整创作背景；以真实游玩中的错误频率、严重程度和恢复能力评估叙事可靠性。明确错误按事实归属走原可审计更正与后续一致上下文。提交前新事实目前仍由KP语义自检，post-commit审核不冒充正史提交前校验，也不新增第三次模型阶段。

**自然可读是必过门。** 结果应直接回应本次行动、因果清楚、指代明确、节奏合适；避免事务术语、机械字段串读、重复结果和无关长段场景重述。NPC 的措辞、态度和表达习惯须与冻结特征及近期发言一致；不要求每次套固定段落、固定句式或制造 NPC 独白。没有必要的新细节时可简短收束。

**调用预算显式分配。** 候选生成后最多一次审核，与现有旁白修订共用 Narration 阶段的两次调用上限。不能悄悄变成“生成→审核→改写→审核”循环。审核失败、不确定、超时或预算不足时，保留已提交/未发布状态并提供现有同材料恢复入口；不要发布原词拼接的伪成功正文。总调用数、token、延迟和失败原因进入现有脱敏遥测。实现前核验实际调用消费者，避免与 Proposal 的首提案/修订预算混算。

## 最小代表性验收矩阵

| 变化维度 | 应通过 | 必须拒绝/保留边界 |
| --- | --- | --- |
| 单物品移动与复合观察 | 正常认证自然语言行动，真实提交后用自然句说明移动量和可见环境；正常改写不误拒 | 改物品/数量/目标、漏消耗、加新景物或重复扣库存 |
| 转交与旁观者 | 接收方、旁观者看到正确角色归属，可用明确的姓名或合法代词 | 从参与者排序猜角色、误称旁观者为行动者、泄漏另一私有堆栈 |
| 两名表达特征不同的 NPC | 相同事实边界下用各自一致的语气表达已获授权的主张 | 性格混同、凭风格补新承诺/敌意、主张改真相 |
| 失败与成本 | 自然说明真实失败及损失，仍有清楚可行动的信息 | 润色成成功、弱化伤害/资源成本、承诺未结算奖励 |
| 叙述承诺与恢复 | 相关旧描写持续，后续引用按承诺固化；恢复不重创环境 | 改外观/位置/来源、重跑 Proposal/随机/资源 |
| 不同语言结构的越界 | 合法同义句、调整语序与跨句连接 | 夹带新断言、否定翻转、因果偷换、操控玩家、内部标识泄漏 |

先用同一冻结材料的正例/最小反例验证新校验器，再做有界正常 HTTP → 真实 DeepSeek → Rules/Room → 可用 Narration 对照。记录误拒、错误接受、信息完整性、可读性、人物一致性、调用与 token，不以“未抛异常”或审核模型自报通过作为唯一成功标准。最终结果须人工逐项对照实际 DO 状态与发布正文。
