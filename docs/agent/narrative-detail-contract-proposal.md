# 环境描写与按需固化：已批准变更记录

日期：2026-09-05。用户已明确回复“确认，按该边界更新并实现”。本文保留具体批准范围；产品合同以同步修订后的 SPEC 0001 和 SPEC 0016 为准，批准不等于实现或验收完成。

## 同步到 SPEC 0001 §§3.3、7、12 的内容

KP 可以在故事锚点、已固化事实与既有叙述约束内，自主补充尚未影响玩家行动或机械结算的环境细节。此类描写无需在首次说出时创建完整 Rules 对象或机械定义，但必须保存为可追溯的叙述承诺；后续 KP 上下文必须能取回相关内容，不能依赖模型临时记忆，也不能无故撤回、改变或相互矛盾。

玩家明确提到、调查、接触、利用该细节，或者它将影响线索判断、通路、位置、危险、检定、资源或其他因果结果时，必须在相应裁决或机械影响前，将本次相关细节按既有叙述固化为权威对象/事实，并补齐必要的规则语义。固化不得借机改写已描述的存在、外观、位置或关系，也不得按骰点、玩家 HP 或 KP 偏好重新选择现实。

叙述承诺不能覆盖故事锚点、已固化事实、真实机械结果、秘密权限或玩家意图。已出现矛盾时，按可审计更正处理，不静默修改历史。

## 同步到 SPEC 0016 §§1、4、5.2、8 的内容

Typed Claims 继续是已提交结果、机械后果和角色知识的权威来源。允许 KP 在此之外创作符合上述条件的环境描写，并将发布文本及其适用场景/受众作为叙述承诺保存。叙述承诺只约束叙事连续性，不直接获得机械权威；玩家引用后的物化仍经冻结上下文、相同 Rules/Room 提交和 Viewer 投影。

Narration 恢复重用原已发布或已冻结的文本/承诺，不为重试创造另一套环境。相关承诺按场景、对象和当前意图检索，既有决定性内容不得为 token 预算任意截断；不得每轮灌入无限完整历史。

## 代表性验收

- KP 自主提及一种环境陈设，后续玩家利用时按同一描述固化并交互，库存/资源按真实规则变化。
- 结构不同的外观或空间细节在后续描述、换场返回与恢复后保持一致；既有权威位置和状态优先。
- 新描写与固化事实冲突、隐藏信息泄漏、借固化追加危险或重试改写环境均不能成为有效结果。

本调整不授权部署、远端 migration 或数据删除；真实模型成功链与其他组件验收继续原任务。
