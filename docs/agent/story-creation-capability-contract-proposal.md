# 故事创作、世界连续性与历史分支：能力合同草案

- 日期：2026-09-08。
- 状态：**用户已认可的本任务能力合同，2026-09-08 授权实施；不代表实现或验收已完成。**
- 用户已明确选择的历史模式：**从历史时点开启新分支，允许改变后续结果。**原团保留，不默认采用同一正史的固定结果补演。
- 本文规定目标行为、能力范围与验收，不冻结模型、提示词、类型名称、目录结构、数据库表或部署拓扑，不授权发布、迁移或数据退役。

## 1. 一句能力合同

> 在世界作者提供的故事圣经、内容边界和当前权威事实内，KP 能根据玩家行动与世界局势，创作并接入不同规模、关联方式和玩法的完整支线，复用和发展既有人物的经历、知识与关系，让未被玩家介入的相关事件依虚构因果推进；所有生效内容由同一世界权威持久保存并按角色权限呈现，支持离开后续接、真实收束、授权导出及从历史时点以新身份开启可改变后续结果的新分支，同时允许创作方法模块化组合和替换，并明确处理预算、上下文和生成失败。

完整交付包括创作、世界接入、实际游玩、连续性、幕后推进和历史分支。仅生成一份好看的故事文本或通过单个模型调用，不满足本合同。

## 2. 需求来源与规格权威

本轮需求来自用户连续提出的目标：

1. 根据世界观、政权、组织、主要人物背景与知识，稳定创作适合跑团的支线。
2. 支持即兴产生、短篇与长篇、主线相关与独立故事，以及不同玩法。
3. 支线生成后应有足以主持的小剧本准备，允许合理的创作投入，并处理玩家路线不确定及中途离开。
4. 同一时期其他地区可以发生自己的事件，记录能够保存、导出，供之后以新身份进入。
5. 创作功能可以像插件一样组合，后续修改宿主代码时尽量减少连带改动。
6. 新故事必须衔接现有世界，现有 NPC 可以参与并获得新知识、补充合理经历。
7. 用户已选择历史重开采用新分支，允许新角色改变后续结果。

用户关于“通过惩罚减少支线随手开启和抛弃”的问题按现有公正合同处理：生成费用不构成世界内惩罚理由；真实承诺和行动可以有相称的世界后果。本文不新增违约自动扣分或强制任务规则。

- [SPEC 0001](../specs/0001-llm-kp-responsibility-contract.md) 全文，重点为 §§3–4、7、9–19：叙事权威、自由行动、事实固化、知识、公正、时间、连续性与收束。
- [SPEC 0006](../specs/0006-module-npc-and-faction-protocol.md)：故事圣经、动态实体、NPC 有限知识和势力计划。
- [SPEC 0007](../specs/0007-multiplayer-room-and-fiction-time.md)：虚构时间、跨地点因果和多人决定权。
- [SPEC 0008](../specs/0008-long-campaign-lifecycle.md)：跨章连续性、新角色身份与合法继承。
- [SPEC 0010](../specs/0010-observer-specific-presentation.md)：Viewer 权限、亲历记录与禁止跨观察者补取。

现有已裁定规格继续生效。本文新增的历史分支导入能力不能被解释为已存在的版本迁移授权；若实现需要改变现役模组、版本或持久化合同，应先处理对应的具体规格条款。

## 3. 使用者、对象与术语

| 使用者 | 获得的能力与权限 |
| --- | --- |
| 世界作者／有权配置者 | 提供世界圣经、创作范围、内容边界及创作偏好；具体入口另行设计 |
| 玩家 | 自由提出行动、介入或离开故事、作出承诺和角色选择；不被自动视为接受任务 |
| KP | 在授权留白中创作、判断可行性、扮演人物和提出世界行动；不能自行提交机械结果 |
| 授权的导出与开团使用者 | 取得相应权限的记录或开团包，并以新身份进入指定历史分支；不因房主或同一账号身份取得全部角色秘密 |

以下名称用于说明合同，不要求实现采用同名类型；新增名称在本草案获裁定前不写入正式领域词表。

| 对象 | 含义 |
| --- | --- |
| 故事圣经 | 既有世界背景、核心真相、重要历史、主题、内容边界及开放留白 |
| 故事准备包 | 足以主持本次规模故事的完整材料，区分既有事实、新事实候选、人物计划与演出建议；草稿阶段不自动生效 |
| 已接入故事 | 准备材料与同一世界中的人物、事实、计划、事件建立联系后的故事；不拥有第二套人物或世界状态 |
| 创作配方 | 可组合或替换的创作方法、素材与专项评审要求；skill 和模板可以承载其中的创作说明 |
| 历史分支 | 从一个明确的历史因果起点建立的新世界分支，保存来源关系，独立发展后续结果 |

故事锚点、已固化事实、叙述承诺、角色知识、来源主张、Activity 和虚构时间沿用 [CONTEXT.md](../../CONTEXT.md) 与上位规格的含义。

## 4. 能力条款

### C01：创作范围与世界衔接

1. 创作对象覆盖场景、地点、人物、组织关系、信息、物品、危险、冲突和故事准备，不限于预写任务或具体名字。
2. 新故事须与当前地点、时间、制度、历史、人物目标、既有关系或玩家行动存在具体且可解释的联系。合理留白可产生全新内容，不要求旧记录已经包含同义事实。
3. 相关既有 NPC、地点、物品和组织复用同一世界分支中的稳定身份；支线不得创建同名副本来绕过死亡、位置、所有权、承诺或知识约束。
4. 创作前取得相关锚点、事实、叙述承诺和人物连续性材料；检索无结果、资料明确未写、已知不存在、明确未知和技术不可用分别处理。
5. 跨地区或跨人物创作按其实际依赖取齐材料，不把当前代码只覆盖本地场景的切片当成永久产品范围。
6. 允许独立的地方故事和新人物。不要求每条支线都揭示主线秘密，不把所有旧 NPC、琐事和伏笔都强行串成一个阴谋。

### C02：规模、关联方式与玩法组合

1. 规模至少区分即景小事、完整短篇和可分阶段持续的长篇；关联方式至少支持主线相关、地方独立和角色个人。
2. 玩法可以围绕调查、探索、社交、护送、战斗或它们的组合展开；这些是代表性维度，不是玩家行动白名单。
3. 短篇须有局部完整冲突和明确收束；长篇须有可辨认的阶段问题、阶段成果、持续关系及续接材料。
4. 长短是准备规模与节奏目标，不保证玩家必须经历指定场景数或现实游玩时长。玩家合理地提前解决问题时，应承认实际结果。
5. 角色个人故事回应玩家实际表达的背景和关注，保留多人聚光灯；不替玩家决定过去未授权的选择、情绪、信念或承诺。

### C03：完整故事准备与创作质量

投入完整创作后，准备包至少回答以下问题；无此类内容时明确不适用，不以填表为理由硬造内容：

| 材料 | 完整性要求 |
| --- | --- |
| 起因与真实局势 | 为什么发生、哪些事情已经成立、秘密与世界约束是什么 |
| 主要参与者 | 各自的身份、目标、知识、资源、顾虑、关系及下一步打算 |
| 介入机会 | 当前玩家如何自然接触，以及有哪些能够理解的利益、压力或关联 |
| 地点与场景 | 场景问题、可互动对象、空间和环境条件；机械生效所需定义完整 |
| 信息与证据 | 关键结论的来源、取得条件及可交叉验证方式；调查不依赖唯一线索或一次骰点 |
| 无人介入时的发展 | 各方计划、触发条件、可观察痕迹以及改变计划的条件；未来结果保持待定 |
| 收束与回响 | 解决、失败、放弃、机会消失或阶段结束的识别依据，以及应持续的后果 |

质量验收同时要求：因果可信、人物动机成立、信息支持行动、合理选择能改变结果、多人有参与空间、场景能够结束。文学修辞、反转数量、道德困境数量和任务完成率不单独代表质量。

准备包可完整描述核心起因至收束边界，不预写全部玩家路线与台词。尚未承担因果作用的远处细节允许以后补充；决定性真相、危险、线索或已发布承诺不能以节省预算为由事后重选。

创作必须有明确的完整性、语义一致性及玩法检查结果，并定位需修订的材料。引用、hash 或模型自报“兼容”不能单独作为人物历史无矛盾、秘密没有泄露或故事好玩的证明；检查方法不在本文固定。

### C04：触发、演出与自由行动

1. 玩家实际目标、持续调查、主动前往、投入行动，以及既有世界局势，可以构成展开故事的依据；不依赖固定“接受任务”按钮或动作关键词。
2. 一次询问、路过或表达兴趣可以只形成正常回应或短场景；允许没有支线、奖励或隐藏阴谋的结果。
3. 主持过程识别何时需要完整准备，复用已经存在的故事，不为同一机会反复生成互不相容的版本。
4. 一旦发生具有因果意义的证据、引用或作用，须按上位规格先固化相应内容；不能等待玩家正式接任务后才决定证据背后的真相。
5. 创作出的场景顺序、路线和解法均为准备，不限制未预写的合理行动。拒绝、提前发现真相、选择第三种办法或离开均能继续按实际事实裁决。
6. 机会在玩家合理可感知的情境中出现；演出维护既有场景的重要选择和多人聚光灯。独立支线不被默认为返回主线的门槛。

### C05：既有 NPC 的经历、知识与关系扩展

1. 同一 NPC 可同时关联多条故事，持续保留身份、背景约束、声口、当前目标、位置、资源、伤势、关系、承诺与债务。目标、关系等可以通过有依据的世界事件变化，不能为了支线便利静默重置；新故事的参与理由必须符合其处境。
2. 可以在合理留白内补充此前未记载的经历，包括既有 NPC 共同参与的经历；历史发生时间与本次记录时间分别表达。
3. 可以通过观察、交谈、文件、传闻及其他成立的世界内链路取得新知识。每项明确知情者、取得时间或历史依据、来源及可知范围。
4. “实际发生某事”“某人说过某事”“听者听到了”“听者相信或推断某事”分别保存。误信、误记、夸张与谎言不自动改变世界真相。
5. 明确的既往未知不能被补写成一直知道；后来确实取得的信息可以更新认知。不得为接入支线临时宣布先前发言是谎言，以掩盖新稿矛盾。
6. KP 的创作上下文不授予 NPC 全知。新知情者必须有成立的取得理由，不从主 KP 的秘密材料或其他 NPC 的记忆直接复制知识。
7. 新事实及其应同时成立的知情记录须一致提交；当前回应使用新记忆时，必须经过相应事实与知识接入。后续计划须使用当时已经合法取得的本人认知，并按执行合同推进。
8. 后续主线、支线、离场返回和恢复均读取同一 NPC 的运行时事实与知识；不回写静态模组的初始知识，也不建立插件专属人物记忆。

### C06：幕后世界与跨地点发展

1. 重要 NPC 和势力依据目标、有限知识、资源、位置与既有计划行动；玩家未介入不等于计划暂停。
2. 推进依据来自虚构时间、已提交事件、合法取得的信息或明确触发。玩家阅读、思考、离线以及模型延迟不推进世界时间。
3. 计划形成只说明准备尝试什么；执行可能成功、失败、中断、取消或修订，不把计划直接登记为已经发生的历史。
4. 幕后结果留下可在后来观察或传递的因果痕迹。信息传播遵守媒介、时间和接收者权限，不能因为玩家关心某事就直接通知其角色。
5. 跨地点事件遵守因果前沿，不让一个地点取得尚未发生的他处结果。玩家正在进行的活动、通知与决定点服从其已批准的时间和控制合同。
6. 不要求逐个模拟所有人物的日常；但已生效且到期、或将影响当前裁决的计划不能因画面不聚焦、玩家离开或预算不足被静默跳过。

### C07：离开、承诺与真实收束

1. 区分玩家暂时离开、明确承诺、承诺未履行和冲突已经结束。暂停创作或移出聚光灯不撤销已生效的世界计划。
2. 未承诺的好奇或拒绝没有自动成立的违约责任；世界中的其他事件可以按因果继续发展。
3. 承诺后果根据承诺内容、参与者实际行为、依赖与损失、知情范围及人物反应产生。解释、退款、重新协商或安排接替可以改变实际结果。
4. 生成费用、未使用内容或偏离主线不构成惩罚理由；不以自动世界声望扣分、额外敌人或强制事件追收创作成本。
5. 玩家返回时面对同一个已经变化的世界。事实、物品、伤势、关系、知识、债务和未决计划持续，不按新任务重置。
6. 问题解决、彻底失败或故事被真实放弃后，允许收束；尚存的独立冲突可以继续存在，不追加幕后黑手撤销已有成果。

### C08：预算、失败与恢复

1. 允许对值得展开的支线投入完整创作成本，包括较长准备包；具体额度、计费方式和模型选择另定，不将成本目标变成故事规模的隐性禁令。
2. 创作、评审、修订、上下文准备和相关模型调用纳入可追溯预算；插件不能绕过宿主预算自行调用 Provider。
3. 优先复用世界材料和已保存准备包，按当前需求读取相关内容；必需的真相、约束、知识与因果依赖不能任意截断或猜补。
4. 上下文不足、相关状态冲突、能力不可表达、预算不足和 Provider 失败分别返回可处理结果；不得伪造成功或把技术失败叙述为世界里没有这件事。
5. 生成与修订采用有界流程。中断恢复复用已保存的材料和结果；外部调用结果不确定时明确处理，不静默重采样或无限重写。
6. 草稿完成不自动改变角色状态或虚构时间；接入失败不向玩家发布半成立的事实。世界已提交而叙述失败时，只恢复相应呈现，不重掷、重复扣费或重写历史。

### C09：持久化、权限与唯一事实源

1. 玩家拥有角色意图；KP 拥有合同内的创作与叙事权；Rules 拥有机械权威；Room Authority 拥有活跃正史写权。
2. 创作作业、候选准备材料、已固化事实、NPC 计划和玩家叙述分别标明性质。草稿库、Prompt、摘要和搜索索引不参与活跃裁决。
3. 所有新内容的机械作用、物品与实体状态、知识、关系和时间变化，通过同一验证、原子提交和 Viewer 投影路径。
4. 接入前复核实际依赖的事实及集合变化；生成期间主体死亡、关系改变或相关新事实出现时，旧稿不得静默覆盖。无关变化不应要求整本故事无条件重写。
5. 秘密不经草稿预览、错误、评审、日志、导出或恢复旁路泄露。语义一致性检查位于事实生效之前，提交后润色不能承担正史审查。
6. 已提交错误按现有可审计更正处理；未经批准不修改锚点、规格或旧事件来使新故事表面成立。

### C10：保存、导出与历史新分支

1. 保存足以解释故事和世界变化的起始事实、实际事件、相关定义、时间与因果、人物身份、关系、知识归属及未决计划；保留必要的版本和来源。
2. 区分玩家有权取得的亲历记录、结构化世界记录和授权系统开团包。全知系统材料不直接成为玩家下载记录，新身份也不继承旧角色全部秘密。
3. 开团者可以选择一个可支持的历史时点、相关地区或事件及合法的新身份，基于该时点的有效状态建立新分支，记录来源房间／分支和因果起点。
4. 原团记录保留；新分支中玩家可以改变后续结果。起点之前的事实继承，原团起点之后的历史不强制重演；受新行动影响的发展重新结算，来源未来资料不成为新角色知识。
5. 起点需要满足相关因果闭包，区分事实发生、被记录和角色取得知识的时刻；后来补录过去经历不授予角色提前知情。不能从最终状态猜测过去、只倒退一个时间字段、混用不同地点的未来状态，或忽略尚未结算的机械与待决。
6. 新身份取得物品、知识、职位和关系须有对应起始或世界内依据。选择同一账号或熟悉旧团故事不构成角色继承。
7. 缺少必需历史、定义或兼容解释器时，明确说明该起点当前不可恢复；不自动换版本或补造历史。具体导入格式、范围选择与新房间 genesis 协议在实施设计中补齐。

### C11：模块化组合与持续演进

1. 创作方法、规模要求、素材和专项评审能够组合，并通过共同的 Interface 产出可接入的故事准备。至少以两个结构不同的创作配方证明组合能力。
2. 共同合同覆盖输入要求、输出语义、错误、预算、版本和权限。调用者不需要了解某个配方内部提示词、调用次数或私有流程。
3. 宿主 Adapter 负责读取权威材料、运行时能力匹配和正常提案接入；不要求所有领域逻辑彻底无耦合。Rules、Room、身份、时间及知识相关合同可以作为明确的共同依赖。
4. 更换配方或重构创作 Implementation 后，既有消费者只依赖共同 Interface；修改当前提案格式时，连带变化应集中在对应 Adapter。
5. 已生成内容保存可由平台解释的材料和版本，不依赖创作插件的私有记忆或未登记执行函数。停用或升级创作方法不删除已有世界内容，也不重写旧故事。
6. 内容配方不授予世界写权限、任意代码执行权、机械规则覆盖权或玩家行动限制权。新增机械语义仍需进入正常规则定义和版本合同。
7. 本文不要求插件市场、第三方脚本热加载、多个常驻 Agent、独立服务或跨房间共享活跃世界；是否需要这些设施由后续真实需求决定。
