# 耗时活动中的通知与决定点

2026-09-08。状态：**用户已批准非战斗范围内的时间结算取舍，明确排除战斗；本地机制与代表性矩阵已通过，真实模型活动场景待验。** 实现、测试与本合同纳入 `cloudflare` 本次本地提交，父提交为 `e657162`。用户裁定原话：“非战斗状态可以，战斗不可以”。证据与未覆盖范围见[实现回执](vnext-activity-attention-validation.md)。

## 1. 用户目标与范围

用户明确需要通知与打断发生在玩家进行其他活动、长休等正常游玩过程中；直接等待一两个小时不是本能力的主场景。长休是代表性样例，不能把能力缩成休息专用通知，也不能要求玩家额外发送 passTime 才使活动推进。

能力合同：角色在**非战斗状态**进行耗时活动时，虚构时间按真实因果推进；途中发生该角色有权感知、并构成重要决定点的变化时，先提交已经发生的时间和事件、通知相应玩家，再让玩家决定继续或改变行动。未完成活动的最终效果不提前发放，已发生的事实和成本不回滚；进行状态、待决与已取得知识归 Room 权威持久化，按 Viewer 投影，恢复不能重复执行或代答。**战斗内不产生本能力的通知暂停，不推进活动时长来跳过回合；已有战斗反应、豁免和玩家选择继续服从战斗规则。**

普通时长、计划到期与通知时刻分别表达。本能力不新增“一小时承诺自动在二十分钟兑现”，也不把通知当成完成承诺的证据。

## 2. 已有规格约束

- [SPEC 0001](../specs/0001-llm-kp-responsibility-contract.md) §§9、12、15、19：提供合法感知的信息，保守秘密，重要选择不能被时间压缩跳过，决定权归玩家。
- [SPEC 0004](../specs/0004-kp-and-noncombat-mechanics.md) §§7–8：休整和耗时行为归 Activity；中断只结算已经经过的时间和成本，最终效果在满足完成条件后发生；长休遵守 2014 规则。
- [SPEC 0007](../specs/0007-multiplayer-room-and-fiction-time.md) §§3–7：待决只交给相应控制者，现实时间不推进世界，分支不得读取尚未到达的未来事件。

睡着或身处别处的角色不会因“玩家关心这个任务”就知道幕后变化。事件需要经过实际感知或世界内传递；其后才适用通知。给玩家一个决定点不等于角色已经醒来、离开、施法或取消活动。

| 入口或消费者 | 当前实现 | 证据边界 |
| --- | --- | --- |
| `room/action.ts`、`room/durable-object.ts` | activityControl 保存原活动、决定点及继续/结束选择，可信控制者绑定 | 本地 Room 越权、过期/重复请求及驱逐恢复；未实测浏览器点击 |
| `rules/v2/campaign-actions.ts` | 休息仍在完成后恢复收益；普通活动的继续先核验原前提 | 长休与调查代表性路径通过；通知本身不取消休息或自动醒来 |
| `rules/v2/due-activities.ts` | 通用活动复用 activityTimeSchedule；按真实期限先推进再处理到期工作 | 原等待和长施法调度定向通过；不外推全部原生机械动作时长 |
| 普通提案与 `rules/v2/world-interactions.ts` | 玩家非零共享时长先创建 Activity，完成计划在预分配的完成根执行 | 调查、检定、澄清、物品/危险的原子计划通过；lowering 直接调用者已按阶段迁移并核对，未运行全项目回归 |
| Room 到期队列、Viewer Delivery、`play-table.tsx` | 已合法获得的新信息触发通知，保留活动，展示继续/结束按钮；遭遇中拒绝继续 | 本地正常、途中和完成时刻通知、骰子恢复及 Table 私有投影通过；真实模型传话待验 |

通知选择器只消费已经过既有规则取得的角色知识，不执行新的 observe、不基于幕后计划给玩家消息；装饰旁白不进入这条因果通道。没有新增“任意世界变化是否重要”的分类器。本地检查通过不能代替实际 NPC 模型传话、睡眠感知或连续游玩验收。

## 4. 已批准取代的既有取舍

[虚构时长合同 §4.4](vnext-fiction-time-contract-proposal.md#44-跨过到期点本合同的一个明确取舍) 记录了此前选择的乙案：普通行动“一次推进 D，结果盖在结束时刻”，中间到期的事在行动后处理；明确接受“这次行动的旁白无法反映中途打断”。

新需求在调查等普通耗时行动上需要取代这一行为：**遇到途中决定点时先停在事件发生处；尚未完成的活动结果留到继续并完成后结算。** 已实际获得的信息和已发生的效果仍立即固化，不能因为后面的整体活动未完成而隐瞒它们。长休本来就要求完成后才恢复收益，不改变这条规则。

用户已明确批准上述取舍仅用于非战斗，取代原合同 §4.4 在这一范围内“期间不能打断”的行为。主 PRD 的权限、因果、玩家能动性和 Rules 权威继续生效。非战斗活动途中若进入遭遇，随后由战斗规则接管，不用本能力暂停战斗或自动继续余下活动。

## 5. 处理边界

1. 无重要决定点时，KP 可以概括活动过程并推进到合法完成点，不要求玩家手动逐段等待。
2. 重要事件实际发生、角色依法感知后，保存新知识及决定点，暂停受影响的活动推进。普通环境变化不必次次要求选择；玩家明确关注的进展、需要及时处理的变化及危险按 SPEC 0001 的决定点原则处理。
3. 选择继续时，使用原活动的实际已用时间与成本，验证当前前提，再推进；选择其他行动后，是否保留进度、是否中断长休收益由该类活动及 2014 Rules 判定。通知本身不伪造 ActivityInterrupted 或恢复收益。
4. 无权感知、未获传递、其他时间分支尚未到达的变化，不进入通知，也不泄漏通知数量或隐藏原因。
5. 模型/网络失败保留真实停止位置，不把余下时间、最终结果或玩家回答自动补齐。中途新增世界事实、机械后果与每个阶段仍走同一 Rules/Room 提交路径。
6. 战斗资格由服务端权威遭遇状态决定，不能依赖模型或前端声明。遭遇进行中不创建活动通知待决；已暂停活动在进入遭遇后不能借“继续”推进非战斗时间或发放完成收益。
