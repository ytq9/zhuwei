# ADR 0136：持有者记得手上每叠物品是怎么到手的

- 状态：已接受
- 日期：2026-10-10
- 依据：[物品引用审计](../../tests/kp/items/item-reference-audit.test.mjs)在 [ADR 0134](0134-a-taker-remembers-which-container-it-took-an-item-from.md) 之后仍发现 3 个上下文缺口：
  - 捡起的东西没有记录，"刚捡起来的钥匙"会匹配所有钥匙；
  - 别人交给的东西不记来源，"他刚给我的麻绳"会匹配所有麻绳；
  - 两块同类布条分别从两个容器取出后合成一叠，先取那块的来源被覆盖。

  用户批准把"取出来源"推广为"物品怎么到手"。
- 当前规则：[SPEC 0001 §16](../specs/0001-llm-kp-responsibility-contract.md)（物品与角色知识持续）；条款不变。
- 取代范围：ADR 0134 的记录形状和范围。原来只记"从哪个容器取出"、每件物品一条，现在按到手方式记、每叠可有多条。

## 决定

1. **记录归拿到的人，按到手方式记。** 物品散放到某个角色手上时，`vNextItemAuthority.acquiredFrom[持有者][物品]` 追加一条，记录来源类别、引用、数量和事件序号：
   - 从容器取出（容器引用）；
   - 从地上捡起（场景引用）；
   - 从别的角色那里得到（那个角色）：别人交给时记在接收的一方，经检定从别人手里拿到时也记这一条。

   每叠最多保留最近 8 条。
2. **合成一叠时各自保留。** 同类物品到手后合成一叠，来源分条保存。叠内的单件没有物理区别，"把从木桶拿的那块放回木桶"放回 1 件即可。
3. **数量少了就扣，不在手上就忘。** 一叠数量减少时，放回某个容器先扣来自该容器的那部分，其余情况先扣最早的。物品被放进容器、交出、丢下或用掉后，记录删除。合成记录和清单行都按当前数量截断，只给当前散放持有者本人。
4. **KP 只看行动者自己的记录。** 冻结的物品记录和随身物清单行都带 `acquiredFrom`，取代 `takenFrom`。带记录的那叠不和同类物品合成一行。
5. **发新版本。** 按 [ADR 0120](0120-a-new-runtime-version-retires-open-rooms.md) 换用 `runtime-srd51-2014-authoritative-vnext-stage3-v10` 与事件格式 `room-world-events-vnext-stage3-v8`。ADR 0134 的 v9 没有部署过，所以实际只退役一次已开房间。模型上下文升为 vnext-19。

## 后果

- 记录不进入玩家视图。
- 带记录的随身物在请求里多出几条来源信息，固定请求体积不变。
- 模型会不会用这些记录，要靠真实样本确认。
