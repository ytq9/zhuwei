# ADR 0103：地点间通用移动、地图上前往与拼合地图

- 状态：已接受
- 日期：2026-10-05
- 依据：第 166 批真实验证中，玩家说"我从后门出去，到后院。"，KP 新建了一个后院，模组里原有的后院与排水沟没有用上。原因有三：
  - 现行规则开房时没有登记模组的地点间连接；
  - KP 的上下文只含当前场景；
  - 新版 KP 只能经自己新建的通道移动。

  用户确认方向："KP 应该优先用模组中的地图……应该改为通用移动"，并要求"地图中也可以选择前往，多场景地图应该可以拼合到一起，玩家自己选拼哪几个"。拟写的 SPEC 0014 §§4、8 条款经用户确认。
- 当前规则：[SPEC 0014 §§4、8](../specs/0014-observer-tactical-map-and-environment.md)
- 取代范围：KP 写的"穿过通道"（`traversePassage`）作为玩家移动的唯一方式。

## 决定

1. **连接以模组为准。** 开房时按模组的连接（黑橡 v4 的 `tacticalSite.connections`）登记地点之间的路。每条连接两头各是地图上的一扇门或开口，门的状态决定能否通过，路上时间取模组所写。KP 新建地点时也写明它和已有地点的连接，并入同一张表。
2. **通用移动。** 玩家去某地时，KP 写一步"前往"。Rules 找一条门都开着的路线，先让行动者走到出发的门前，再扣路上时间，让行动者出现在目的地门前的到达位置。原来的"穿过通道"并入这一步，不再单独存在；开发期不做兼容。
3. **KP 优先用模组地点。** 冻结上下文列出当前地点能去的地点和路线状态。指引写明：有现成地点用现成的，模组里没有时才新建。
4. **地图上前往。** 门或开口上的"前往"把一句行动交给 KP，与玩家亲口说的一样，照常裁定和写旁白。遭遇中不提供。
5. **拼合地图。**
   - 玩家可以从到过或正看得见的地点中选几个，按模组总图（`sitePlan`）拼在一起显示：同一楼层拼在一处，不同楼层分层切换。
   - 没到过的地点不显示内部。
   - 拼合只是显示，不改变机械。

## 影响

- 同一扇门两面各有一个要素、各有耐久，两面的状态需要同步。
- 战斗中的旁白时机另见 ADR 0104。
