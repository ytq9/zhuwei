# ADR 0052：vNext 行动只存它冻结所用投影的身份

- 状态：已接受
- 日期：2026-09-25
- 依据：每次行动的准备数据都存着一份完整的 KP 世界投影。本地预览那一桌第 20 次行动，这一行共 453,377 字节，投影占 270,530，每次行动多约 10,600 字节：行动者的投影、每个在场 NPC 的投影（连同她们的全部记忆）、所有动态事实都在里面。一行是一个 SQLite 值，上限 2MB（[ADR 0027](0027-entry-level-correction-audit-and-chunked-room-state.md) 撞过一次），归档又逐次带上这一行。vNext 的玩家行动让模型读冻结上下文；冻结之后，存下来的投影只剩一个读者：归档核对它的 hash、状态版本和分支。用户同意让冻结内容不再随房间增长（“可以”）。
- 当前规则：[SPEC 0011 §3](../specs/0011-reliability-correction-observability-and-evaluation.md)（条款不变：冻结输入按记录核对）
- 取代范围：每个 vNext 玩家行动都存完整 KP 投影的做法。

## 决定

1. 有冻结上下文的 vNext 玩家行动，准备数据里只存投影的身份：类型、视角、状态版本、分支和 hash。完整投影在准备时算出，用来冻结上下文，然后不再保存。冻结上下文的绑定本来就记着这个 hash。
2. NPC 到期计划和旧路径照旧存完整投影，因为它们会把投影交给模型。
3. 归档的核对不变：用重放出来的状态重新计算投影，比较 hash、状态版本和分支。之前准备的行动存着完整投影，照样通过。

## 后果

- 按第 20 次行动的数据，这一行会是约 18 万字节（冻结上下文），原来 453,377；每次行动的增长少约 10,600 字节，归档里每次行动也少这么多。
- 还在增长的是冻结上下文本身，见 [ADR 0051](0051-unread-memories-are-read-when-named.md)。
