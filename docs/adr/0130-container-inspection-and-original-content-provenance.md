# ADR 0130：容器查看记录与原有内容来源

- 状态：已接受
- 日期：2026-10-06
- 依据：用户裁定关闭容器显示上次打开后的清单，重新打开才更新；其余采用普通背包直接取用、有依据才能物化原内容、损坏依实际后果裁定。
- 产品规则：[SPEC 0001 §16](../specs/0001-llm-kp-responsibility-contract.md)、[SPEC 0016 §7.3](../specs/0016-part-c-compound-actions-and-claims.md)。
- 取代范围：ADR 0128 中关闭便携容器内容完全从库存读数消失的实现选择；不改变实物身份、机械权限或调用额度。

关闭后的访问限制与已经获得的知识是不同状态。沿用现有事件折叠，在 `vNextItemAuthority` 保存按角色和容器索引的紧凑查看记录，并在提交和 replay 使用同一更新函数；记录仅包含已见身份、名称、数量和状态，不复制定义或可执行动作。桌面把它独立显示为历史清单，KP 只读取本行动相关容器中属于行动者的记录，实际库存仍由 ItemEntry 保存。DO 的现有 JSON 保存、驱逐恢复和归档承接这些字段，不增加 SQL 表或远端 migration。

场景级留白授权不足以证明个人资源存在。物化原内容额外核对取得来源或与目标容器绑定的已固化来源；已有叙述承诺仍先按原内容固化，再执行检查。已检查或已经物化的原内容封闭，后续增减使用实物转换。起始装备继续使用现有装备包展开链。新创作的普通袋子由结构化标签声明访问方式，标准袋子由新运行版本的初始化政策按固定定义引用判断，既有目录数据及其校验和保持不变，不从名称或描写猜测；明确封口是原袋子的真实状态转换，不能借补全改写明确无机制的其他物件。

服务器把实物的冻结容器路径带入内部计划，按有限开关链推导访问前后的依赖，Rules 独立核对路径并复算依赖。填写坐标保持原类型分组，修订无需重排组。损坏的开关后果进入同一生命周期转换，已经损坏的物件可以接受 KP 裁定的操作而不恢复耐久。

新版本把物品权威中的查看记录、来源、唯一绑定与识别记录纳入现有逐记录更正审计。更正恢复相应记录的原值及缺省状态，不能用已恢复的真实库存重算旧清单，也不整体替换其他观察者或实物的记录。新分支激活后保留各角色独立的时钟和恢复后的时间，将当前时钟绑定到新分支，保证下一次行动仍可重放；旧版本事件的审计解释保持不变。

当前开发 Profile 更新为 stage3 v8 / event schema v6；本决定不授权部署、远端资源操作或真实模型调用。验收证据在本轮完成后记录，不把本地脚本模型当作真实 Provider 通过。
