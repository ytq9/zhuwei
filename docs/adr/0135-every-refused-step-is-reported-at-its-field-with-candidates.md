# ADR 0135：每个被拒的步骤都在它的字段上报出，并附可选引用

- 状态：已接受
- 日期：2026-10-10
- 依据：[物品引用审计](../../tests/kp/items/item-reference-audit.test.mjs)按功能而不是按单句检查，列出 12 个修订诊断缺口：
  - 6 个拒绝不指向出错的字段：只给错误代码，或把"物品在地上"报成"接收者不可用"。
  - 3 个引用选错时不给可选引用。
  - Rules 只报第一个被拒的步骤。
  - 取放声明一出错，表单其余步骤不再检查。

  用户批准按审计清单修复。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)；条款不变。延续 [ADR 0095](0095-one-revision-lists-every-problem.md)"一次修订列出全部问题"到 Rules 预检和取放声明。
- 取代范围：无。

## 决定

1. **Rules 的拒绝带位置。** 库存操作的每个拒绝出口都附结构化诊断：路径指向要改的字段（`entryRef`、`containerRef`、`targetCharacterRef`、`sceneRef`、`quantity`、`slot` 等），并写明要求。错误代码不变，读代码的调用方不受影响。给出地上的物品时报在 `entryRef`，原因写成"给出的人没拿着它"。
2. **可选引用由 KP 一侧给出。** Rules 诊断不带候选引用。物品引用被拒时，修订工单从这一阶段收到的内容里列出可以改填的物品，已读的和只在清单里的都算，同 [ADR 0133](0133-a-draft-naming-a-listed-carried-item-reads-it.md)。放入时不列目标容器和装着它的容器。候选按并集计算，现场和 Room 复核得到同一张工单。降级阶段遇到没读到的引用时，报在草稿里出现它的字段上。
3. **Rules 预检报出每个独立的被拒步骤。** 预检时某一步被拒，就记下来并继续后面的步骤。后面的步骤若依赖已失败的步骤（`dependsOn`，包括先开盖才能取物），就跳过不报，避免连带误报。只有一个步骤被拒时，结果和以前完全一样。
4. **取放声明出错不挡住其余步骤。** 被拒的声明换成它会展开成的普通操作，其余部分照常做本地校验，诊断合并到同一轮；落在这几个步骤上的诊断丢弃，因为它们已经有自己的诊断。

## 后果

- 修订工单更长，只在有错时出现，固定请求体积不变。
- 解析器契约升为 v91。
- 仍未覆盖：本地被拒的表单不会进入降级和 Rules 预检，所以另一个步骤上只有降级或 Rules 才能发现的问题，要等下一轮才报。Rules 的拒绝目前只能通过一次提交尝试回到 KP；要在同一张工单里报出，需要 Room 在生成工单前先做预检，属于协议改动，另行决定。
