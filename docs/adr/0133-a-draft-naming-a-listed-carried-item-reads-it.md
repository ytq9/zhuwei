# ADR 0133：填写或修订点到清单里的随身物时读取它

- 状态：已接受
- 日期：2026-10-10
- 依据：[真实调用检查](../agent/receipts/possession-recall-live-20261010.md)四次放回都没有提交。两次模糊放回，选择阶段都没有点名散放的布条；首稿都把盒里剩下的那叠当成来源。修订轮只能重填表单，清单里的物品已无法再读，诊断候选里因此没有正确来源，只剩盒子本身，模型照着写成"把盒子放进盒子"。用户要求修复修订轮不能补读的问题。
- 当前规则：[SPEC 0016 §4.3](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)（精确读取行动者持有物）、[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)（修订诊断）；条款不变。
- 取代范围：[ADR 0132](0132-carried-items-are-listed-and-read-when-named.md) 第 3 条中"只有选择或补选点名才读取"，以及第 5 条"声明里的物品没读到时，指出要先在 `requestedItemRefs` 里选出"。

## 决定

1. **草稿点到即读取。** 首次填写或任何一轮修订的回复里，只要出现清单里某件随身物的引用，Room 就在检查这份回复之前，按清单记录的版本读出这件物品，与 `requestedItemRefs` 的读取方式相同（核对版本和内容哈希，存进这次行动的准备数据，冻结后变了就按读取失效失败）。之后的轮次、降级和归档恢复都读这一份。
2. **发给模型的内容不变。** 读取不改变系统消息里的冻结上下文，也不改变短引用表；修订轮仍是同一段对话往后追加。
3. **每一轮按自己点过的检查。** 一份回复的校验上下文是：冻结记录，加上本阶段选择或补选点过的随身物，再加上这份回复自己点到的随身物。Room 保存了所有轮次读过的记录，复核早先的轮次时也按这个规则排除后面才读到的记录，所以现场和 Room 对同一份回复给出同一张修订工单。
4. **诊断列出可选的来源。** 取放声明的来源错误时，候选包括已读的和清单里未读的散放随身物，去掉目标容器本身和装着它的容器；所声明的错误来源能查到名称（定义或该容器的查看记录）时，另列同名的候选（`sameName`）。只有既没读到、也不在清单里的引用才报 `container-transfer:source-not-read`。

## 后果

- 固定请求不增加：选择和填写的表单不变，只有修订工单的诊断内容变化。
- 模型仍需要在某一轮点到正确的物品；这一点要靠新的真实样本确认。
- 解析器契约升为 v90。
