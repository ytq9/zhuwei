# ADR 0030：Activity 的推进阶段不是已到达的 due

- 状态：已接受
- 日期：2026-09-18
- 依据：用户于 2026-09-18 在修复 `tests/platform/recovery/stable-recovery.test.mjs` 时裁定，取推荐项。
- 当前规则：[SPEC 0013 §7.2 Activity 与到期](../specs/0013-part-c-time-and-conformance.md)
- 取代范围：不取代既有条款；§7.2 补一句先前未明示的到期判定。

## 背景

被 Medicine 稳住的伤员进入 3 小时自然恢复。另一角色在同一瞬间发起攻击时，Rules 的到期预检把恢复的"推进阶段"当作已到期先结算：时钟直接推进 3 小时、伤员醒来，攻击随后才执行，于是 SPEC 0012 B21 的"稳定后受伤打断恢复"在这条路径上永远不会发生。§7.2 原文只规定"开始时刻不早于 due 的新行动前先提交到期活动"，没有说明推进阶段算不算 due。

## 决定

推进或提醒阶段是尚待经过的一段时间，不是已到达的瞬间。只有三种到期工作在新行动前先提交：完成瞬间已到达（含已过期）的 Activity、已排定到期的 NPC 计划，以及内部决定（NPC 工作、承诺审核）。其余情况下同一瞬间开始的新行动先执行，可以打断该 Activity；推进阶段在新行动提交后由房间的到期尾部结算。

Rules 的预检（`settleDueActivityBeforeInput`）与房间提交前的到期守卫共用同一个判定（`dueActivityPreemptsAction`）。

## 后果

- 稳定恢复门转绿；已过期但完成已不合法的旅行仍按原样在结算时被中断，不阻塞时间线。
- 多人同场景时，一名角色处于长时活动中不再使其他角色的即时行动被迫等待时钟推进。
