# ADR 0033：链内内部决定失败时保留已完成的进度

- 状态：已接受
- 日期：2026-09-19
- 依据：用户于 2026-09-19 在两种读法之间选择「保留部分进度」。
- 当前规则：[SPEC 0003 §1 事务与候选](../specs/0003-authoritative-action-transaction.md)
- 取代范围：SPEC 0003 §1 2026-09-17 修订中「终局失败取消整个未交付候选」对链内内部决定失败的适用。

## 背景

等待跨过 NPC 截止点时，NPC 的决定是玩家候选链里的一个内部阶段。供应商丢失响应或决定被拒绝时，SPEC 0003 §1 的字面要求取消整个候选：等待没有发生，玩家重新提交。回复优先之前的实现则让等待停在截止点，保留已推进的时间，并把活动标为不能安全继续，`tests/kp/time/time-passage.room.test.ts` 的多个用例以此为前提。

## 决定

链内内部决定的失败或未知响应不是玩家行动的终局失败。房间把候选组原样提交（开始与已完成的推进），不生成玩家的回复；行动的 Activity 停在该截止点，不再花费剩余时间；投影向其控制者报告不能安全继续。该决定的日志保留，恢复后从截止点继续。玩家自己阶段的拒绝仍取消候选。

## 后果

- 玩家不会因为 NPC 侧的故障失去已经过去的时间，也不会被重新裁定。
- 剩余等待要等该决定恢复；恢复只能通过重发同一提交或显式恢复，不由闹钟重采样。
- 实现位置：`drainDueActivities` 里对到期计划决定失败的分支，用 `appendAuthorityTransition(state, [], candidate)` 提交候选。
