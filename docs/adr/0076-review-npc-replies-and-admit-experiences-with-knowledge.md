# ADR 0076：NPC 回答先审核，批准的经历与本人知识一起保存

- 状态：已接受，按 A 段实施。
- 日期：2026-09-30。
- 依据：用户阅读补全后的 [NPC 新内容方案](../agent/proposals/npc-introduced-content-proposal.md)，询问“NPC 申报候选”的含义后明确回复“方案通过，去做”；实施按推荐顺序先完成 A 段。
- 当前规则：[SPEC 0006 §7](../specs/0006-module-npc-and-faction-protocol.md)、[SPEC 0016 §7.2、§7.3、§8.2](../specs/0016-part-c-compound-actions-and-claims.md)。
- 取代范围：窄取代 ADR 0073 中“本人未读到的经历一律不补”的实现选择，增加与其本人视图隔离并存的主持人审核；扩展 ADR 0074 的同一根行动显式恢复至新审核阶段。NPC 本人写台词与有限知识原则保留，故事作业额度与未知结果策略不变。

## 原因

[round154](../agent/receipts/vnext-round154-validation.md) 中，莉安对未记载的同一日常往事给出相反回答。只要求一律不知道会压缩世界留白；允许自由补写又不能靠近期 Prompt 维持长期一致性。用户要求先审核，错误交还 NPC 修改，允许合理补充进入真实游戏。

已有 worldFact 支持此前未记载的经历与本人知识原子接入。复用这一权威路径比另建人物记忆库更简单。来源主张继续沿正常交谈事件保存；声明的新内容、认知态度和来源附于本人私有动机材料，不向听众公开，也不把所述命题自动变真。

## 技术选择

- 以单一纯状态转换决定下一步本人作答、整组审核、一次修改或终止；Adapter 与 Room 从同一保存证据取得相同结论。
- 审核面向整组回答，空申报也审核，避免漏报绕过；批准候选的原内容不能由审核改写，表单生成与 Rules 准入仍确定性验证。
- 审核回传 NPC 的诊断由受限类别、原字段与本人已读记录构成，主持人自由文本理由仅留私有证据。
- 审核阶段使用现有 proposal 调用账本、来源预算及显式替补，不新建调用平台。序号 139–146 用于四份可能的裁决各至多两次审核；SQLite 的新建表采用 1–146，既有 1–138 表在构造迁移中原子重建并保留记录，原已发布迁移不改写。
- 提交核对原裁决、本人保存的回应、审核和最终组合；完整事实/知识前提并入后再作 Rules 预检。工作流绑定包含作答表单与审核协议，未冻结的旧工作按现役换版规则重问。

## 范围与验证

本次只开放围绕已有对象的经历与来源主张。新增人物/地点/物件的身份接续、机会目录和故事触发仍属于方案 B/C；不能以 A 段验收代替全部能力完成。A 段以定向 Node 和真实本地 Room/SQLite/Rules 测试验证，Provider 为受控响应；真实模型质量及成本另需有界授权批次。迁移、持久恢复与实际验证证据由对应回执记录，不把本 ADR 当作测试结果。
