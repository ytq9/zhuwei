# ADR 0128：已有对象按需补全并保持实物连续性

- 状态：已接受
- 日期：2026-10-06
- 依据：用户明确确认将通用补全扩展到 NPC、实物、场景物件和地形；物品持久化及多次正确读取优先，图形界面仅为可选想法。
- 产品规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)、[SPEC 0001 §§3.3、7、16](../specs/0001-llm-kp-responsibility-contract.md)。
- 取代范围：ADR 0089 对补全对象类别的限制，以及 ADR 0125 将库存实物列为待裁定的边界。原有开关与锁定机制继续复用。

## 决定原因

同一个对象在不同阶段需要不同的规则资料。首次需要某项机械时重建对象，会丢失已有身份、位置或资源；把未定资料直接解释为不存在，也会拒绝本来合理的行动。入口应共享冻结与验证协议，结果仍写各领域原生记录，后续消费者读取同一个对象。

数量、伤势、持有、容器归属和已耗资源是持续状态，不能用重新生成定义恢复。明确未定的物品机械需要独立标记，不能追认所有旧 null 为可创作留白。补全产生完整下一定义，引用原版本；共享定义不能因补全一件实物而隐式改变其他实例。

## 实现边界

容器归属写入 ItemEntry 的 `containerRef`。已有 `holderRef`／`sceneRef` 保留为库存与空间消费者使用的有效位置索引，由原生物品转换随容器一起维护和校验，不由 KP 独立填写两套位置。不同容器中的同类物品不能因位于同一场景而合并，禁止容器循环。拿取、放回及移动容器走同一库存生命周期；读取、恢复和重试不生成内容。

图形界面、现实材料物理模拟、实际模型调用和部署均不属于这一决定。已存在的引用、秘密权限、规则随机、时间与原子提交边界保持现行合同；具体实现与验证状态记录在[任务方案](../agent/proposals/dynamic-object-completion-plan-20261006.md)，本决定不证明代码已经完成。
