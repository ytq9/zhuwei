# ADR 0131：冻结短引用与声明式容器取放

- 状态：已接受
- 日期：2026-10-07
- 依据：用户批准在隔离 worktree 实施四项调用优化并测试，要求优化正确完成行动的调用、上下文与缓存成本。
- 产品边界：[SPEC 0001 §16](../specs/0001-llm-kp-responsibility-contract.md)、[SPEC 0016 §§4.3、7.1、7.2、7.3](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)。
- 取代范围：ADR 0044 的上下文内字段排布、简单执行表单使用通用补丁修订的实现选择；延续 ADR 0043 的阶段共享上下文、ADR 0092 的有限脚本及 ADR 0130 的容器访问依赖。调用额度、Rules 原语和持久化结构不变。

真实失败样本显示，高修订缓存命中仍可能连续无法提交。降低固定输入不能代替可表达完整意图的表单；长身份和确定性绑定也不应反复由模型抄写。

在模型传输层采用冻结身份的短引用，按原身份的 hash 确定，新增读取记录不改变已有短引用。只变换类型化引用槽，正文与枚举词汇保留原文；共享 schema 的引用枚举按使用位置处理。原始 RequiredContext、readSet、回复字节、sourceDraftVersion 和事件身份保留原值，解析时反向绑定；短引用不授予权限。当前场景内 worldInteraction、observe、social 的场景绑定由冻结行动者记录组装，目标、方法、风险、时间与后果仍由 KP 选择。

上下文内不随选择变化的定义和模组约束先发送，当前状态随后，按选择增加的正文仍放在最后一组；意图和本轮 hash 后移。保留所有原有因果和权限材料，不按 token 数截断事实。跨行动缓存只覆盖实际相同的前缀，变化状态始终重新发送。填写到修订继续保持同一 system 与首个表单；修订说明仅在首份工具结果写一次，后续附加原始回复与新工单。

`inventoryOperation.operation.containerTransfer` 是已有原语的有限填写声明，显式选择 takeOut/putIn、原容器、原条目、数量、普通打开与取放后是否合盖。两种方向的引用候选分别由冻结库存生成：取出指向容器内原条目，放入指向行动者独立持有且未装备的原条目，排除盒内剩余堆和他人持有物；没有合法来源的方向不提供。其余合法组合继续使用原有库存原语。服务器展开 open → acquire/store → close，编译器和 Rules 沿现有依赖链验证。仅从冻结现有对象展开，不自动解锁、损坏、修复、创作、补完属性或猜测玩家方法；同束新对象仍使用原有创建及操作表单。对同一容器的多条一致声明共用一次开合区间，互相冲突的访问要求拒绝。仅由展开器产生的确切步骤可在只选库存表单时通过类型检查，模型自写 worldInteraction 不获得豁免；诊断返回源声明的填写坐标及合法引用候选。

简单库存、物件操作和故事接续的修订仅提供原结构化表单替换，避免 JSON 字符串与补丁路径的额外填错面；复杂创作和独立 NPC 决策继续使用既有协议。Room 从原回复和冻结上下文重建同一工具、展开与诊断，拒绝未提供的修订工具。请求体积门按冻结场景下的实际传输表单测量固定成本，世界正文另计。

不保证模型语义判断或填写永远正确；是否减少修订与费用须以原意图、实际提交状态、调用账本和缓存用量验证。真实失败保留原证据，不通过重抽样或增加调用额度制造通过。
