# ADR 0075：没有记录的社交分组只交给旁白审核

- 状态：已接受
- 日期：2026-09-29
- 依据：用户于 2026-09-29 要求在旁白事实层处理 round153-2 的结算句，不用提示词处理，并提出“空分组只交给审核、不交给生成”作为待评估的做法。用户此前已裁定旁白不念裁决账本。
- 当前规则：[SPEC 0016 §8.3](../specs/0016-part-c-compound-actions-and-claims.md)。本决定不修改任何 SPEC 条款。
- 取代范围：2026-09-09 用户决定“把空记录也发给旁白”（记录在[承诺与计划回执](../agent/receipts/vnext-promise-lifecycle-validation.md)），当时生成和审核收到同一份材料。本决定取代其中交给生成调用的部分；交给审核的部分不变。

## 原因

[round153](../agent/receipts/vnext-round153-validation.md) 153-2 发布的旁白结尾是“交涉到此为止，没有欠下人情，也没有许下承诺。”

- 那次生成请求的必述事实是两名说话者的原话和一条关系变化，没有一条说“没有债务或承诺”。
- 请求的材料里有 `socialRecords`：`newDebts: []`、`newPromises: []`、`relationshipChanges: [{claimIndex: 3}]`。正文里“人情”“承诺”的先后与材料里这两个键的先后相同。
- `newDebts` 只出现在材料里，生成提示里没有。
- 审核的思考记录把这句话对应到这两个空分组，写明它们是内部结算字段，仍然判为通过：这句话与审核收到的材料一致。
- 空分组不是 Claim。它由旁白层从当前 Viewer 的 Claims 列表派生，表示本次回执没有给出这一类记录。SPEC 0016 §8.3 规定旁白表达的是 Claims。

2026-09-09 把空分组交给旁白，是因为真实批次里 NPC 台词有许诺、提案却没有登记承诺。生成调用的事实依据只有 `facts` 和 `payloads`，这一点不靠空分组；正文有没有自行建立义务，由审核对照 `socialRecords` 核对。

## 决定

1. 生成调用收到的 `socialRecords` 只含有记录的分组和 `scope`。三个分组都没有记录时，材料里没有 `socialRecords`。旧策略的修稿调用用的是生成调用的材料，做法相同。
2. 审核调用收到的材料不变：三个分组都在，没有记录的是空数组。旧策略审核可引用的 `/socialRecords/*` 地址不变。
3. `plainText-v1` 和旧策略 `narration-vnext` 共用同一份材料构造，两条路径一起改。
4. 生成提示、审核提示和策略版本都不变。

## 评估过的其他做法

- 生成调用完全不带 `socialRecords`。有记录的分组只是指向 `payloads` 的索引，去掉它不丢事实。没有采用：旧策略的生成提示有一段专门说明 `socialRecords`，材料里不再有这个字段时这一段要跟着删，策略版本和工作流 hash 随之变化；本次问题只出在空分组上。
- 在提示里写明不要说出空记录。没有采用：用户已裁定这类句子在事实层处理。
- 审核也不带空分组。没有采用：审核提示按 `socialRecords` 核对社交后果，旧策略审核的地址表里有这三个分组。

## 影响

- 部署时尚未发布、第一阶段请求已保存且材料里带空分组的旁白，按 [SPEC 0016 §9.2](../specs/0016-part-d-staging-and-supersede.md) 重问一轮，因为 Room 重建出的生成请求与保存的不同。材料里没有 `socialRecords` 的旁白和已发布的旁白不受影响。
- 用 153-2 保存的冻结请求重建：生成请求的材料由 4,805 字节变为 4,774 字节，其余字段和提示不变；审核请求与当时发出的相同。
- 旧策略的修稿调用收到的审核意见可能引用 `/socialRecords/newDebts` 这样的地址，而它的材料里没有这个分组。全部记录都在 `payloads` 里，修稿按 `payloads` 核对。
- 门：`tests/kp/narration/social-context.test.mjs`、`tests/kp/npc/promise-lifecycle.room.test.ts`。

## 没有解决的

- 没有发起真实调用。真实模型在新材料下是否不再写出这类句子，要由一个编号的真实批次验证。
- 审核仍会通过这样的句子：它与审核收到的空分组一致。
- 两份生成提示里仍有提到空列表的文字：`plainText-v1` 的“newPromises等空列表不表示既有台词不存在”，旧策略的“空数组也有意义”一段。生成调用的材料里现在没有空列表。删掉这些文字会改变策略版本，本次没有改。
- “交涉到此为止”的来源没有确定。生成材料里仍有只作结算记录的 payload（`evidenceRole` 为 `stepSettlement`、`receiptStatus`），本次没有动。
