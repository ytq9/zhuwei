# ADR 0139：重复字段按一次读取，或退回模型重写

- 状态：已接受
- 日期：2026-10-10
- 依据：[矩阵批次](../agent/receipts/carried-reference-matrix-20261010.md)里有一次木桶用例只用了 2 次调用就结束，玩家看到"KP 返回的数据未通过格式检查"。原因是模型在 `result` 对象的开头和结尾各写了一次 `"outcomeCode": "put-back-cloth"`，两次的值相同。实测发现处理前后不一致：首次填写里有重复字段，行动直接失败；修订回复里有同样的重复字段，会再给一轮。用户裁定"最优先目的是让游戏顺畅稳定的游玩下去，其次才是预算"，并确认修改 SPEC 0016 §7.2 的措辞。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)（本次修订）。
- 取代范围：`74e713d3`（2026-09-07）中"重复成员是对可见稿子的策略拒绝、不得重发"这一条边界。服务器不替模型选值的原则不变。

## 决定

1. **值相同，按一次读取。** KP 提案工具的参数（选择、填写、修订外层及其中的稿子）由 `parseProposalArgumentsJson` 读取。同一对象里某个字段重复出现、两次的值相同时，按一次读取。值相同时不需要选择，所以不算替模型做决定。
2. **值不同，退回重写一次。** 服务器不在两个值之间选择。
   - 首次填写里出现时，与无法解析的回复走同一条重发路径：只允许整份重写，诊断 `json:duplicate-object-member` 指出字段的路径和位置，Room 从保存的回复自行证明这次调用合法。
   - 修订回复里出现时，和以前一样：同一份稿子再发一轮，并附上这条诊断。
3. **其他读取保持严格。** 存储、存档、NPC 回答等其他读取 JSON 的地方仍拒绝任何重复字段：那些地方出现重复，说明数据已经出错。
4. 解析合同升为 v94。运行版本、事件格式和上下文版本不变。按 [ADR 0038](0038-reask-unfinished-work-after-a-version-change.md)，进行中的提案重问一轮。

## 后果

- 值相同的重复不再让行动失败，也不多花调用。
- 值不同的重复多花一次调用（重发），行动不会因此直接失败。只有选择终结决定、没有第三次调用额度时，仍按以前的方式失败。
- 没有真实调用验证。今天 26 次真实运行里只出现过 1 次值相同的重复，值不同的情况还没有出现过。
