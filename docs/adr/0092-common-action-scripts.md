# ADR 0092：常用动作脚本

- 状态：已接受
- 日期：2026-10-04
- 依据：[round161](../agent/receipts/vnext-round161-validation.md) 中 KP 对"把奈斯拦腰抱起，扛到炉边"写对了对抗擒抱，却没有写出带到炉边的第二步，扛人仍只在文字里。用户提出把常用动作写成程序脚本由 LLM 调用，询问这是否违背 SPEC 0001、是否保留自由度；按"脚本是 KP 可选的工具，自由组合保留，KP 仍决定是否检定、优势劣势、DC 与后果，脚本只固定 SRD 写死的机制和步骤顺序"的做法确认，并确认了动作清单、固定机械与实现顺序，以及 SPEC 0016 §3.1、SPEC 0014 §4、SPEC 0004 §4 的条款文字。帮助与预备另行讨论。
- 当前规则：[SPEC 0016 §3.1](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)、[SPEC 0014 §4](../specs/0014-observer-tactical-map-and-environment.md)、[SPEC 0004 §4](../specs/0004-kp-and-noncombat-mechanics.md)
- 取代范围：SPEC 0016 §3.1"Catalog 不按动作名称继续细分"对已登记常用动作的适用。

## 原因

SPEC 0001 §5 要求接受自由的自然语言行动，§6 让 KP 决定是否检定、技能、DC、优劣势和后果，§20 禁止把 LLM 降为候选命令解析器。另一方面，擒抱、扛走、推撞这类动作的机械和步骤顺序由 SRD 5.1 写死，让 KP 每次自己拼"走过去、对抗、效果、成功后再走"容易漏步：round161 的旁白把成功摘要里的"扛到炉边"当作已发生，世界状态里两人没动。

## 决定

1. **脚本是可选工具。** KP 在 world-interaction 家族里可以写一个已登记的常用动作及其参数（目标、目的地、推倒或推开、挣脱用的技能）；没有登记的做法照常用自由组合的步骤。脚本不是玩家菜单，玩家照旧用自然语言行动。
2. **裁决仍归 KP。** 是否检定（直接成功、对抗或检定）、优势或劣势、风险、时长与成败描述由 KP 写；SRD 写死的部分（对抗用的技能、拖带减速、推开 5 尺、跳跃距离与 DC 10）由脚本固定，KP 写的与之不符时按诊断修订。
3. **展开成现有步骤。** 脚本在提案解析后展开成原有的原子世界互动步骤（`approach`、对抗、擒抱等效果、只在成功后执行的下一步），校验、降级、Rules 与旁白都沿用原路径；诊断定位回脚本所在的位置。
4. **清单与顺序。** 第一批：走到、趴下或起身、擒抱、扛走或拖走、放下、挣脱、推撞、开门或关门；随后跳过；最后躲藏与搜索找人，它们需要新的"谁看不到谁"状态并改变地图投影。攀爬与游泳涉及高程，暂不提供。
5. **战斗中。** 地图按钮调用同一套固定机械（ADR 0091）。

## 影响

- 新增的效果（自己趴下或起身、推开 5 尺、开关门）进入 Rules 的世界互动效果与重放。
- 填写表单多一类步骤，请求体积按实测告知后接受（ADR 0057）。
- 是否稳定由真实调用验证，首个验证用例是"扛到炉边"。
