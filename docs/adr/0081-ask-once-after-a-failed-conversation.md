# ADR 0081：交谈失败后再争取，KP 先问一次

- 状态：已接受
- 日期：2026-10-02
- 依据：排查行动 B（"我再尝试说服莉安"）后，用户要求"玩家多一个跟 KP battle 的选择"，确认了规则：第一次尝试不问；失败后又来争取却没说有什么不同时，先问一次，玩家用自己的话补充或不补充；同一次失败只问一次；硬规则、已固化事实和已掷出的骰子不重议。在"退回并保留原话"和"挂起回答"两种做法之间，用户选了"挂起回答"。
- 当前规则：[SPEC 0001 §19](../specs/0001-llm-kp-responsibility-contract.md)、[SPEC 0004 §2](../specs/0004-kp-and-noncombat-mechanics.md)、[SPEC 0003 §5](../specs/0003-authoritative-action-transaction.md)、[SPEC 0009 §3](../specs/0009-failure-pacing-conclusion-and-interaction.md)、[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)
- 取代范围：SPEC 0001 §19 原先"只在重大危险、显著消耗、攻击同伴或不可逆后果有歧义时澄清"的限定，对交谈失败后的再争取放宽为可以问一次。[ADR 0079](0079-the-kp-rules-a-conversation-retry-from-context.md) 的裁决规则不变：玩家补充后仍没有实质变化，就不再检定，结果写这番话没有起作用。

## 原因

行动 B 中玩家只说"再试一次"，KP 替玩家编了一整段新说辞和新做法，走完 8 次调用、28.1 万输入 token 才得到结果。真人 DM 遇到这种情况会先问一句"这次有什么不同"，玩家补一句理由，或者照原样进行。先问一次，只多一次选择调用，KP 也不必替玩家编理由。

## 决定

1. **在第一次调用时问。** 选择阶段在可以问时多提供一个工具 `ask_player_what_changed`（`threadRef` 加一句 `question`）。冻结上下文里，行动者有一次失败的交谈、且没有后续交谈的 `addressedThreadRef` 指向它，这次失败才可以问。本行动问过就不再提供这个工具。可问的范围由适配器和 Room 按同一份冻结上下文用同一个函数算出（`vnextRetryQuestionThreads`），Room 逐字核对请求。
2. **问题挂在原行动上，不产生世界事件。** Room 从保存的第一次响应里读出问题（与适配器同一个解析函数），把它写进该行动尚未冻结的准备记录（`retryQuestion`），返回待决输入：`clarification` 类，id 为 `retry-question:<提交 id>`。观察结果把它并入玩家的 `pendingInputs`。等待期间这个行动不发任何模型调用。
3. **回答让同一行动接着走。** 回答（自由文字，或 `{decline: true}`）写入同一条准备记录，提问那一轮调用按 ADR 0038 的机制移作审计，然后同一行动在原冻结上下文上从选择重新开始。玩家回答不单独形成一次提交；重发同一回答走同一路径，不同的回答会被拒绝。
4. **回答放在任务消息里。** 选择、填写和修订请求的第二条消息（任务）后面加上问题和回答（以 JSON 引用，回答为 null 表示不补充）以及怎么读它们。系统消息（阅读说明加冻结上下文）与提问那一轮逐字相同，所以续跑的选择调用可以命中提问那一轮写入的缓存。
5. **由服务器写明接着哪次交谈。** 降阶时，每次交谈的 `addressedThreadRef` 都指向行动者与同一 NPC 最近解决的那次交谈（按 `resolvedEventSeq`）；回答了追问的行动，指向问题所问的那次失败。这个字段由服务器推出，KP 的表单里没有它（ADR 0079），Rules 照常核对它指向同一角色和同一 NPC 的交谈。于是只有最新一次交谈可能是"没有后续交谈回应的失败"：玩家带着理由再试、KP 没有问时，那次失败也已被回应，同一个目标不会再被问第二次。
6. **对话记录的顺序。** 行动提交时，在玩家原话之后依次写入 KP 的问题和玩家的回答，只写给提问的玩家；不补充时写"就这样，不补充。"。等待期间，问题显示在待决框里，玩家原话以本地未确认的形式留在屏幕上。
7. **界面。** 待决问题沿用现有的 `clarification` 展示：输入框的文字就是回答。另外加一个"就这样，不补充"按钮，发送 `{decline: true}`。
8. 指引升为 `zhuwei.proposal-guidance/v69`，提问工具的说明和回答块的文字都钉在指引策略里。工作流 hash 随之变化，尚未冻结的方案按 [ADR 0038](0038-reask-unfinished-work-after-a-version-change.md) 重问。

同时修正了两处遥测：`unchangedRetry` 登记为世界裁定（不再是 unclassified）；Rules 诊断以 JSON pointer 字符串给出的路径，按与数组路径相同的字段表识别（不再是 unrecognized）。

## 影响

- 本 ADR 之前产生的交谈都没有 `addressedThreadRef`。已有房间里若有多次未被回应的旧失败，在它们随六轮记忆退出 NPC 视图之前，可能各被问一次；本 ADR 之后的交谈只会留下最新一次。
- 只有交谈能问。非交谈检定失败后，KP 读的材料里没有"这个目标失败过"的记录，要扩展到能力效果、其他检定和 KP 判定的"做不到"，需要先按 SPEC 0004 §11 产生裁定先例，那是下一步，用户尚未决定。
- 一次追问约多一次选择调用。续跑的选择调用与提问那次系统消息和工具前缀相同，预计大部分命中缓存；实际命中以真实调用为准，本次没有真实调用。
- 选择阶段的固定规则文字不变，提问工具和它的说明只在可以问时出现，所以没有可问失败的请求与原来字节相同。
- `AuthorityCommitOutcome` 的 `awaitingInput` 现在允许没有回执，读取缓存结果和到期工作回执的几处改为显式判断。
- 一个行动问而未答时，玩家的输入框发出的就是回答；玩家想做别的事，需要先回答或选择不补充。
