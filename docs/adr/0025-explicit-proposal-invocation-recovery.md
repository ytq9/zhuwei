# ADR 0025：未冻结提案的显式未知调用恢复

- 状态：已接受
- 日期：2026-09-16
- 依据：故障 ZW-mu3qdzkw 的首轮提案在 45 秒中止后成为未知调用，之后的点击一直重读未知状态。用户在确认一次显式恢复方案及其边界后要求“模型速度不是我们可以决定的，但要保证恢复机制工作正常”。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md#72-bundle-语义冻结与一次窄修复)、[SPEC 0011 §2–3](../specs/0011-reliability-correction-observability-and-evaluation.md)。

仅凭未知调用不能证明 Provider 没有执行，因此清空调用、重置状态或释放预算会丢失真实费用与晚到响应的归属。另一方面，尚未冻结任何可执行方案的提案不存在可保护的骰前裁定结果，将这种调用永久封死会使恢复按钮无效。本决定窄取代该阶段未知调用永久禁止替补的行为；保留普通重复请求不重新派发以及其他模型职责的未知调用隔离。

原语义阶段证明保持不可变。替补以版本化后缀关联原物理调用，保存到同一个调用账本，使用原来源和房间预算。准入事务同时取消原调用的裁定资格；旧能力只能补记旧调用的响应和用量，不能更新当前有效阶段。这样能复用现有精确请求和工作流哈希，包括故障发生前已经冻结的请求，不要求改房间 Profile 或重新准备上下文。

Room 负责身份、控制权、冻结边界和恢复次数；调用账本负责费用占额、一次派发及晚到证据。前端发送显式恢复意愿，不能自行决定是否获准。已完成阶段继续从账本返回。包含替补的提案归档使用 v2 宿主格式，同时携带原调用与替补关联；原 v1 归档仍可读，恢复隔离继续执行。使用既有 SQLite 表，不新增表、迁移、远端资源或预算策略。

确定性验收覆盖首轮、填写和修订超时，重复点击，晚到旧响应，两次失败后的停止，来源预算与恢复隔离，以及归档往返。验证恢复机制不等于改善真实模型延迟；本决定保持提案原有 45 秒时限，也不包含发布授权。
