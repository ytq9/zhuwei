# ADR 0065：无新增的补选不结束行动，改为不带选择工具再发一次表单

- 状态：已接受
- 日期：2026-09-27（实现自 2026-09-11 起，`0f60228`）
- 依据：2026-09-11 一间新房里的普通行动在 Rules 看到任何提案前就失败了。可补选的填写轮把选择工具和表单一起给模型，模型把第 1 次的选择一字不差又发了一遍（69 个输出 token）；`vnextProposalAmendmentRequest` 正确地读出“什么都没新增”并返回空，回复随后落到填写解析器，被判为调用了错误的工具且不许修正，行动就此结束。修复改为：这种回复既不是提案也不是补选，服务器把同一请求不带选择工具再发一次，占用补选本来会花的那一次调用；Room 用 `vnextProposalCalledSelectionTool` 从保存的第 2 次响应推出同一结论，不需要修正票。当时没有改 [SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md) 里把“无新增类型的补选”列为技术失败的那句，也没有 ADR。2026-09-27 用户得知这一差异后裁定：不能因此杀死行动，规格按实现改写。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)。
- 取代范围：§7.2 原文里“无新增类型的补选……是技术失败”这一项，以及“第四次仅在保存响应证明补选已发生时存在”对重复选择的遗漏。

## 决定

1. **重复的选择不是决定。** 补选没有新增任何类型、NPC 视图或记忆（含原样重复首轮选择，以及按 [ADR 0064](0064-ruling-kinds-are-decision-values-and-a-selection-naming-one-is-read-without-it.md) 剔除裁决种类后一无所剩的补选）时，服务器把同一张表单不带选择工具再发一次，占用补选那一次调用；下一轮只能是表单。
2. **Room 从保存字节证明这一轮。** 再发的一轮不附带修正票，也不能再次提供选择工具；这一轮的表单若需要它的一次修正，占用第四次调用，与补选后的修正同样由保存的回复和票据证明。
3. **仍不是 clarification、世界内拒绝或成功结果。** 这一轮照常计入 RootAction 的调用、token、费用和延迟预算；其他技术失败项不变。

## 后果

- 这类回复多花一次调用，行动得以继续；回执按“重复选择”记录，便于看它出现的频率。
- 可补选轮的选择工具自 `4ea651c` 起按补选呈现（写明已加载项、只枚举还能新增的），用来减少这类回复；服务器的再发路径仍然保留。
