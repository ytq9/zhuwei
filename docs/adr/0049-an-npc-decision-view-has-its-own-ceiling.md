# ADR 0049：NPC 决策视图有自己的大小上限

- 状态：已接受
- 日期：2026-09-25
- 依据：冻结上下文里每条记录有 64,000 字节的上限，NPC 决策视图也按这个上限冻结，超过就冻结成“不可用”。决策视图收着这个 NPC 持有的全部原话、对话和所见事实。本地预览那一桌，莉安的视图随交谈轮数是 7,708、13,896、20,416、27,572、33,604 字节，每轮约多 6,500，再聊约 5 轮就会超过。超过以后，每次和她交谈都会以 `CONTEXT_INSUFFICIENT`（`social:npc-decision-context-unavailable`）失败。[SPEC 0016 §4.3](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md) 规定大对象上限只作异常防爆保护，不能代表正常可接受规模，而这个上限在一段普通长度的对话里就会碰到。用户同意先提高这个上限，再让冻结内容不再随房间增长（“先做 A 里单个条目的上限，然后接着做 B”）。
- 当前规则：[SPEC 0016 §4.3](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)（条款不变）
- 取代范围：NPC 决策视图沿用每条记录 64,000 字节上限的做法（上下文工作量配置 vnext-1）。

## 决定

1. 上下文工作量配置增加 `maxDecisionViewBytes`，设为 256,000 字节，只用于 NPC 决策视图；其余记录仍按 64,000 字节。配置改为 vnext-2。
2. 超过新上限的决策视图照旧冻结成“不可用”，整份冻结上下文的总上限（160,000 单位）不变。

## 后果

- 按每轮约 6,500 字节估算，莉安的视图要再聊约 34 轮才会碰到新上限。
- 这只是推迟，冻结内容仍随房间增长。让它不再增长是下一步的工作。
- 工作量配置不写进冻结数据，归档也不核对它，所以旧房间不受影响。
