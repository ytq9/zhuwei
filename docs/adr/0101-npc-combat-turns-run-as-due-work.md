# ADR 0101：NPC 的战斗回合作为到期工作，一次决定整回合

- 状态：已接受
- 日期：2026-10-05
- 依据：轮到 NPC 时遭遇会停住，[SPEC 0006 §§6、7](../specs/0006-module-npc-and-faction-protocol.md) 要求 NPC 回合由 KP 按该 NPC 本人的投影决定，不得用默认战术。用户确认这一批实现，费用约为每个 NPC 回合 1–3 次模型调用。
- 当前规则：[SPEC 0006 §§6、7](../specs/0006-module-npc-and-faction-protocol.md)
- 取代范围：无。

## 决定

1. **到期工作。** 遭遇的当前行动者是 NPC、且没有待选或待掷时，Rules 把它的回合列为到期工作。
   - 让它到期的那个请求在尾部接着跑，用该请求的模型通道。
   - 连续的 NPC 回合在同一请求里跑完，直到轮到玩家或有玩家待选，每个请求最多 6 个。
   - 闹钟没有模型通道，不调用模型。
   - 等待中的回合由玩家下一次请求重试。
   - 它不抢占其他输入，回合顺序本身已挡住玩家在 NPC 回合里行动。
2. **一次决定整回合。**
   - 该 NPC 的投影与 Rules 算出的可选项一起发给模型，模型返回整回合的计划：移动、能力、基础动作、预备，最后结束回合，1–8 步。
   - 可选项只列该 NPC 知道的东西：对它躲藏的敌人只以"瞄准一点"出现。
   - 计划逐步交给与玩家相同的战斗输入。
   - 玩家的反应在中途打断时，回答后接着执行原计划，不再调用。
   - 后面的步骤因死亡、目标移动等变得不合法时，计划停下，已发生的保留，并为剩余部分再问一次。
3. **状态与事件。** 执行中的计划存在 `combatRuntime.npcTurnPlans`，以三个内部事件记录：`NpcCombatTurnPlanned`、`NpcCombatTurnStepTaken`、`NpcCombatTurnSettled`。
4. **失败。** 模型失败或回复不合法时，回合停在等待点，不替它选行动、不跳过；同一段决定最多重试 10 次。
5. **不能行动的 NPC。** 已死亡或失能的 NPC 没有可选的行动，直接结束回合，不调用模型。
6. **旁白。** 一个回合段落提交后，按观察者生成一次旁白；被打断后再问的那一段另有一次。
7. **读模型。** 玩家看得到的地图上当前行动者是该 NPC 时，`readModel.npcCombatTurn` 给出 `acting`、`waitingForAnswer` 或 `waitingForRetry`。

## 影响

- 每个 NPC 回合约一次决定调用加一次旁白；遭遇里 NPC 多时费用随之增加。
- 交谈、谈判、投降、起身、趴下、锥形或线形范围的方向和多目标选择还不在计划步骤里。
