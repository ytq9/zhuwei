# ADR 0079：交谈失败后能否再试，由 KP 依上下文判断

- 状态：已接受
- 日期：2026-10-02
- 依据：排查 2026-09-30 本地预览的行动 B（"我再尝试说服莉安"）后，用户在"给表单补上旧交谈选项"和"由 KP 根据上下文判断"之间选了后者："先修让 kp 判断的那个问题"。
- 当前规则：[SPEC 0001 §6](../specs/0001-llm-kp-responsibility-contract.md)（KP 根据虚构情境决定是否检定；同一行动失败后，只有做法、条件、成本或局势发生实质变化时才重新检定；条款不变）
- 取代范围：交谈表单的 `addressedThreadRef`、`retryChange` 两个字段，以及 Rules 对交谈重试的拦截（`socialRetryIssue`：按引用或目标、台词指纹找出此前失败的交谈，再要求声明并核对变化）。战役行动的 `unchangedRetry`（SPEC 0009）不受影响。

## 原因

- 表单给不出旧交谈。选项取自依据引用目录，而目录里从来没有交谈记录；那个房间的 10 个行动，选项数都是 0。两个字段只能填 none，指导却要求 KP 填写。
- Rules 判断不了"实质变化"。做法变化是拿 KP 自己写的做法文字去比对，换个写法就能通过；KP 不声明时，Rules 拿目标和台词逐字比对，换个说法就认不出，碰巧一样时又无法声明真实的变化。
- 行动 B 中，模型越过表单写了失败交谈的编号，同时声明没有变化。Rules 在第 8 次调用、28.1 万输入 token 之后才拒绝。同一份计划去掉那个编号，Rules 会放行第三次掷骰。
- 判断需要的材料已经在上下文里：NPC 决策视图的 conversation 记录列出此前每次交谈说了什么、结果如何。

## 决定

1. 交谈表单和 KP 方案不再有 `addressedThreadRef`、`retryChange`；降阶交给 Rules 的计划里，这两项一律为 null。
2. Rules 不再拦截交谈重试。交谈线程照旧记录，包括指纹和基线，记录格式不变；此前提交的、带这两项的事件照旧通过校验和回放。
3. 指导改写原句：npc-decision 的 conversation 记录里，行动者为同一目标对该 NPC 的交谈已经失败，而做法、条件、成本和局势都没有实质变化时，不再检定，result 写这番话没有起作用；换措辞不算变化。
4. 指引升为 `zhuwei.proposal-guidance/v68`，解析器升为 `kp-vnext2-proposal-parser-v79`。工作流 hash 随之变化，尚未冻结的方案按 [ADR 0038](0038-reask-unfinished-work-after-a-version-change.md) 重问。

## 影响

- 原样重试由 KP 在填写时直接给出世界内的结果（NPC 不松口），不再在提交时以系统提示拒绝。
- 没有确定性的兜底：KP 若替玩家编出新做法再安排检定，Rules 不会拦。行动 B 中 KP 就这样做过。这只能靠指导约束，需要真实批次观察。
- 交谈表单少两个字段，含交谈的选择请求随之变小；指导里的那句话比原句短。
- 本次没有真实模型调用。
