# ADR 0095：一次修订列出所有问题

- 状态：已接受
- 日期：2026-10-04
- 依据：[round164](../agent/receipts/vnext-round164-validation.md) 的 164-4（扛到炉边再放下）用完三轮修订仍未提交：KP 依次犯了四个不同的错（有检定却没有把步骤放进 check、扛走没用对抗、多写字段并漏写 sceneRef、时长写成 none），而每轮修订单只列出最先遇到的一类。用户要求"修订单一次列出所有问题"。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)（本地表单错误与 Rules 预检错误共用一次修订额度，后者由 Room 对保存的草稿执行同一 lowering/Rules 预检证明）
- 取代范围：无。

## 原因

修订轮次有限，每轮只告诉 KP 一类问题时，问题多的草稿必然用尽轮次。校验器已经逐个步骤汇总；没有汇总的是 lowering（第一个失败的步骤即返回，时长要等所有步骤都降级后才判断）、常用动作的检查（第一个不符即返回），以及解码就失败的草稿（不产出草稿，后面的检查都不运行）。

## 决定

1. **lowering 跑完所有步骤。** 一个步骤失败后继续降级其余步骤，失败的诊断与重复的常用动作、按步骤表单提前判断的时长规则合在一起返回，按约束与路径去重。时长的正式判断仍在原处，规则不变。
2. **常用动作一次列全。** 每个常用动作的所有不符（需对抗、对抗项、不能检定、跳跃与躲藏的检定、被抱者的感受、跳不过去）一起报告。
3. **被本地退回的草稿也读常用动作。** 解码与领域校验退回时，追加只看草稿就能判断的常用动作问题（不需要谁抱着谁、地图的部分留给 lowering）；解码在放置步骤时就失败的，用已解码的部分步骤读，只用于报告，不作领域输入。路径换成 KP 写的线上位置。
4. **不增加权限。** 追加的诊断由草稿或 Room 的 lowering 推出，调用方不能单独授予修订；修订额度与轮次不变。解析器契约升为 v81，旧版本生成的修订单不会被当作新版本恢复。

## 影响

- 一张修订单可能比以前长；提示词不变。
- 是否减少修订用尽，由重跑 carry-put-down 的真实调用验证。
