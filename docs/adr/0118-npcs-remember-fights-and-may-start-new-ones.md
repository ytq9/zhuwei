# ADR 0118：NPC 记得打过的仗，也可以自己开战

- 状态：已接受
- 日期：2026-10-05
- 依据：用户裁定（2026-10-05）："投降 NPC 按照自己的视角决定，可以部分投降，也可以投降后反叛，这要看 NPC 的决定。"遭遇中的部分投降、停手和改口由并行的 ADR 0117 处理；本 ADR 处理战斗之后。当时战斗不产生任何知识记录，战斗结束后 NPC 对它一无所知；NPC 的当场反应只能用 worldInteraction，到期的本人工作也没有开战的表单，所以投降过、被饶过的 NPC 没有任何途径再动手。
- 当前规则：[SPEC 0012 §13](../specs/0012-part-b-abilities-damage-and-conclusion.md)（战斗记忆、再次开战建立新遭遇）、[SPEC 0006 §7](../specs/0006-module-npc-and-faction-protocol.md)（NPC 本人开战）。
- 取代范围：[ADR 0060](0060-bystander-reactions-run-on-the-spot-and-lapse-on-failure.md) 决定 2 中"反应只用 worldInteraction"：当场反应另可用 startCombat。[ADR 0112](0112-vnext-kp-ends-combat.md) 影响里"投降或停战后某个 NPC 重新敌对"在战斗结束之后的部分由本 ADR 补上。

## 决定

1. **战斗记忆由 Rules 记在遭遇上，结束时交给 NPC。**
   - 战斗进行时，事件折叠顺带在遭遇记录里记一本账（`fightMemory`），只记每个 NPC 参战者察觉到的、和它本人有关的事：谁攻击它、它攻击谁，次数和得手次数，谁把谁打倒，它与别人之间谁不再或开始敌对及原因。
   - 察觉的条件与战斗观察者相同（在遭遇场景里），另加：活着、清醒、生命值高于 0。倒下或离开之后发生的事不记。
   - 账按对手一行计数，打得再久也不变长。掷骰、伤害数值和生命值不记。
   - 账只存在 Rules 状态里，玩家与 NPC 的投影、KP 的冻结上下文都不带它（投影只取遭遇的固定字段）。
   - 玩家接受结束、`EncounterConcluded` 提交时，同一个根里为每个活着、在任的 NPC 参战者追加两条事件：一条只有 Rules 可见的观察事实（沿用 `worldInteractionSensoryEvidence`，观察者是该 NPC），一条只给该 NPC 的 `SensoryEvidenceAcquired`。正文是几句中文，例如"与爱丽丝在蒸汽廊道交战。爱丽丝对本人出手1次，得手1次。……本人投降，不再与爱丽丝为敌。投降被接受，战斗结束。"结束时它已倒下或离开，最后一句改成"本人倒下后的事不知道。"或"本人离开后的事不知道。"
   - 记忆是普通知识记录，靠已有的选取（[ADR 0111](0111-a-layered-knowledge-directory.md)、[ADR 0115](0115-long-play-context-stays-bounded.md)）进入该 NPC 之后的当场反应、到期工作、交谈回答和主持 KP 冻结的该 NPC 视图：刚结束时它在最近六轮里，正文照发；更早时按目录行和话语涉及的内容读取。
   - 为什么不用玩家的 Claims：Rules 的 `step` 读不到事件日志，Claims 由 Room 从提交范围生成，不能作为 Rules 写知识的依据。账在折叠里按同一套事件记下，回放得到同样的结果。
   - 只在新版 Profile（world-interaction 扩展）下记账和发记忆，旧 Profile 的战斗事件不变。
2. **玩家角色不得到这条记忆。** 玩家的决定由玩家本人作出，他读过这场战斗的旁白；之后玩家对 NPC 提起这场战斗时，回答它的是该 NPC 本人的记忆。给玩家角色也加一条，会在其后每次冻结里占用行动者最近六轮的正文，却没有读它的消费者。
3. **NPC 本人开战。**
   - 当场反应（察觉、擒抱、听到交谈）的工具加上 startCombat 表单；到期的本人工作在选择阶段可以选 startCombat，单独填写。
   - 说明只写开战做什么，不写何时开战。NPC 用自己的一份填写说明（`NPC_START_COMBAT`），代替主持 KP 那份"互相敌对写两条"的说明：参战者只列本人和本人要攻击的生物；敌对关系只写本人这一方，对方是否还手由对方决定；本人还没有战斗属性时按模组里本人的属性行写一次，不为别人写。
   - 该 NPC 本人的冻结视图在它还没有战斗属性时带上它自己的模组属性行（`npcCombatAnchors` 只留它自己），别人的属性行仍只给主持 KP。
   - Rules 对 NPC 发起的开战另查两条（降级和 `step` 共用 `combatStartIssues`）：每条敌对的 `fromRefs` 只能是该 NPC；参战者恰好是该 NPC 和它敌视的对象。反应没有修订机会，违反时这次反应作废（lapse）。
   - 开战按已有的 `startCombat` 执行：遭遇编号由这次反应或工作的根派生，所以投降、被饶过之后再动手是一个新遭遇，旧遭遇保持结束。对象已在进行中的遭遇里时是加入。
   - 原子执行结束时，行动者若有尚未结算的当场反应，就在这里结算为 reacted；worldInteraction 步骤仍在自己的结算里关闭它。到期工作原本就在这里记为开始。
4. **玩家掷先攻时，同一动作的其他反应照常结算。** NPC 的反应开战后要等玩家掷先攻。之前回复发布时，续办只看这次掷骰恢复的那个到期根的后代，同一动作里排在它后面的另一个反应就留到了下一次请求。现在续办的根若本身是到期工作，就沿它的起因找到引发它的那次动作，从那里判断还欠哪些到期工作，与没有指定续办根时相同。
5. **探针。** 新增 `combat-spared-rebel`：开局在奈斯身边交战，玩家要他投降，接受结束后背对他取走黑橡叶。他是否投降、是否反应、是否再开战都由他决定；接受结束的一步检查他记得这场战斗。`combat-strike` 接受结束时也检查倒下但活着的奈斯记得。

## 影响

- 请求体积（主持 KP 的 22 项选择不变；以下是 NPC 本人的请求，未接受，未运行 `--accept-request-size`）：
  - 当场反应：探针夹具里瓦罗的反应 16,847 → 18,417 token（+1,570，其中表单 +1,226）；模组 NPC 还没有战斗属性时另加本人属性行一行。
  - 到期工作：选择阶段 6,779 → 6,960（+181）；填写 worldInteraction 19,425 → 19,435（+10）；填写 inventoryOperation 14,969 → 14,979（+10）；新增填写 startCombat 10,900。
- 反应与工作的绑定哈希 schema 升为 `npc-reaction-vnext-4`、`npc-work-vnext-5`，尚未冻结的工作按 [ADR 0038](0038-reask-unfinished-work-after-a-version-change.md) 重问。
- 遭遇记录多了 `fightMemory` 字段；状态哈希已不校验（ADR 0054–0056），旧房间回放时同样重建。
- 没有做的：
  - 不参战的旁观 NPC 看到的战斗不记。
  - 记忆不写同一方其他人的遭遇（例如同伴被谁打倒）。
  - NPC 不能把还没有战斗属性的另一个 NPC 列为开战对象（它不知道对方的属性行，降级会拒绝）。
  - 遭遇中的投降、停手和改口归 ADR 0117。
- 本次没有真实调用验证。
