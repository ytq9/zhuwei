# ADR 0124：普通主持读取已成立的局势

- 状态：已接受
- 日期：2026-10-06
- 依据：用户批准同一模组的沙盒剧情接续方案。[SPEC 0001 §§11、16](../specs/0001-llm-kp-responsibility-contract.md) 要求当前计划和后果持续影响世界；[SPEC 0009 §1](../specs/0009-failure-pacing-conclusion-and-interaction.md) 要求问题解决后转入下一场景。
- 取代范围：补齐 [ADR 0122](0122-story-continuity-uses-the-current-atomic-proposal.md) 仅默认读取开放问题和最终结局、未保存中间问题答案供本人长期检索的边界。不修改产品条款，也不把剧本的发展建议直接执行为世界事件。

## 决定

普通冻结上下文仍由现有 context 管道构造。除了开放问题及最近结局，每个进行中故事读取最近一个已回答问题；更早的答案沿本人知识目录回读。`SceneQuestionAnswered` 记录回答时的事件序号，并只为受众固化私有记忆。答案的来源、权限、重放及归档均使用现有事实和知识事件；当次旁白由问题回答的 Claim 承担，不重复播报新增记忆。

场景答案和结局的事实记录显式保留记忆持有者，按与感知记录相同的读取条件进入事实材料。否则旧记忆虽然退出近期窗口，仍会经场景／人物的事实关联再次整批载入。200 条旧答案和结局的回归用例证明：普通请求只读取最近六轮正文，其余保留在本人分层目录；显式回读仍绑定原记录。

同场景里实际保存的待执行、已排期或推迟的 NPC 计划进入主持上下文，即使本次玩家没有点名该 NPC。目录绑定当前计划集合的版本，只提供本场景选中引用；正文分别绑定原记录。读取遵守现有工作预算，超限明确失败，不静默删除必要依据。已结束计划、异地计划和完整剧本不由这条入口载入；NPC 的独立请求仍由 `npcOwnRequiredContext` 从本人视图另建，不能继承主持材料。

计划是已经成立的意图，不是已经发生的结果。形成计划不产生其未来痕迹；执行、取消或修改继续走既有 ActorPlan 和虚构时间。准备稿候选的本人采纳工作另待持续调用成本的确认，不在本决定中隐式启用。

本次沿 [ADR 0120](0120-a-new-runtime-version-retires-open-rooms.md) 更新本地 runtime 为 `runtime-srd51-2014-authoritative-vnext-stage3-v5`；不因此部署或迁移现有远端房间。未增加固定 prompt 或模型调用；新增的动态输入只在有关记录存在时出现，仍受 ADR 0058 的 90k 输入门约束，放在随上下文变化的材料中。

## 验收接缝

`tests/kp/stories/story-continuity.room.test.ts` 从相同模组开场比较公开与秘密调查：实际知情的 NPC 可以依据那条知识形成计划，未获知的 NPC 不能引用玩家私有发现；下一次不点名 NPC 的普通主持读取已形成计划，玩家投影不取得其私有下一步。另覆盖问题回答、下一问题、私人受众、驱逐及归档恢复。到期计划执行沿 `tests/kp/npc/npc-plan-formation.room.test.ts` 的真实 Room 接缝验证。

这些是确定性本地证据。不同真实模型选择能否长期持续、剧本候选的采纳和多人多路线样本仍按实施方案分别验收。
