# ADR 0129：补全按已选机械片段加载表单

- 状态：已接受
- 日期：2026-10-06
- 依据：用户要求精简补全表单并优化调用；[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md) 已要求按所选类型加载填写面。
- 取代范围：ADR 0128 实现中统一 `completeObject` 选择携带全部机械 schema 的加载方式。补全产品规则、Rules 操作、权威事件和持久化结构保持不变，不修改已裁定 SPEC。

## 原因与决定

NPC 战斗数据和完整物品定义是不同的填写材料。一项补全需要其中之一时，另一项不应占用请求；按玩家用词猜测需要什么又会把选择职责移到服务端。

沿用现有首轮扁平类型选择，按同一领域 schema 的判别值提供 `completeObject`（描写／开关）、`completeItem`、`completeNpcCombat`、`completeTerrain` 和 `completeDurability`。只加载实际选中的机械片段与依赖，现有补选次数、预算和恢复规则不变，没有新增模型阶段。

填写仍用一个 `steps.completeObject` 数组：多个已选机械种类共用引用、摘要和冻结字段，保留原步骤顺序，不能因拆分选择把一项准备排到另一项之后。内部仍是原 `completeObject` 操作，目标、版本、缺项和秘密权限继续交给现役 Rules 检查。所选片段保存在原调用账本中；没有选择的片段即使形成合法领域提案也不能提交。

修订沿用原精简表单和已发送消息前缀，Room 从保存的选择／补选响应重建同一请求。公共补全约束只写一次，各片段只写自身说明；未涉及的 NPC、物品和地形结构不随其他片段发送。完整物品内容和 NPC 战斗数据仍与已有创作／开战表单共享 schema。

## 验收范围

能力合同：同一次行动只传递 KP 选中的补全材料，既有操作、调用阶段和恢复语义不变，原对象的后续真实操作仍能执行。代表性矩阵：物品补全后操作；NPC 补全并开战；多种片段同选共用表单；未选择种类拒绝；补选与修订／恢复保留精确片段及缓存前缀。

成本按选择、单片段填写和代表性组合分别测量，不能只报告一个最小表单而隐藏选择目录成本。请求体积沿用原保守计数器和预算上限；本地脚本测量不等于真实模型用量。测试与测量证据见[本地验收回执](../agent/receipts/completion-schema-routing-local-20261006.md)。
