# ADR 0074：显式恢复也用于结果未知的 NPC 作答调用

- 状态：已接受
- 日期：2026-09-29
- 依据：实现 [ADR 0073](0073-an-npc-writes-its-own-reply-from-its-own-view.md) 后向用户说明，NPC 作答调用超时后行动不能恢复；用户选定“扩展到 NPC 作答调用”。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)。
- 取代范围：取代 ADR 0073 “影响”里“作答调用结果未知时行动不能恢复”一条，以及“决定”里把作答调用记为 NPC 调用的说法。[ADR 0038](0038-reask-unfinished-work-after-a-version-change.md) 和显式恢复原有的资格、次数和隔离规则不变。

## 原因

NPC 作答调用是一次普通的模型调用，会超时或断连。ADR 0073 沿用了 SPEC 0016 §7.2 原文“此例外不扩展到 NPC 的未知调用”，于是这次调用结果未知时，玩家只能重新提交行动，已经完成的选择和裁决调用都作废。

原文里的“NPC 调用”指 NPC 自己做决定的调用：察觉后的当场反应、履行承诺的工作和待决输入。它们不属于玩家这次行动的方案。作答调用不同：它回答的就是这份方案，方案在它返回之前不会冻结。

## 决定

NPC 作答调用是它所回答的方案的一个阶段。结果未知时，玩家显式点击恢复后，Room 可以用同一来源根行动的那一次替补调用重发原请求。

- 这一次替补与选择、补选、填写、修订共用，不按阶段另加。裁决阶段已经用过替补的行动，作答调用结果未知时不能再恢复。
- 替补使用原精确请求。原未知调用保留为私有证据，晚到的原响应不参与方案。
- Room 把作答调用记在方案的调用键空间里（`proposal:<preparedActionId>:<序号>`，序号从 11 起），用途标为 proposal。替补准入、归档和恢复沿用已有实现。
- NPC 自己做决定的调用和冻结旁白的未知调用仍不适用显式恢复。

## 影响

- 作答调用超时后，页面显示与裁决调用超时相同的恢复入口。
- 账本里按用途统计时，作答调用计入 proposal。
