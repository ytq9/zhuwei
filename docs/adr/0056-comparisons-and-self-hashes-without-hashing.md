# ADR 0056：比较不再经过哈希，自带哈希的对象不再重算核对

- 状态：已接受
- 日期：2026-09-25
- 依据：用户问去哈希第三步能否保证功能正常。回答是剩下的哈希多数在实际功能里起作用，只能分两部分做；用户对「3a：比较用途的哈希改成直接比较，纯核对的删掉」回答「可以」。版本号、身份、id、幂等、骰子绑定、Profile 版本和 D1 键留在 3b，另行设计。前两步见 [ADR 0054](0054-archives-are-copied-without-replay-checks.md)、[ADR 0055](0055-events-state-and-replay-carry-no-hashes.md)。
- 当前规则：[SPEC 0003 §3](../specs/0003-authoritative-action-transaction.md)；[SPEC 0005 §10](../specs/0005-world-facts-and-knowledge.md)；[SPEC 0011 §6](../specs/0011-reliability-correction-observability-and-evaluation.md)；[SPEC 0013 §3.3](../specs/0013-versioned-runtime-profiles.md)。
- 取代范围：SPEC 0003 §3 随机结算恢复重新验证 recovery envelope 的 hash；SPEC 0005 §10 「哈希不符的分支图」；SPEC 0011 §6 恢复前验证 recovery hash；SPEC 0013 §3.3 「上述字段用于局部完整性验证」。

## 决定

1. 判断两个值是否相同时，直接比较它们的规范 JSON。`sameCanonical` 得出的结果与原先比较两个 canonical SHA-256 相同，对非规范值也抛出同样的错误；归档一侧的 `sameArchiveJson` 对应 `archiveSha256`。只为检查规范 JSON 而算哈希的地方，改用 `assertCanonical` 或 `assertArchiveJson`；按内容去重改用规范 JSON 文本作键。
2. 自带哈希的对象不再重算自己的哈希来核对，包括：故事归档信封、宿主载荷、故事账本快照、D1 分块、世界归档与历史分支的源归档、故事库的制品/条目/种子/目录/快照、故事上下文与冻结上下文、世界事件触发器与宿主上下文、旁白上下文与旁白材料、渲染声明与权威声明、修订工单、冻结条目的版本号、NPC 决策投影、随机请求、能力注册、章节连续性清单、环境定义、随机结算恢复记录、历史会话行。这些哈希字段照旧写入，仍作为名称或键使用。
3. 已存对象连值一起保存时，直接与这个值比较，不再比哈希：冻结的知识目录、故事准备稿、能力注册里的定义、场景几何。
4. 留在 3b：只存了哈希、没有存值的比对，包括读取集版本、Profile 与工作流版本、事件里记录的前置与后置哈希、冻结计划和复核帧的哈希；由哈希生成的 id；幂等载荷哈希；骰子承诺；D1 键；Profile 内容核对。事件里记录的前置哈希不只是核对：暂存行动重排到新的基准上时，靠它发现事件已经过时，所以不能直接删。

## 后果

- 真实房间 9DCMQN 的归档（40 个事件）在本地：从创世重放一次约 136 → 118 毫秒 CPU，读取校验归档约 46 → 11 毫秒。重放里仍有约 22% 花在哈希上，主要是读取集版本、NPC 决策记录、定义快照、投影哈希和 Profile 版本，属于 3b。
- 不再能发现：上述对象的内容被改动而哈希未改。只测这类篡改的用例已删除，或改为只测结构；故事归档 D1 的「重算分块哈希」用例改为由检查点的世代发现。
- 行为不变的部分：约 220 处哈希相等比较和十余处「值与已存哈希」比较改为直接比较，Node 套件与 Worker 套件的结果与改动前相同。
