# ADR 0023：放宽旁白等待窗口，保留冻结恢复身份

- 状态：已接受
- 日期：2026-09-15
- 依据：用户在确认线上 MBDE3S 每次约 45 秒失败、获知生成与审核共用时限后，明确要求“先把超时窗口改宽，确保玩家至少能正常游玩”。
- 当前规则：[SPEC 0011 §2](../specs/0011-reliability-correction-observability-and-evaluation.md#2-slo)。

原总窗口会在较慢但仍可完成的生成之后拒绝开始审核；仅改外层计时器又会被 Room RPC 内的旧传输计时器中断。本决定窄取代 SPEC 0011 §2 对冻结旁白沿用通用调用时限的部分，保留延迟优化目标与其他阶段的时限。

剩余时限作为服务端调用参数穿过旁白适配、Room 和物理传输，独立于 Provider 请求正文。发布有效期从同一超时常量派生并留出回写余量。时间控制不进入模型/Profile、冻结 Provider 请求或外部调用身份，既有房间和已存生成/审核响应仍按原身份恢复。

既有持久化预算及其哈希保持：外部调用账本的 `elapsedMs` 预留是冻结的入账估算与未知状态判定依据，不是物理请求的强制截止；完成仍记录实际耗时并受原来源累计额度约束。不能因改等待窗口而改写旧预算账户、已提交事件，或重新派发未知调用。

这项调整允许慢回复继续完成，不能证明 Provider 延迟、最初的 Room 通信故障或长期游玩成功率已经恢复；对应证据由当次发布回执记录。
