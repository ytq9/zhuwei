# ADR 0055：事件、世界状态和重放不再使用哈希

- 状态：已接受
- 日期：2026-09-25
- 依据：用户裁定「不要算哈希，这没用，都去掉」，并确认分三步去掉哈希，保留登录与会话哈希和日志脱敏，已有房间继续可读；远端 migration 另行请示。本 ADR 是第二步，第一步是 [ADR 0054](0054-archives-are-copied-without-replay-checks.md)。第一步部署后，线上房间 9DCMQN 的归档（40 个事件）在本地从创世重放一次仍要 1.6 秒 CPU，主要花在每个事件对整个世界状态做规范化 JSON 和 SHA-256、逐条核对事件哈希链，以及重新执行冻结选择的行动片段来比对记录。
- 当前规则：[SPEC 0003 §2.1、§10、§11](../specs/0003-authoritative-action-transaction.md)；[SPEC 0011 §6、§7](../specs/0011-reliability-correction-observability-and-evaluation.md)；[SPEC 0013 §3.2、§3.4](../specs/0013-versioned-runtime-profiles.md) 与[分册 §9](../specs/0013-part-c-time-and-conformance.md) 的 P04、P05、P07、F08。
- 取代范围：SPEC 0003 中 step 状态缓存与状态哈希一致、replay 验证状态哈希、增量读取的起止哈希；SPEC 0011 §6 的逐条事件副本与哈希链、§7 的 hash-bound `CorrectionContext` 与「审计不进入状态哈希」；SPEC 0013 事件 envelope 中的 payload hash、前一事件 hash、前后状态 hash、scope proof hash，以及 replay 验证 hash 链和状态 hash；ADR 0054 决定 4（事件照旧写入哈希字段）。

## 决定

1. 新事件不再带载荷哈希、前一事件哈希、前后状态哈希、作用域证明哈希和事件哈希，按 `eventSeq` 与 `parentEventId` 衔接。已有事件里的这些字段照原样保留，不再读取或核对。
2. 世界状态不再保存头部事件哈希，折叠时删去旧状态里的这一字段。`replay` 按记录折叠事件，只检查结构、序号连续、父事件衔接、分支、Profile 和虚构时间；不计算状态哈希，不比对事件哈希，也不重新执行冻结选择或行动片段来比对已记录的事件。
3. 重放头部由 runtime epoch、事件序号、genesis 哈希和最后一条事件 id 组成。同一 runtime epoch 内事件序号不重复，所以序号与最后一条事件 id 标识一个状态。更正请求的基准、NPC 待办与故事上下文的新鲜度、增量读取游标、暂存机械的基准和归档检查点都按它们判断是否过期。
4. 作用域证明改为交易作用域，只列读取、写入和创建的权威引用，供原子交互核对它导入的原生事件；不再计算证明哈希。随机数能力按状态版本号绑定。
5. 更正审计记录另存该事件的载荷。同一根内后续事件核对此前事件（社交结算的首句与后续事件、代价前缀、骰子、反应回答、死亡、物件补全）时比较载荷内容，不再比较载荷哈希。
6. D1 不再写逐条事件、创世和投影审计副本：故事归档已带完整世界归档，没有读者使用这些行。归档检查点里两个 NOT NULL 的旧哈希列改存最后一条事件 id 与空串；Room 暂存机械的 `base_event_hash` 列改存基准状态的最后一条事件 id。不做远端 migration，旧表和旧行保留、不再读取。
7. 已有房间照常可读：旧事件的哈希字段、旧检查点、头部带事件和状态哈希的旧归档、旧 Receipt 的 `scopeProofHash` 都被接受，不再核对。

## 后果

- 9DCMQN 的 40 个事件从创世重放：CPU 从 1.6 秒降到约 0.14 秒。整份世界状态的哈希只在创建 genesis 时计算一次，由第三步去掉。
- 审计为仍在执行的根多存事件载荷：9DCMQN 当前 12 条审计记录多 50 KB，状态共 299 KB。
- 不再能发现：事件或状态被改动、重放结果与原执行不同、冻结片段的记录与重新执行不一致。依赖这些核对的拒绝路径及其测试一并删除。
- 仍在使用、由第三步处理的哈希：冻结上下文 `contextHash`、知识 `revisionOrHash`、投影哈希、阶段证明、Profile 与工作流哈希、幂等载荷哈希、骰子承诺、genesis 哈希、归档内容哈希、`damagePacketHash` 等。
