# ADR 0114：新建地点的门第一次用到时补全

- 状态：已接受
- 日期：2026-10-05
- 依据：
  - KP 新建地点的地图可以画门，但 KP 的几何表单不带状态图与耐久。这样的门开不了、关不了、开不了锁，也打不坏。
  - 用户说明："比如这次的门，一开始建地点时没有完整补全，等用到时要完整补完"。
  - SPEC 0015 §11.1 已规定对象的 AC、耐久与状态图由 KP 决定，并在任何骰面前固化。
- 当前规则：[SPEC 0014 §4](../specs/0014-observer-tactical-map-and-environment.md)、[SPEC 0015 §11.1](../specs/0015-part-c-adoption-and-observability.md)
- 取代范围：无。

## 决定

1. **标准门状态图共用。** 模组门用的状态图搬到 Rules 的公共位置，模组和补全的门共用同一份：
   - 状态：开、关、上锁、毁坏；
   - 开锁转换只由 KP 裁决的一步走；
   - 免疫毒素与心灵伤害。
2. **补全写在 completeObject 里。** 用到一扇还没补全的门时，KP 在同一次行动里用 completeObject 写明：
   - 它现在开着、关着还是上锁；
   - 它的 AC 与耐久。
3. **Rules 先补全再执行。** Rules 记一条补全事件（`EnvironmentFeatureCompleted`，由原子步骤 `completeEnvironmentFeature` 提交），装上状态图与耐久，再执行同一行动里的开门、开锁或关门。这条事件可以回放，也可以纠错。
4. **没补全就退回修订。** 门没补全就写开门时，退回 KP 修订，说明要先补全。

## 影响

- completeObject 多一个门的机械栏位，只在有需要补全的门时提供：提供时请求多约 166 token。开门那句说明多约 16 token，没有需要补全的门时不出现。
- 修订不能新增选择的类型，所以开门的说明里也写了要同束补全。
- 模组的门数据不变。
