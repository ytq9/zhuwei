# ADR 0073：NPC 在交谈中说的话由本人单独作答

- 状态：已接受
- 日期：2026-09-29
- 依据：用户看过 round152 的结果后问“提案阶段为什么会有台词”，在三种做法里选定“台词单独生成”，并要求由实现方划分裁决、NPC 和旁白各自负责的内容；随后确认了四处规格改动。真实批次的额度用户决定在实现完成后再定。
- 当前规则：[SPEC 0006 §7](../specs/0006-module-npc-and-faction-protocol.md)、[SPEC 0009 §2](../specs/0009-failure-pacing-conclusion-and-interaction.md)、[SPEC 0016 §7.2、§7.3](../specs/0016-part-c-compound-actions-and-claims.md)。
- 取代范围：取代 [ADR 0037](0037-branch-bound-outcomes-and-quoted-npc-lines.md) 决定第 1 条里“NPC 台词不超出分支摘要”的部分；摘要仍是结果说明和后果的上限。取代 [ADR 0015](0015-coarse-forms-frozen-context-and-typed-claims.md) 所记“一次裁决调用填写完整的成败分支”中交谈回答的部分。[SPEC 0001](../specs/0001-llm-kp-responsibility-contract.md) §14 和验收场景 K 不变，本决定是它们的实现方式。

## 原因

[round152](../agent/receipts/vnext-round152-validation.md) 第三问里，玩家问莉安第三份遗嘱在哪，莉安的台词指向了神龛。莉安本人的记录只有“父亲说过还有第三份遗嘱，没有见过原件，也不知道藏处”；藏处写在剧本核心真相里，只有主持人该知道。

原因在调用的结构上。裁决调用同时拿着主持人的全部材料和 NPC 的决策视图，又由它来写 NPC 的台词。提示词要求只按 NPC 本人的知识回答，但两类材料在同一次调用里，模型写台词时用了主持人的材料。台词写出来以后只有结构校验：字段是否齐全、引用的记录是否属于这名 NPC。文字有没有超出这些记录，没有任何一步核对。旁白审核也发现不了，因为台词对旁白来说是已经冻结的事实。

仓库里 NPC 自己做决定的调用（察觉后的当场反应、履行承诺的工作）已经只给 NPC 本人的视图。

## 决定

三方各自负责的内容：

| 内容 | 谁决定 | 读到什么 |
| --- | --- | --- |
| 对方是谁、对方听到什么、要不要检定、DC、风险、耗时 | 裁决 | 主持人的全部材料 |
| 对方亲眼看到行动者做了什么 | 裁决 | 同上 |
| 值得注意的环境细节、感官证据、物品变化、交给 NPC 知道的新事实 | 裁决，先固化为事实或叙述承诺 | 同上 |
| 行动者自己的承诺和对既有承诺的变更 | 裁决 | 行动者说出口的话 |
| NPC 说的话或沉默、私下的动机、依据本人的哪些记录 | NPC 本人的调用 | 本人的视图，加上听到和看到的内容 |
| NPC 自己的承诺、改约、债务，对说话人态度的变化 | NPC 本人的调用 | 同上 |
| 语气、把结果讲清楚、衔接 | 旁白 | 冻结的结果、NPC 的声口、裁决固化的环境细节 |

- NPC 的调用读不到裁决写的文字。目标、做法、摘要、风险和检定用的技能都不传给它；检定的成败只告诉它这番话对自己有没有起作用。
- 模组为主持人列出的“该 NPC 不知道什么”不进入 NPC 本人的视图。这份清单的条目本身就是 NPC 没听说过的事。
- 回答并入裁决方案后再整体校验和 lowering。合并后的方案与原先的形状相同，Rules、事件、回放和旁白不变。NPC 改约时引用的原话由服务端取回答的正文填写。
- Room 把作答调用记在它所回答的方案名下，排在裁决调用之后（序号从 11 起）。提交前 Room 核对方案里的每份回答都是本人调用保存的那一份。
- 作答调用的提示词和表单版本并入工作流版本。
- 提案提示词升为 `zhuwei.proposal-guidance/v67`，解析合同升为 `kp-vnext2-proposal-parser-v76`。

## 没有采用

- 给台词加一次审核：改动小，但审核本身会漏，round149、round150 的旁白审核已经出现过。
- 只加强提示词：原提示已有“只按本人知识回答”，没有拦住。
- 第一版让裁决为每个分支圈定 NPC 可以说的记录：能保留剧本里“失败时只说到哪一层”的节奏，但提示词和实现都更多。用户选择先不做。

## 影响

- 每名被交谈的 NPC 多一次调用，重问时再多一次。
- 裁决的交谈表单去掉了台词和 NPC 一侧的四张表，提案请求变小；作答调用有自己的提示词和表单。
- 阶段记录表 `authority_vnext_stage_proofs` 和 `authority_vnext_superseded_stage_proofs` 的序号约束由 1–6 改为 1–138。已有房间在 Durable Object 启动时原地重建这两张表并保留全部记录。
- 作答调用结果未知时行动不能恢复，玩家需要重新提交行动。是否把显式恢复扩展到作答调用，尚未裁定。
- 交谈摘要不再约束台词。失败分支里 NPC 说到哪一层，由 NPC 按“这番话没有起作用”和本人的目标、行为边界决定，效果需要真实批次确认。
- NPC 本人的视图只含冻结上下文里已读取正文的记忆和目录里的摘要。话题需要更早的记忆时，由选择阶段按 handle 读取；选择阶段没有读取的，NPC 作答时也读不到。
