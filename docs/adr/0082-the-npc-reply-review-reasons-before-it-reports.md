# ADR 0082：回答审核在 DeepSeek 上先低档思考再报告

- 状态：已接受
- 日期：2026-10-02
- 依据：用户指出旁白审核开思考工作得很好；看过低档思考的对照实验后回复“可以，开吧”。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)（同一有效裁决版本的整组回答另经一次主持人审核；审核回复读不出时同一请求重发一次；条款不变）
- 取代范围：回答审核在 DeepSeek 上“不带思考、强制调用工具、输出上限 4,000”的传输选择，以及它沿用的 45 秒调用超时。其他服务商不变。

## 原因

[低档思考实验](../agent/receipts/deepseek-low-effort-thinking-probe-20261002.md)重发了 6 次保存的回答审核：

- 不带思考时，行动 B 的两次审核面对完全相同的回答和候选，一次批准、一次退回；低档思考两次都批准。
- 三次原本通过的审核改为退回：莉安在成功分支被告知 `swayed=yes`，台词却仍然拒绝讲，成功与失败两支都是拒绝。不带思考的审核放过了这些回答。
- 格式 6/6 合格；耗时中位 21.9 秒，最长 34.3 秒；思考中位 3,566 token。

旁白审核从 [ADR 0069](0069-the-deepseek-narration-review-reasons-before-it-reports.md) 起用同样的做法，保存的 22 次调用没有违规。裁决填写开思考则需要约 1 分钟，不采用（[实验回执](../agent/receipts/deepseek-thinking-filling-probe-20261002.md)）。

## 决定

1. DeepSeek 上的回答审核请求使用 `thinking: enabled`、`reasoning_effort: low`、`tool_choice: auto`，输出上限 16,384 token，上限同时覆盖思考和审核报告。审核提示、表单、候选、阶段与重发规则不变。
2. 思考模式不接受强制调用工具，所以工具改为提供而不强制。回复没有调用工具、被截断或参数读不出时，按读不出的审核处理，同一请求重发一次（[ADR 0077](0077-an-unreadable-review-or-second-reply-is-sent-once-more.md)）。
3. 审核调用的超时由 45 秒改为 120 秒；其他提案调用仍是 45 秒。
4. 其他服务商的审核请求保持原样：强制调用、不带思考、输出上限 4,000。
5. 审核策略升为 `zhuwei.npc-reply-review/v8`；工作流 hash 随之变化，尚未冻结的方案按 SPEC 0016 §9.2 重问。

## 影响

- 每次审核多约 15–20 秒，多约 3–4 千输出 token。一个交谈行动通常有 1–3 次审核。
- 思考请求与不带思考的请求不共用 DeepSeek 的缓存，所以每个行动的第一次审核不再命中填写调用缓存的冻结上下文（[ADR 0078](0078-the-review-request-opens-like-its-filling-call.md) 的这部分收益在 DeepSeek 上失去），同一行动后续的审核仍命中第一次审核的前缀。
- 审核更严，NPC 重答会增加，每次重答再加一次作答和一次审核。
- 保存的审核响应带 `reasoning_content`，属于私有调用证据，体积比原来大。
- 本次没有真实调用；新排列下的实际耗时、命中和重答次数需要真实批次确认。
