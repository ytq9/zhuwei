# ADR 0051：未读的记忆不冻结，按编号调取时再读

- 状态：已接受
- 日期：2026-09-25
- 依据：[ADR 0050](0050-an-npc-decision-view-carries-its-latest-rounds.md) 之后，冻结上下文仍按房间年龄增长。16 轮测试里，第 8 轮到第 16 轮每轮多约 11,800 字节：行动者和每个在场 NPC 的全部记忆正文都冻结着，以便按编号调取时直接亮出来。其中旧记忆正文每轮约 4,200 字节，它们的引用登记约 2,300，摘要目录约 1,500。每次行动都把这份冻结上下文存下来，归档又逐次带上。用户同意让冻结内容不再随房间增长（“可以”）。
- 当前规则：[SPEC 0016 §4.2–4.3](../specs/0016-coarse-forms-frozen-adjudication-context-and-typed-claims.md)（条款不变）
- 取代范围：冻结行动者和在场 NPC 全部记忆正文的做法（[ADR 0048](0048-each-character-carries-its-latest-six-rounds.md) 所说的“冻结上下文仍保存每个角色的全部记忆”）；摘要目录 vnext-1 的行格式；知识回顾“全部已知”要求每条正文都已冻结的做法。

## 决定

1. 行动者和 NPC 只冻结选择器要读的正文。其余每条记忆在目录里只有摘要和编号，`references.knowledgeRecall` 记着它的条目引用和冻结时的版本。其他角色（例如作为目标的另一名玩家）的知识照旧全部冻结。
2. 选择或补选点名某个编号时，适配器请房间调取（`recallKnowledgeForAction`）。房间从权威状态读出正文，核对版本和单条大小上限，把它存进这次行动的准备数据（`recalledKnowledge`），再返回“冻结上下文 + 已调回正文”。绑定仍是冻结时的那个。之后的各阶段、降级、房间的阶段核对和归档恢复都用这一份；归档逐条按冻结目录里的版本核对调回的正文。
3. 单条正文本身超过选择器的总字数上限时照样算作要读，冻结时按单条上限报告超预算（SPEC 0016 §4.3），不会被当成普通旧记忆放进目录。不读的超大记忆留在目录里，调取时被拒。
4. 知识回顾：“全部已知”选中完整知识目录里的每条记录，未冻结的按目录里的版本进入读取集；“回顾相关已知”只能选已读的记录。
5. 摘要目录改为 vnext-2，每行只有摘要和编号；已冻结的 vnext-1 目录照样展示。

## 后果

- 16 轮测试：第 8 轮到第 16 轮，冻结上下文每轮多约 5,700 字节，原来约 11,800；旧记忆正文不再在冻结上下文里。
- 还在增长的：NPC 视图里的完整记忆目录、知识目录和未读清单（每条 NPC 记忆约 500 字节），调取编号（每条未读记忆约 220 字节），每轮的感知事实（约 750 字节），以及行动者的知识目录条目。要再缩小，需要一个新的 NPC 视图版本，规则侧的比对也要跟着改。
- 交谈事件里存的 NPC 视图现在带着未读清单，每轮多约 300 字节。
- 本改动之前冻结的上下文带着全部正文，照样可用：不带版本的调取编号指向已冻结的正文。
- 调取时如果发现正文在冻结之后变了，这次行动失败（`KNOWLEDGE_RECALL_STALE`）；记忆一般不会再变，这种情况很少。
- NPC 自主行动的请求仍然冻结这个 NPC 的全部记忆正文，这次没有改。
