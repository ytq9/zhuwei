# ADR 0146：地图与行动列表组成的句子放进输入框，行动集中到角色栏

- 状态：已接受
- 日期：2026-10-11
- 依据：用户要求统合背包、动作、法术与资源的放置和触发方式；对"战斗外选好能力与目标后直接发给 KP，还是把句子放进输入框"选择了"放进输入框"，并要求按[桌面统合方案](../agent/proposals/table-ui-consolidation-plan-20261011.md)实施第二期。
- 当前规则：[SPEC 0014 §§4、8](../specs/0014-observer-tactical-map-and-environment.md)
- 取代范围：ADR 0091 第 3 条与 ADR 0103 第 4 条中"点一下即把句子交给 KP"的发送方式；它们交 KP 裁定的结论不变。也取代人物卡上法术条的施放表单和狂暴、动作如潮、回气按钮这两条文字意图入口。

## 原因

同一能力原来有两三个入口，走不同路径：人物卡法术条与职业能力按钮把原始编号拼成一句话交 KP，地图动作条在战斗中直接交 Rules，地图探索面板又是一句话交 KP。人物卡法术条的目标列表取自现役房间恒为空的旧投影，需要目标的法术点不了。

自然语言输入是主入口（SPEC 0009 §7）。地图和行动列表组成的句子放进输入框后，玩家可以补上"趁他转身时"之类的说法再发送，提交的仍是玩家的一句话，与亲口说的一样交 KP 裁定。

## 决定

1. 能力只有一个列表：角色栏"行动"页读 Rules 投影的 `combatControls`。战斗中自己回合选中即直接交 Rules（ADR 0091 第 2 条不变）；遭遇之外组成句子放进输入框。
2. 回合（轮次、剩余动作、附赠、反应与移动、移动与结束回合）和正在进行的选择（目标、范围、帮助、预备、路径、目的地及其确认）放在输入框上方；窄屏全屏地图底部显示同一条确认。地图只负责显示、点选与路径。
3. 门的"前往"、战斗中的攀爬与游泳同样组成句子放进输入框。
4. 有待决选择时不放入新句子，原有限制不变。

## 实现边界

只改展示与触发：`moveOnMap`、`combatAbility`、`endTurn` 与 `sendAction` 的载荷不变，不需要房间迁移。服务端与客户端的 `castSpell`、`useFeature`、`useHitDie` 入口仍被 SPEC 0004/0010 的验收门固定，本次只删除页面上的调用；删除这些入口需另行裁定。
