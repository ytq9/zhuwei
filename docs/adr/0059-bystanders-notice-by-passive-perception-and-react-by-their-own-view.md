# ADR 0059：旁人按被动察觉判定是否发现隐蔽动作，发现后按本人视图当场反应

- 状态：已接受
- 日期：2026-09-26
- 依据：round128–133 里，补选常为了「旁人会不会察觉」加载旁观 NPC 的完整决策视图（每人约 2,500–4,000 token），隐蔽动作的 DC 也由模型自定。用户指出：旁人是否察觉确实影响裁决，但不能加载旁人的完整视图；每个人都掷骰太繁；远处、没注意的人要有处理办法；战术地图还不能跟随剧情，距离不准。提出按 5e 被动检定处理后，用户决定：察觉的人由模型按该角色决定是否当场反应、怎样反应；可能察觉的人由规则按权威状态确定。条款草稿经用户逐段确认（「可以」）。
- 当前规则：[SPEC 0005 §6.2](../specs/0005-world-facts-and-knowledge.md)（察觉判定与感知证据）；[SPEC 0016 §7.3](../specs/0016-part-c-compound-actions-and-claims.md)（隐蔽动作的 DC）；[SPEC 0006 §7](../specs/0006-module-npc-and-faction-protocol.md)（察觉后的当场反应）。
- 取代范围：SPEC 0016 §7.3 中检定 DC 一律由模型填写的做法，对隐蔽动作改由 Rules 给出；提示词里「在场 NPC 能察觉时各写一条所见所闻」由模型逐人书写旁人见证的做法。

## 决定

1. 隐蔽动作只由行动者掷一次骰，旁人不掷骰，用各自的被动察觉比较（5e 被动检定）。可能察觉的人由 Rules 按权威状态确定，模型不增删。
2. KP 只给每个候选人一个注意档位（+5 / 0 / −5 / 看不到）并引用本次冻结上下文里的依据，没有依据时按 0；被动察觉数值、DC 与逐人比较都由 Rules 计算。主 PRD §6 写 KP 决定 DC；用户认可这里的解释：KP 仍决定是否检定、用什么技能和各人的注意档位（相当于有利、不利），DC 的数字按 5e 被动检定取对方属性块，不违背 §6。
3. 察觉者得到感知证据；主要对象的反应写在检定成败分支里；其他察觉了的 NPC 各调用一次模型，只用本人投影，当场决定是否反应、怎样反应，随本次行动发布。玩家角色只得到感知证据。
4. 档位按场景叙述判断，不用战术地图坐标。NPC 目前没有换场景的事件，叙述中已离开的 NPC 暂由 KP 定为「看不到」；NPC 场景移动与状态显示另立后续任务。

## 后果

- 旁观 NPC 不再为了察觉而加载完整视图；每个候选人只在裁决里多约 30 个输出 token。察觉了才为该 NPC 调用一次模型（估计 1–2 万输入 token，实现前实测）。
- 隐蔽动作的 DC 由规则算出，同一场面下不同的人按同一套数值比较，结果可复算。
- 实现涉及检定表单、Rules 结算与事件、房间在同一请求内的 NPC 反应调用和发布；验证需要真实批次覆盖无人察觉、主要对象察觉、旁人察觉并反应三种情况。
