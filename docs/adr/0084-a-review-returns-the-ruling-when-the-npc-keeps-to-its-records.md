# ADR 0084：回答按本人记录成立而与裁决结果冲突时，审核退回裁决

- 状态：已接受
- 日期：2026-10-02
- 依据：round155-3 的失败。用户看过原因和两个方案后回复"第2件按A来"。A 是给审核加一个指向裁决的结论，交给 KP 用现有修订轮次改裁决。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md)（审核在这种情形退回裁决；拒绝同时涉及裁决和回答时先修订裁决；修订后本人输入不变的回答复用，审核绑定新的裁决版本）
- 取代范围：[ADR 0076](0076-review-npc-replies-and-admit-experiences-with-knowledge.md) 中"审核的退回一律交还 NPC 修改"。回答本身有问题时仍交还 NPC，台词仍只由本人修改。

## 原因

[round155-3](../agent/receipts/vnext-round155-validation.md)：玩家没报姓名，就要莉安交出酒窖铁钥。KP 判说服检定 DC 13，成功分支写"她愿意就铁钥和酒窖的事继续谈下去"。莉安的行为边界写着没介绍前不谈，铁钥也不在她手上。她在成功、失败两种情形都回答"你先把你叫什么、来守灵还是办事告诉我。酒窖的事今晚先不提。"审核指出成功分支的回答和成功结果冲突，退回莉安重答。她重答还是这一句，第二次审核又退回，行动以 `PROPOSAL_REPAIR_EXHAUSTED` 结束。

错的是裁决：成功结果要莉安做她本人记录不允许的事。审核的结论只能指向回答，处理只有让本人重答一次、再不过就失败，没有让 KP 改裁决的路径。

另一个方案是只收紧 KP 的写法（B）。指引已经要求交谈摘要只写这番话起没起作用，模型没有遵守；而且莉安两份回答相同，审核仍会退回。所以不采用。

## 决定

1. 审核表单的 `reason` 增加 `rulingConflict`：回答依照本人记录和行为边界成立，而这种情形的裁决结果要本人做出这些记录不允许的回应。审核在 `ownRefs` 里选出那条记录。
2. 结算读到针对当前回答的 `rulingConflict` 时，不再让本人重答，而是把方案连同裁决诊断 `npc-review:ruling-conflicts-with-npc` 交回 KP。诊断指向该分支的结果摘要，带上 NPC、它的回答和所依据的记录引用；审核者的私有理由不随诊断发送。同一次审核里还有针对回答的其他问题时，先改裁决，回答的问题由新裁决的审核重新判断。
3. KP 在现有修订轮次内改判，占用裁决的修订额度，不新增调用类型。改判后，NPC 听到的内容不变时复用原回答；变了（例如去掉检定）则重新作答。审核绑定新的裁决版本，重新计审核阶段。
4. 适配器和 Room 用同一个结算函数。Room 从保存的审核证明这次修订应当发生，调用方的诊断不能单独授予修改。
5. 审核策略升为 `zhuwei.npc-reply-review/v9`；工作流 hash 随之变化，尚未冻结的方案按 SPEC 0016 §9.2 重问。

## 影响

- 审核请求的系统消息多一句（102 个字符，估计约 60 token），表单的 `reason` 多一个枚举值。提案的选择和填写请求不变。
- 这类冲突从"NPC 重答一次后失败"变为"KP 改一次裁决后再审核"：多一次 KP 修订调用和一次审核，可能多一次 NPC 作答。总次数仍受修订轮次和审核序号上限约束。
- 审核需要分辨回答错了还是裁决错了。把回答的错误判成裁决的错误，会多一次 KP 修订，回答的问题仍在新裁决的审核里退回本人；把裁决的错误判成回答的错误，结果和以前一样失败。
- 本次没有真实调用。审核是否会选用这个类别、KP 会怎样改判，需要真实批次确认。
