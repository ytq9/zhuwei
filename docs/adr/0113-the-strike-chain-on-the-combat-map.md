# ADR 0113：地图上的一击：武器名称、徒手攻击、急救与 NPC 的攻击选项

- 状态：已接受
- 日期：2026-10-05
- 依据：一次战斗审计发现，"玩家出手 → 命中或落空 → 伤害 → 0 HP → 死亡豁免或急救"这条链从未在真实调用中跑通，并有几处具体缺陷：玩家用武器攻击，回复材料把它叫作"该能力"；地图上的"徒手攻击"按 1d4 + 力量结算；地图不提供急救；真实运行里奈斯只移动、闪避、结束回合。0111、0112 可能被并行的其他任务占用，本 ADR 取 0113。
- 当前规则：[SPEC 0016 §8.2](../specs/0016-part-c-compound-actions-and-claims.md)（能力名称）、[SPEC 0012 §6.3](../specs/0012-authoritative-combat-mechanics.md)（擒抱与推撞）、[SPEC 0012 §§9.1、12.1](../specs/0012-part-b-abilities-damage-and-conclusion.md)（能力模型、0 HP 与急救）、[SPEC 0014 §8](../specs/0014-observer-tactical-map-and-environment.md)（地图）、[SPEC 0006 §§6、7](../specs/0006-module-npc-and-faction-protocol.md)（NPC 的战斗回合）
- 取代范围：无。规格条款没有改动，本 ADR 记录实现上的选择。

## 决定

1. **武器的名称从物品来，按每个观察者自己知道的算。** 编译出的武器攻击只记着所用的物品条目（`weapon:<条目>`），本身没有名字。Rules 给每个观察者的 Claims 名称表加上这次出手所用武器的名字：观察者自己的投影列出这件物品时，用投影里的名字（没辨认出的物品不给名字）；没列出时，只要这件物品的定义对他公开或他已辨认过，就用物品的名称。谁拿着什么仍按原规则保密，但一次出手会让看见的人看到所用的武器。都不满足时叫"武器"。出手者和旁观的玩家看到同一个名字，和行动栏一致。攻击者的能力目录不作为别人的名称来源，与原有约定相同。
2. **徒手攻击按 SRD 5.1。** 伤害是 1 + 力量调整值的钝击，无骰子，熟练。伤害公式允许不带骰子的定值（如 `1+3`），这一份不请求伤害骰，重击也没有骰子可以加倍；只有伤害部分接受定值，治疗、临时生命值和危害仍要求骰子。机械键由 `improvised-strike` 改为 `unarmed-strike`，定义编号随之改变。目录里已经冻结了旧"徒手攻击"（1d4 + 力量）的房间继续编译旧的那一份，已记录的事件照原样回放；新房间和新角色用新的。
3. **地图上的急救。** Rules 在行动栏的可选项里加上急救：在自己触及内、看得见、0 HP、要做死亡豁免、尚未稳定、未死亡的生物。表格只在有这样的生物时列出"急救"，目标限于 Rules 列出的生物（`onlyRefs`），提交走与其他地图动作相同的结构化路径（ADR 0091、0104）。DC 10 感知（医药）检定的结果作为一条 Claim 给看得见双方的观察者，成功时由死亡豁免那条 Claim 说明伤势已稳定。
4. **NPC 回合的选项写明每个攻击是什么、够多远。** 选项里每个能力加上 NPC 对它的称呼（所持武器、KP 写的攻击名、法术名、内置动作名）和触及或射程（尺）。此前 NPC 只能看到一个引用和"此刻够不够得着"，它自己的能力定义在投影里也不含目标和名称。擒抱、推撞和推开以一名玩家为目标时，需要那名玩家自己选择用运动还是体操对抗，NPC 的回合没有办法拿到这个选择，Rules 执行时总是拒绝；这类选项此前列出，并把紧挨着的玩家标为够不着。现在不再对玩家列出。没有规定 NPC 该选什么。
5. **探针开局给奈斯一个攻击。** 探针用 Rules 直接开局时，奈斯的战斗属性此前没有任何攻击，所以他的回合只能移动、闪避或结束。现在开局时他带一把钉头锤（近战，触及 5 尺，1d6 钝击），写法与 KP 开战时写的攻击相同。这影响所有直接开局的探针样例。

## 影响

- 新增探针样例 `combat-strike` 和 `combat-strike-down`。
- NPC 回合请求：对玩家不再列出的三项对抗使请求变短；每个能力多出名称和距离几个字段。提案请求体积不变。
- 没有做的：NPC 对玩家的擒抱和推撞（需要玩家选择对抗技能）；把 KP 写的攻击名告诉旁观的玩家（KP 写的名字可能带出看不到的信息，留待裁定）；职业特性（回气、动作如潮）对观察者的名称；NPC 的急救选项；双武器、投掷、临时武器和 NPC 多重攻击由另一项任务处理。
- 本次没有真实调用验证。
