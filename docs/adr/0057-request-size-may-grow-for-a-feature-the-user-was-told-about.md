# ADR 0057：提案请求体积可以为告知过的功能增长，不能冗余

- 状态：已接受
- 日期：2026-09-26
- 依据：提议在检定规则里加 5e 的 DC 档位时，按 [ADR 0035](0035-ratchet-the-vnext-proposal-request-size.md) 说明了提示词只能降不能升、需要从别处删掉同样长度。用户回答：「提示词不是只能降不能升，合理的功能添加告知后可以加提示词但不能冗余」。起因是 DC 没有锚点：同一句请莉安配合的话在 round123–125 三个新房间里分别定成 DC 15、7、15。
- 当前规则：[SPEC 0016 §7.2](../specs/0016-part-c-compound-actions-and-claims.md) 管调用额度与预算，本指标守的是它；体积如何记账见下面的决定与 `tools/gate.mjs`。
- 取代范围：ADR 0035 决定 1 中的「只降不升」。

## 决定

1. `requestSize` 仍按 22 个选择逐项测量。任何一项变大，`node tools/gate.mjs --check` 仍然失败，增长不会悄悄进入仓库。
2. 为一项合理的功能加提示词时，先告诉用户加什么、为什么加、各选择大约多多少 token。之后在加文字的同一次提交里运行 `node tools/gate.mjs --accept-request-size`，把 `requestSize` 基线改成实测值，提交说明写明功能和增量。`--update` 仍然只收紧。
3. 新加的文字不能重复提示词已有的内容。加之前先查已有措辞，能改写已有句子就不另加句子。
4. 其他棘轮组（模块边界违规、测试失败、断链等）不变，仍然只收紧。
5. 运行时的输入预算上限 `VNEXT_PROPOSAL_BUDGET` 不在本决定范围内：请求超出预算时仍按相关性缩减上下文，不抬高上限。

## 后果

- 首次按本决定增长：提示词 v50–v52 加入 5e DC 档位（写在其他 DC 规则旁），并把「瞒着旁人的举动或话要检定」写明。与 `450da31` 相比，22 个选择各多 42–43 个估算 token。
- `tools/gate.mjs` 新增 `--accept-request-size`。它只改 `requestSize` 组；同时给出 `--update` 时，其他组照常只收紧。
