# ADR 0026：先准备自然语言回复，再提交行动结果

- 状态：已接受
- 日期：2026-09-17
- 依据：用户明确要求无法回复时自动回滚，随后批准“可以改，连带着前面那些修改内容一起改了”。
- 当前规则：[SPEC 0003 §1、7、11](../specs/0003-authoritative-action-transaction.md)、[SPEC 0015 §7–8](../specs/0015-part-b-proposal-and-narration.md)、[SPEC 0016 §8.3](../specs/0016-part-c-compound-actions-and-claims.md)、[SPEC 0010 §8.2](../specs/0010-part-b-delivery-and-acceptance.md)、[SPEC 0011 §2](../specs/0011-reliability-correction-observability-and-evaluation.md)。

先提交机械再生成旁白，会把模型输出故障变成玩家已经付出代价却拿不到结果的问题。单独取消最终 Activity 结算也不够，因为其开始和时间推进可能已在同次请求中先行写入。选择在同一 Room DO 中保存私有候选事件与随机 journal，由原 Rules replay 恢复该准备状态；只有因果相连的内部继续点读取它，普通 observe 始终读取已提交事件。完整回复与世界由同一个 SQLite 同步事务提交，外部模型调用始终在事务外。

该决定窄取代旧提交顺序以及新未提交结果的逐受众独立发布。既有已提交结果仍保留原恢复语义，故障历史只能通过审计更正；不建立提交后偷偷删除事件的回滚路径。无关作用域的并发事件保留，相关依赖变化取消候选；重新排序准备事件只更新权威日志地址，不能改骰面、决定、事实或授权。

自然语言生成与简短审核减少了与表达无关的结构失败面。新策略独立版本化，服务端用精确调用记录绑定正文和材料；旧 Prompt、Schema、工作流 hash、物理调用与计费身份不变。此次取代 ADR 0024 中新回复沿用 v17 前两阶段结构的选择，保留其一次实质修稿、禁止无限重试和原调用恢复原则。ADR 0025 的提案显式恢复不受影响。

候选取消证据单独进入私有旁白宿主归档，包含可回放的准备分支和终局身份；恢复只重建取消结果与物理调用证据，不把候选事件写入世界，不还原公共 Delivery 文本。该记录解释失败并防止相同 submission 重执行，不形成第二个活跃世界。

开发期验证覆盖真实本地 Room/Rules/action/调用账本，包括资源扣除、持续行动时间、固定随机、多受众隔离、响应丢失、重启/截止恢复、并发及归档往返；模型 I/O 使用脚本。真实模型审核准确性和生产表现不能由这些确定性测试证明。本决定不授权部署、远端 migration、创建资源或修改 Secrets。
