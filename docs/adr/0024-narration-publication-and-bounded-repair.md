# ADR 0024：旁白发布分级与一次有界修稿

- 状态：已接受
- 日期：2026-09-15
- 依据：用户在 A48CY8 的同句回复被表达审核反复阻断后，明确批准“可以，改吧”：表达意见不单独阻断，实质问题一次修稿及复审，移除无效重试。
- 当前规则：[SPEC 0016 §8.3](../specs/0016-part-c-compound-actions-and-claims.md#83-narrationgrounding-与重试)、[SPEC 0015 §7–8](../specs/0015-part-b-proposal-and-narration.md)、[SPEC 0011 §2–3](../specs/0011-reliability-correction-observability-and-evaluation.md)。

旧发布流程把表达问题与事实、权限问题一并拒绝；恢复复用原生成和审核响应，因而相同表达拒绝不会因点击而变化。本决定窄取代旧流程对所有表达意见硬拒绝、仅初稿加一次审核且不能修稿的部分。保留事实、机械、来源、保密及玩家自主权边界；结构校验不能证明语义审核一定正确，实质不确定意见不作为已证实的错误修稿。

线上房间已绑定 v17 传输策略和精确的前两阶段请求。修改其 Prompt 或 maximumCalls 会改变整个工作流哈希，并破坏现有调用及归档恢复。因此增加独立的发布策略及哈希；前两阶段保持原请求和绑定，第三、四阶段使用新策略绑定。新增阶段请求由原冻结材料及已保存响应重建，调用账本、预算和未知结果规则继续复用，不增加持久化表或迁移。包含新增阶段的旁白归档使用 v2 宿主格式；仅有原两阶段的 v1 格式不变，两种格式均严格重建请求。

发布策略和阶段构造集中在 `narration-publication.ts`，由适配器、Room 和归档验证共用。Room 从自己的调用记录推导恢复资格及最终可发布正文；前端只展示该资格，不根据错误文案授予新调用。私有原稿、报告及修稿留在原调用账本，普通日志继续采用现有脱敏字段。

验收采用同一通路覆盖 NPC 台词和机械数量的纯表达意见、数量/玩家自主权/保密实质拒绝、混合问题、损坏或矛盾报告、实质不确定、修稿后再次拒绝、阶段中断及未知结果、原房间恢复和新增归档往返。真实模型判断的稳定性仍须以线上结果评估，确定性测试不等同于真实模型语义证明。
